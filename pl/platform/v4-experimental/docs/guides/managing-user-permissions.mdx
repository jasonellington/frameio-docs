title: "Zarządzanie uprawnieniami użytkowników"
---

Ten przewodnik wyjaśnia, jak zarządzać uprawnieniami użytkowników za pomocą Frame.io V4 API. Opisuje, jak działają uprawnienia na poziomie konta (Account), Workspace'u i projektu (Project) oraz których endpointów należy używać na każdym z tych poziomów.

---

## Poziomy uprawnień {#permission-levels}

Uprawnienia w Frame.io są zarządzane na poziomie konta, Workspace'u i projektu. Każdy poziom korzysta z własnego zestawu ról:

```
Account 
│
├── (admin)  - full access to all Workspaces, Projects, and Restricted Projects
│
└── (member)
        │
        ├── Workspace - (full_access | editor | edit_only | commenter | viewer)
        │       │
        │       └── Project - (full_access | editor | edit_only | commenter | viewer)
        │
        └── Restricted Project - (members require direct invite)
```

Każdy użytkownik ma rolę na poziomie konta. Za pomocą API możesz ustawić rolę użytkownika na <Tooltip tip="W odpowiedziach API mogą pojawiać się role Owner i Reviewer, ale nie można ich konfigurować za pomocą API. Więcej szczegółów znajdziesz w sekcji Uprawnienia na poziomie konta.">`admin` lub `member`.</Tooltip>
Administratorzy konta (Account Admins) mają pełny dostęp do wszystkich Workspace'ów i projektów. Członków konta (Account Members) można selektywnie dodawać do potrzebnych im Workspace'ów i projektów.

Gdy dodajesz członka konta do Workspace'u, przypisany przez Ciebie poziom uprawnień (`full_access`, `editor`, `edit_only`, `commenter` lub `viewer`) obowiązuje we wszystkich istniejących i przyszłych projektach w tym Workspace. Na przykład jeśli dodasz członka konta jako `viewer`, będzie on miał uprawnienia `viewer` za każdym razem, gdy uzyska dostęp do dowolnego projektu w tym Workspace.

Tego samego członka konta można dodać do konkretnego projektu w tym Workspace jako `editor`. W rezultacie za każdym razem, gdy uzyska dostęp do tego projektu, będzie miał uprawnienia `editor`. Jego uprawnienia `viewer` nadal obowiązują we wszystkich pozostałych projektach w tym Workspace.

Ponieważ przypisania do projektów są niezależne od przypisań do Workspace'ów, po usunięciu tego członka konta z Workspace'u zachowa on swoje uprawnienia `editor` do tego jednego projektu.

Wyjątkiem są projekty z ograniczonym dostępem (Restricted Projects). Członkowie konta zawsze potrzebują bezpośredniego zaproszenia. Więcej na ten temat w sekcji Uprawnienia na poziomie projektu poniżej.

## Uprawnienia na poziomie konta {#account-level-permissions}

Każdy użytkownik na Twoim koncie ma przypisaną rolę:

| Rola | Uprawnienia | Konfigurowalna przez API | Endpoint |
| --- | --- | --- | --- |
| Owner | Pełny dostęp do wszystkich Workspace'ów i projektów. Jeden na konto | Nie | — |
| <Tooltip tip="W interfejsie oznaczona jako 'Content Admin'">`admin`</Tooltip> | Pełny dostęp do wszystkich Workspace'ów i projektów | Tak | `PATCH /accounts/:account_id/users/:user_id` |
| `member` | Uprawnienia ustawiane na poziomie Workspace'u i/lub projektu | Tak | `PATCH /accounts/:account_id/users/:user_id` |
| Reviewer | Dostęp wyłącznie przez linki udostępniania. Tworzony, gdy użytkownik zostanie dodany do bezpiecznego udostępnienia | <Tooltip tip="Recenzenci (Reviewers) pojawiają się na listach użytkowników konta, ponieważ uwierzytelniają się w Frame.io, ale funkcjonują poza systemem uprawnień Workspace'ów i projektów. Uzyskują dostęp do treści wyłącznie przez bezpieczne linki udostępniania.">Nie</Tooltip> | — |

---

Administratorzy konta mają pełny dostęp wszędzie. Aby ograniczyć dostęp administratora do określonych zasobów, najpierw zmień jego rolę na koncie na Member, a następnie dodaj go do potrzebnych mu Workspace'ów lub projektów.

Na przykład:

<Steps>

<Step title="Wyświetl listę ról użytkowników konta, aby znaleźć identyfikator użytkownika i potwierdzić jego bieżącą rolę:">

```bash

curl https://api.frame.io/v4/accounts/:account_id/users \
     -H "Authorization: Bearer <token>"
```

</Step>

<Step title="Zmień rolę na koncie na Member:">

```bash

curl -X PATCH https://api.frame.io/v4/accounts/:account_id/users/:user_id \
 -H "Authorization: Bearer <token>" \
 -H "Content-Type: application/json" \
 -d '{
"data": {
"role": "member"
}
}'
```

</Step>

<Step title="Dodaj użytkownika do projektu:">

```bash

curl -X PATCH https://api.frame.io/v4/accounts/:account_id/projects/:project_id/users/:user_id \
  -H "Authorization: Bearer <token>" \
  -H "Content-Type: application/json" \
  -d '{
"data": {
 "role": "edit_only"
}
}'
```

</Step>

</Steps>

## Uprawnienia na poziomie Workspace'u {#workspace-level-permissions}

Gdy dodajesz członka konta do Workspace'u, otrzymuje on dany poziom uprawnień we wszystkich projektach w tym Workspace. Dostęp do Workspace'ów odbywa się wyłącznie na zaproszenie, więc członkowie konta widzą tylko te Workspace'y, do których zostali dodani.

<br />

| Rola | Uprawnienia |
| --- | --- |
| `full_access` | Przesyłanie, zarządzanie, udostępnianie, komentowanie, wyświetlanie, pobieranie, zarządzanie ustawieniami i zapraszanie użytkowników |
| `editor` | Przesyłanie, zarządzanie, udostępnianie, komentowanie, wyświetlanie, pobieranie |
| `edit_only` | Przesyłanie, zarządzanie, komentowanie, wyświetlanie. Brak możliwości udostępniania i pobierania |
| `commenter` | Wyświetlanie i komentowanie |
| `viewer` | Tylko wyświetlanie |

<br />

## Uprawnienia na poziomie projektu {#project-level-permissions}

Projekty korzystają z tych samych poziomów uprawnień co Workspace'y. Dodaj użytkownika bezpośrednio do projektu, gdy potrzebuje dostępu tylko do tego konkretnego projektu lub gdy potrzebuje innego poziomu uprawnień niż wynikający z przypisania do Workspace'u. Użytkownicy nie muszą mieć dostępu do Workspace'u, aby można ich było dodać do projektu.

<br />

| Rola | Uprawnienia |
| --- | --- |
| `full_access` | Przesyłanie, zarządzanie, udostępnianie, komentowanie, wyświetlanie, pobieranie, zarządzanie ustawieniami i zapraszanie użytkowników |
| `editor` | Przesyłanie, zarządzanie, udostępnianie, komentowanie, wyświetlanie, pobieranie |
| `edit_only` | Przesyłanie, zarządzanie, komentowanie, wyświetlanie. Brak możliwości udostępniania i pobierania |
| `commenter` | Wyświetlanie i komentowanie |
| `viewer` | Tylko wyświetlanie |

<br />

**Przykład: dodawanie użytkownika do projektu**

```bash

curl -X PATCH https://api.frame.io/v4/accounts/:account_id/projects/:project_id/users/:user_id \
     -H "Authorization: Bearer <token>" \
     -H "Content-Type: application/json" \
     -d '{
  "data": {
    "role": "full_access"
  }
}'
```

---

### Projekty z ograniczonym dostępem {#restricted-projects}

Projekty z ograniczonym dostępem wymagają bezpośredniego zaproszenia. Dostęp do Workspace'u nie jest przenoszony,
więc użytkownicy mogą uzyskać dostęp do projektu z ograniczonym dostępem tylko wtedy, gdy zostali do niego dodani bezpośrednio.

Aby przyznać dostęp członkowi konta, dodaj go do projektu z odpowiednim poziomem uprawnień.

<Note>

Wyjątkiem są administratorzy i właściciele konta, którzy mają dostęp do wszystkich
projektów z ograniczonym dostępem.

</Note>
