## Dostęp dla wszystkich kont {#all-account-access}

Wszystkie konta Frame V4 — nie tylko te zarządzane za pośrednictwem Adobe Admin Console — mogą tworzyć tokeny i korzystać z API V4. Klienci i partnerzy mogą testować, tworzyć i dopracowywać swoje przepływy pracy z wykorzystaniem naszych najnowszych funkcji API.

<Steps>

<Step title="Utwórz token uwierzytelniania użytkownika">

Przejdź do Adobe Developer Console, aby utworzyć token uwierzytelniania użytkownika. Aby zweryfikować dostęp do tokenu API, użytkownik musi używać tego samego Adobe ID, którego używa do logowania się we Frame.

</Step>

<Step title="Utwórz dane uwierzytelniające API">

Po uzyskaniu dostępu do interfejsów API następnym krokiem jest utworzenie danych uwierzytelniających API, czyli tokenu API, do komunikacji z Frame. Dane uwierzytelniające API utworzysz na stronie developer.adobe.com.

</Step>

</Steps>

![Account Access](/images/platform/docs/guides/accounts-projects-and-workspaces/706a4eb9324bc24a3465388a838455baf58384f128882a185dad2d1900f728a3.webp)

<Info>

Wszystkie konta V4, zarówno zarządzane przez Frame (V4F), jak i przez Adobe (V4A), mogą utworzyć projekt w Adobe Developer Console, a następnie utworzyć dane uwierzytelniające. Gdy masz zestaw danych uwierzytelniających (OAuth Client ID/Client Secret), możesz zintegrować się z trójstronnym przepływem OAuth (three-legged OAuth) platformy Adobe Developer Platform. Zaloguj się za pomocą swojej tożsamości Adobe, aby otrzymać prawidłowy token uwierzytelniający i token odświeżania, i wysyłaj żądania do Frame.io V4 Developer API!

</Info>

## Projekty i obszary robocze {#projects-and-workspaces}

### Zmiany w obszarach roboczych {#workspace-updates}

Strona startowa Frame.io jest nowa i nosi nazwę strony Workspace. Użytkownicy mogą przeglądać obszary robocze i projekty, do których mają dostęp w ramach konta. Dzięki nowemu projektowi łatwiej sprawdzić, kto należy do danego obszaru roboczego, i szybko zapraszać nowe osoby.

<Note>

We Frame V3 obszary robocze nazywano zespołami (Teams).

</Note>

W V4 obszary robocze są ustawione jako dostępne wyłącznie na zaproszenie, więc użytkownicy widzą tylko te obszary robocze, do których zostali wyraźnie zaproszeni. Ponadto w ustawieniach konta nie ma strony Team Directory.

Do zarządzania uprawnieniami i powiązanymi operacjami używaj punktów końcowych Create, List, Delete i Update Workspace.

<CardGroup cols={1}>

<Card title="Operacje zarządzania obszarami roboczymi" icon="users" iconType="solid" horizontal={true}>

- Wyświetlanie listy ról użytkowników dla danego obszaru roboczego.
- Usuwanie użytkownika z danego obszaru roboczego.
- Aktualizowanie ról użytkownika w danym obszarze roboczym, jeśli użytkownik został już do niego dodany. Jeśli użytkownik nie został dodany do obszaru roboczego, zostanie dodany z podaną rolą.

</Card>

</CardGroup>

### Zmiany w projektach {#project-updates}

W V4 zmienił się proces tworzenia projektów. Rozpoczynając nowy projekt, wybierasz teraz pusty projekt lub szablon projektu. Do wyboru jest dwanaście szablonów zaprojektowanych z myślą o typowych kreatywnych przepływach pracy. Możesz też dołączyć zasoby demonstracyjne szablonu lub zacząć tylko od jego struktury. Wybranie szablonu projektu natychmiast tworzy nowy projekt w Twoim obszarze roboczym.

Do zarządzania uprawnieniami i powiązanymi operacjami używaj punktów końcowych Create, List, Delete i Update Project.

<CardGroup cols={1}>

<Card title="Operacje zarządzania projektami" icon="folder" iconType="solid" horizontal={true}>

- Wyświetlanie listy ról użytkowników dla danego projektu.
- Usuwanie użytkownika z danego projektu.
- Aktualizowanie ról użytkownika w danym projekcie, jeśli użytkownik został już do niego dodany. Jeśli użytkownik nie został dodany do projektu, zostanie dodany z podaną rolą.

</Card>

</CardGroup>
