## Pytania dotyczące zgodności {#compatibility-questions}

<AccordionGroup>

<Accordion title="Czy Frame.io V4 API jest wstecznie zgodne?">

<Warning>

Nie. Produkt Frame.io zaprezentowany na Adobe MAX działa w zasadniczo inny sposób i kładzie nacisk na inne przepływy pracy niż starsza wersja. Ze względu na te różnice nowe API nie jest wstecznie zgodne.

</Warning>

</Accordion>

<Accordion title="Jak w przyszłości będzie zapewniana zgodność wsteczna?">

Zdajemy sobie sprawę, że zgodność wsteczna jest kluczową kwestią dla klientów utrzymujących produkcyjne integracje o wysokich wymaganiach dotyczących dostępności. Dlatego projektujemy V4 API tak, aby obsługiwało dodatkowy poziom wersjonowania za pomocą niestandardowego nagłówka HTTP. Pozwoli to klientom świadomie korzystać z endpointów eksperymentalnych, uniknąć zmian powodujących niezgodność i zapewni gwarancje zgodności wstecznej w przestrzeni nazw API `/v4`.

</Accordion>

<Accordion title="Czy po udostępnieniu V4 API automatyzacje skonfigurowane w starszym produkcie będą nadal działać? Tzn. czy zostaną automatycznie zmigrowane do V4?">

<Warning>

Wszystkie automatyzacje korzystające ze starszych tokenów programisty (developer tokens) przestaną działać na kontach V4. **Nie mamy** żadnej możliwości ich migracji do V4.

</Warning>

</Accordion>

</AccordionGroup>

## Multimedia i pliki {#media-&-files}

<AccordionGroup>

<Accordion title="Jak długo ważne są adresy URL linków do multimediów?">

Adresy URL zwracane w `media_links` (takie jak `download_url`, `inline_url` i `url`) to **tymczasowe podpisane adresy URL** — wygasają i nie można ich używać bezterminowo.

| Typ adresu URL | Czas ważności |
| --- | --- |
| Adresy URL do pobierania i wyświetlania inline (`original`, `high_quality`, `efficient`, `video_h264_180`) | Do 24 godzin |
| Adresy URL miniatur i podglądów (`thumbnail`) | Do 24 godzin |

W praktyce wygasanie jest wyrównane do południa lub północy UTC, więc rzeczywisty czas pozostały w chwili otrzymania adresu URL może wynosić od kilku minut do 24 godzin, w zależności od momentu wysłania żądania.

**Nie przechowuj tych adresów URL ani nie zapisuj ich w pamięci podręcznej.** Za każdym razem, gdy musisz udostępnić plik lub uzyskać do niego dostęp, pobieraj nowy zestaw `media_links`. Próba użycia wygasłego adresu URL spowoduje zwrócenie przez CDN błędu `403`.

</Accordion>

</AccordionGroup>
