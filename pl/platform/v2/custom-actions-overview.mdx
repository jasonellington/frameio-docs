Custom Actions to sposób na budowanie integracji bezpośrednio w Frame.io w postaci programowalnych komponentów interfejsu użytkownika. Umożliwia to całą klasę workflowów, które użytkownicy mogą uruchamiać w aplikacji, z wykorzystaniem tego samego mechanizmu routingu zdarzeń co [Webhooks](/pl/platform/v2/webhooks-overview). Obecnie Custom Actions są dostępne dla Assetów i wyświetlają się w menu kontekstowym (pod prawym przyciskiem myszy) dostępnym dla każdego Assetu, jak pokazano na poniższym obrazku.

![actions-1](/images/platform/v2/custom-actions-overview/69bc65d3924a350e0c1d5a8062e41b15cbc3b01f1f3b8ec5050356b76aa1989a.webp)

Asset to rozbudowana reprezentacja pliku w S3 i jego kontekstu w Frame.io. Obejmuje transkodowania, kontekst użytkownika/zespołu/projektu oraz metadane. Gdy użytkownik kliknie Custom Action na Assecie, Frame.io wyśle payload na podany przez Ciebie adres URL. Aplikacja odbierająca może wtedy odpowiedzieć kodem statusu HTTP, aby jedynie potwierdzić odbiór, lub niestandardowym callbackiem, który może wyświetlić dodatkowy interfejs w Frame.io.

## Skonfiguruj swoją Custom Action {#setup-your-custom-action}

<Info>

**Sprawdź swoje uprawnienia**

Do tworzenia Custom Actions dla zespołu wymagane są uprawnienia Team Managera. Jeśli nie masz dostępu, poproś administratora o zmianę uprawnień.

</Info>

Custom Actions można skonfigurować w sekcji [Custom Actions](https://developer.frame.io/actions) witryny [developer.frame.io](/pl/platform/v2). Akcja wymaga:

| Nazwa pola | Opis |
| --- | --- |
| Name | Wybrana przez Ciebie nazwa Custom Action. Będzie widoczna w menu dostępnych Custom Actions w Frame.io. |
| Description | Wyjaśnienie, co robi akcja, do celów informacyjnych (opis nie pojawia się w aplikacji webowej Frame.io). |
| Event | Wewnętrzny klucz zdarzenia, który pomaga odróżnić standardowe zdarzenia webhooków od Twoich własnych. |
| URL | Adres, na który mają być dostarczane zdarzenia. |
| Team | Zespół, który będzie korzystać z Custom Action. |

## Kliknięcie – co zawiera payload otrzymywany z Frame.io {#click-what’s-in-the-payload-you-receive-from-frame-io}

Gdy użytkownik kliknie Twoją Custom Action, payload zostanie wysłany na adres URL podany w polu URL.

```json
POST /your/url
{
  "action_id": "2444cccc-7777-4a11-8ddd-05aa45bb956b",
  "interaction_id": "aafa3qq2-c1f6-4111-92b2-4aa64277c33f",
  "project": {
    "id": "a7d6a74b-d45d-4019-9069-24651e0b9f64"
  },
  "resource": {
    "id": "9q2e5555-3a22-44dd-888a-abbb72c3333b",
    "type": "asset"
  },
  "team": {
    "id": "54353cd2-c6ee-4aa1-954a-ce9e19602aa9"
  },
  "type": "my.action",
  "user": {
    "id": "fb57eee0-79f2-4bc7-9b70-99fbc175175c"
  }
}
```

Na podstawie tego payloadu możesz ustalić:

- Która z Twoich Custom Actions została kliknięta
- Który zasób został kliknięty
- Który użytkownik wykonał akcję

| Nazwa pola | Opis |
| --- | --- |
| `action_id` | Unikalny identyfikator tej akcji. Dla danej akcji jest zawsze taki sam. |
| `interaction_id` | Unikalny identyfikator generowany przez Frame.io, którego możesz używać do śledzenia swojej transakcji. Identyfikator ten pozostaje taki sam przez całą pojedynczą sekwencję akcji, łącznie z formularzami callback. |
| `type` | Nazwa zdarzenia wpisana w polu Event podczas konfigurowania akcji. |
| `resource.id` | Identyfikator zasobu, z którego uruchomiono akcję (zwykle Asset). |
| `resource.type` | Typ zasobu, z którego uruchomiono akcję (zwykle *asset*) |

<Info>

**Informacje o interakcjach**

`interaction_id` jest udostępniany jako unikalny identyfikator, który pomaga śledzić interakcję w miarę jej rozwoju. Jeśli nie musisz odpowiadać użytkownikowi, po prostu zwróć kod statusu 200 i gotowe. Choć jest to opcjonalne, zalecamy dołączenie informacji o wyniku akcji, np. prostego komunikatu o powodzeniu lub alertu o błędzie. Custom Actions obsługują callbacki z komunikatami.

</Info>

<Info>

**Ponowienia i limity czasu**

Nasza aplikacja oczekuje odpowiedzi w czasie krótszym niż 5 sekund i podejmie do 5 ponownych prób w oczekiwaniu na pomyślną odpowiedź. Najlepiej odpowiadaj natychmiast, a wszelkie działania wykonuj asynchronicznie po ich wyzwoleniu przez Custom Action.

</Info>

## Utwórz callback z komunikatem {#create-a-message-callback}

W odpowiedzi HTTP na zdarzenie webhooka możesz zwrócić obiekt JSON opisujący komunikat, który zostanie wyświetlony użytkownikowi inicjującemu akcję w interfejsie Frame.io. Jeśli chcesz spróbować zbudować komunikat i zobaczyć, jak będzie wyglądał, skorzystaj z naszego [Custom Action Builder](https://next.frame.io/settings/actions), który pozwala skonfigurować callbacki z komunikatami lub formularze i zobaczyć, jak wyglądałyby w aplikacji webowej Frame.io.

Oto przykładowy obiekt:

```json
{
  "title": "Success!",
  "description": "The thing worked! Nice."
}
```

Spowoduje to wyświetlenie użytkownikowi alertu, który wygląda tak:
![actions-3](/images/platform/v2/custom-actions-overview/a7fe1ec18a4467f8b450b31d1e3a70ab26beece9f5ed828166f4d35973e55c3c.webp)

Komunikaty to prosty sposób na zamknięcie cyklu życia akcji, który dostarcza użytkownikowi zmienny kontekst bez konieczności przełączania się do innego miejsca.

To wystarcza w wielu przypadkach użycia, ale czasem początkowy payload i kolejne wywołania API Frame.io nie zapewniają aplikacji odbierającej wystarczającego kontekstu. Na potrzeby takich scenariuszy obsługujemy również **callbacki z formularzami**.

## Utwórz callback z formularzem {#create-a-form-callback}

Załóżmy, że przed rozpoczęciem procesu potrzebujesz więcej informacji. Na przykład możesz przesyłać treści do systemu, który wymaga dodatkowych szczegółów i ustawień. W odpowiedzi możesz „opisać” formularz, który użytkownik faktycznie zobaczy! I wypełni! A on zostanie odesłany prosto do Ciebie!

Oto przykład, który wyświetli w interfejsie Frame.io formularz, który użytkownik inicjujący akcję może wypełnić i przesłać:

```json
{
  "title": "Need some more info!",
  "description": "Getting ready to submit this file!",
  "fields": [
    {
      "type": "text",
      "label": "Title",
      "name": "title",
      "value": "MyVideo.mp4"
    },
    {
      "type": "select",
      "label": "Captions",
      "name": "captions",
      "options": [
        {
          "name": "Off",
          "value": "off"
        },
        {
          "name": "On",
          "value": "on"
        }
      ]
    }
  ]
}
```

![actions-form](/images/platform/v2/custom-actions-overview/4538043046be16b30b0230c21291dde8ae51554dc1da719bec8b9f7561c7c8a1.webp)

Gdy użytkownik prześle formularz, otrzymasz zdarzenie na ten sam adres URL co początkowy POST:

```json
POST /your/url​
{
  "type": "your-specified-event-name",
  "interaction_id": "the-same-id-as-before",
  "action_id": "unique-id-for-this-custom-action",
  "data":{
    "title": "MyVideo.mp4",
    "captions": "off"
  }
}
```

Wszystkie niestandardowe pola dodane do formularza pojawiają się w sekcji `data` payloadu JSON wysyłanego przez Frame.io

Użyj `interaction_id`, aby powiązać początkowe żądanie z nowymi danymi formularza. I znowu, jeśli chcesz, możesz odpowiedzieć komunikatem (a nawet kolejnym formularzem!).

Łącząc akcje, formularze i komunikaty, możesz skutecznie zaprogramować w Frame.io całe workflowy Assetów z logiką biznesową pochodzącą z zewnętrznego systemu.

Wykaż się wyobraźnią! Ograniczeń praktycznie nie ma.

### Szczegóły formularzy {#form-details}

Podobnie jak komunikaty, formularze obsługują atrybuty `title` i `description`, które wyświetlają się u góry formularza. Poza tym każde pole formularza przyjmuje następujące atrybuty podstawowe:

- `type` — informuje interfejs Frame.io, jakiego typu danych się spodziewać oraz jaki komponent wyświetlić.
- `label` — pojawia się w interfejsie jako nagłówek nad polem.
- `name` — klucz, za pomocą którego pole będzie identyfikowane w kolejnym payloadzie.
- `value` — wartość, którą pole zostanie wstępnie wypełnione.

### Obsługiwane typy pól {#supported-field-types}

**Pole tekstowe**
Proste pole tekstowe bez dodatkowych parametrów.

```json
{  
  "type": "text",
  "label": "Title",
  "name": "title",
  "value": "MyVideo.mp4"
}
```

**Obszar tekstowy**
Prosty obszar tekstowy bez dodatkowych parametrów.

```json
{  
  "type": "textarea",
  "label": "Description",
  "name": "description",
  "value": "This video is really, really popular."
}
```

**Lista wyboru**
Definiuje listę, z której użytkownik może wybrać opcję. Musi zawierać listę `options`, której każdy element powinien zawierać czytelną dla człowieka nazwę `name` oraz wartość `value` możliwą do przetworzenia maszynowo.

```json
{
  "type": "select",
  "label": "Captions",
  "name": "captions",
  "value": "off",
  "options": [
       {
         "name": "Off",
         "value": "off"
       },
       {
         "name": "On",
         "value": "on"
      }
   ]
}
```

## Custom Actions a model uprawnień Frame.io {#custom-actions-and-the-frame-io-permissions-model}

Webhooki i Custom Actions mają specjalny model uprawnień: należą do **zespołu (Team)**, a nie do konkretnego użytkownika należącego do zespołu lub konta. Oznacza to, że:

- Każdy Admin lub Team Manager może utworzyć Custom Action w zespole.
- Każdy Admin lub Team Manager może zmodyfikować lub usunąć Custom Action istniejącą w zespole. Po modyfikacji wszyscy użytkownicy natychmiast zobaczą efekt zmiany.

## Bezpieczeństwo {#security}

Domyślnie dla każdej Custom Action podczas jej tworzenia generowany jest klucz podpisujący. Nie można tego skonfigurować. Klucza tego można użyć do weryfikacji, że żądanie pochodzi z Frame.io.

### Weryfikacja {#verification}

Żądanie `POST` zawiera następujące elementy

| Nazwa | Opis |
| --- | --- |
| `X-Frameio-Request-Timestamp` | Czas wyzwolenia Twojej Custom Action. |
| `X-Frameio-Signature` | Obliczony podpis. |

**Znacznik czasu** to moment podpisania żądania w chwili opuszczania sieci Frame.io. Można go użyć do zapobiegania atakom typu replay. Zalecamy sprawdzanie, czy ten czas mieści się w granicach 5 minut od czasu lokalnego.

**Podpis** to skrót HMAC SHA-256 utworzony przy użyciu klucza podpisującego udostępnionego podczas pierwszego tworzenia Custom Action.

#### Weryfikowanie podpisu {#verifying-the-signature}

1. Wyodrębnij podpis z nagłówków HTTP
2. Utwórz wiadomość do podpisania, łącząc wersję, czas dostarczenia i treść żądania

- `v0:timestamp:body`

3. Oblicz podpis HMAC SHA256 przy użyciu swojego sekretu podpisującego.

- Uwaga: udostępniony podpis ma prefiks `v0=`. Obecnie Frame.io ma tylko tę jedną wersję podpisywania żądań. Musisz dodać ten prefiks do obliczonego przez siebie podpisu.

4. Porównaj!

```python title="Python"
import hmac
import hashlib

def verify_signature(curr_time, req_time, signature, body, secret):
    """
    Verify webhook/custom action signature
    :Args:
        curr_time (float): Current epoch time
        req_time (float): Request epoch time
        signature (str): Signature provided by the frame.io API for the given request
        body (str): Custom Action body from the received POST
        secret (str): The secret for this Custom Action that you saved when you first created it
    """
    if int(curr_time) - int(req_time) < 500:
        message = 'v0:{}:{}'.format(req_time, body)
        calculated_signature = 'v0={}'.format(hmac.new(
            bytes(secret, 'latin-1'),
            msg=bytes(message, 'latin-1'),
            digestmod=hashlib.sha256).hexdigest())
        if calculated_signature == signature:
            return True
    return False
```
