Frame.io Actions zapewniają szybki dostęp do typowych operacji na multimediach, takich jak pobieranie, zmiana nazwy i duplikowanie elementów — a także umożliwiają wyświetlanie integracji z narzędziami i usługami firm trzecich bezpośrednio w interfejsie użytkownika [Frame.io](https://next.frame.io/).

## Informacje o Actions {#about-actions}

Dzięki wprowadzeniu Custom Actions programiści mogą konfigurować własne Actions we Frame.io V4 i nimi zarządzać. Custom Actions, korzystające z tego samego bazowego systemu zdarzeń co [Webhooks](https://developer.adobe.com/frameio/guides/Webhooks/), są alternatywnym mechanizmem, który pozwala programistom łączyć zasoby z narzędziami najważniejszymi dla użytkowników ich konta Frame.io.

Actions może wykonać każdy użytkownik będący członkiem (Member) Workspace Frame.io, w którym dana Action jest włączona. Podczas wykonywania Action Frame.io wysyła payload na podany przez Ciebie URL. Aplikacja odbierająca odpowiada kodem statusu HTTP, aby potwierdzić odbiór, lub niestandardowym wywołaniem zwrotnym (callback), które wyświetla dodatkowe pola formularza w interfejsie Frame.io. Aplikacją odbierającą może być Twój własny hostowany program, usługa, a nawet narzędzie IPaaS typu low-code/no-code, takie jak Workfront Fusion lub Zapier.

Używaj Custom Actions, aby tworzyć integracje bezpośrednio w [Frame.io](https://next.frame.io/) jako programowalne komponenty interfejsu. Umożliwia to tworzenie workflow, które użytkownicy mogą uruchamiać w aplikacji, z wykorzystaniem tego samego bazowego routingu zdarzeń co w przypadku webhooków. Możesz tworzyć uruchamiane przez użytkownika formularze jedno- lub wieloetapowe, które wracają do Frame.io jako kolejny formularz lub prosta odpowiedź. Gdy użytkownik kliknie Custom Action na zasobie (Asset), Frame.io wysyła payload na podany przez Ciebie URL. Aplikacja odbierająca odpowiada kodem statusu HTTP, aby potwierdzić odbiór, lub niestandardowym wywołaniem zwrotnym, które może wyświetlić dodatkowy interfejs we Frame.io.

## Limity żądań {#rate-limits}

Zdarzenia Custom Actions wliczają się do tych samych limitów na poziomie konta co zdarzenia webhooków: **1000 zdarzeń na minutę** i **20 000 zdarzeń na godzinę**. Oba limity dotyczą łącznej liczby zdarzeń w całym koncie, a nie oddzielnie każdej Custom Action czy subskrypcji webhooka.

Po osiągnięciu któregokolwiek z limitów kolejne zdarzenia Custom Actions są **odrzucane** — nie są kolejkowane ani automatycznie ponawiane.

Są to limity liczby zdarzeń, a nie limity żądań API służących do zarządzania Custom Actions. Szczegóły znajdziesz w sekcji [Limity żądań webhooków](/pl/platform/docs/guides/webhooks#webhook-rate-limits).

## Zmigrowane Actions {#migrated-actions}

Podczas migracji do konta Frame.io V4 zawierającego Custom Actions utworzone wcześniej w starszej wersji Frame.io należy pamiętać o kilku kwestiach.

### Status Action {#action-status}

Po migracji konta do Frame.io V4 wszystkie Custom Actions utworzone we wcześniejszych wersjach będą miały status ‘null’ i zostaną automatycznie wyłączone. Daje to użytkownikom możliwość zaktualizowania Actions do korzystania z V4 API przed ich włączeniem, ponieważ wszystkie niezaktualizowane Actions zakończą się niepowodzeniem. Aby zidentyfikować Actions w tym stanie, przejdź na stronę ustawień Actions i sprawdź kolumnę „Status” lub, jeśli korzystasz z API, sprawdź pole is_active.

### Zasoby obsługiwane przez Actions: pliki, foldery i Version Stacks {#actionable-resources-files-folders-&-version-stacks}

Ponieważ we Frame.io V4 API typy zasobów są rozdzielone na osobne zasoby, interpretując ID zasobu otrzymane w payloadzie Action, warto wziąć pod uwagę pewne zachowania. W przypadku pojedynczych plików (Files) sprawa jest prosta — ID odpowiada konkretnemu plikowi, na którym wykonano Action. Podobnie w przypadku folderów (Folders) otrzymasz ID folderu, na którym wykonano Action; jednak w zależności od przypadku użycia masz kilka możliwości zdefiniowania zachowania Action. Użyj ID folderu do kolejnych wywołań Frame.io API, jeśli chcesz pracować z samym zasobem folderu. Możesz też pobrać elementy podrzędne tego folderu, aby dalej przetwarzać znajdujące się w nim zasoby. Gdy Action zostanie wykonana na Version Stack, payload będzie zawierać ID ‘Head Asset’, czyli najwyższego pliku w stosie, który jest wyświetlany w interfejsie Frame.io.

Więcej o różnicach między Frame.io Legacy API a V4 przeczytasz w naszym [przewodniku po migracji](/pl/platform/docs/resources/migration).

## Interakcje, ponowne próby i limity czasu {#interactions-retries-and-timeouts}

`interaction_id` to unikalny identyfikator służący do śledzenia interakcji w miarę jej rozwoju. Jeśli nie musisz odpowiadać użytkownikowi, zwróć kod statusu 200 i gotowe. Choć jest to opcjonalne, zalecamy dołączenie informacji o wyniku akcji, np. komunikatu o powodzeniu lub alertu o błędzie. Custom Actions obsługują wywołania zwrotne z komunikatami (message callbacks).

<Note>

Frame.io oczekuje odpowiedzi w czasie krótszym niż 10 sekund i podejmuje do 5 ponownych prób, czekając na pomyślną odpowiedź. Najlepiej, aby odpowiedź była natychmiastowa, a działania asynchroniczne następowały po uruchomieniu przez Custom Action.

</Note>

## Tworzenie Message Callback {#create-a-message-callback}

W odpowiedzi HTTP na zdarzenie webhooka możesz zwrócić obiekt JSON opisujący komunikat, który zostanie wyświetlony użytkownikowi inicjującemu w interfejsie Frame.io.

```json
{
  "title": "Success!",
  "description": "The thing worked! Nice."
}
```

Komunikaty pozwalają przekazać użytkownikowi informację zwrotną bezpośrednio w interfejsie Frame.io. Jeśli musisz zebrać od użytkownika dodatkowe informacje, użyj zamiast tego **Form Callbacks**.

## Tworzenie Form Callback {#create-a-form-callback}

Załóżmy, że przed rozpoczęciem procesu potrzebujesz więcej informacji. Na przykład możesz przesyłać treści do systemu, który wymaga dodatkowych szczegółów. W odpowiedzi możesz opisać formularz (Form), który użytkownik wypełni i odeśle do Ciebie. Oto przykład:

```json
{
  "title": "Need some more info!",
  "description": "Getting ready to submit this file!",
  "fields": [
    {
      "type": "text",
      "label": "Title",
      "name": "title",
      "value": "MyVideo.mp4"
    },
    {
      "type": "select",
      "label": "Captions",
      "name": "captions",
      "options": [
        {
          "name": "Off",
          "value": "off"
        },
        {
          "name": "On",
          "value": "on"
        }
      ]
    }
  ]
}
```

Gdy użytkownik prześle formularz, otrzymasz zdarzenie pod tym samym adresem URL co początkowe żądanie POST:

```json
POST /your/url
{
  "type": "your-specified-event-name",
  "interaction_id": "the-same-id-as-before",
  "action_id": "unique-id-for-this-custom-action",
  "data":{
    "title": "MyVideo.mp4",
    "captions": "off"
  }
}
```

Wszystkie niestandardowe pola dodane do formularza pojawiają się w sekcji `data` payloadu JSON wysyłanego przez Frame.io. Użyj `interaction_id`, aby powiązać początkowe żądanie z nowymi danymi formularza. Możesz odpowiedzieć komunikatem lub połączyć w łańcuch kolejny formularz. Łącząc Actions, Forms i Messages, możesz skutecznie programować wieloetapowe workflow we Frame.io z logiką biznesową pochodzącą z zewnętrznego systemu.

## Bezpieczeństwo i weryfikacja {#security-and-verification}

Domyślnie dla każdej Custom Action podczas jej tworzenia generowany jest klucz podpisujący. Nie można tego skonfigurować. Klucz ten może służyć do weryfikacji, czy żądanie pochodzi z Frame.io. Żądanie `POST` zawiera następujące elementy:

| Nazwa | Opis |
| --- | --- |
| `X-Frameio-Request-Timestamp` | Czas uruchomienia Twojej Custom Action. |
| `X-Frameio-Signature` | Obliczony podpis. |

<CardGroup cols={2}>

<Card title="Weryfikacja znacznika czasu" icon="clock" iconType="solid">

### Weryfikacja podpisu {#verifying-the-signature}

<Steps>

<Step title="Wyodrębnij podpis">

Wyodrębnij podpis z nagłówków HTTP.

</Step>

<Step title="Utwórz wiadomość do podpisania">

Utwórz wiadomość do podpisania, łącząc wersję, czas dostarczenia i treść żądania: `v0:timestamp:body`.

</Step>

<Step title="Oblicz HMAC SHA256">

Oblicz podpis HMAC SHA256 przy użyciu swojego sekretu podpisującego.

</Step>

<Step title="Porównaj podpisy">

Porównaj obliczony podpis z otrzymanym!

</Step>

</Steps>

<Note>

Otrzymany podpis ma prefiks `v0=`. Obecnie Frame.io ma tylko tę jedną wersję podpisywania żądań. Musisz dodać ten prefiks do obliczonego podpisu.

</Note>

```python title="Python"
import hmac
import hashlib

def verify_signature(curr_time, req_time, signature, body, secret):
    """
    Verify webhook/custom action signature
    :Args:
        curr_time (float): Current epoch time
        req_time (float): Request epoch time
        signature (str): Signature provided by the frame.io API for the given request
        body (str): Custom Action body from the received POST
        secret (str): The secret for this Custom Action that you saved when you first created it
    """
    if int(curr_time) - int(req_time) < 500:
        message = 'v0:{}:{}'.format(req_time, body)
        calculated_signature = 'v0={}'.format(hmac.new(
            bytes(secret, 'latin-1'),
            msg=bytes(message, 'latin-1'),
            digestmod=hashlib.sha256).hexdigest())
        if calculated_signature == signature:
            return True
    return False
```
