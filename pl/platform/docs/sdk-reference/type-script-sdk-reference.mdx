### Instalacja {#installation}

```bash
npm i -s frameio
```

### Użycie {#usage}

Utwórz instancję klienta i używaj go w następujący sposób:

```typescript
import { FrameioClient } from "frameio";

const client = new FrameioClient({ token: "YOUR_TOKEN" });
await client.metadataFields.metadataFieldDefinitionsCreate("b2702c44-c6da-4bb6-8bbd-be6e547ccf1b", {
    data: {
        field_type: "select",
        field_configuration: {
            enable_add_new: false,
            options: [
                {
                    display_name: "Option 1",
                },
                {
                    display_name: "Option 2",
                },
            ],
        },
        name: "Fields definition name",
    },
});
```

### Typy żądań i odpowiedzi {#request-and-response-types}

SDK eksportuje wszystkie typy żądań i odpowiedzi jako interfejsy TypeScript. Wystarczy zaimportować je z następującej przestrzeni nazw:

```typescript
import { Frameio } from "frameio";

const request: Frameio.UpdateFieldDefinitionParams = {
    ...
};
```

---

### Obsługa wyjątków {#exception-handling}

Gdy API zwróci kod stanu oznaczający niepowodzenie (odpowiedź 4xx lub 5xx), zostanie zgłoszona podklasa następującego błędu.

```typescript
import { FrameioError } from "frameio";

try {
    await client.metadataFields.metadataFieldDefinitionsCreate(...);
} catch (err) {
    if (err instanceof FrameioError) {
        console.log(err.statusCode);
        console.log(err.message);
        console.log(err.body);
        console.log(err.rawResponse);
    }
}
```

### Zaawansowane {#advanced}

#### Dodatkowe nagłówki {#additional-headers}

Jeśli chcesz wysłać dodatkowe nagłówki w ramach żądania, użyj opcji żądania headers.

```typescript
const response = await client.metadataFields.metadataFieldDefinitionsCreate(..., {
    headers: {
        'X-Custom-Header': 'custom value'
    }
});
```

#### Dodatkowe parametry ciągu zapytania {#additional-query-string-parameters}

Jeśli chcesz wysłać dodatkowe parametry ciągu zapytania w ramach żądania, użyj opcji żądania queryParams.

```typescript
const response = await client.metadataFields.metadataFieldDefinitionsCreate(..., {
    queryParams: {
        'customQueryParamKey': 'custom query param value'
    }
});
```

---

#### Ponowne próby {#retries}

SDK obsługuje automatyczne ponawianie żądań z wykładniczym wydłużaniem odstępów (exponential backoff). Żądanie będzie ponawiane, dopóki zostanie uznane za możliwe do ponowienia, a liczba prób nie przekroczy skonfigurowanego limitu ponowień (domyślnie: 2).

Żądanie jest uznawane za możliwe do ponowienia, gdy zostanie zwrócony którykolwiek z następujących kodów stanu HTTP:

- 408 (Przekroczenie limitu czasu)
- 429 (Zbyt wiele żądań)
- 5XX (Wewnętrzne błędy serwera)

<br />

Użyj opcji żądania `maxRetries`, aby skonfigurować to zachowanie.

```typescript
const response = await client.metadataFields.metadataFieldDefinitionsCreate(..., {
    maxRetries: 0 // override maxRetries at the request level
});
```

---

#### Limity czasu {#timeouts}

Domyślny limit czasu w SDK wynosi 60 sekund. Użyj opcji timeoutInSeconds, aby skonfigurować to zachowanie.

```typescript
const response = await client.metadataFields.metadataFieldDefinitionsCreate(..., {
    timeoutInSeconds: 30 // override timeout to 30s
});
```

#### Przerywanie żądań {#aborting-requests}

SDK pozwala użytkownikom przerwać żądanie w dowolnym momencie przez przekazanie sygnału przerwania (abort signal).

```typescript
const controller = new AbortController();
const response = await client.metadataFields.metadataFieldDefinitionsCreate(..., {
    abortSignal: controller.signal
});
controller.abort(); // aborts the request
```

---

#### Dostęp do surowych danych odpowiedzi {#access-raw-response-data}

SDK zapewnia dostęp do surowych danych odpowiedzi, w tym nagłówków, za pomocą metody `.withRawResponse()`. Metoda `.withRawResponse()` zwraca obietnicę (promise), która rozwiązuje się do obiektu z właściwościami `data` i `rawResponse`.

```typescript
const { data, rawResponse } = await client.metadataFields.metadataFieldDefinitionsCreate(...).withRawResponse();

console.log(data);
console.log(rawResponse.headers['X-My-Header']);
```

#### Zgodność ze środowiskami uruchomieniowymi {#runtime-compatibility}

SDK działa w następujących środowiskach uruchomieniowych:

- Node.js 18+
- Vercel
- Cloudflare Workers
- Deno v1.25+
- Bun 1.0+
- React Native

---

#### Dostosowywanie klienta Fetch {#customizing-fetch-client}

SDK umożliwia dostosowanie bazowego klienta HTTP / funkcji Fetch. Jeśli korzystasz z nieobsługiwanego środowiska, jest to awaryjny sposób na zapewnienie działania SDK.

```typescript
import { FrameioClient } from "frameio";

const client = new FrameioClient({
    ...
    fetcher: // provide your implementation here
});
```

#### Uwierzytelnianie {#auth}

<AccordionGroup>

<Accordion title="new ServerToServerAuth({ clientId, clientSecret, ... })">

Uwierzytelnianie za pomocą przyznania OAuth 2.0 `client_credentials`. Ten przepływ nie angażuje użytkownika i nie zwraca tokenu odświeżania. Gdy token dostępu wygaśnie, SDK automatycznie żąda nowego przy użyciu poświadczeń klienta.

```typescript title="usage"
import { FrameioClient, ServerToServerAuth } from "frameio";

const auth = new ServerToServerAuth({
    clientId: "YOUR_CLIENT_ID",
    clientSecret: "YOUR_CLIENT_SECRET",
});
const client = new FrameioClient({ token: () => auth.getToken() });
```

**Parametry**

`clientId`: `string` — identyfikator klienta OAuth Adobe IMS.

`clientSecret`: `string` — klucz tajny klienta OAuth Adobe IMS.

`scopes`: `string` — zakresy rozdzielone spacjami (OAuth 2.0 RFC 6749). Domyślnie zakresy server-to-server.

`imsBaseUrl`: `string` — bazowy adres URL IMS dla środowisk testowych/alternatywnych. Domyślnie środowisko produkcyjne.

`fetch`: `typeof fetch` — niestandardowa implementacja fetch (dla serwera proxy, TLS itp.).

`onTokenRefreshed`: `OnTokenRefreshed` — opcjonalne wywołanie zwrotne uruchamiane po każdym pobraniu tokenu.

`timeout`: `number` — limit czasu żądania HTTP w milisekundach. Domyślnie 30000.

`maxRetries`: `number` — maksymalna liczba ponowień w przypadku przejściowych błędów. Domyślnie 2.

`refreshBuffer`: `number` — liczba sekund przed wygaśnięciem, po której następuje zapobiegawcze odświeżenie. Domyślnie 60.

`logger`: `Logger` — instancja loggera dla danych diagnostycznych.

**Metody**

`getToken(): Promise<string>` — zwraca ważny token dostępu, odświeżając go w razie potrzeby. Przekaż go do klienta: `new FrameioClient({ token: () => auth.getToken() })`.

`authenticate(): Promise<TokenResponse>` — jawnie pobiera nowy token dostępu.

`revoke(): Promise<void>` — unieważnia tokeny po stronie serwera i czyści stan lokalny.

`exportTokens(): ExportedTokens` — eksportuje bieżący stan tokenów w celu jego trwałego zapisania.

`importTokens(data: ExportedTokens): void` — przywraca stan tokenów z wcześniej wyeksportowanego obiektu.

</Accordion>

<Accordion title="new WebAppAuth({ clientId, clientSecret, redirectUri, ... })">

Uwierzytelnianie za pomocą przyznania OAuth 2.0 `authorization_code`. Używaj go w aplikacjach po stronie serwera, które mogą bezpiecznie przechowywać klucz tajny klienta.

```typescript title="usage"
import { randomBytes } from "crypto";
import { FrameioClient, WebAppAuth } from "frameio";

const auth = new WebAppAuth({
    clientId: "YOUR_CLIENT_ID",
    clientSecret: "YOUR_CLIENT_SECRET",
    redirectUri: "https://myapp.com/callback",
});
const url = auth.getAuthorizationUrl({ state: randomBytes(24).toString("hex") });
// redirect the user to url ...
await auth.exchangeCode("CODE_FROM_CALLBACK");
const client = new FrameioClient({ token: () => auth.getToken() });
```

**Parametry**

`clientId`: `string` — identyfikator klienta OAuth Adobe IMS.

`clientSecret`: `string` — klucz tajny klienta OAuth Adobe IMS.

`redirectUri`: `string` — zarejestrowany identyfikator URI przekierowania.

`scopes`: `string` — zakresy rozdzielone spacjami (OAuth 2.0 RFC 6749).

`imsBaseUrl`: `string` — bazowy adres URL IMS dla środowisk testowych/alternatywnych. Domyślnie środowisko produkcyjne.

`fetch`: `typeof fetch` — niestandardowa implementacja fetch (dla serwera proxy, TLS itp.).

`onTokenRefreshed`: `OnTokenRefreshed` — opcjonalne wywołanie zwrotne uruchamiane po każdym odświeżeniu tokenu.

`timeout`: `number` — limit czasu żądania HTTP w milisekundach. Domyślnie 30000.

`maxRetries`: `number` — maksymalna liczba ponowień w przypadku przejściowych błędów. Domyślnie 2.

`refreshBuffer`: `number` — liczba sekund przed wygaśnięciem, po której następuje zapobiegawcze odświeżenie. Domyślnie 60.

`logger`: `Logger` — instancja loggera dla danych diagnostycznych.

**Metody**

`getToken(): Promise<string>` — zwraca ważny token dostępu, odświeżając go w razie potrzeby.

`getAuthorizationUrl({ state }): string` — tworzy adres URL autoryzacji Adobe IMS. Przekaż nieprzezroczystą wartość CSRF/state, która zostanie zwrócona z powrotem.

`exchangeCode(code: string): Promise<TokenResponse>` — wymienia kod autoryzacji na tokeny dostępu i odświeżania.

`refresh(): Promise<TokenResponse>` — ręcznie wywołuje odświeżenie tokenu.

`revoke(): Promise<void>` — unieważnia tokeny po stronie serwera i czyści stan lokalny.

`exportTokens(): ExportedTokens` — eksportuje bieżący stan tokenów w celu jego trwałego zapisania.

`importTokens(data: ExportedTokens): void` — przywraca stan tokenów z wcześniej wyeksportowanego obiektu.

<Accordion title="new SPAAuth({ clientId, redirectUri, ... })">

Uwierzytelnianie za pomocą `authorization_code` + PKCE (bez klucza tajnego klienta). Używaj go w jednostronicowych aplikacjach przeglądarkowych, które nie mogą bezpiecznie przechowywać klucza tajnego klienta.

```typescript title="usage"
// redirect the user to result.url, store result.codeVerifier ...
await auth.exchangeCode({ code: "CODE_FROM_CALLBACK", codeVerifier: result.codeVerifier });
const client = new FrameioClient({ token: () => auth.getToken() });
```

`redirectUri`: `string` — zarejestrowany identyfikator URI przekierowania.

`scopes`: `string` — zakresy rozdzielone spacjami (OAuth 2.0 RFC 6749).

`imsBaseUrl`: `string` — bazowy adres URL IMS dla środowisk testowych/alternatywnych. Domyślnie środowisko produkcyjne.

`fetch`: `typeof fetch` — niestandardowa implementacja fetch (dla serwera proxy, TLS itp.).

`onTokenRefreshed`: `OnTokenRefreshed` — opcjonalne wywołanie zwrotne uruchamiane po każdym odświeżeniu tokenu.

`timeout`: `number` — limit czasu żądania HTTP w milisekundach. Domyślnie 30000.

`maxRetries`: `number` — maksymalna liczba ponowień w przypadku przejściowych błędów. Domyślnie 2.

`refreshBuffer`: `number` — liczba sekund przed wygaśnięciem, po której następuje zapobiegawcze odświeżenie. Domyślnie 60.

`logger`: `Logger` — instancja loggera dla danych diagnostycznych.

**Metody**

`exchangeCode({ code, codeVerifier }): Promise<TokenResponse>` — wymienia kod autoryzacji + weryfikator PKCE na tokeny.

`refresh(): Promise<TokenResponse>` — ręcznie wywołuje odświeżenie tokenu.

`revoke(): Promise<void>` — unieważnia tokeny po stronie serwera i czyści stan lokalny.

`exportTokens(): ExportedTokens` — eksportuje bieżący stan tokenów w celu jego trwałego zapisania.

`importTokens(data: ExportedTokens): void` — przywraca stan tokenów z wcześniej wyeksportowanego obiektu.

<Accordion title="new NativeAppAuth({ clientId, redirectUri, ... })">

```typescript title="usage"
// open result.url in the system browser, store result.codeVerifier ...
await auth.exchangeCode({ code: "CODE_FROM_CALLBACK", codeVerifier: result.codeVerifier });
const client = new FrameioClient({ token: () => auth.getToken() });
```

**Parametry**

`clientId`: `string` — identyfikator klienta OAuth Adobe IMS.

`redirectUri`: `string` — zarejestrowany identyfikator URI przekierowania (obsługiwany niestandardowy schemat).

`scopes`: `string` — zakresy rozdzielone spacjami (OAuth 2.0 RFC 6749).

`imsBaseUrl`: `string` — bazowy adres URL IMS dla środowisk testowych/alternatywnych. Domyślnie środowisko produkcyjne.

`fetch`: `typeof fetch` — niestandardowa implementacja fetch (dla serwera proxy, TLS itp.).

`onTokenRefreshed`: `OnTokenRefreshed` — opcjonalne wywołanie zwrotne uruchamiane po każdym odświeżeniu tokenu.

`timeout`: `number` — limit czasu żądania HTTP w milisekundach. Domyślnie 30000.

`maxRetries`: `number` — maksymalna liczba ponowień w przypadku przejściowych błędów. Domyślnie 2.

`refreshBuffer`: `number` — liczba sekund przed wygaśnięciem, po której następuje zapobiegawcze odświeżenie. Domyślnie 60.

`logger`: `Logger` — instancja loggera dla danych diagnostycznych.

**Metody**

Takie same jak w `SPAAuth`: `getToken()`, `getAuthorizationUrl({ state })`, `exchangeCode({ code, codeVerifier })`, `refresh()`, `revoke()`, `exportTokens()`, `importTokens(data)`.

</Accordion>

<Accordion title="AuthorizationUrlResult">

Obiekt zwracany przez `SPAAuth.getAuthorizationUrl()` i `NativeAppAuth.getAuthorizationUrl()`. Zawiera adres URL autoryzacji oraz weryfikator kodu PKCE.

**Właściwości**

`url`: `string` — pełny adres URL autoryzacji, na który należy przekierować użytkownika.

`codeVerifier`: `string` — weryfikator kodu PKCE do zapisania i przekazania do `exchangeCode()`.

</Accordion>

#### Wyjątki uwierzytelniania {#auth-exceptions}

Wszystkie błędy uwierzytelniania rozszerzają `FrameioAuthError` i można je zaimportować z `frameio`.

| Wyjątek | Opis |
| --- | --- |
| `FrameioAuthError` | Błąd bazowy dla wszystkich błędów SDK uwierzytelniania. |
| `AuthenticationError` | Wymiana lub odświeżenie tokenu nie powiodło się. Ma właściwości `errorCode` i `errorDescription`. |
| `TokenExpiredError` | Token odświeżania wygasł; wymagane jest ponowne uwierzytelnienie. |
| `NetworkError` | Żądanie sieciowe nie powiodło się (przekroczenie limitu czasu, błąd połączenia itp.). |
| `RateLimitError` | Adobe IMS zwróciło kod 429, a limit ponowień został wyczerpany. Ma właściwość `retryAfter`. |
| `PKCEError` | Weryfikacja PKCE nie powiodła się. |
| `ConfigurationError` | Brak wymaganej konfiguracji lub jest ona nieprawidłowa. |

Jeśli dołączysz `media_links.original`, a użytkownik nie ma uprawnień do pobierania plików w odpowiednim projekcie, ten endpoint zwróci błąd `403 Forbidden`. Jeśli zawartość jest niedostępna, ponieważ dla tego użytkownika wymagany jest znak wodny, który nie jest obsługiwany przez żądane media_links, żądanie zakończy się powodzeniem, ale nieobsługiwane linki do multimediów zostaną ustawione na null. Podobnie, jeśli żądany link do transkodu nie istnieje dla danego pliku (np. przy dołączeniu `media_links.video_h264_180` do statycznego pliku obrazu) lub proces transkodowania nie został zakończony (tzn. plik ma status „uploaded”, a nie „transcoded”), link do multimediów również zostanie ustawiony na null w treści odpowiedzi. Krótko mówiąc, klient musi poprawnie obsługiwać linki do multimediów o wartości null.

</Note>
