title: "Frame.io MCP"
---

`https://mcp.frame.io/v1/mcp` でホストされている Frame.io MCP は、Claude、ChatGPT、Cursor、VS Code、GitHub Copilot などの MCP 対応クライアントを Frame.io アカウントに接続します。接続すると、AI エージェントを使って Frame.io での作業を進められるようになります。

このガイドでは、MCP の仕組み、接続方法、実行後にできることについて説明し、あわせてツールリファレンスと、始めるためのプロンプト例も紹介します。MCP を初めて使う場合は、次のセクションで接続手順の前にプロトコルについて説明しています。

---

## Model Context Protocol {#model-context-protocol}

MCP は、AI クライアントを外部システムに接続するために Anthropic が作成したオープンスタンダードです。接続されたシステムは、AI エージェントが呼び出せる操作である一連のツールを公開します。リクエストを行うと、エージェントは適切なツールを選択してサーバーを呼び出し、そのレスポンスを使用してリクエストを処理します。

MCP の詳細については、Anthropic の[最初の発表](https://www.anthropic.com/news/model-context-protocol)をご覧ください。

---

## 仕組み {#how-it-works}

### アーキテクチャ {#architecture}

```
┌───────────────┐        ┌─────────────────────┐        ┌───────────────┐
│   AI Agent    │        │     Frame.io MCP    │        │ Frame.io API  │
│(Claude, etc.) │◀──────▶│  mcp.frame.io/mcp   │◀──────▶│ api.frame.io  │
└───────────────┘        └──────────┬──────────┘        └───────────────┘
                                    │
                           ┌────────┴────────┐
                           │   Adobe Login   │
                           │  (OAuth 2.0)    │
                           └─────────────────┘
```

### 認証 {#authentication}

認証には Adobe IMS を介した OAuth 2.0 を使用し、Frame.io アカウントに関連付けられた Adobe ID が必要です。MCP は Frame.io Legacy アカウントをサポートしていません。

接続手順はクライアントごとに異なり、以下で説明しますが、基本的な流れは次のとおりです。認証は最初の接続時に一度だけ行われ、それ以降は MCP がトークンの更新を自動的に処理します。Adobe のログイン画面にリダイレクトされてサインインし、アクセスを承認すると、接続が有効になった状態で AI エージェントに戻ります。

ツールの呼び出しは、あなたの Frame.io 権限で実行されます。MCP はあなたのアカウントロールですでに許可されている操作しか実行できないため、アクセス権を超える操作を試みたツールは、操作を実行する代わりに権限エラーを返します。ロールと機能の対応については、[ユーザー権限の管理](/ja/platform/docs/guides/managing-user-permissions)をご覧ください。

#### Adobe Managed Accounts（AMA）と Frame Managed Accounts（FMA） {#adobe-managed-accounts-ama-and-frame-managed-accounts-fma}

Frame.io には管理方法の異なる 2 種類のユーザーアカウントがあり、これは認証時に重要になります。詳しくは、[Frame Managed vs. Adobe Managed Accounts](https://help.frame.io/en/articles/13719174-frame-managed-vs-adobe-managed-accounts) をご覧ください。

**Frame Managed Accounts（FMA）** は、Frame.io 内で直接作成、管理されるアカウントです。IMS のプロンプトで Adobe の認証情報を使用してサインインし、アクセスを承認すれば接続されます。

**Adobe Managed Accounts（AMA）** は、Adobe Admin Console を通じて管理されるアカウントで、通常はエンタープライズチーム向けです。FMA と同様に IMS を介して認証しますが、主な違いは、同じ Adobe ID が複数の組織（アカウントやアカウントプロファイルと表示されることもあります）に所属できる点です。どの組織で認証するかによって、MCP がアクセスできる Frame.io アカウントが決まります。

ブラウザで OAuth フローが開くと、Adobe IMS はすでにログインしているかどうかを確認します。ログインしている場合は、プロファイルの選択を求めずにそのセッションを再利用します。そのセッションが Frame.io アカウントに紐づく組織とは別の組織に属している場合、認証自体は成功しますが、誤った場所にたどり着きます。MCP はエラーなく接続されますが、Frame.io API の呼び出しは空の結果または権限エラーを返します。

AMA を使用していて、接続後にこのような動作が見られる場合は、トラブルシューティングの [AMA のマルチアカウント認証エラー](#ama-multi-account-authentication-errors)を参照してください。

---

接続するには、Adobe ID が関連付けられた有効な Frame.io アカウントが必要です（Adobe 認証への接続について詳しくは[こちら](https://help.frame.io/en/articles/11758018-connecting-to-adobe-authentication)をご覧ください）。

## Claude への接続 {#connecting-to-claude}

この手順は Claude Desktop を対象としています。Claude は Web、iOS、Cowork、Code Desktop でも利用できます。使用している環境でのセットアップ手順については、[Anthropic のコネクターに関するドキュメント](https://support.claude.com/en/articles/11176164-use-connectors-to-extend-claude-s-capabilities)を確認してください。

<Steps>

<Step title="コネクターを開く">

Claude Desktop で、メニューバーから **Customize** を開きます。左サイドバーで **Connectors** を選択し、Connectors パネルの右上隅にある **+** をクリックします。

</Step>

<Step title="サーバーの詳細を入力する">

**Add custom connector** ダイアログで、両方のフィールドに入力します。

```
  Name: Frame.io
  URL: https://mcp.frame.io/v1/mcp
```

**Add** をクリックします。

</Step>

<Step title="認証する">

Frame.io が **CUSTOM** ラベル付きで **Not connected** セクションに表示されます。右パネルの **Connect** をクリックします。Adobe IMS に移動するので、Frame.io アカウントに関連付けられた Adobe ID でサインインします。承認後、Claude Desktop に戻ります。

</Step>

<Step title="ツールの権限を確認する">

認証が完了すると、Frame.io は **Web** セクションに移動します。右パネルには、**Interactive tools** と **Read-only tools** に分けてツールが一覧表示されます。

各グループには権限設定があり、デフォルトでは **Needs approval** に設定されています。ドロップダウンをクリックして変更します。

| 設定 | 動作 |
| --- | --- |
| Always allow | Claude は確認なしでツールを呼び出します |
| Needs approval | Claude は各ツール呼び出しの前に一時停止して確認を求めます |
| Blocked | Claude はこれらのツールを使用できません |
| Custom | ツールごとに権限を設定します |

読み取り専用ツールは **Always allow** に設定しても安全です。その他のツールはすべて、以下の[ツールの承認設定](#tool-approval-settings)セクションを確認するまで **Needs approval** のままにしておいてください。

詳しくは、Claude の[コネクターの権限](https://support.claude.com/en/articles/11176164-use-connectors-to-extend-claude-s-capabilities)に関するドキュメントをご覧ください。

</Step>

<Step title="Frame.io ツールを使用する">

接続したら、Claude に自然な言葉で Frame.io のタスクを依頼します。Claude はコネクターのツールを自動的に認識し、リクエストごとに適切なツールを選択します。

</Step>

</Steps>

<Tip>

接続が機能していることを確認するには、Claude に *「Frame.io のアカウントを一覧表示して」* と尋ねてみてください。

</Tip>

</Tab>

## ChatGPT への接続 {#connecting-to-chatgpt}

この手順は ChatGPT デスクトップアプリを対象としています。Frame.io MCP ツールは ChatGPT Web と ChatGPT iOS でもサポートされています。使用している環境でのセットアップ手順については、[ChatGPT のアプリに関する OpenAI のヘルプセンター](https://help.openai.com/en/articles/11487775-connectors-in-chatgpt)を確認してください。

<Steps>

<Step title="サーバーを追加する">

ChatGPT で **Settings** を開き、**Plugins**（左メニューの **Integrations** の下）を選択します。右上の **Add** メニューを開き、**Add MCP Server** を選択します。タイプを **Streamable HTTP** に設定し、次のように入力します。

```
 Name: Frame.io
 URL: https://mcp.frame.io/v1/mcp
```

**Save** をクリックします。Frame.io が **Authenticate** ボタン付きでサーバーテーブルに追加されます。

</Step>

<Step title="認証する">

Frame.io の横にある **Authenticate** をクリックして、Adobe ログインを開始します。Frame.io アカウントに関連付けられた Adobe ID でサインインし、アクセスを承認します。

</Step>

<Step title="ツールの権限を確認する">

ChatGPT は、操作の内容とアプリの権限に応じて、特定の操作の前に確認を求めます。これらのデフォルト設定を変更する前に、[ツールの承認設定](#tool-approval-settings)セクションを確認してください。アップロード、ファイルの移動、削除、共有の変更など、書き込みや削除を行うツールは、自動化する前に確認しておくことをお勧めします。

管理対象のワークスペースでは、利用できる操作がワークスペース管理者によって制御されている場合もあります。

</Step>

<Step title="Frame.io ツールを使用する">

関連する場面で Frame.io を使うよう ChatGPT に依頼するか、コンポーザーから **Frame.io** を選択するか、**@Frame.io** で直接メンションします。

<Tip>

接続が機能していることを確認するには、*「@Frame.io Frame.io のアカウントを一覧表示して」* と尋ねてみてください。

</Tip>

</Step>

</Steps>

```json
  }
}
```

## GitHub Copilot CLI への接続 {#connecting-to-the-github-copilot-cli}

この手順は、GitHub Copilot CLI がすでにインストールされていることを前提としています。セットアップについては、[GitHub の Copilot CLI ドキュメント](https://docs.github.com/en/copilot/how-tos/use-copilot-agents/use-copilot-cli)をご覧ください。

<Steps>

<Step title="サーバーを追加する">

アクティブな Copilot CLI セッションで、次のコマンドを実行します。

```
/mcp add frameio
```

CLI が短いフォームを 1 フィールドずつ案内します。

```
Type: HTTP
URL: https://mcp.frame.io/v1/mcp
HTTP Headers: leave blank
Tools: * to enable all of Frame.io's tools
Defer Tools: Auto
```

**Tools** は、サーバーのツールのうちどれを利用可能にするかを制御します。`*` を指定するとすべてのツールが有効になります。特定のツールのみを有効にするには、ツール名をカンマ区切りで列挙します。

**Defer Tools** は、それらのツールの読み込み方法を制御します。`Auto` はツール検索を通じてオンデマンドでツールを読み込むため、必要になるまでツールの定義がコンテキストウィンドウを占有しません。これは Frame.io のような大規模なツールセットに適しています。`Never` はすべてのツールを最初から読み込んだままにします。ここでは `Auto` のほうが適したデフォルトです。

</Step>

<Step title="認証する">

フォームの入力後、CLI に `Server Saved` と `OAuth authentication is required` が表示されます。

Enter キーを押して認証すると、ブラウザウィンドウで Adobe ログインが開きます。Frame.io アカウントに関連付けられた Adobe ID でサインインし、アクセスを承認します。

成功すると、CLI に `Successfully authenticated with frameio` が表示され、アクティブな MCP サーバーの一覧に戻ります。

</Step>

<Step title="Frame.io ツールを使用する">

Copilot に自然な言葉で依頼すると、リクエストに必要な場合に Frame.io ツールを使用します。`/mcp show frameio` または `/mcp list` を実行して、サーバーが接続済みと表示されることを確認します。

<Tip>

接続が機能していることを確認するには、*「Frame.io のアカウントを一覧表示して」* と尋ねてみてください。

</Tip>

</Step>

## 利用可能なツール {#available-tools}

Frame.io MCP で利用可能なツールのリファレンスです。必要なツールや機能が見当たらない場合は、お知らせください。

<Tip>

**命名についての注意**

この MCP では、ファイル、フォルダー、バージョンスタックの一覧表示を  `read_assets` に統合しています。メタデータの値は、専用の読み取りツールではなく、ファイルおよびフォルダーのオブジェクト上でインラインに読み取られます。

</Tip>

利用可能なツールは、**Setup**、**Read**、**Write**、**Delete**、**Feedback** のいずれかに分類されます。

**Read** ツールは、変更を加えずにデータを取得します。**Write** ツールは、コンテンツを作成、更新、移動、または復元します。**Delete** ツールは、コンテンツを削除します。削除したファイルとフォルダーは復元できますが、その他の種類のリソースの削除は元に戻せません。

### ツールの承認設定 {#tool-approval-settings}

この MCP に限らず、どの MCP サーバーを接続する場合でも、AI エージェントはあなたのアクセス権と認証情報を使って操作を実行できるようになります。アカウントやファイルにアクセスできる他のインテグレーションと同様に、慎重に扱ってください。

権限設定をデフォルトから変更する前に、ツールの実行の仕組みを確認してください。

ツールカテゴリーが **Always allow** に設定されている場合、AI エージェントはそれらのツールを自動的に呼び出し、確認も、これから何が起こるかのプレビューもありません。読み取り専用の参照であれば問題ありません。しかし、*「これらを適切なフォルダーに整理して」* のようなプロンプトでは、移動先を確認する前にファイルが誤った場所に移動されてしまう可能性があります。

**推奨されるデフォルト：**

| ツールの種類 | 推奨される扱い |
| --- | --- |
| Read | クライアントが対応していれば、自動承認しても安全です |
| Write | 実行前に各呼び出しを確認してください |
| Delete | 実行前に各呼び出しを確認してください。これらはコンテンツを削除します |

<Tip>

**読み取り専用ツール**

読み取り専用ツールには標準の `readOnlyHint` アノテーションが付いています。Claude、ChatGPT、VS Code、Cursor はこれを使用して読み取りを非変更操作として識別し、通常は別のグループにまとめたり、承認プロンプトを省略したりします。具体的な扱いはクライアントによって異なります。

</Tip>

承認の実装方法はクライアントごとに異なります。どこでも同じように機能する単一の設定はありません。

- **Claude Desktop：** コネクターの設定パネルで、ツールカテゴリーごと、または **Custom** 設定を使って個々のツールごとに権限を設定します。Claude の[コネクターの権限](https://support.claude.com/en/articles/11176164-use-connectors-to-extend-claude-s-capabilities)に関するドキュメントをご覧ください
- **ChatGPT：** デフォルトで、特定の操作の前に確認を求めます。会話の残りの部分については選択を記憶させることができますが、新しい会話を始めるとリセットされます。詳しくは、[ChatGPT のアプリに関する OpenAI のヘルプセンター](https://help.openai.com/en/articles/11487775-connectors-in-chatgpt)をご覧ください。
- **VS Code：** 最初にプロンプトが表示されたときにサーバーを信頼することを確認し、その後はツール呼び出しの実行時に承認します。Chat ビューの **Configure Tools** ボタンで個々のツールを有効または無効にし、コマンドパレットの **MCP: Reset Trust** でサーバーを再確認できます。詳しくは、VS Code の[承認と権限の管理](https://code.visualstudio.com/docs/agents/run/approvals)に関するドキュメントをご覧ください。
- **Cursor：** **Settings > Agents > Approvals & Execution** で Run Mode を選択します。Auto-review（デフォルト）は、リスクのある呼び出しの前に確認を求めます。Allowlist と Run Everything は承認を完全にスキップします。詳しくは、Cursor の [Run Modes](https://cursor.com/docs/agent/security/run-modes) に関するドキュメントをご覧ください。
- **GitHub Copilot CLI：** Copilot はツールを実行する前に確認を求め、1 回だけ許可するか、セッション中は許可するかを選択できます。`/mcp` を実行すると、設定済みのサーバーとそのツールを確認できます。

迷った場合は、クライアントのデフォルトの承認動作を維持してください。確認のステップが 1 つ増えますが、ミスを未然に防ぐのに役立ちます。

## 接続の解除 {#disconnecting}

Frame.io MCP の接続解除や削除の方法は、クライアントごとに異なります。

- **Claude Desktop：** **Customize > Connectors** に移動し、Frame.io を見つけて削除します。詳しくは、Claude の[コネクター](https://support.claude.com/en/articles/11176164-use-connectors-to-extend-claude-s-capabilities)に関するドキュメントをご覧ください。
- **ChatGPT：** 2 つの方法があります。**接続を解除**する（プラグインはインストールしたままアクセスを停止する）には、**Settings > Plugins > Frame.io** を開いてオフに切り替えます。再接続するにはオンに戻します。完全に削除するには、サイドバーで **Plugins** を開き、**Installed** の下にある **Frame.io** を選択して **Uninstall** を選びます。再度使用するには、プラグインディレクトリから再インストールする必要があります。詳しくは、[ChatGPT のアプリに関する OpenAI のヘルプセンター](https://help.openai.com/en/articles/11487775-connectors-in-chatgpt)をご覧ください。
- **VS Code：** MCP 設定から Frame.io のエントリを削除します。詳しくは、VS Code の [MCP サーバーの管理](https://code.visualstudio.com/docs/agent-customization/mcp-servers)に関するドキュメントをご覧ください。
- **Cursor：** 追加時に使用したのと同じファイルである `~/.cursor/mcp.json` から、`frameio-mcp` のエントリを削除します。
- **GitHub Copilot CLI：** `/mcp delete [server-name]` を実行してサーバーを削除します。

## トラブルシューティング {#troubleshooting}

### 2026 年 10 月 7 日より前に Frame.io MCP を設定した場合 {#configured-the-frame-io-mcp-before-october-7-2026}

サーバー URL が現在の V1 URL と一致していることを確認してください：**`https://mcp.frame.io/v1/mcp`**

必要に応じて更新し、MCP サーバーを再起動または再接続してください。

### OAuth のループまたは認証の失敗 {#oauth-loop-or-authentication-failure}

Frame.io アカウントにリンクされた Adobe ID でサインインしてください。複数の Adobe アカウントをお持ちの場合は、正しいアカウントを使用していることを確認してください。クライアントで Frame.io MCP を削除して再度追加すると、新しい OAuth セッションが開始されます。

### AMA のマルチアカウント認証エラー {#ama-multi-account-authentication-errors}

Adobe IMS が既存のブラウザセッションを暗黙的に再利用すると、選択を求められることなく誤った組織で認証される場合があります。解決策は、再利用されている Adobe セッションをクリアすることです。再接続する前に Adobe のログインドメインのブラウザ Cookie を消去するか、同じブラウザで別の Adobe タブを開いてそこから完全にサインアウトしてください。以前のセッションがクリアされると、認証時にプロファイルの選択肢が表示され、正しい組織を選択できるようになります。

### 追加後に Frame.io MCP が表示されない、または接続されない {#frame-io-mcp-not-visible-or-not-connecting-after-adding}

URL が正確に `https://mcp.frame.io/v1/mcp` であることを確認してください。追加後にクライアントの再起動が必要な場合があります。

### 会話でツールが利用できない {#tools-not-available-in-conversation}

クライアントで Frame.io MCP が接続済みと表示されていることを確認してください。接続されているのにツールが表示されない場合は、権限設定でツールカテゴリーが **Blocked** に設定されていないか確認してください。

さらに、

### 接続には成功したが、ワークスペースやプロジェクトが表示されない {#connected-successfully-but-no-workspaces-or-projects-appear}

認証は完了していますが、接続先のアカウントにワークスペースがないか、まったく別のアカウントにいる可能性があります。まず AI エージェントにすべてのアカウントを一覧表示するよう依頼してください。複数のアカウントにアクセスできる場合は、別のアカウント ID を指定する必要があるかもしれません。AMA ユーザーは、正しい Adobe 組織で認証したかどうかも確認してください（上記参照）。

### 特定のツールでの権限エラー {#permission-errors-on-specific-tools}

ツールの呼び出しには、Frame.io アカウントの権限が反映されます。アップロードには Contributor のアクセス権が必要です。詳しくは、[ユーザー権限の管理](/ja/platform/docs/guides/managing-user-permissions)をご覧ください。

### アップロードが停止した、またはアセットが処理中のまま進まない {#upload-stalled-or-asset-stuck-in-processing}

AI エージェントにステータスを直接確認するよう依頼してください：*「最近アップロードしたファイルのアップロードステータスを教えて」*。エージェントは `get_upload_status` を呼び出します。大容量または高解像度のファイルは、トランスコードに数分かかることがあります。
