### インストール {#installation}

```bash
npm i -s frameio
```

---

### 使い方 {#usage}

次のようにクライアントをインスタンス化して使用します。

```typescript
import { FrameioClient } from "frameio";

const client = new FrameioClient({ token: "YOUR_TOKEN" });
await client.metadataFields.metadataFieldDefinitionsCreate("b2702c44-c6da-4bb6-8bbd-be6e547ccf1b", {
    data: {
        field_type: "select",
        field_configuration: {
            enable_add_new: false,
            options: [
                {
                    display_name: "Option 1",
                },
                {
                    display_name: "Option 2",
                },
            ],
        },
        name: "Fields definition name",
    },
});
```

---

### リクエストとレスポンスの型 {#request-and-response-types}

SDK は、すべてのリクエストとレスポンスの型を TypeScript インターフェースとしてエクスポートしています。次の名前空間を使ってインポートするだけで利用できます。

```typescript
import { Frameio } from "frameio";

const request: Frameio.UpdateFieldDefinitionParams = {
    ...
};
```

---

### 例外処理 {#exception-handling}

API が成功以外のステータスコード（4xx または 5xx レスポンス）を返した場合、次のエラーのサブクラスがスローされます。

```typescript
import { FrameioError } from "frameio";

try {
    await client.metadataFields.metadataFieldDefinitionsCreate(...);
} catch (err) {
    if (err instanceof FrameioError) {
        console.log(err.statusCode);
        console.log(err.message);
        console.log(err.body);
        console.log(err.rawResponse);
    }
}
```

### 高度な使い方 {#advanced}

#### 追加のヘッダー {#additional-headers}

リクエストに追加のヘッダーを含めて送信したい場合は、headers リクエストオプションを使用します。

```typescript
const response = await client.metadataFields.metadataFieldDefinitionsCreate(..., {
    headers: {
        'X-Custom-Header': 'custom value'
    }
});
```

#### 追加のクエリ文字列パラメーター {#additional-query-string-parameters}

リクエストに追加のクエリ文字列パラメーターを含めて送信したい場合は、queryParams リクエストオプションを使用します。

```typescript
const response = await client.metadataFields.metadataFieldDefinitionsCreate(..., {
    queryParams: {
        'customQueryParamKey': 'custom query param value'
    }
});
```

---

#### リトライ {#retries}

SDK には、指数バックオフによる自動リトライ機能が組み込まれています。リクエストがリトライ可能と判断され、かつリトライ回数が設定されたリトライ上限（デフォルト: 2）を超えていない限り、リクエストはリトライされます。

次のいずれかの HTTP ステータスコードが返された場合、リクエストはリトライ可能と判断されます。

- 408（タイムアウト）
- 429（リクエスト過多）
- 5XX（内部サーバーエラー）

<br />

この動作を設定するには、`maxRetries` リクエストオプションを使用します。

```typescript
const response = await client.metadataFields.metadataFieldDefinitionsCreate(..., {
    maxRetries: 0 // override maxRetries at the request level
});
```

---

#### タイムアウト {#timeouts}

SDK のデフォルトのタイムアウトは 60 秒です。この動作を設定するには、timeoutInSeconds オプションを使用します。

```typescript
const response = await client.metadataFields.metadataFieldDefinitionsCreate(..., {
    timeoutInSeconds: 30 // override timeout to 30s
});
```

#### リクエストの中止 {#aborting-requests}

SDK では、中止シグナルを渡すことで、任意の時点でリクエストを中止できます。

```typescript
const controller = new AbortController();
const response = await client.metadataFields.metadataFieldDefinitionsCreate(..., {
    abortSignal: controller.signal
});
controller.abort(); // aborts the request
```

---

#### 生のレスポンスデータへのアクセス {#access-raw-response-data}

SDK では、`.withRawResponse()` メソッドを通じて、ヘッダーを含む生のレスポンスデータにアクセスできます。`.withRawResponse()` メソッドは、`data` プロパティと `rawResponse` プロパティを持つオブジェクトに解決される Promise を返します。

```typescript
const { data, rawResponse } = await client.metadataFields.metadataFieldDefinitionsCreate(...).withRawResponse();

console.log(data);
console.log(rawResponse.headers['X-My-Header']);
```

#### ランタイムの互換性 {#runtime-compatibility}

SDK は次のランタイムで動作します。

- Node.js 18+
- Vercel
- Cloudflare Workers
- Deno v1.25+
- Bun 1.0+
- React Native

---

#### Fetch クライアントのカスタマイズ {#customizing-fetch-client}

SDK では、内部で使用される HTTP クライアント / Fetch 関数をカスタマイズできます。サポート対象外の環境で実行している場合でも、この方法を緊急手段として使うことで SDK を確実に動作させられます。

```typescript
import { FrameioClient } from "frameio";

const client = new FrameioClient({
    ...
    fetcher: // provide your implementation here
});
```

#### 認証 {#auth}

<AccordionGroup>

<Accordion title="new ServerToServerAuth({ clientId, clientSecret, ... })">

OAuth 2.0 の `client_credentials` グラントを使用して認証します。このフローはユーザーを介さず、リフレッシュトークンも返しません。アクセストークンの有効期限が切れると、SDK はクライアント認証情報を使って新しいトークンを自動的にリクエストします。

```typescript title="usage"
import { FrameioClient, ServerToServerAuth } from "frameio";

const auth = new ServerToServerAuth({
    clientId: "YOUR_CLIENT_ID",
    clientSecret: "YOUR_CLIENT_SECRET",
});
const client = new FrameioClient({ token: () => auth.getToken() });
```

**パラメーター**

`clientId`: `string` — Adobe IMS の OAuth クライアント ID。

`clientSecret`: `string` — Adobe IMS の OAuth クライアントシークレット。

`scopes`: `string` — スペース区切りのスコープ（OAuth 2.0 RFC 6749）。デフォルトはサーバー間認証用のスコープです。

`imsBaseUrl`: `string` — ステージング環境や別環境用の IMS ベース URL。デフォルトは本番環境です。

`fetch`: `typeof fetch` — カスタムの fetch 実装（プロキシ、TLS などに使用）。

`onTokenRefreshed`: `OnTokenRefreshed` — トークンを取得するたびに呼び出される任意のコールバック。

`timeout`: `number` — HTTP リクエストのタイムアウト（ミリ秒）。デフォルトは 30000 です。

`maxRetries`: `number` — 一時的な障害に対する最大リトライ回数。デフォルトは 2 です。

`refreshBuffer`: `number` — 有効期限の何秒前に事前リフレッシュを行うか。デフォルトは 60 です。

`logger`: `Logger` — 診断出力用のロガーインスタンス。

**メソッド**

`getToken(): Promise<string>` — 有効なアクセストークンを返します。必要に応じてリフレッシュします。クライアントには次のように渡します: `new FrameioClient({ token: () => auth.getToken() })`。

`authenticate(): Promise<TokenResponse>` — 新しいアクセストークンを明示的に取得します。

`revoke(): Promise<void>` — サーバー側でトークンを失効させ、ローカルの状態をクリアします。

`exportTokens(): ExportedTokens` — 永続化のために現在のトークンの状態をエクスポートします。

`importTokens(data: ExportedTokens): void` — 以前にエクスポートしたオブジェクトからトークンの状態を復元します。

</Accordion>

<Accordion title="new WebAppAuth({ clientId, clientSecret, redirectUri, ... })">

OAuth 2.0 の `authorization_code` グラントを使用して認証します。クライアントシークレットを安全に保管できるサーバーサイドアプリケーションで使用します。

```typescript title="usage"
import { randomBytes } from "crypto";
import { FrameioClient, WebAppAuth } from "frameio";

const auth = new WebAppAuth({
    clientId: "YOUR_CLIENT_ID",
    clientSecret: "YOUR_CLIENT_SECRET",
    redirectUri: "https://myapp.com/callback",
});
const url = auth.getAuthorizationUrl({ state: randomBytes(24).toString("hex") });
// redirect the user to url ...
await auth.exchangeCode("CODE_FROM_CALLBACK");
const client = new FrameioClient({ token: () => auth.getToken() });
```

**パラメーター**

`clientId`: `string` — Adobe IMS の OAuth クライアント ID。

`clientSecret`: `string` — Adobe IMS の OAuth クライアントシークレット。

`redirectUri`: `string` — 登録済みのリダイレクト URI。

`scopes`: `string` — スペース区切りのスコープ（OAuth 2.0 RFC 6749）。

`imsBaseUrl`: `string` — ステージング環境や別環境用の IMS ベース URL。デフォルトは本番環境です。

`fetch`: `typeof fetch` — カスタムの fetch 実装（プロキシ、TLS などに使用）。

`onTokenRefreshed`: `OnTokenRefreshed` — トークンをリフレッシュするたびに呼び出される任意のコールバック。

`timeout`: `number` — HTTP リクエストのタイムアウト（ミリ秒）。デフォルトは 30000 です。

`maxRetries`: `number` — 一時的な障害に対する最大リトライ回数。デフォルトは 2 です。

`refreshBuffer`: `number` — 有効期限の何秒前に事前リフレッシュを行うか。デフォルトは 60 です。

`logger`: `Logger` — 診断出力用のロガーインスタンス。

**メソッド**

`getToken(): Promise<string>` — 有効なアクセストークンを返します。必要に応じてリフレッシュします。

`getAuthorizationUrl({ state }): string` — Adobe IMS の認可 URL を構築します。そのまま返送される不透明な CSRF/state 値を渡します。

`exchangeCode(code: string): Promise<TokenResponse>` — 認可コードをアクセストークンとリフレッシュトークンに交換します。

`refresh(): Promise<TokenResponse>` — トークンのリフレッシュを手動で実行します。

`revoke(): Promise<void>` — サーバー側でトークンを失効させ、ローカルの状態をクリアします。

`exportTokens(): ExportedTokens` — 永続化のために現在のトークンの状態をエクスポートします。

`importTokens(data: ExportedTokens): void` — 以前にエクスポートしたオブジェクトからトークンの状態を復元します。

</Accordion>

<Accordion title="new SPAAuth({ clientId, redirectUri, ... })">

```typescript title="usage"
import { randomBytes } from "crypto";
import { FrameioClient, SPAAuth } from "frameio";

const auth = new SPAAuth({
    clientId: "YOUR_CLIENT_ID",
    redirectUri: "https://myapp.com/cb",
});
const result = await auth.getAuthorizationUrl({ state: randomBytes(24).toString("hex") });
// redirect the user to result.url, store result.codeVerifier ...
await auth.exchangeCode({ code: "CODE_FROM_CALLBACK", codeVerifier: result.codeVerifier });
const client = new FrameioClient({ token: () => auth.getToken() });
```

**パラメーター**

`clientId`: `string` — Adobe IMS の OAuth クライアント ID。

`redirectUri`: `string` — 登録済みのリダイレクト URI。

`scopes`: `string` — スペース区切りのスコープ（OAuth 2.0 RFC 6749）。

`imsBaseUrl`: `string` — ステージング環境や別環境用の IMS ベース URL。デフォルトは本番環境です。

`fetch`: `typeof fetch` — カスタムの fetch 実装（プロキシ、TLS などに使用）。

`onTokenRefreshed`: `OnTokenRefreshed` — トークンをリフレッシュするたびに呼び出される任意のコールバック。

`timeout`: `number` — HTTP リクエストのタイムアウト（ミリ秒）。デフォルトは 30000 です。

`maxRetries`: `number` — 一時的な障害に対する最大リトライ回数。デフォルトは 2 です。

`refreshBuffer`: `number` — 有効期限の何秒前に事前リフレッシュを行うか。デフォルトは 60 です。

`logger`: `Logger` — 診断出力用のロガーインスタンス。

**メソッド**

`getToken(): Promise<string>` — 有効なアクセストークンを返します。必要に応じてリフレッシュします。

`exchangeCode({ code, codeVerifier }): Promise<TokenResponse>` — 認可コードと PKCE ベリファイアをトークンに交換します。

`refresh(): Promise<TokenResponse>` — トークンのリフレッシュを手動で実行します。

`revoke(): Promise<void>` — サーバー側でトークンを失効させ、ローカルの状態をクリアします。

`exportTokens(): ExportedTokens` — 永続化のために現在のトークンの状態をエクスポートします。

`importTokens(data: ExportedTokens): void` — 以前にエクスポートしたオブジェクトからトークンの状態を復元します。

</Accordion>

<Accordion title="new NativeAppAuth({ clientId, redirectUri, ... })">

デスクトップアプリやモバイルアプリ向けに、`authorization_code` + PKCE を使用して認証します。API は `SPAAuth` と共通です。カスタムスキームのリダイレクト URI（例: `myapp://callback`）を使用してください。

```typescript title="usage"
// open result.url in the system browser, store result.codeVerifier ...
await auth.exchangeCode({ code: "CODE_FROM_CALLBACK", codeVerifier: result.codeVerifier });
const client = new FrameioClient({ token: () => auth.getToken() });
```

**パラメーター**

`clientId`: `string` — Adobe IMS の OAuth クライアント ID。

`redirectUri`: `string` — 登録済みのリダイレクト URI（カスタムスキームに対応）。

`scopes`: `string` — スペース区切りのスコープ（OAuth 2.0 RFC 6749）。

`imsBaseUrl`: `string` — ステージング環境や別環境用の IMS ベース URL。デフォルトは本番環境です。

`fetch`: `typeof fetch` — カスタムの fetch 実装（プロキシ、TLS などに使用）。

`onTokenRefreshed`: `OnTokenRefreshed` — トークンをリフレッシュするたびに呼び出される任意のコールバック。

`timeout`: `number` — HTTP リクエストのタイムアウト（ミリ秒）。デフォルトは 30000 です。

`maxRetries`: `number` — 一時的な障害に対する最大リトライ回数。デフォルトは 2 です。

`refreshBuffer`: `number` — 有効期限の何秒前に事前リフレッシュを行うか。デフォルトは 60 です。

**メソッド**

</Accordion>

<Accordion title="AuthorizationUrlResult">

`SPAAuth.getAuthorizationUrl()` と `NativeAppAuth.getAuthorizationUrl()` が返すオブジェクトです。認可 URL と PKCE コードベリファイアを保持します。

**プロパティ**

`url`: `string` — ユーザーのリダイレクト先となる完全な認可 URL。

#### 認証の例外 {#auth-exceptions}

すべての認証エラーは `FrameioAuthError` を継承しており、`frameio` からインポートできます。

| 例外 | 説明 |
| --- | --- |
| `FrameioAuthError` | 認証 SDK のすべてのエラーの基底エラー。 |
| `AuthenticationError` | トークンの交換またはリフレッシュに失敗しました。`errorCode` プロパティと `errorDescription` プロパティを持ちます。 |
| `TokenExpiredError` | リフレッシュトークンの有効期限が切れています。再認証が必要です。 |
| `NetworkError` | ネットワークリクエストに失敗しました（タイムアウト、接続エラーなど）。 |
| `RateLimitError` | Adobe IMS が 429 を返し、リトライ回数の上限に達しました。`retryAfter` プロパティを持ちます。 |
| `PKCEError` | PKCE の検証に失敗しました。 |
| `ConfigurationError` | 必須の設定が不足しているか、無効です。 |
