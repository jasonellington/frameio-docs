このガイドでは、Frame.io V4 API を使用してファイルをアップロードする一連の流れを詳しく説明します。ローカルアップロードとリモートアップロードの両方について、未加工の API リクエストとレスポンスを取り上げます。

<Info>

**SDK 固有のガイドをお探しですか?** チャンク分割、再試行、進捗状況の追跡が組み込まれたアップロードの実装については、[Python SDK アップロードガイド](/ja/platform/docs/guides/uploading-to-frame-io/python-sdk-upload-guide)を参照してください。

</Info>

## 前提条件 {#prerequisites}

ファイルのアップロードを始める前に、次のセットアップ手順が完了していることを確認してください。

<Steps>

<Step title="Frame.io V4 アカウント">

[Adobe Admin Console](https://adminconsole.adobe.com/) で管理されている Frame.io V4 アカウントを持っているか、アカウントユーザーを [Adobe 認証に切り替え](https://help.frame.io/en/articles/11758018-connecting-to-adobe-authentication)済みであること

</Step>

<Step title="Adobe Developer Console のセットアップ">

[Adobe Developer Console](https://developer.adobe.com/console) にログインし、新規または既存のプロジェクトに Frame.io API を追加済みであること

</Step>

<Step title="認証情報">

プロジェクト用の[適切な認証情報](https://developer.adobe.com/frameio/guides/Authentication/)を生成済みであること

</Step>

<Step title="アクセストークン">

その認証情報を使用してアクセストークンを正常に生成済みであること

</Step>

</Steps>

## アップロード方法の選択 {#choosing-your-upload-method}

Frame.io API を使用してファイルをアップロードする方法は、`Create File (local upload)` と `Create File (remote upload)` の 2 つです。

<CardGroup cols={2}>

<Card title="ローカルアップロード" icon="upload" iconType="solid">

デスクトップからファイルをドラッグするのと同様に、メディアがアプリケーションからローカルにアクセスできる場合に使用します

</Card>

<Card title="リモートアップロード" icon="link" iconType="solid">

## リモートアップロード {#remote-upload}

リモートアップロードでファイルを作成するには、**Create File (remote upload)** エンドポイントを選択します。リクエスト本文には、ファイル名とそのソース URL が必要です。

<Warning>

リモートアップロードには現在 **500 GB のファイルサイズ制限**があります。500 GB を超えるファイルの場合は、代わりに[ローカルアップロード](#local-upload)を使用してください。

</Warning>

### リクエスト例 {#request-example}

```json
{ 
    "data": {
        "name": "my_file.jpg",
        "source_url": "https://upload.wikimedia.org/wikipedia/commons/e/e1/White_Pixel_1x1.jpg"
    }
}
```

### レスポンス例 {#response-example}

リクエストが成功すると、次のようなレスポンスが返されます。

## ローカルアップロード {#local-upload}

ローカルアップロードでファイルを作成するには、**Create File (local upload)** エンドポイントを選択します。リクエスト本文には、ファイル名とバイト単位で指定したファイルサイズが必要です。

### リクエスト例 {#request-example-1}

```json
{ 
    "data": {
        "name": "my_file.jpg",
        "file_size": 50645990
    }
}
```

### レスポンス例 {#response-example-1}

リクエストが成功すると、コンテンツを持たないプレースホルダーのファイルリソースが作成されます。ファイルサイズに応じて、レスポンス本文には 1 つ以上の `upload_urls` が含まれます。この例では、アップロードを複数のパートに分けて管理する必要があります。

```json
{
    "data": {
        "id": "fa18ba7b-b3ee-4dd6-9b31-bd07e554241d",
        "name": "my_file.jpg",
        "status": "created",
        "type": "file",
        "file_size": 50645990,
        "updated_at": "2025-06-26T20:08:06.823170Z",
        "media_type": "image/jpeg",
        "parent_id": "2e426fe0-f965-4594-8b2b-b4dff1dc00ec",
        "project_id": "7e46e495-4444-4555-8649-bee4d391a997",
        "created_at": "2025-06-26T20:08:06.751313Z",
        "upload_urls": [
            {
                "size": 16881997,
                "url": "https://frameio-uploads-development.s3-accelerate.amazonaws.com/parts/fa18ba7b-b3ee-4dd6-9b31-bd07e554241d/part_1?..."
            },
            {
                "size": 16881997,
                "url": "https://frameio-uploads-development.s3-accelerate.amazonaws.com/parts/fa18ba7b-b3ee-4dd6-9b31-bd07e554241d/part_2?..."
            },
            {
                "size": 16881996,
                "url": "https://frameio-uploads-development.s3-accelerate.amazonaws.com/parts/fa18ba7b-b3ee-4dd6-9b31-bd07e554241d/part_3?..."
            }
        ],
        "view_url": "https://next.frame.io/project/7e46e495-4444-4555-8649-bee4d391a997/view/fa18ba7b-b3ee-4dd6-9b31-bd07e554241d"
    }
}
```

<Warning>

**アップロードに関する重要な要件:**

後続のアップロードリクエストを送信する際は、次の重要な点に留意してください。

- HTTP リクエストメソッドは `PUT` である必要があります
- `x-amz-acl` ヘッダーを含め、private に設定する必要があります
- `Content-Type` ヘッダーは、元の **Create File (local upload)** リクエストで指定された `media_type` と一致する必要があります。これは、ファイルを複数のパートに分けてアップロードする場合も同様です。上記の例では、`media_type` の値は `image/jpeg` です。したがって、`Content-Type` の値も `image/jpeg` である必要があります。

</Warning>

## マルチパートアップロード {#multi-part-upload}

ファイルに対して複数のアップロード URL が返された場合は、ソースファイルをチャンクに分割し、それぞれに対して PUT リクエストを送信する必要があります。

<Info>

**推奨:** [Python SDK アップロードガイド](/ja/platform/docs/guides/uploading-to-frame-io/python-sdk-upload-guide)では、`FrameioUploader` を使用したマルチパートアップロードについて説明しています。`FrameioUploader` は、チャンク分割、並列アップロード、再試行、進捗状況の追跡をすぐに使える形で処理します。

</Info>

SDK がない言語を使用する場合や、プロセスを完全に制御したい場合など、アップロードを手動で実装する必要があるときは、以下のスクリプトで、ファイルをチャンクに分割し、署名付き URL を使用して各チャンクをアップロードする方法を確認できます。

### Python の実装例 {#python-implementation-example}

```python title="Multi-part Upload Script"
import requests
import math
from typing import List
from tqdm import tqdm  # For progress bar

def upload_file_in_chunks(file_path: str, upload_urls: list[str], content_type: str | None = None, chunk_size: int | None = None) -> bool:
    """
    Upload a file in chunks using presigned URLs.
    """
    try:
        # Auto-detect content type based on file extension
        if content_type is None:
            detected_content_type, _ = mimetypes.guess_type(file_path)
            content_type = detected_content_type # Default fallback

        print(f"Detected content type: {content_type}")

        # Get file size
        with open(file_path, 'rb') as f:
            f.seek(0, 2)  # Seek to end of file
            file_size = f.tell()

        # Calculate chunk size if not provided
        if chunk_size is None:
            chunk_size = math.ceil(file_size / len(upload_urls))

        print(f"File size: {file_size} bytes")
        print(f"Chunk size: {chunk_size} bytes")
        print(f"Number of chunks: {len(upload_urls)}")

        # Upload each chunk
        with open(file_path, 'rb') as f:
            with tqdm(total=len(upload_urls), desc="Uploading chunks") as pbar:
                for i, url in enumerate(upload_urls):
                    start_byte = i * chunk_size
                    end_byte = min(start_byte + chunk_size, file_size)

                    # Read chunk from file
                    f.seek(start_byte)
                    chunk = f.read(end_byte - start_byte)

                    print(f"Uploading chunk {i+1}: {len(chunk)} bytes")

                    # Upload chunk with minimal headers matching the signature
                    response = requests.put(
                        url,
                        data=chunk,
                        headers={
                            'content-type': content_type,
                            'x-amz-acl': 'private'
                        }
                    )

                    if response.status_code != 200:
                        print(f"Failed to upload chunk {i+1}. Status code: {response.status_code}")
                        print(f"Response text: {response.text}")
                        print(f"Response headers: {dict(response.headers)}")
                        return False
                    else:
                        print(f"Chunk {i+1} uploaded successfully!")

                    pbar.update(1)

        return True

    except Exception as e:
        print(f"Error during upload: {str(e)}")
        return False

# Example usage
if __name__ == "__main__":
    # Replace these with your actual values
    file_path = "/Users/MyComputer/local_upload/sample.jpg"  # Path to your file
    upload_urls = [
        "https://frameio-uploads-development.s3-accelerate.amazonaws.com/parts/fa18ba7b-b3ee-4dd6-9b31-bd07e554241d/part_1?...",
        "https://frameio-uploads-development.s3-accelerate.amazonaws.com/parts/fa18ba7b-b3ee-4dd6-9b31-bd07e554241d/part_2?...",
        "https://frameio-uploads-development.s3-accelerate.amazonaws.com/parts/fa18ba7b-b3ee-4dd6-9b31-bd07e554241d/part_3?..."
    ]
    content_type = "image/jpeg"

    print("Starting file upload...")
    success = upload_file_in_chunks(file_path, upload_urls, content_type)

    if success:
        print("File upload completed successfully!")
    else:
        print("File upload failed!")
```

## アップロードフローのまとめ {#upload-flow-summary}

<Steps>

<Step title="アップロード方法を選択する">

リモートアップロード(URL 経由でアクセス可能なファイル)とローカルアップロード(システム上のファイル)のどちらを使用するかを決めます

</Step>

<Step title="Create File リクエストを送信する">

必要なメタデータを指定して、ファイルリソースを作成する最初のリクエストを送信します

</Step>

<Step title="アップロード URL を処理する">

ローカルアップロードの場合は、返された upload_urls(単一または複数のパート)を処理します

</Step>

<Step title="ファイルのコンテンツをアップロードする">

適切なヘッダーを付けた PUT リクエストを使用して、指定された URL にファイルのコンテンツをアップロードします

</Step>

<Step title="アップロードを確認する">

ファイルのステータスをチェックして、アップロードと処理が正常に完了したことを確認します

</Step>

</Steps>

<Info>

**次のステップ**: ファイルがアップロードされたら、返されたファイル ID を使用して、Frame.io V4 API でコメントの追加、共有の作成、その他の操作を実行できます。

</Info>
