Make は、アプリやサービスを接続するノーコードの自動化プラットフォームです。ビジュアルインターフェースを使用し、さまざまなモジュールを順番に並べてシナリオと呼ばれるワークフローを構築します。

すべてのシナリオには、トリガー（「Frame.io で新しいプロジェクトが作成された」など）と、それに続くアクション（「Google Sheets に行を追加する」など）があります。これらのモジュールを視覚的に接続して、何がどの順序で行われるかを定義します。

## Frame.io を Make に接続する理由 {#why-connect-frame-io-to-make}

Make は Frame.io をワークフロー全体に拡張します。ファイルをストレージに同期したり、プロジェクト管理ツールを更新したり、レポートを生成したり、チームに通知したり、Frame.io のアクティビティに基づいてカスタムワークフローを構築したりできます。Frame.io を技術スタックに接続すればするほど、その力は大きくなります。

**自動化のアイデア：**

- クライアントが受付フォームを送信したときに Frame.io プロジェクトを自動作成する
- Frame.io の動画にコメントが追加されたときに Slack に投稿する
- 新しい Frame.io プロジェクトが作成されたときに Google Sheet を更新する

これらはほんの一例です。利用可能な Frame.io モジュールの完全なリストについては、[Make.com](https://www.make.com/en/integrations/frame-io#:~:text=All-,Modules,-(26)) のこちらのページをご覧ください。

## 必要なもの {#what-you-need}

- **Frame.io アカウント**（サブスクリプション情報は[こちら](https://frame.io/pricing)）
- **Make アカウント**（無料プランあり）

## モジュールの種類 {#module-types}

Make には、トリガー、検索、アクション、ユニバーサルモジュールの 4 種類のモジュールがあります。

<CardGroup cols={2}>

<Card title="トリガー" icon="bell" iconType="solid" horizontal={true}>

トリガーは、サービス内の変更を監視し、それを Make に取り込むことで、そのデータをシナリオで使用できるようにします。トリガーモジュールはシナリオごとに **1 つ**追加できます。

<br />

ポーリングトリガーとインスタントトリガーの詳細については、以下の **トリガーの種類** セクションを参照してください。

<br />

- シナリオのツールバーで **Schedule settings** をクリックすると、トリガーモジュールの実行頻度を設定できます
- Make では、シナリオをトリガーモジュールから始めることを強く推奨しています。

</Card>

<Card title="検索" icon="magnifying-glass" iconType="solid" horizontal={true}>

検索モジュールは、サービスから特定のデータを取得します。検索モジュールはシナリオ内の任意の場所に複数追加できます。ほとんどの検索は、1 回の実行で最大 3,200 個のオブジェクトを返します。

<br />

**検索モジュールの種類：**

<br />

- **Search モジュール** では、フィルターやクエリを使用して特定のデータを検索できます
  （Search Records、Search Rows など）
- **List モジュール** は、フィルタリングせずにすべてのデータを取得します。（List Projects、List Sheets など）

</Card>

<Card title="アクション" icon="bolt" iconType="solid" horizontal={true}>

アクションモジュールは、サービスから取得したデータを処理します。アクションは必要な数だけ、シナリオ内の任意の場所に追加できます。

<br />

**アクションの種類：**

<br />

- GET
- CREATE
- UPDATE
- DELETE

<br />

</Card>

<Card title="ユニバーサルモジュール" icon="code" iconType="solid" horizontal={true}>

ユニバーサルモジュール（通常は **Make an API Call** と呼ばれます）を使用すると、必要な機能に対応する既製のモジュールが Make に用意されていない場合に、カスタム API 呼び出しを行えます。

<br />

ユニバーサルモジュールは必要な数だけ追加でき、シナリオ内の任意の場所に配置できます。

</Card>

</CardGroup>

## トリガーの種類 {#trigger-types}

Make では、ポーリングとインスタントの 2 種類のトリガーを使用します。

**ポーリングトリガー** は、スケジュールに従ってサービスアカウントに新しいデータがないかを確認します。通常、「Watch Records」や「Watch Rows」のような名前が付いています。シナリオが実行されると、Make はサービスに新しいものがあるかどうかを問い合わせます。あれば、シナリオがそれを処理します。

**インスタントトリガー** は動作が異なります。Webhook を使用するため、何かが起きるとサービスが即座に Make に通知します。シナリオはすぐに実行されます。モジュール上の稲妻アイコンと「Instant」タグで見分けることができます。

Frame.io の Watch Events モジュールはインスタントトリガーなので、後で構築するシナリオはリアルタイムで実行されます。

さまざまなモジュールタイプの実行方法の詳細については、Make の[ヘルプセンターのこちらのセクション](https://help.make.com/types-of-modules)を参照してください。

# Make のインターフェース {#the-make-interface}

Make のダッシュボードには、すべてのシナリオが表示されます。ここでは、アクティブなシナリオ、シナリオのパフォーマンス、クレジットの使用状況を監視します。ヘッダーの **Create scenario** をクリックすると、ビルダーが開きます。

### アプリケーションとモジュールの追加 {#adding-applications-+-modules}

シナリオにモジュールを追加するには、ビルダーの中央にあるプラスボタンをクリックします。パネルが開き、Frame.io や Google Sheets など必要なアプリを検索して、目的のモジュール（「Watch Events」や「Add a Row」など）を選択できます。ビルダー内でモジュールをドラッグ＆ドロップして接続し、シナリオを構築します。

### アプリの管理と再接続 {#managing-+-reconnecting-apps}

左側のサイドバーから、シナリオ、接続、Webhook、その他の Make の機能にアクセスできます。

Frame.io やその他のアプリを再接続する必要がある場合は、左側のサイドバーで **Connections** をクリックします。接続されているすべてのアプリが表示され、それぞれの横に **Reauthorize** ボタンがあります。これをクリックすると、認証フローを再度実行できます。

### テスト {#testing}

シナリオをテストするには、ツールバーで **Run once** をクリックします。テストが完了すると、各モジュールの上にオペレーションバブルが表示され、実行されたオペレーションの数が示されます。バブルをクリックすると、そのステップの入力データと出力データを確認できます。

**既存のデータでのテスト：**

デフォルトでは、トリガーは新しいイベントのみを処理します。既存のデータでテストするには、**Run once** ボタンの横にあるドロップダウン矢印をクリックします。ダイアログが開き、以前に受信した Webhook イベントのデータを再実行できます。

# 最初のシナリオの構築：新しいプロジェクトを Google Sheets に記録する {#building-your-first-scenario-log-new-projects-to-google-sheets}

始める前に、次の列見出しを持つ Google Sheet を作成してください。

**Event Type**、**Resource ID**、**Workspace ID**、**User ID**。この例では、シート名を「Frame Projects」とします。

<Steps>

<Step title="Frame.io に接続してトリガーを追加する">

Make ビルダーでプラス記号をクリックしてモジュールを追加します。「Frame.io」を検索し、**Watch Events** を選択します。これにより、Frame.io で特定のイベントが発生したときにトリガーされる Webhook が作成されます。

**Frame.io の接続：**

- 接続フィールドの横にある **Add** をクリックします
- デフォルトの接続名をそのまま使用するか、名前を変更します
- Adobe アカウントにログインして Make を承認するよう求められます
- 接続されると、利用可能なすべての Frame.io アカウントとワークスペースがドロップダウンに表示されます

**Webhook の設定：**

- アカウントと、監視するワークスペースを選択します。この例では「New Workspace」を使用します
- イベントで **Project Created** を選択します（サポートされているイベントの詳細については、[Webhooks のドキュメント](https://developer.adobe.com/frameio/guides/Webhooks/#webhook-event-subscriptions)を参照してください）
- Webhook に名前を付けて、変更を保存します

</Step>

<Step title="Google Sheets を追加する">

プラス記号をクリックして次のステップを追加します。Google Sheets アプリを検索して選択し、**Add a Row** モジュールをクリックします。

**Google Sheets の接続：**

- **Add** をクリックして新しい接続を作成します
- **Sign in with Google** をクリックし、Make が Google アカウントにアクセスすることを承認します
- 接続されると、アカウントのシートがドロップダウンに表示されます
- シート/タブ名（この例では「Frame Projects」）を選択します

**データのマッピング：**
次に、Frame.io のデータをスプレッドシートの列にマッピングします。各フィールドをクリックし、Frame.io トリガーから対応するデータを選択します。

- **Event Type** → Frame.io の Event Type にマッピング
- **Resource ID** → Frame.io の Resource にマッピング
- **Workspace ID** → Frame.io の Workspace ID にマッピング
- **User ID** → Frame.io の User ID にマッピング

</Step>

<Step title="テストして有効化する">

**Run once** をクリックしてシナリオをテストし、選択した Frame.io ワークスペースで新しいプロジェクトを作成します。すべてが正しく設定されていれば、スプレッドシートに新しい行が表示されます。

![Sheet](/images/platform/docs/guides/make/frame_sheet_example.gif)

本番運用の準備ができたら、トグルを **Active** に切り替えると、自動的に実行されるようになります。

</Step>

</Steps>

これで最初の自動化が完成しました。ここから、このシナリオにさらにステップを追加したり、[Make.com](https://www.make.com/en/integrations/frame-io#:~:text=All-,Modules,-(26)) で利用可能な他の Frame.io モジュールを使用して新しいシナリオを構築したりできます。

問題が発生した場合、質問がある場合、または構築したものを共有したい場合は、[コミュニティフォーラム](https://forum.frame.io/)をご覧ください。
