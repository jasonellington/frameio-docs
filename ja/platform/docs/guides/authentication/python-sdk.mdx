このガイドでは、**Frame.io Python SDK**（`frameio`）を使用して Frame.io API で認証する方法を説明します。Frame.io V4 API は、Adobe の OAuth 2.0 アイデンティティプラットフォームである [Adobe Identity Management Service（IMS）](https://developer.adobe.com/developer-console/docs/guides/authentication/)を使用します。

これは Python 開発者向けの独立したリファレンスです。以下のコード例とフローはすべて `frameio` パッケージ専用です。

---

## Python SDK の認証タイプ {#authentication-types-in-the-python-sdk}

Python SDK は 4 つの認証オプションをサポートしています。

| 方式 | ユースケース | ユーザー操作の有無 | クライアントシークレットが必要か |
| --- | --- | --- | --- |
| **静的トークン** | 簡単なスクリプト、テスト、またはすでにトークンを持っている場合 | なし | 不要 |
| **Server-to-Server** | バックエンドサービス、cron ジョブ、自動化 | なし | 必要 |
| **Web App** | サーバーサイドアプリ（Flask、Django、FastAPI） | あり | 必要 |
| **SPA（PKCE）** | ブラウザーアプリ、CLI、またはシークレットを保存できないアプリ | あり | 不要 |

**Server-to-Server** を使うと、アプリはユーザーの操作なしでサービスアカウントとして動作できます。[Adobe Admin Console](https://adminconsole.adobe.com/) で管理されている Frame.io V4 アカウントでのみ利用できます。

**Web App** と **SPA** を使うと、アプリは特定のユーザーとして動作できます。どちらも内部で Adobe IMS を使用します。ユーザーがアプリを認可し、SDK が受け取ったコードをトークンと交換します。Python SDK は IMS の `/authorize/v2` と `/token/v3` のフローを処理します。Web App ではクライアントシークレットが必要で、SPA では代わりに [PKCE](https://datatracker.ietf.org/doc/html/rfc7636) を使用します。

<Note>

Adobe の [Native App 認証情報](https://developer.adobe.com/developer-console/docs/guides/authentication/UserAuthentication/implementation/#oauth-native-app-credential)には、OS レベルでリダイレクトを受け取るカスタム URI スキームハンドラー（例：`adobe+<hash>://…`）が必要です。Python にはこのようなハンドラーを登録する標準的な方法がないため、Python SDK には `NativeAppAuth` クラスがありません。ユーザーが操作する Python アプリでは、ローカルのコールバックサーバー（例：Flask や FastAPI）とともに `WebAppAuth` を使用してください。非対話型のワークロードには `ServerToServerAuth` を使用してください。

</Note>

## サービスアカウントユーザー {#service-account-users}

Server-to-Server 認証を使用すると、アプリケーションは**サービスアカウントユーザー**として動作します。これは、サービスに代わってアクションを実行できる独自のアカウントタイプです。サービスアカウントは Frame.io 上で他のユーザーにも表示され、サービスアカウントがアクションを実行すると、その名前が UI に表示されます。

サービスアカウントへのアクセスは、[Adobe Admin Console](https://adminconsole.adobe.com/) と [Developer Console](https://developer.adobe.com/console) で付与および取り消しできます。サービスアカウント名は Frame.io の UI から管理します。デフォルトでは、最初の S2S 接続は **Service Account User**、2 番目は **Service Account User 2** というように命名されます。

<Info>

詳しくは、[Frame.io の Server-to-Server サポートを使用してセットアップを自動化する](https://helpx.adobe.com/enterprise/using/automate-using-frame-io.html)を参照してください。

</Info>

## クイックスタート {#quick-start}

### 前提条件 {#prerequisites}

1. [Adobe Developer Console](https://developer.adobe.com/console) で取得した**認証情報**：

   - **クライアント ID** — すべての OAuth フローで必要
   - **クライアントシークレット** — Server-to-Server と Web App のフローで必要
   - **リダイレクト URI** — Web App と SPA のフローで必要。Adobe プロジェクトに登録されている必要があります

2. **SDK をインストールします：**

```bash
pip install frameio
```

### 方式の選択 {#choosing-a-method}

- **ユーザーが関与しない場合：** **Server-to-Server**（`ServerToServerAuth`）を使用します。
- **ユーザーが関与し、シークレットを保存できる場合：** **Web App**（`WebAppAuth`）を使用します。
- **ユーザーが関与するが、シークレットを保存できない場合：** **SPA**（`SPAAuth`）を使用します。

## アクセストークン {#access-token}

すでにアクセストークンを持っている場合（別の OAuth システムや、[API Explorer](/ja/platform/api-reference/accounts/index?explorer=true) などでの以前の交換によって取得したもの）は、直接渡すことができます。

```python
from frameio import Frameio

client = Frameio(token="YOUR_ACCESS_TOKEN")
```

これは最もシンプルな方法ですが、トークンはいずれ期限切れになり、SDK はリフレッシュを行いません。

### レガシー開発者トークン {#legacy-developer-tokens}

V4 に移行済みで、まだ [Adobe Admin Console](https://adminconsole.adobe.com/) で管理されていないアカウントでは、[Frame.io 開発者サイト](https://developer.frame.io/app/tokens)のレガシー開発者トークンを引き続き使用できます。`x-frameio-legacy-token-auth` ヘッダーを含め、値を `true` に設定する必要があります。

```python
from frameio import Frameio

client = Frameio(
    token="YOUR_LEGACY_DEVELOPER_TOKEN",
    headers={"x-frameio-legacy-token-auth": "true"},
)
```

レガシー開発者トークンは期限切れになりませんが、移行期間用の仕組みです。新しい連携や本番ワークロードには、以下のいずれかの OAuth 2.0 フローを使用することをお勧めします。詳細については、[移行ガイド](/ja/platform/docs/resources/migration#authentication)を参照してください。

## Server-to-Server（クライアント認証情報） {#server-to-server-client-credentials}

ユーザーの操作なしで Frame.io にアクセスする必要があるバックエンドサービスやスクリプトで使用します。このフローは、[Adobe Admin Console](https://adminconsole.adobe.com/) で管理されている Frame.io V4 アカウントでのみ利用できます。アプリケーションは[サービスアカウントユーザー](#service-account-users)として認証され、人間の介在は必要ありません。

<Tabs>

<Tab title="同期">

```python
from frameio import Frameio
from frameio.auth import ServerToServerAuth

auth = ServerToServerAuth(
    client_id="YOUR_CLIENT_ID",
    client_secret="YOUR_CLIENT_SECRET",
)

client = Frameio(token=auth.get_token)
```

</Tab>

<Tab title="非同期">

```python
from frameio import AsyncFrameio
from frameio.auth import AsyncServerToServerAuth

auth = AsyncServerToServerAuth(
    client_id="YOUR_CLIENT_ID",
    client_secret="YOUR_CLIENT_SECRET",
)

client = AsyncFrameio(token=auth.get_token)
```

</Tab>

</Tabs>

これだけです。`auth.get_token` は、SDK がリクエストのたびに呼び出す呼び出し可能オブジェクトです。現在のトークンがまだ有効であれば、すぐに返します。期限切れが近い場合は、まず新しいトークンを取得します。これらはすべて透過的に行われます。

### 仕組み {#how-it-works}

クライアント認証情報（クライアント ID とシークレット）は**期限切れになりません**。セキュリティ対策として手動でローテーションするだけです。S2S を使えば、手動の介入なしに、事実上永続的かつ途切れることのない API アクセスが得られます。

内部では次のように動作します。

1. 最初の API 呼び出しで、`get_token` は `client_credentials` グラントを使用して Adobe IMS に新しいアクセストークンをリクエストします。
2. トークンはメモリにキャッシュされます。個々のアクセストークンは期限切れになります（通常は 24 時間）が、これは自動的に処理されます。
3. キャッシュされたトークンがリフレッシュバッファー（デフォルト：期限切れの 60 秒前）に入ると、SDK は同じクライアント認証情報を使って新しいトークンを自動的に取得します。
4. リフレッシュトークンは使用されません。クライアント認証情報自体が長期間有効なシークレットであり、いつでも新しいアクセストークンの発行に使用できます。

### 明示的な認証 {#explicit-authentication}

トークンを事前に取得したい場合（たとえば、起動時に誤った認証情報をすぐに検出したい場合）：

```python
auth = ServerToServerAuth(client_id="...", client_secret="...")
auth.authenticate()  # raises AuthenticationError if credentials are invalid
client = Frameio(token=auth.get_token)
```

## Web App（認可コード） {#web-app-authorization-code}

ユーザーが Adobe ID でサインインするサーバーサイドアプリケーションで使用します。このフローにはクライアントシークレットが必要で、サーバー上に安全に保存する必要があります。

<Steps>

<Step title="ユーザーを Adobe IMS にリダイレクトする">

<Tabs>

<Tab title="同期">

```python
from frameio.auth import WebAppAuth

auth = WebAppAuth(
    client_id="YOUR_CLIENT_ID",
    client_secret="YOUR_CLIENT_SECRET",
    redirect_uri="https://yourapp.com/callback",
)

# Generate a cryptographically random state value to prevent CSRF attacks
import secrets
state = secrets.token_urlsafe(32)

authorization_url = auth.get_authorization_url(state=state)
# Store `state` in the user's session, then redirect them to `authorization_url`
```

</Tab>

<Tab title="非同期">

```python
from frameio.auth import AsyncWebAppAuth

auth = AsyncWebAppAuth(
    client_id="YOUR_CLIENT_ID",
    client_secret="YOUR_CLIENT_SECRET",
    redirect_uri="https://yourapp.com/callback",
)

# get_authorization_url is synchronous (no I/O needed)
import secrets
state = secrets.token_urlsafe(32)

authorization_url = auth.get_authorization_url(state=state)
```

</Tab>

</Tabs>

</Step>

<Step title="コールバックを処理する">

Adobe IMS がユーザーを `redirect_uri` にリダイレクトしたら、`code` と `state` のパラメーターを取り出します。state が保存した値と一致することを確認してから、コードをトークンと交換します。

<Tabs>

<Tab title="同期">

```python
# In your callback handler (e.g. a Flask/FastAPI route):
auth.exchange_code(code=request.args["code"])
```

</Tab>

<Tab title="非同期">

```python
# In your async callback handler (e.g. a FastAPI route):
await auth.exchange_code(code=request.query_params["code"])
```

</Tab>

</Tabs>

これにより、認可コードがアクセストークンとリフレッシュトークンに交換され、両方が内部に保存されます。

</Step>

<Step title="クライアントを使用する">

<Tabs>

<Tab title="同期">

```python
from frameio import Frameio

client = Frameio(token=auth.get_token)
```

</Tab>

<Tab title="非同期">

```python
from frameio import AsyncFrameio

client = AsyncFrameio(token=auth.get_token)
```

</Tab>

</Tabs>

これだけです。これ以降、`get_token` がトークンのライフサイクルを自動的に管理します。アクセストークンの期限が近づくと、SDK はリフレッシュトークンを使って新しいトークンを取得します。ユーザーの操作は必要ありません。

</Step>

</Steps>

### Flask の完全な例 {#full-flask-example}

```python
import secrets
from flask import Flask, redirect, request, session
from frameio import Frameio
from frameio.auth import WebAppAuth

app = Flask(__name__)
app.secret_key = secrets.token_bytes(32)

auth = WebAppAuth(
    client_id="YOUR_CLIENT_ID",
    client_secret="YOUR_CLIENT_SECRET",
    redirect_uri="http://localhost:5000/callback",
)

@app.route("/login")
def login():
    state = secrets.token_urlsafe(32)
    session["oauth_state"] = state
    return redirect(auth.get_authorization_url(state=state))

@app.route("/callback")
def callback():
    if request.args.get("state") != session.pop("oauth_state", None):
        return "Invalid state parameter", 403

    auth.exchange_code(code=request.args["code"])

    client = Frameio(token=auth.get_token)
    accounts = client.accounts.index()
    return f"Authenticated — {len(accounts.data)} account(s) accessible."
```

## Single Page App / PKCE（認可コード + PKCE） {#single-page-app-/-pkce-authorization-code-+-pkce}

クライアントシークレットを安全に保存できないブラウザーベースのアプリケーション、デスクトップアプリ、CLI ツールで使用します。このフローでは、[PKCE（RFC 7636）](https://datatracker.ietf.org/doc/html/rfc7636)を使用して認可コードの交換を保護します。

<Steps>

<Step title="認可 URL を生成する">

<Tabs>

<Tab title="同期">

```python
from frameio.auth import SPAAuth

auth = SPAAuth(
    client_id="YOUR_CLIENT_ID",
    redirect_uri="https://yourapp.com/callback",
)

import secrets
state = secrets.token_urlsafe(32)

result = auth.get_authorization_url(state=state)
# result.url            -> redirect the user here
# result.code_verifier  -> store this securely until the callback
```

</Tab>

<Tab title="非同期">

```python
from frameio.auth import AsyncSPAAuth

auth = AsyncSPAAuth(
    client_id="YOUR_CLIENT_ID",
    redirect_uri="https://yourapp.com/callback",
)

# get_authorization_url is synchronous (no I/O needed)
import secrets
state = secrets.token_urlsafe(32)

result = auth.get_authorization_url(state=state)
```

</Tab>

</Tabs>

`get_authorization_url` は、完全な URL（PKCE の `code_challenge` が埋め込まれたもの）と、次のステップで必要になる `code_verifier` を含む `AuthorizationUrlResult` を返します。

</Step>

<Step title="verifier を使ってコードを交換する">

ユーザーがリダイレクトで戻ってきたら：

<Tabs>

<Tab title="同期">

```python
auth.exchange_code(
    code="CODE_FROM_CALLBACK",
    code_verifier=result.code_verifier,
)
```

</Tab>

<Tab title="非同期">

```python
await auth.exchange_code(
    code="CODE_FROM_CALLBACK",
    code_verifier=result.code_verifier,
)
```

</Tab>

</Tabs>

</Step>

<Step title="クライアントを使用する">

<Tabs>

<Tab title="同期">

```python
from frameio import Frameio

client = Frameio(token=auth.get_token)
```

</Tab>

<Tab title="非同期">

```python
from frameio import AsyncFrameio

client = AsyncFrameio(token=auth.get_token)
```

</Tab>

</Tabs>

これだけです。リフレッシュは Web App と同じように動作し、SDK がリフレッシュトークンを自動的に使用します。違いは、SPA フローはパブリッククライアント向けに設計されているため、リフレッシュ時にクライアントシークレットが送信されない点です。

</Step>

</Steps>

## 非同期での使用 {#async-usage}

すべての認証クラスには、`Async` という接頭辞が付いた非同期版があります。上記のコード例には、該当する場合に**同期**タブと**非同期**タブがあります。

| 同期 | 非同期 |
| --- | --- |
| `ServerToServerAuth` | `AsyncServerToServerAuth` |
| `WebAppAuth` | `AsyncWebAppAuth` |
| `SPAAuth` | `AsyncSPAAuth` |

API は同一です。`get_authorization_url` は同期のまま（I/O なし）ですが、`exchange_code`、`refresh`、`revoke`、`get_token` はすべて `async` です。非同期クラスは `AsyncFrameio` と組み合わせて使用してください。

### 手動でのトークンのリフレッシュ {#manual-token-refresh}

Web App と SPA のフローでは、SDK が `get_token` を通じてトークンを自動的にリフレッシュします。明示的に制御する必要がある場合は、`refresh()` を直接呼び出せます。

<Tabs>

<Tab title="同期">

```python
auth.refresh()  # fetches a new access token using the refresh token
```

</Tab>

<Tab title="非同期">

```python
await auth.refresh()
```

</Tab>

</Tabs>

これは、自動リフレッシュのバッファーに頼らず、重要な操作の前にリフレッシュを強制したい場合に便利です。

## トークンの永続化 {#token-persistence}

すべての認証クラスは、再起動をまたいでトークンの状態を永続化するための `export_tokens()` と `import_tokens()` をサポートしています。Web App と SPA のフローでは、アクセストークンとリフレッシュトークンはデフォルトでメモリ上に保持されるため、これは特に重要です。永続化しない場合、アプリケーションが再起動するとユーザーは再認証する必要があります。Server-to-Server では永続化は任意です（クライアント認証情報でいつでも新しいトークンを発行できます）が、キャッシュしたトークンをインポートすると、起動時の余分なラウンドトリップを省けます。

### エクスポートとインポート {#export-and-import}

```python
# After exchange_code(), save the token state
token_data = auth.export_tokens()
# token_data is a dict: {"access_token": "...", "refresh_token": "...", "expires_at": 1234567890.0}
# Save it to your database, file, or secret store

# On next startup, restore it
auth.import_tokens(token_data)
client = Frameio(token=auth.get_token)
# The SDK will automatically refresh if the token is near expiry
```

### `on_token_refreshed` による自動永続化 {#automatic-persistence-with-on_token_refreshed}

トークンがリフレッシュされるたびに自動的に永続化するには、`on_token_refreshed` コールバックを使用します。

```python
import json
from pathlib import Path

TOKEN_FILE = Path("tokens.json")

def save_tokens(tokens: dict):
    TOKEN_FILE.write_text(json.dumps(tokens))

auth = WebAppAuth(
    client_id="...",
    client_secret="...",
    redirect_uri="...",
    on_token_refreshed=save_tokens,
)

# On startup, restore if available
if TOKEN_FILE.exists():
    auth.import_tokens(json.loads(TOKEN_FILE.read_text()))
```

コールバックは `export_tokens()` と同じ形式の dict を受け取り、トークンのリフレッシュが成功するたびに呼び出されます。

非同期クラスでは、`on_token_refreshed` に通常の関数と `async` 関数のどちらも指定できます。

## トークンの取り消し {#revoking-tokens}

ユーザーをサインアウトさせ、Adobe IMS でそのトークンを無効化するには：

```python
auth.revoke()
```

これにより、アクセストークンとリフレッシュトークンの両方について Adobe IMS にベストエフォートで取り消しリクエストを送信し、その後ローカルのトークン状態をすべてクリアします。取り消し後、ユーザーは再認証する必要があります。

<Tip>

非同期クラスでは、`await auth.revoke()` を使用します。

</Tip>

## エラー処理 {#error-handling}

すべての認証エラーは `FrameioAuthError` を継承しているため、まとめてキャッチすることも、特定のケースを個別に処理することもできます。

```python
from frameio.auth import (
    FrameioAuthError,
    AuthenticationError,
    TokenExpiredError,
    ConfigurationError,
    NetworkError,
    RateLimitError,
)

try:
    auth.exchange_code(code="...")
except TokenExpiredError:
    # The refresh token has expired; redirect the user to sign in again
    pass
except AuthenticationError as e:
    # Token exchange failed
    print(f"Error: {e.error_code} - {e.error_description}")
except NetworkError:
    # Timeout or connection failure (after retries)
    pass
except RateLimitError as e:
    # 429 from Adobe IMS; retry after e.retry_after seconds
    pass
except FrameioAuthError:
    # Catch-all for any other auth error
    pass
```

### エラーリファレンス {#error-reference}

| 例外 | 発生する状況 |
| --- | --- |
| `ConfigurationError` | 設定が欠落しているか無効な場合（例：`client_id` が空、リダイレクト URI が HTTPS ではない） |
| `AuthenticationError` | トークンの交換またはリフレッシュが Adobe IMS によって拒否された場合（`.error_code` と `.error_description` を持ちます） |
| `TokenExpiredError` | リフレッシュトークン自体が期限切れの場合。ユーザーは再認証する必要があります |
| `NetworkError` | すべての再試行後も HTTP タイムアウトまたは接続障害が発生した場合 |
| `RateLimitError` | Adobe IMS が 429 を返した場合。バックオフの目安は `.retry_after` を確認してください |
| `PKCEError` | PKCE の検証に失敗した場合（SPA フロー） |

### 本番環境での期限切れリフレッシュトークンの処理 {#handling-expired-refresh-tokens-in-production}

<Warning>

Web App と SPA のフローでは、リフレッシュトークンはいずれ期限切れになります。その場合、`get_token` は `TokenExpiredError` を発生させます。これをキャッチして、ユーザーに再度認可フローを通過させてください。

</Warning>

```python
from frameio.auth import TokenExpiredError

try:
    client = Frameio(token=auth.get_token)
    assets = client.files.list(project_id="...")
except TokenExpiredError:
    # Clear persisted tokens and redirect user to login
    auth.revoke()
    return redirect("/login")
```

### ステージング環境 {#staging-environments}

`ims_base_url` を上書きして、ステージング用の Adobe IMS インスタンスを指定します。本番環境の値をプログラムから参照する必要がある場合のために、SDK は `DEFAULT_IMS_BASE_URL`（`https://ims-na1.adobelogin.com`）もエクスポートしています。

```python
auth = ServerToServerAuth(
    client_id="...",
    client_secret="...",
    ims_base_url="https://ims-na1-stg1.adobelogin.com",
)
```

### カスタム HTTP クライアント {#custom-http-client}

プロキシのサポートやカスタム TLS 設定の場合：

```python
import httpx

http_client = httpx.Client(
    proxy="http://corporate-proxy:8080",
    verify="/path/to/custom-ca-bundle.pem",
)

auth = ServerToServerAuth(
    client_id="...",
    client_secret="...",
    http_client=http_client,
)
```

## スレッドセーフ {#thread-safety}

同期の認証クラスは完全にスレッドセーフです。複数のスレッドが同時に `get_token` を呼び出し、リフレッシュが必要になった場合でも、リフレッシュを実行するのは 1 つのスレッドだけです。他のスレッドは待機し、同じ結果を受け取ります。外部でのロックは不要です。

非同期クラスは `asyncio.Lock` を使用して同じことを保証しており、単一のイベントループ内の並行コルーチンで安全に使用できます。
