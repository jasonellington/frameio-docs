## トークン更新の基本 {#basics-of-token-refresh}

OAuth2.0 の認証情報リクエストに ***offline*** スコープを含めている場合、Frame.io の Accounts アプリケーションによる認証に成功すると、次のようなペイロードが返されます。

```json
{
  "access_token":"BEARER_TOKEN",
  "expires_in":3600,
  "refresh_token":"REFRESH_TOKEN",
  "scope":"account.read offline",
  "token_type":"bearer"
}
```

`access_token` は、認証済みユーザーに代わって操作するために使用できる bearer トークンです。これは 3600 秒(1 時間)後に期限切れになり、その後は `refresh_token` を使って新しい `access_token` を取得できます。リフレッシュトークンは 30 日後に期限切れになり、その時点でユーザーに最初からログインしてもらい、新しいアクセストークンとリフレッシュトークンのペアを発行する必要があります。以降も同様です。

*offline* スコープを明示的に要求しない場合、`refresh_token` は返されません。そのため、1 時間後にはユーザーを完全に再認証する必要があります。

### 認証成功時にリフレッシュトークンを取得する {#capturing-the-refresh-token-on-successful-authentication}

言うまでもなく、持っていない `refresh_token` は使用できないため、アプリでは必ず次のことを行ってください。

- **offline** スコープを要求する
- 成功したコールバックで返される `refresh_token` を取得する

便宜上、[OAuth 2 アプリガイド](https://developer.frame.io/oauth-2-applications/building-an-oauth-2-app)のコールバックを、リフレッシュトークンを保存するための `os` 呼び出しを加えてここに再掲します。2 つの例を示している点に注意してください。1 つは PKCE を設定した場合(Basic 認証ヘッダーを含まない)、もう 1 つは設定しない場合(Basic 認証ヘッダーを含む)です。

### PKCE を使用しない場合 {#without-pkce}

```python title="Python"
def callback():
  # Where `request` refers to our initial call to the auth URL
  state = request.args.get('state')
  scope = request.args.get('scope')
  code = request.args.get('code')
  error = request.args.get('error')

  if error:
    return "Error: " + error

  # Set up for client authorization and set up the data you need to send.
  client_auth = requests.auth.HTTPBasicAuth(CLIENT_ID, CLIENT_SECRET)

  post_data = {
    "grant_type": "authorization_code",
    "code": code,
    "redirect_uri": REDIRECT_URI,
    "state": state,
    "scope": SCOPE
  }

  # Send a POST request with the data you need to receive an access token. 
  response = requests.post(TOKEN, auth=client_auth, data=post_data)    
	# Stash the refresh token for later
  os.environ['REFRESH_TOKEN'] = response.json()["refresh_token"]

  return response.text
```

### PKCE を使用する場合 {#with-pkce}

```python title="Python"
def callback():
  # Where `request` refers to our initial call to the auth URL
  state = request.args.get('state')
  scope = request.args.get('scope')
  code = request.args.get('code')
  error = request.args.get('error')

  if error:
    return "Error: " + error

  # If using PKCE, you must include the CLIENT_ID in your request body  
  post_data = {
    "grant_type": "authorization_code",
    "code": code,
    "redirect_uri": REDIRECT_URI,
    "state": state,
    "scope": SCOPE
    "client_id": CLIENT_ID 
  }

  # Send a POST request with the data you need to receive an access token.
  # If using PKCE, use the below request with no auth
  response = requests.post(TOKEN_URL, data=post_data)
  # Stash the refresh token for later
  os.environ['REFRESH_TOKEN'] = response.json()["refresh_token"]

  return response.text
```

## 更新を実行する {#executing-a-refresh}

更新自体は、Frame.io のトークン URL への 1 回の呼び出しで行います。

- メソッド: POST
- URL: **[https://applications.frame.io/oauth2/token](https://applications.frame.io/oauth2/token)**
- `Content-Type`: *application/x-www-form-urlencoded*

更新のフォームデータには、少なくとも次の 3 つの属性が常に含まれます。

- `grant_type`: *refresh_token*
- `scope`: &lt;SCOPES>
- `refresh_token`: &lt;REFRESH_TOKEN>

PKCE を使用している場合は、このフォームデータにアプリの `client_id` を含める必要があります。使用していない場合は、アプリの `client_id` と `client_secret` をそれぞれユーザー名とパスワードとする Basic 認証ヘッダーを含める必要があります。

### PKCE を使用しない場合 {#without-pkce-1}

PKCE を使用せずに[最初の認証コールバックを行う](https://developer.frame.io/oauth-2-applications/building-an-oauth-2-app#the-callback)場合と同様に、この標準的な更新では、Basic 認証ヘッダーのユーザー名とパスワードとして `client_id` と `client_secret` を指定する必要があります。

```python title="Python"
def refresh():
  # Fetch the refresh token, assuming we have it
  REFRESH_TOKEN = os.environ.get('REFRESH_TOKEN')

  client_auth = requests.auth.HTTPBasicAuth(CLIENT_ID,CLIENT_SECRET)
  post_data = {
    "grant_type": "refresh_token",
    "scope": SCOPE,
    "refresh_token": REFRESH_TOKEN
    # if using PKCE, you will need to include your client_id as below
    # "client_id": CLIENT_ID 
  }

  response = requests.post(TOKEN_URL, auth=client_auth, data=post_data)
  # Catch + stash a new Refresh Token
  os.environ['REFRESH_TOKEN'] = response.json()["refresh_token"]

  return response.text
```

### PKCE を使用する場合 {#with-pkce-1}

ここでも、最初の `/callback` サイクルのルールにならいます。

- `Authorization` ヘッダーは含めない
- ペイロードに `client_id` を含める必要がある

```python title="Python"
def refresh():
  # Fetch the refresh token, assuming we have it
  REFRESH_TOKEN = os.environ.get('REFRESH_TOKEN')

  post_data = {
    "grant_type": "refresh_token",
    "scope": SCOPE,
    "refresh_token": REFRESH_TOKEN
    "client_id": CLIENT_ID 
  }

  response = requests.post(TOKEN_URL, data=post_data)
  # Catch + stash a new Refresh Token
  os.environ['REFRESH_TOKEN'] = response.json()["refresh_token"]

  return response.text
```
