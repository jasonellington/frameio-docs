<Info>

**サンプルアプリ**

独自の Custom Actions アプリを構築したい場合は、以下のサンプルアプリが役立ちます。

</Info>

- [JavaScript](https://github.com/Frameio/custom-actions-example-app)
- [Python](https://github.com/Frameio/custom-actions-app-python)

Custom Actions は、プログラム可能な UI コンポーネントとして Frame.io に直接インテグレーションを組み込むための仕組みです。これにより、[Webhooks](/ja/platform/v2/webhooks-overview) と同じ基盤のイベントルーティングを活用し、アプリ内でユーザーがトリガーできるさまざまなワークフローが実現できます。現在、Custom Actions は Asset で利用でき、下の画像のように、任意の Asset で表示されるコンテキストメニュー(右クリックのドロップダウンメニュー)に表示されます。

![actions-1](/images/platform/v2/custom-actions-overview/69bc65d3924a350e0c1d5a8062e41b15cbc3b01f1f3b8ec5050356b76aa1989a.webp)

Asset は、S3 上のファイルと、Frame.io におけるそのコンテキストを包括的に表現したものです。これにはトランスコード、ユーザー/チーム/プロジェクトのコンテキスト、メタデータが含まれます。ユーザーが Asset 上で Custom Action をクリックすると、Frame.io は指定された URL にペイロードを送信します。受信側のアプリケーションは、受信を確認するだけの HTTP ステータスコードを返すことも、Frame.io に追加の UI を表示できるカスタムコールバックを返すこともできます。

## Custom Action をセットアップする {#setup-your-custom-action}

<Info>

**権限を確認する**

チームの Custom Actions を作成するには、Team Manager 権限が必要です。アクセス権がない場合は、管理者に権限の変更を依頼してください。

</Info>

Custom Actions は、[developer.frame.io](/ja/platform/v2) の [Custom Actions](https://developer.frame.io/actions) セクションで設定できます。アクションには以下が必要です。

| フィールド名 | 説明 |
| --- | --- |
| Name | Custom Action に付ける名前です。Frame.io で利用可能な Custom Actions のメニューに表示されます。 |
| Description | 参照用に、アクションの動作を説明します(説明は Frame.io Web アプリには表示されません)。 |
| Event | 標準の Webhook イベントと独自のイベントを区別するための内部イベントキーです。 |
| URL | イベントの送信先です。 |
| Team | Custom Action を使用するチームです。 |

## クリック - Frame.io から受け取るペイロードの内容 {#click-what’s-in-the-payload-you-receive-from-frame-io}

ユーザーが Custom Action をクリックすると、URL フィールドで指定した URL にペイロードが送信されます。

```json
POST /your/url
{
  "action_id": "2444cccc-7777-4a11-8ddd-05aa45bb956b",
  "interaction_id": "aafa3qq2-c1f6-4111-92b2-4aa64277c33f",
  "project": {
    "id": "a7d6a74b-d45d-4019-9069-24651e0b9f64"
  },
  "resource": {
    "id": "9q2e5555-3a22-44dd-888a-abbb72c3333b",
    "type": "asset"
  },
  "team": {
    "id": "54353cd2-c6ee-4aa1-954a-ce9e19602aa9"
  },
  "type": "my.action",
  "user": {
    "id": "fb57eee0-79f2-4bc7-9b70-99fbc175175c"
  }
}
```

このペイロードを使用して、以下を識別できます。

- どの Custom Action がクリックされたか
- どのリソースがクリックされたか
- どのユーザーがアクションを実行したか

| フィールド名 | 説明 |
| --- | --- |
| `action_id` | この Action の一意の ID です。特定の Action に対しては常に同じ値になります。 |
| `interaction_id` | Frame.io が生成する一意の識別子で、トランザクションを追跡するために使用できます。この識別子は、コールバックフォームを含む Action の一連の処理全体を通じて同じ値になります。 |
| `type` | Action の設定時に Event フィールドに入力したイベント名です。 |
| `resource.id` | Action をトリガーしたリソース(通常は Asset)の ID です。 |
| `resource.type` | Action をトリガーしたリソースのタイプです(通常は *asset*)。 |

<Info>

**インタラクションについて**

`interaction_id` は、時間の経過とともに進行するインタラクションを追跡するための一意の識別子として提供されます。ユーザーに応答する必要がない場合は、200 ステータスコードを返すだけで完了です。必須ではありませんが、簡単な成功メッセージやエラーアラートなど、アクションの結果に関する情報を含めることをお勧めします。Custom Actions はメッセージコールバックをサポートしています。

</Info>

<Info>

**リトライとタイムアウト**

アプリケーションは 5 秒以内の応答を想定しており、成功の応答を待つ間に最大 5 回までリトライを試みます。理想的には即座に応答し、Custom Action によってトリガーされた後の処理は非同期で実行してください。

</Info>

## メッセージコールバックを作成する {#create-a-message-callback}

Webhook イベントに対する HTTP レスポンスで、Frame.io UI 上で操作を開始したユーザーに返すメッセージを記述した JSON オブジェクトを返すことができます。メッセージを作成してどのように表示されるかを試したい場合は、[Custom Action Builder](https://next.frame.io/settings/actions) を使用できます。メッセージコールバックやフォームを設定し、Frame.io Web アプリでどのように表示されるかを確認できます。

オブジェクトの例を次に示します。

```json
{
  "title": "Success!",
  "description": "The thing worked! Nice."
}
```

これにより、ユーザーには次のようなアラートが表示されます。
![actions-3](/images/platform/v2/custom-actions-overview/a7fe1ec18a4467f8b450b31d1e3a70ab26beece9f5ed828166f4d35973e55c3c.webp)

メッセージは、操作したユーザーにコンテキストを切り替えさせることなく、状況に応じた情報を提供してアクションのライフサイクルを完結させるシンプルな方法です。

多くのユースケースではこれで十分ですが、最初のペイロードとその後の Frame.io API 呼び出しだけでは、受信側アプリケーションに十分なコンテキストが得られない場合もあります。そのような場合のために、**フォームコールバック**もサポートしています。

## フォームコールバックを作成する {#create-a-form-callback}

処理を開始する前に、さらに情報が必要だとします。たとえば、追加の詳細や設定が必要なシステムにコンテンツをアップロードする場合などです。レスポンスでフォームを「記述」すると、ユーザーに実際に表示されます。ユーザーが入力すると、その内容がそのまま返送されます。

以下は、Frame.io UI にフォームを表示し、最初に操作したユーザーが入力して送信できるようにするフォームの例です。

```json
{
  "title": "Need some more info!",
  "description": "Getting ready to submit this file!",
  "fields": [
    {
      "type": "text",
      "label": "Title",
      "name": "title",
      "value": "MyVideo.mp4"
    },
    {
      "type": "select",
      "label": "Captions",
      "name": "captions",
      "options": [
        {
          "name": "Off",
          "value": "off"
        },
        {
          "name": "On",
          "value": "on"
        }
      ]
    }
  ]
}
```

![actions-form](/images/platform/v2/custom-actions-overview/4538043046be16b30b0230c21291dde8ae51554dc1da719bec8b9f7561c7c8a1.webp)

ユーザーがフォームを送信すると、最初の POST と同じ URL でイベントを受け取ります。

```json
POST /your/url​
{
  "type": "your-specified-event-name",
  "interaction_id": "the-same-id-as-before",
  "action_id": "unique-id-for-this-custom-action",
  "data":{
    "title": "MyVideo.mp4",
    "captions": "off"
  }
}
```

フォームに追加したすべてのカスタムフィールドは、Frame.io から送信される JSON ペイロードの `data` セクションに含まれます。

`interaction_id` を使用して、最初のリクエストとこの新しいフォームデータを対応付けます。また必要に応じて、メッセージ(あるいは別のフォーム)で応答することもできます。

Action、フォーム、メッセージを連鎖させることで、外部システムのビジネスロジックを使って Frame.io 内の Asset ワークフロー全体を効果的にプログラムできます。

想像力を働かせてください。可能性は無限大です。

### フォームの詳細 {#form-details}

メッセージと同様に、フォームはフォームの上部に表示される `title` 属性と `description` 属性をサポートしています。さらに、各フォームフィールドは以下の基本属性を受け付けます。

- `type` — 想定するデータの種類と、表示するコンポーネントを Frame.io UI に伝えます。
- `label` — フィールドの上に見出しとして UI に表示されます。
- `name` — 後続のペイロードでフィールドを識別するためのキーです。
- `value` — フィールドにあらかじめ入力しておく値です。

### サポートされているフィールドタイプ {#supported-field-types}

**テキストフィールド**
追加パラメーターのないシンプルなテキストフィールドです。

```json
{  
  "type": "text",
  "label": "Title",
  "name": "title",
  "value": "MyVideo.mp4"
}
```

**テキストエリア**
追加パラメーターのないシンプルなテキストエリアです。

```json
{  
  "type": "textarea",
  "label": "Description",
  "name": "description",
  "value": "This video is really, really popular."
}
```

**選択リスト**
ユーザーが選択できる選択リストを定義します。`options` リストを含める必要があり、その各要素には人が読める `name` と、機械で解析可能な `value` を含める必要があります。

```json
{
  "type": "select",
  "label": "Captions",
  "name": "captions",
  "value": "off",
  "options": [
       {
         "name": "Off",
         "value": "off"
       },
       {
         "name": "On",
         "value": "on"
      }
   ]
}
```

## Custom Actions と Frame.io の権限モデル {#custom-actions-and-the-frame-io-permissions-model}

Webhooks と Custom Actions には特別な権限モデルがあります。これらはチームやアカウントに属する特定のユーザーではなく、**チーム**に属します。つまり、次のようになります。

- 任意の Admin または Team Manager がチームで Custom Action を作成できます。
- 任意の Admin または Team Manager が、チームに存在する Custom Action を変更または削除できます。変更すると、すべてのユーザーにその結果が即座に反映されます。

## セキュリティ {#security}

デフォルトでは、すべての Custom Actions には作成時に署名キーが生成されます。これは設定変更できません。このキーを使用して、リクエストが Frame.io から送信されたものであることを検証できます。

### 検証 {#verification}

`POST` リクエストには以下が含まれます。

| 名前 | 説明 |
| --- | --- |
| `X-Frameio-Request-Timestamp` | Custom Action がトリガーされた時刻です。 |
| `X-Frameio-Signature` | 計算された署名です。 |

**タイムスタンプ**は、リクエストが Frame.io のネットワークから送信される際に署名された時刻です。リプレイ攻撃の防止に使用できます。この時刻がローカル時刻から 5 分以内であることを検証することをお勧めします。

**署名**は、Custom Action の初回作成時に提供される署名キーを使用した HMAC SHA-256 ハッシュです。

#### 署名を検証する {#verifying-the-signature}

1. HTTP ヘッダーから署名を抽出します
2. バージョン、配信時刻、リクエストボディを組み合わせて、署名するメッセージを作成します

- `v0:timestamp:body`

3. 署名シークレットを使用して HMAC SHA256 署名を計算します。

- 注: 提供される署名には `v0=` というプレフィックスが付いています。現在、Frame.io がリクエストの署名に使用しているバージョンはこの 1 つのみです。計算した署名にこのプレフィックスを追加する必要があります。

4. 比較します。

```python title="Python"
import hmac
import hashlib

def verify_signature(curr_time, req_time, signature, body, secret):
    """
    Verify webhook/custom action signature
    :Args:
        curr_time (float): Current epoch time
        req_time (float): Request epoch time
        signature (str): Signature provided by the frame.io API for the given request
        body (str): Custom Action body from the received POST
        secret (str): The secret for this Custom Action that you saved when you first created it
    """
    if int(curr_time) - int(req_time) < 500:
        message = 'v0:{}:{}'.format(req_time, body)
        calculated_signature = 'v0={}'.format(hmac.new(
            bytes(secret, 'latin-1'),
            msg=bytes(message, 'latin-1'),
            digestmod=hashlib.sha256).hexdigest())
        if calculated_signature == signature:
            return True
    return False
```
