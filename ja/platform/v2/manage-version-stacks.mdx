## 概要 {#overview}

バージョンスタックは Frame.io における整理の仕組みで、Asset をフォルダーに入れることなく縦方向に「積み重ねる」ことができます。スタックされたバージョンにより、Frame.io の UI 内で Asset 間の移動が簡単になり、並べての比較レビューも可能になります。

現在、スタックへの直接アップロードはサポートされていないため、基本的なバージョンスタックのワークフローを管理するための API の手順は、Frame.io の UI と同じ流れになります。

1. Asset をアップロードします(任意: 非公開としてマークします)。
2. Asset をスタックに割り当てます。

既存のバージョンスタックは並べ替えることができ、個々のバージョンをスタックから外すこともできます。さらに、バージョンスタックは、それを構成する Asset を削除することなく削除できます。

<Info>

**すべてのバージョンスタックには cover_asset があります**

バージョンスタックには、最上位に `cover_asset_id` という属性が必ずあります。これは、Frame.io の Web UI でサムネイルが表示される Asset の `id` であり、スタック内で最も番号の大きいバージョンです。

</Info>

### 基本概念 {#core-concepts}

**バージョンスタック**は、**フォルダー**と同様に、Asset の特別な `types` です。同じエンドポイントで取得でき、API レスポンスの `type` キーの値に基づいて解析し、適切に処理を振り分けることができます。実際には通常シンプルですが、大規模にスタックを管理する場合にはいくつか注意点があります。

バージョンスタックを扱ううえでの鍵は、**最も一般的な 4 つのシナリオ**を区別することです。

1. Asset を別の Asset に追加すると、新しい `id` を持つスタックが作成されます。
2. Asset を既存のスタックに追加できます。
3. スタックを並べ替えることができます。
4. 個々のバージョンを削除できます。

**最初の 2 つのシナリオ**は同じ[エンドポイント呼び出し](/ja/platform/v2/api-reference/assets/add-version-to-asset)を使用するため、実際に注意すべき点は、(2 つの Asset から)新しいスタックを作成するのか、既存のスタックに Asset を追加するのかを把握しておくことだけです。それ以外の制約は予測可能です。

1. スタックは `asset_type` が一致している必要があります(例: *image* を *stream* にスタックすることはできません)。
2. 操作する User は、ソースの Asset と、宛先の Asset またはスタックの両方に対する権限を持っている必要があります。
3. Asset は順番にスタックされます。
4. スタックをスタックに重ねることはできません。
5. フォルダーは対象外です。

**後半の 2 つのシナリオ**も非常にシンプルですが、スタック自体についてもう少し詳しく知っておく必要があります。たとえば、スタック内の Asset を並べ替えるには、対象の Asset を配置したい位置の両隣にある Asset の `id` を知っておく必要があります。つまり、通常はすでにスタック全体を取得していることになります。

### 必要なスコープ {#required-scopes}

このガイドを始める前に、次のスコープを含むトークンを用意しておく必要があります。

| スコープ | 理由 |
| --- | --- |
| **Assets:** Read、Update | - ソースと宛先の Asset を取得する。<br />- Asset をバージョンスタックに追加する。<br />- スタックを並べ替える。<br />- スタックから Asset を削除する。<br />- スタックを削除する。 |

## バージョンスタックに Asset を追加する {#adding-assets-to-version-stacks}

### ステップ 1: 宛先を特定する {#step-1-locate-your-destination}

最初のステップは、2 つの主要なシナリオのどちらに該当するかを判断することです。つまり、Asset を別の Asset に追加してスタックを作成するのか、Asset をスタックに追加してそのスタックを拡張するのかです。

バージョン管理されていない Asset を扱っていることがわかっている場合、またはすでにバージョンスタックの `id` がある場合は、ステップ 2 に進んでかまいません。

そうでない場合、宛先の Asset がすでにスタックの一部かどうかを判断する最も簡単な方法は次のとおりです。

1. `/v2/assets/:id​` を呼び出して、対象の Asset を `GET` します
2. 返ってきた `type` を確認します。

- *version_stack* であれば、今確認した uuid が宛先の uuid です。ステップ 2 に進みます。

3. `type` が *file* であれば、`parent_id` を取得します
4. 同じエンドポイントで親を GET し、その `type` を確認します。

親の `type` が *version_stack* であれば、その `id` を宛先として使用します。

`type` がそれ以外の場合は通常の Asset を扱っているので、元の id を宛先として使用できます。

### ステップ 2: ペイロードを準備する {#step-2-prepare-your-payload}

宛先の uuid がわかったので、次はスタックに追加する Asset の uuid を把握する必要があります。

1. 新しい Asset をアップロードする場合は、[Asset を作成](/ja/platform/v2/api-reference/assets/create-asset)したときの成功レスポンスで返された id をそのまま使用します。
2. 既存の Asset をスタックする場合は、上記の手順で `id` を取得しているはずです。

バージョンスタックへの追加に必要なボディパラメーターは `next_asset_id` だけです。

```json
{
    "next_asset_id": "<source-asset-id>"
}
```

### ステップ 3: ソースの Asset を宛先に追加する {#step-3-add-your-source-asset-to-the-destination}

両方の Asset の `id` パラメーターが揃ったら、`/assets/:id/version` に `POST` する準備ができました。ここで :id は宛先の Asset またはバージョンスタックで、ソースの(新しい)Asset はボディのペイロードに含めます。

## バージョンスタックを並べ替える {#reordering-version-stacks}

バージョンスタックは、各 Asset が `next_asset_id` と `prev_asset_id` という隣接要素を持つというシンプルな順序の概念に基づいています。ここでの順序はバージョン番号ではなく、各 Asset の `index` 属性を指します。`index` はバージョン番号とは逆方向に並ぶため、次のようになります。

- スタック内の最初の(最も番号の小さい)バージョンには、`prev` の Asset はありますが、`next` の Asset はありません
- スタック内の最新の(最も番号の大きい)バージョンには、`next` の Asset はありますが、`prev` の Asset はありません
- すべての「内側」のバージョンには `prev` と `next` の両方の Asset があり、それぞれバージョン ID がより大きい Asset とより小さい Asset です。

これにより、3 つの異なるシナリオがありますが、いずれも同じエンドポイント呼び出しを使用します。

**呼び出し:**

```
PUT https://api.frame.io/v2/asset/:id/tween
```

**ボディ:**

```json
{
  "prev_asset_id": "<asset_id>",
  "next_asset_id": "<asset_id>"
}
```

いずれの場合も、URL パスの `id` は移動する Asset になります。

| シナリオ | `prev_asset_id` | `next_asset_id` |
| --- | --- | --- |
| スタックの最上部に移動 | `null` | 以前の最上部の Asset(最も大きいバージョン番号)の `id`。 |
| スタックの最下部に移動 | 以前の最下部の Asset(v1)の `id`。 | `null` |
| スタック内でバージョンを移動 | Asset を移動したい位置のすぐ*上*にある Asset の `id`。 | 新しい Asset を移動したい位置のすぐ*下*にある Asset の `id`。 |

## Asset の削除とバージョンスタックの削除 {#removing-assets-and-deleting-version-stacks}

### Asset を削除する {#removing-assets}

Asset がバージョンスタックに移動されると、その Asset はスタック自体の子になります。Asset をバージョンスタックから外すには、実質的に、その Asset の親をスタックを含むフォルダーに戻す必要があります。

1. `/v2/assets/:id` を呼び出して、バージョンスタック自体を `GET` します
2. スタック自体の `parent_id` を取得します(これが新しい移動先フォルダーの `id` になります)
3. 次のようにして、対象の Asset をフォルダーに移動します。

**呼び出し**:

```
POST https://api.frame.io/v2/assets/:parent_id/move
```

**ボディ**:

```json
{
    "id":"<asset_id>"
}
```

### バージョンスタックを削除する {#deleting-version-stacks}

バージョンスタックの削除は非常に簡単です。

```
DELETE https://api.frame.io/v2/assets/:version_stack_id/unversion
```

これだけです。スタックを削除すると、それを構成するすべての Asset が、スタックを含むフォルダーに戻されます。

<Info>

**サイズが 1 のスタックは削除してください**

バージョンスタックからすべての要素を削除すると、要素が 1 つだけのバージョンスタックが残ります。これは簡単に見分けられます。バージョンスタックを `id` で `GET` すると、`"version": 1` という属性があることがわかります。

</Info>

技術的にはこの状態でも問題はありません。単一のバージョンは読み込みも再生もでき、新しいバージョンを追加することもでき、すべて通常どおりに動作します。ただし、Frame.io の Web やその他のアプリケーションでユーザーを混乱させないよう、単一要素のスタックは削除することをお勧めします。

バージョンスタックのエンドポイントの詳細については、[Assets](/ja/platform/v2/api-reference/assets/library-search-get) のドキュメントを参照してください。
