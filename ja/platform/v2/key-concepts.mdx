## API の構造 {#api-structure}

Frame.io API は、レート制限、リソースコレクションのページネーション、バージョニング、エラーといった一般的な概念をサポートしています。このセクションでは、それぞれの詳細について説明します。

### 構成とスタイル {#organization-and-style}

API は一般的な [REST](https://restfulapi.net/) の原則に基づいて構成されています。すべてのリクエストは SSL 経由で行う必要があります。エラーを含むすべてのリクエストボディとレスポンスボディは、JSON でエンコードされます。

特に明記されていない限り、API メソッドは以下に準拠します。

- 値を持たないプロパティは、未定義ではなく `null` になります
- 属性名には「スネークケース」が使われます(例: `first_name`)
- タイムスタンプは ISO-8601 形式で表されます(例: `2016-02-03T16:38:46.985Z`)

### パスの規則 {#path-conventions}

Accounts > Teams > Projects > Assets > Comments

一般に、Frame.io API のリソースパスは、親レベル 1 つ分の範囲内で上記の階層モデルに従います。直感的に理解しやすい場合、論理的に見て所有関係が厳密なオブジェクトについては、API は単独のリソースパスもサポートしています。

たとえば、Frame.io API は次のパスをいずれもサポートしています。

- `GET /accounts/:id/teams` — Account のすべての Team を返します。
- `GET /teams` — 呼び出し元の User のすべての Team を返します。
- `GET /teams/:id` — 特定の Team の詳細を返します。

別の例として、Comment は Asset のコンテキストの外ではあまり意味を持たないため、Comment の一覧取得と作成のメソッドは Asset のスコープ内に置かれています。ただし、Comment を更新または削除する場合は Asset のコンテキストはそれほど意味を持たないため、リソースパスから省略されています。

- `GET /assets/:id/comments`
- `POST /assets/:id/comments`
- `PUT /comments/:id`
- `DELETE /comments/:id`

## スコープ {#scopes}

OAuth2.0 経由でトークンを取得する場合も、[開発者ポータル](/ja/platform/v2)から直接取得する場合も、すべての API トークンは明示的な「スコープ」のリストに関連付けられている必要があります。スコープとは、リソース(例: `Asset`)とアクション(例: `create`)の組み合わせを指し、ドット表記で表されます。

たとえば、`asset.create` スコープを持つトークンでは、新しい Asset を作成できます。

開発者トークンを使った実装の場合、スコープはアクセストークン自体に設定・割り当てられます。OAuth アプリケーションを使用している場合、スコープはアプリケーションに対して定義され、ユーザーが初めてアプリケーションを操作するときに、要求されたスコープでの操作権限をアプリケーションに付与することに同意します。

開発者トークンとアプリケーションで使用できるスコープは以下のとおりです(一部のスコープはすべてのユーザーが利用できるわけではなく、その場合は明記されています)。

| スコープのカテゴリ | 説明 |
| --- | --- |
| Accounts、Users、Teams | アクセス権のある Account と Team に関する情報を取得します。認証済みの User が管理者などの場合、そのアカウント内の追加の User や Team に関する情報にアクセスできることがあります。<br />**注**: Team を更新する(例: Webhooks を管理する)には、Team Manager または Account Admin のロールが必要です。 |
| Projects と Assets | Project の基本情報の取得、User のメンバーシップの確認または更新、Asset の作成または更新を行います |
| Comments | Asset のコメントの取得、作成、削除、または特定の Comment への返信の作成を行います。<br />**注:** コメントの更新または削除のリクエストは、コメントの作成者が行う必要があります。 |
| Review Links | Review Link の作成や設定の管理を行います。<br />**注:** Review Link は、Asset をまとめ、明示的な Team や Project へのアクセス権を必要とせずに単一の URL でフィードバック用に送付するための、Frame.io の中核機能です。 |
| Webhooks | Webhooks を使うと、Frame.io 内で発生したイベントを通知に変換し、外部システムに送信して、処理、API コールバック、最終的にはワークフローの自動化に活用できます。 |
| Audit Logs | Frame.io は、アプリケーション内で行われるアクティビティの大部分についてログを公開しています。これには、中核リソースに対する基本的な CRUD と、いくつかの特別な抽象化(例: `AssetVersioned`)の両方が含まれます。ログにアクセスするには Admin である必要があります。 |
| Presentations | 既存の Presentation ページのオプションや Asset の作成・編集を行います。 |

## ページネーション {#pagination}

結果のコレクションを返す API メソッドは、常にページネーションされます。ページネーションされた結果を返すすべてのメソッドは、次のクエリパラメーターに応答し、次のヘッダー属性を返します。

| 説明 | クエリパラメーター | ヘッダー属性 |
| --- | --- | --- |
| ページサイズ | `page_size` | `per-page` |
| ページ番号 | `page` | `page-number` |
| ページ数 | N/A | `total-pages` |
| 合計件数 | N/A | `total` |

さらに、ページネーションされた結果には、次の情報を含む `Link` レスポンスヘッダー([RFC-5988 を参照](https://tools.ietf.org/html/rfc5988))が含まれます。

- `next` — 対応する URL は次のページへのリンクです。
- `prev` — 対応する URL は前のページへのリンクです。
- `last` — 対応する URL は最後のページへのリンクです。

**注:** `next` と `prev` のどちらのリンクも存在しない場合、返された最初のページが唯一のページであることを示します。
