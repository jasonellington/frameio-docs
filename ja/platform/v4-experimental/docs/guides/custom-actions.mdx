Frame.io のアクション (Actions) を使用すると、ダウンロード、名前の変更、アイテムの複製といった一般的なメディア操作にすばやくアクセスできます。また、サードパーティのツールやサービスとのインテグレーションを [Frame.io](https://next.frame.io/) のユーザーインターフェース内に直接表示することもできます。

## アクションについて {#about-actions}

カスタムアクション (Custom Actions) の導入により、開発者は Frame.io V4 で独自のアクションを設定・管理できるようになりました。カスタムアクションは [Webhook](https://developer.adobe.com/frameio/guides/Webhooks/) と同じ基盤となるイベントシステムを活用しており、開発者がアセットを Frame.io アカウントのユーザーにとって最も重要なツールに接続するための代替手段です。

アクションは、そのアクションが有効化されている Frame.io ワークスペースのメンバーであれば、どのユーザーでも実行できます。アクションが実行されると、Frame.io は指定された URL にペイロードを送信します。受信側のアプリケーションは、受信を確認するための HTTP ステータスコード、または Frame.io UI に追加のフォームフィールドを表示するためのカスタムコールバックで応答します。受信側のアプリケーションには、独自にホストしているプログラムやサービスのほか、Workfront Fusion や Zapier のようなローコード/ノーコードの IPaaS ツールも使用できます。

カスタムアクションを使用して、プログラム可能な UI コンポーネントとして [Frame.io](https://next.frame.io/) に直接インテグレーションを組み込みましょう。これにより、Webhook と同じ基盤となるイベントルーティングを活用し、アプリ内のユーザーがトリガーできるワークフローを実現できます。ユーザーがトリガーする単一ステップまたは複数ステップのフォームを作成し、別のフォームまたは基本的なレスポンスとして Frame.io に返すことができます。ユーザーがアセット上のカスタムアクションをクリックすると、Frame.io は指定された URL にペイロードを送信します。受信側のアプリケーションは、受信を確認するための HTTP ステータスコード、または Frame.io に追加の UI を表示できるカスタムコールバックで応答します。

## レート制限 {#rate-limits}

カスタムアクションのイベントは、Webhook イベントと同じアカウントレベルの制限にカウントされます: **1 分あたり 1,000 イベント**、**1 時間あたり 20,000 イベント**。どちらの制限も、カスタムアクションや Webhook サブスクリプションごとに個別に適用されるのではなく、アカウント全体の合計量に適用されます。

いずれかの制限に達すると、それ以降のカスタムアクションのイベントはキューに入れられることも自動的に再試行されることもなく、**破棄** されます。

これらはイベント量の制限であり、カスタムアクションを管理するための API リクエストの制限ではありません。詳細については [Webhook のレート制限](/ja/platform/docs/guides/webhooks#webhook-rate-limits)を参照してください。

## 移行されたアクション {#migrated-actions}

レガシーバージョンの Frame.io で作成したカスタムアクションを含む Frame.io V4 アカウントに移行する際には、いくつか留意すべき点があります。

### アクションのステータス {#action-status}

アカウントを Frame.io V4 に移行すると、以前のバージョンで作成されたすべてのカスタムアクションのステータスは「null」になり、自動的に無効化されます。更新されていないアクションは失敗するため、これにより、有効化する前にまずアクションを V4 API を使用するよう更新する機会が得られます。この状態のアクションを特定するには、アクション設定ページで「Status」列を確認するか、API を使用している場合は is_active フィールドを確認します。

### アクションの対象リソース: ファイル、フォルダー、バージョンスタック {#actionable-resources-files-folders-&-version-stacks}

Frame.io V4 API ではアセットタイプが個別のリソースとして分離されているため、アクションのペイロードで受け取るリソース ID を解釈する際には、考慮すべき動作がある場合があります。個々のファイルの場合の動作は単純で、ID はアクションが実行された特定のファイルを表します。同様にフォルダーの場合も、アクションが実行されたフォルダーの ID を受け取ります。ただし、ユースケースによっては、アクションの動作を定義する方法が複数あります。フォルダーリソース自体を操作したい場合は、フォルダー ID を使用して Frame.io API への後続の呼び出しを行います。あるいは、フォルダー内のアセットに対してさらに処理を行うために、そのフォルダーの子要素を取得することもできます。バージョンスタックに対してアクションが実行された場合、ペイロードには「Head Asset」の ID が含まれます。これはスタックの最上位にあるファイルで、Frame.io UI に表示されるものです。

Frame.io Legacy API と V4 の違いについて詳しくは、[移行ガイド](/ja/platform/v4-experimental/docs/resources/migration)を参照してください。

<Info>

API を使用して[カスタムアクション](/ja/platform/v4-experimental/api-reference/custom-actions/actions-show)を設定します。

</Info>

カスタムアクションには次の項目が必要です。

| フィールド名 | 説明 |
| --- | --- |
| Name | カスタムアクションに付ける名前。Frame.io で利用可能なカスタムアクションのメニューに表示されます。 |
| Description | 参照用に、アクションの動作を説明します (説明は Frame.io の Web アプリには表示されません)。 |
| Event | 標準の Webhook イベントと独自のイベントを区別するための内部イベントキー。 |
| URL | イベントの配信先。 |
| Workspace | カスタムアクションを使用するワークスペース。 |

## カスタムアクションを設定する {#configure-your-custom-action}

ユーザーがカスタムアクションをトリガーすると、Frame.io は指定された URL にペイロードを送信します。受信側のアプリケーションは、受信を確認するための HTTP ステータスコード、または [Frame.io](https://next.frame.io/) に追加の UI を表示するカスタムコールバックで応答できます。

<Warning>

ワークスペースのカスタムアクションを作成するには、アカウント管理者の権限が必要です。アクセス権がない場合は、管理者に権限の変更を依頼してください。

</Warning>

### 複数アセットの設定 {#multi-asset-configuration}

複数アセットのサポートは設定によって制御され、[Web](https://next.frame.io/settings/actions) 上のアクションの設定モーダルから明示的に有効化する必要があります。これは新しいアクションの作成時、または既存のアクションの更新時に行えます。

複数アセットのサポートを有効にすると、ペイロードの形式はすぐに切り替わります。レガシーのペイロードと複数アセット対応のペイロードは相互に排他的です。

### レガシーペイロードからの移行 {#migrating-from-the-legacy-payload}

<Warning>

**レガシーペイロードは非推奨となる予定です**

レガシーペイロードは非推奨となる予定のため、新しいペイロードを処理するようサービスを移行することを強くおすすめします。

設定フラグを有効にしてペイロードの処理を更新することで、アクションをシームレスに複数アセットのペイロードに対応させることができます。

1. 単数形の `resource` オブジェクトの使用を `resources` リストに置き換える
2. `resources` リストを反復処理するようにコードを更新する
3. アクションの設定で Multi-asset フラグを有効にする

</Warning>

| フィールド名 | 説明 |
| --- | --- |
| `account_id` | アクションの一意のアカウント ID。 |
| `action_id` | アクションの一意の ID。 |
| `interaction_id` | 連鎖するメッセージコールバックやフォームコールバックなど、複数のリクエストにわたってトランザクションを追跡するために Frame.io が生成する一意の識別子。アクションの一連のシーケンスを通じて同じ値のままです。 |
| `project_id` | アクションの一意のプロジェクト ID。 |
| `resource.id` | アクションをトリガーしたリソースの ID。 |
| `resource.type` | アクションをトリガーしたリソースのタイプ。 |
| `type` | アクションの設定時に `event` フィールドで指定した名前。 |
| `user.id` | アクションをトリガーしたユーザーの ID。 |
| `workspace.id` | アクションを使用しているワークスペースの ID。 |
| `data` | ユーザーが選択したフォームフィールドの名前と値を含むキーと値のペア。アプリはこれを受け取って、どのような選択が行われたかを把握します。 |

## インタラクション、再試行、タイムアウト {#interactions-retries-and-timeouts}

`interaction_id` は、時間の経過とともに進行するインタラクションを追跡するための一意の識別子です。ユーザーに応答する必要がない場合は、200 ステータスコードを返せば完了です。任意ではありますが、成功メッセージやエラー通知など、アクションの結果に関する情報を含めることをおすすめします。カスタムアクションはメッセージコールバックをサポートしています。

<Note>

Frame.io は 10 秒以内のレスポンスを想定しており、成功レスポンスを待つ間に最大 5 回まで再試行します。理想的には、レスポンスは即座に返し、非同期のアクションはカスタムアクションによるトリガーの後に実行するようにします。

</Note>

## メッセージコールバックを作成する {#create-a-message-callback}

Webhook イベントに対する HTTP レスポンスで、Frame.io UI 上で操作を開始したユーザーに返されるメッセージを記述した JSON オブジェクトを返すことができます。

```json
{
  "title": "Success!",
  "description": "The thing worked! Nice."
}
```

メッセージを使用すると、Frame.io UI 内で直接ユーザーにフィードバックを提供できます。ユーザーから追加の情報を収集する必要がある場合は、代わりに **フォームコールバック** を使用してください。

## フォームコールバックを作成する {#create-a-form-callback}

処理を開始する前に、さらに情報が必要な場合を考えてみましょう。たとえば、追加の詳細情報を必要とするシステムにコンテンツをアップロードする場合などです。レスポンスでフォームを記述すると、ユーザーがそれに入力して送信し返します。以下に例を示します。

```json
{
  "title": "Need some more info!",
  "description": "Getting ready to submit this file!",
  "fields": [
    {
      "type": "text",
      "label": "Title",
      "name": "title",
      "value": "MyVideo.mp4"
    },
    {
      "type": "select",
      "label": "Captions",
      "name": "captions",
      "options": [
        {
          "name": "Off",
          "value": "off"
        },
        {
          "name": "On",
          "value": "on"
        }
      ]
    }
  ]
}
```

ユーザーがフォームを送信すると、最初の POST と同じ URL でイベントを受け取ります。

```json
POST /your/url
{
  "type": "your-specified-event-name",
  "interaction_id": "the-same-id-as-before",
  "action_id": "unique-id-for-this-custom-action",
  "data":{
    "title": "MyVideo.mp4",
    "captions": "off"
  }
}
```

フォームに追加されたすべてのカスタムフィールドは、Frame.io から送信される JSON ペイロードの `data` セクションに含まれます。`interaction_id` を使用して、最初のリクエストとこの新しいフォームデータを対応付けます。メッセージで応答することも、別のフォームを連鎖させることもできます。アクション、フォーム、メッセージを連鎖させることで、外部システムのビジネスロジックを使って Frame.io 内で複数ステップのワークフローを効果的にプログラムできます。

## フォームの詳細 {#form-details}

メッセージと同様に、フォームはフォームの上部に表示される `title` 属性と `description` 属性をサポートしています。それに加えて、各フォームフィールドは次の基本属性を受け付けます。

<CardGroup cols={2}>

<Card title="フィールドのプロパティ" icon="tarp" iconType="solid">

- **type** — どの種類のデータを想定し、どのコンポーネントをレンダリングするかを Frame.io UI に伝えます。
- **label** — フィールドの上に見出しとして UI に表示されます。

</Card>

<Card title="フィールドのデータ" icon="database" iconType="solid">

- **name** — 後続のペイロードでフィールドを識別するためのキー。
- **value** — フィールドにあらかじめ入力しておく値。

</Card>

</CardGroup>

## サポートされているフィールドタイプ {#supported-field-types}

### テキストフィールド {#text-field}

追加のパラメーターを持たないシンプルなテキストフィールドです。

```json
{  
  "type": "text",
  "label": "Title",
  "name": "title",
  "value": "MyVideo.mp4"
}
```

### テキストエリア {#text-area}

追加のパラメーターを持たないシンプルなテキストエリアです。

```json
{  
  "type": "textarea",
  "label": "Description",
  "name": "description",
  "value": "This video is really, really popular."
}
```

### 選択リスト {#select-list}

ユーザーが選択できる選択肢リストを定義します。`options` リストを含める必要があり、その各要素には人が読める `name` と、機械が解析できる `value` を含める必要があります。

```json
{
  "type": "select",
  "label": "Captions",
  "name": "captions",
  "value": "off",
  "options": [
       {
         "name": "Off",
         "value": "off"
       },
       {
         "name": "On",
         "value": "on"
      }
   ]
}
```

### チェックボックス {#checkbox}

追加のパラメーターを持たないシンプルなチェックボックスです。

```json
{ 
   "type": "boolean", 
   "name": "enabled", 
   "label": "Enabled", 
   "value": "false"
}
```

### リンク {#link}

追加のパラメーターを持たないシンプルなリンクです。

```json
{
  "type": "link",
  "name": "videoLink",
  "label": "Video Link",
  "value": "https://www.youtube.com/watch?v=XtX1zv9CEVc"
}
```

## Frame.io の権限モデル {#the-frame-io-permissions-model}

カスタムアクションには特別な権限モデルがあります。カスタムアクションはワークスペースに属し、アカウント上に存在する特定のユーザーには属しません。つまり、次のようになります。

- どの管理者でも、ワークスペースにカスタムアクションを作成できます。
- どの管理者でも、チームに存在するカスタムアクションを変更または削除できます。

</Card>

<Card title="即時反映" icon="arrows-rotate" iconType="solid">

- 変更すると、すべてのユーザーにその変更結果がすぐに反映されます。

</Card>

## セキュリティと検証 {#security-and-verification}

デフォルトでは、すべてのカスタムアクションには作成時に署名キーが生成されます。これは設定で変更できません。このキーを使用して、リクエストが Frame.io から送信されたものであることを検証できます。`POST` リクエストには次のものが含まれます。

| 名前 | 説明 |
| --- | --- |
| `X-Frameio-Request-Timestamp` | カスタムアクションがトリガーされた時刻。 |
| `X-Frameio-Signature` | 計算された署名。 |

<CardGroup cols={2}>

<Card title="タイムスタンプの検証" icon="clock" iconType="solid">

**タイムスタンプ** は、リクエストが Frame.io のネットワークから送信される際に署名された時刻です。リプレイ攻撃の防止に使用できます。この時刻がローカル時刻から 5 分以内であることを確認することをおすすめします。

</Card>

<Card title="署名の検証" icon="shield" iconType="solid">

**署名** は、カスタムアクションの初回作成時に提供される署名キーを使用した HMAC SHA-256 ハッシュです。

</Card>

</CardGroup>

### 署名の検証 {#verifying-the-signature}

<Steps>

<Step title="署名を抽出する">

HTTP ヘッダーから署名を抽出します。

</Step>

<Step title="署名するメッセージを作成する">

バージョン、配信時刻、リクエストボディを組み合わせて、署名するメッセージ `v0:timestamp:body` を作成します。

</Step>

<Step title="HMAC SHA256 を計算する">

署名シークレットを使用して HMAC SHA256 署名を計算します。

</Step>

<Step title="署名を比較する">

計算した署名と提供された署名を比較します。

</Step>

</Steps>

<Note>

提供される署名には `v0=` というプレフィックスが付いています。現在、Frame.io がリクエストの署名に使用しているバージョンはこの 1 つだけです。計算した署名にこのプレフィックスを追加する必要があります。

</Note>

```python title="Python"
import hmac
import hashlib

def verify_signature(curr_time, req_time, signature, body, secret):
    """
    Verify webhook/custom action signature
    :Args:
        curr_time (float): Current epoch time
        req_time (float): Request epoch time
        signature (str): Signature provided by the frame.io API for the given request
        body (str): Custom Action body from the received POST
        secret (str): The secret for this Custom Action that you saved when you first created it
    """
    if int(curr_time) - int(req_time) < 500:
        message = 'v0:{}:{}'.format(req_time, body)
        calculated_signature = 'v0={}'.format(hmac.new(
            bytes(secret, 'latin-1'),
            msg=bytes(message, 'latin-1'),
            digestmod=hashlib.sha256).hexdigest())
        if calculated_signature == signature:
            return True
    return False
```
