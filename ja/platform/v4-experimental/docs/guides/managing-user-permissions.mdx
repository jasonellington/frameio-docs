---
title: "ユーザー権限の管理"
---

このガイドでは、Frame.io V4 APIを使ってユーザー権限を管理する方法を説明します。Account、Workspace、Projectの各レベルで権限がどのように機能するか、またそれぞれのレベルでどのエンドポイントを使用するかを取り上げます。

---

## 権限レベル {#permission-levels}

Frame.ioの権限は、Account、Workspace、Projectの各レベルで管理されます。各レベルには、それぞれ独自のロールがあります。

```
Account 
│
├── (admin)  - full access to all Workspaces, Projects, and Restricted Projects
│
└── (member)
        │
        ├── Workspace - (full_access | editor | edit_only | commenter | viewer)
        │       │
        │       └── Project - (full_access | editor | edit_only | commenter | viewer)
        │
        └── Restricted Project - (members require direct invite)
```

すべてのユーザーにはアカウントロールがあります。APIを通じて、ユーザーのロールを<Tooltip tip="APIレスポンスでOwnerやReviewerが返されることがありますが、これらのロールはAPIでは設定できません。詳細はアカウントレベルの権限のセクションで説明しています。">`admin`または`member`</Tooltip>に設定できます。
Account Adminは、すべてのWorkspaceとProjectにフルアクセスできます。Account Memberは、必要なWorkspaceとProjectに個別に追加できます。

Account MemberをWorkspaceに追加すると、割り当てた権限レベル(`full_access`、`editor`、`edit_only`、`commenter`、`viewer`)が、そのWorkspace内の既存および今後作成されるすべてのProjectに適用されます。たとえば、Account Memberを`viewer`として追加すると、そのユーザーはそのWorkspace内のどのProjectにアクセスする場合でも`viewer`権限を持ちます。

同じAccount Memberを、そのWorkspace内の特定のProjectに`editor`として追加することもできます。その結果、そのユーザーはそのProjectにアクセスするときは常に`editor`権限を持ちます。そのWorkspace内の他のすべてのProjectには、引き続き`viewer`権限が適用されます。

Projectへの割り当てはWorkspaceへの割り当てとは別に管理されるため、そのAccount MemberをWorkspaceから削除しても、その1つのProjectに対する`editor`権限は保持されます。

Restricted Projectは例外です。Account Memberには常に直接の招待が必要です。詳細は、以下のプロジェクトレベルの権限のセクションで説明します。

## アカウントレベルの権限 {#account-level-permissions}

アカウント内のすべてのユーザーにはロールがあります。

| ロール | 権限 | APIで設定可能 | エンドポイント |
| --- | --- | --- | --- |
| Owner | すべてのWorkspaceとProjectへのフルアクセス。アカウントごとに1人 | 不可 | — |
| <Tooltip tip="UIでは「Content Admin」と表示されます">`admin`</Tooltip> | すべてのWorkspaceとProjectへのフルアクセス | 可 | `PATCH /accounts/:account_id/users/:user_id` |
| `member` | WorkspaceレベルやProjectレベルで設定された権限 | 可 | `PATCH /accounts/:account_id/users/:user_id` |
| Reviewer | 共有リンク経由でのみアクセス。ユーザーがセキュアな共有に追加されたときに作成される | <Tooltip tip="ReviewerはFrame.ioに認証してログインするためアカウントのユーザーリストに表示されますが、WorkspaceやProjectの権限システムの外に存在します。コンテンツにはセキュアな共有リンクを通じてのみアクセスします。">不可</Tooltip> | — |

---

Account Adminはすべての場所にフルアクセスできます。Adminのアクセスを特定のリソースに制限するには、まずそのユーザーのアカウントロールをMemberに変更し、その後、必要なWorkspaceやProjectに追加します。

例:

<Steps>

<Step title="アカウントのユーザーロールを一覧表示して、ユーザーIDと現在のロールを確認します:">

```bash

curl https://api.frame.io/v4/accounts/:account_id/users \
     -H "Authorization: Bearer <token>"
```

</Step>

<Step title="アカウントロールをMemberに更新します:">

```bash

curl -X PATCH https://api.frame.io/v4/accounts/:account_id/users/:user_id \
 -H "Authorization: Bearer <token>" \
 -H "Content-Type: application/json" \
 -d '{
"data": {
"role": "member"
}
}'
```

</Step>

<Step title="Projectに追加します:">

```bash

curl -X PATCH https://api.frame.io/v4/accounts/:account_id/projects/:project_id/users/:user_id \
  -H "Authorization: Bearer <token>" \
  -H "Content-Type: application/json" \
  -d '{
"data": {
 "role": "edit_only"
}
}'
```

</Step>

</Steps>

## ワークスペースレベルの権限 {#workspace-level-permissions}

Account MemberをWorkspaceに追加すると、そのユーザーはWorkspace内のすべてのProjectでその権限レベルを持ちます。Workspaceは招待制のため、Account Memberには追加されたWorkspaceのみが表示されます。

<br />

| ロール | 権限 |
| --- | --- |
| `full_access` | アップロード、管理、共有、コメント、閲覧、ダウンロード、設定の管理、ユーザーの招待 |
| `editor` | アップロード、管理、共有、コメント、閲覧、ダウンロード |
| `edit_only` | アップロード、管理、コメント、閲覧。共有とダウンロードは不可 |
| `commenter` | 閲覧とコメント |
| `viewer` | 閲覧のみ |

<br />

## プロジェクトレベルの権限 {#project-level-permissions}

Projectでは、Workspaceと同じ権限レベルを使用します。ユーザーが特定のProjectにのみアクセスする必要がある場合や、Workspaceでの割り当てとは異なる権限レベルが必要な場合は、ユーザーをProjectに直接追加します。ユーザーをProjectに追加するために、Workspaceへのアクセス権は必要ありません。

<br />

| ロール | 権限 |
| --- | --- |
| `full_access` | アップロード、管理、共有、コメント、閲覧、ダウンロード、設定の管理、ユーザーの招待 |
| `editor` | アップロード、管理、共有、コメント、閲覧、ダウンロード |
| `edit_only` | アップロード、管理、コメント、閲覧。共有とダウンロードは不可 |
| `commenter` | 閲覧とコメント |
| `viewer` | 閲覧のみ |

<br />

**例: ユーザーをProjectに追加する**

```bash

curl -X PATCH https://api.frame.io/v4/accounts/:account_id/projects/:project_id/users/:user_id \
     -H "Authorization: Bearer <token>" \
     -H "Content-Type: application/json" \
     -d '{
  "data": {
    "role": "full_access"
  }
}'
```

---

### Restricted Project {#restricted-projects}

Restricted Projectには直接の招待が必要です。Workspaceへのアクセス権は引き継がれないため、
ユーザーはRestricted Projectに直接追加された場合にのみアクセスできます。

Memberにアクセス権を付与するには、適切な権限レベルでそのユーザーをProjectに追加します。

<Note>

Account AdminとOwnerは例外で、すべての
Restricted Projectにアクセスできます。

</Note>
