## C2C Integration Requirements

This checklist outlines the best practices and requirements for joining the C2C ecosystem. While not every item applies to all C2C devices or applications, the C2C Partnerships team will work with you to define specific requirements during the C2C Certification Program.

## Basic Integration Requirements

All integrations must include:

<CardGroup cols={2}>

<Card title="User Code" icon="keyboard" iconType="solid">

Display a 6-digit code to the user. For web interfaces or QR code-capable devices, use the `verification_url_complete` to provide users a hyperlink option for logging in and selecting a project to connect to.

</Card>

<Card title="Project Display" icon="folder" iconType="solid">

Shows the connected project name so users can quickly verify their connection without searching through [Frame.io](http://frame.io/)’s UI

</Card>

<Card title="Upload Status" icon="upload" iconType="solid">

Clear indicators for:

- Remaining file count
- Total remaining file size
- Current file upload progress
- Status of completed, queued, and failed uploads

</Card>

<Card title="Network Status" icon="network-wired" iconType="solid">

Network connection status display and automatic access token refresh after 8 hours with no user interaction or alerts (unless there’s a refresh error)

</Card>

</CardGroup>

Additional requirements:

- Cancellable authorization flow at each step
- Socket status for real-time communication
- Firmware version header in all HTTPS endpoint calls

## Security Requirements

At [Frame.io](http://frame.io/), security is paramount. Our requirements include:

<CardGroup cols={2}>

<Card title="HTTPS &amp; Direct Connection" icon="shield-halved" iconType="solid">

- HTTPS-only requests (HTTP requests are rejected)
- Direct device/application connection to [Frame.io](http://frame.io/) (no intermediary services)

</Card>

<Card title="Credential Protection" icon="lock" iconType="solid">

- Protected `client_secret` and `client_id` (not user-accessible)
- Protected `access_token` and `refresh_token` credentials
- Encrypted storage of secrets and tokens (optional but recommended)

</Card>

</CardGroup>

## Uploader Requirements

Reliable media upload is crucial, especially in challenging conditions. Integrations must:

<CardGroup cols={2}>

<Card title="Upload Features" icon="upload" iconType="solid">

- Support automatic uploads either in real-time during recording (preferred) or upon file completion
- Show clear upload status, including queue and results
- Write files to user-accessible local storage

</Card>

<Card title="Queue Management" icon="list" iconType="solid">

Maintain a robust upload queue that handles:

- Concurrent uploads
- Network interruptions
- Power cycles

</Card>

</CardGroup>

<CardGroup cols={2}>

<Card title="Error Handling" icon="triangle-exclamation" iconType="solid">

Implement automatic retry for:

- Network issues
- Power interruptions
- Non-fatal errors (timeouts, network errors, expired tokens)

</Card>

<Card title="Upload Control" icon="play" iconType="solid">

- Resume uploads from last successful chunk
- Honor **PAUSED** state
- Handle AWS non-fatal errors
- Manage corrupted media without blocking other uploads

</Card>

</CardGroup>

<CardGroup cols={2}>

<Card title="Upload Options" icon="sliders" iconType="solid">

Provide flexible upload options:

- Toggle automatic/manual uploads
- Individual/bulk file selection
- File type prioritization (optional)
- Queue prioritization (optional)
- Parallel uploads (optional)
- Allow cancellation of individual or all uploads

</Card>

</CardGroup>

## Networking Requirements

Integrations must:

<CardGroup cols={2}>

<Card title="Speed &amp; Security" icon="gauge-high" iconType="solid">

- Achieve minimum 50Mbps upload speeds (network conditions permitting)
- Support WPA2 WiFi security (Ethernet optional but recommended)

</Card>

<Card title="Network Management" icon="network-wired" iconType="solid">

- Handle DHCP and static IP
- Display clear network status (connection type, speed, health)
- Switch networks without project re-pairing
- Save known WiFi networks

</Card>

</CardGroup>

## Testing Requirements

C2C is designed for challenging conditions, requiring thorough testing across:

<CardGroup cols={2}>

<Card title="Network Configurations" icon="network-wired" iconType="solid">

Test all applicable connection types:

- Commercial router with:

  - Hardline WAN
  - Bonded cellular modem
  - Commercial cellular modem
  - Hotspot-style modem

- Meshed router setups (including 802.11r FT protocol)

- Direct connections to various modem types

</Card>

<Card title="Resilience Testing" icon="bolt" iconType="solid">

- Unexpected power outages
- Network disconnections
- ISP issues
- Corrupted media handling
- Offline asset creation and reconnection

</Card>

</CardGroup>

## Workflow Requirements

C2C is an ecosystem, not just a feature. Device/application-specific requirements include:

<CardGroup cols={2}>

<Card title="SDI/HDMI Recording" icon="video" iconType="solid">

- Automatic recording trigger from camera
- Flexible camera options
- Timecode offset adjustment
- Manual recording capability
- Consistent filename handling
- Accurate timecode synchronization

</Card>

<Card title="Proxy Files" icon="file-video" iconType="solid">

- Matching filename/timecode/metadata with hero file/OCF
- LTE-optimized (1-12Mbps bitrate)
- Standard codec support for video and audio

</Card>

</CardGroup>

<CardGroup cols={2}>

<Card title="General Requirements" icon="list-check" iconType="solid">

- Timecode streams for video/audio
- Multi-format upload support (Proxy, OCF, LUT, WAV, RAW, JPG, HEIF, TIFF)
- Project name change handling (use `project_id` instead of name strings)

</Card>

</CardGroup>

## Quality Assurance

At [Frame.io](http://frame.io/), quality is essential. Key test areas include:

<CardGroup cols={2}>

<Card title="Basic Functionality" icon="check" iconType="solid">

- Stable launch and operation
- Project connection
- Hardware code generation
- Login/logout capability
- Project/user info display
- Device management
- Asset upload
- Format support

</Card>

<Card title="Technical Requirements" icon="gear" iconType="solid">

- Upload resumption after interruptions
- Progress display
- Network status indication
- 8-hour connection persistence
- Cancellable authorization
- Direct Frame.io connection
- Credential security
- Network speed optimization

</Card>

</CardGroup>
