## Introduction {#introduction}

Ce guide présente le processus d’authentification et d’autorisation des appareils Camera to Cloud (C2C) sur un projet Frame.io. Nous verrons à la fois la méthode standard de saisie manuelle du code et l’approche améliorée d’appairage par QR code, pour une expérience utilisateur optimale.

## De quoi ai-je besoin ? {#what-will-i-need}

Si ce n’est pas déjà fait, consultez le guide [Before We Start Implementing](/fr/camera-to-cloud/implementing-c2c-setting-up).

Vous devriez avoir reçu de notre équipe un `client_secret` permettant d’identifier votre intégration. Si ce n’est pas le cas, consultez [cette introduction](/fr/camera-to-cloud/getting-started-with-cloud-device-integrations) à l’écosystème C2C et contactez notre équipe.

### Prérequis pour l’appairage par URL et QR code {#prerequisites-for-url-&-qr-code-pairing}

Pour mettre en œuvre l’appairage par URL et QR code, assurez-vous de remplir les conditions suivantes :

- **Compatibilité de l’appareil** : vérifiez que votre appareil prend en charge la génération d’URL/de QR code pendant le processus d’appairage.

## Parcourir le flux d’authentification {#walking-through-the-auth-flow}

Pour comprendre le flux d’autorisation du point de vue de l’utilisateur, consultez les ressources suivantes :

- [Article d’assistance](https://help.frame.io/en/collections/8960335-frame-io-c2c) sur l’ajout de nouveaux appareils.
- [Vidéo de formation](https://help.frame.io/en/articles/5091124-camera-to-cloud-training-series) sur l’autorisation d’un Teradek Cube.

Ce processus d’autorisation réduit au minimum les exigences d’implémentation. Vous n’aurez pas besoin de :

- Rediriger vers un navigateur web (sauf si vous utilisez l’appairage par code URL)
- Gérer l’authentification des utilisateurs Frame.io
- Proposer des interfaces de sélection de compte/projet
- Développer des composants d’interface complexes au-delà de l’affichage d’informations de base

### Améliorer l’expérience utilisateur avec l’appairage par code URL {#enhancing-the-user-experience-with-url-code-pairing}

Les utilisateurs d’aujourd’hui attendent des interactions efficaces avec leurs appareils. Bien que le processus d’appairage manuel actuel fonctionne correctement, il peut être optimisé.

En mettant en œuvre l’appairage par URL et QR code, à l’image des services de streaming comme Netflix ou Disney+, nous pouvons considérablement simplifier le processus, réduire les erreurs de saisie et raccourcir le temps d’appairage.

## Identification de l’appareil (client_id) {#device-identification-client_id}

Chaque appareil physique nécessite un identifiant unique pour le suivi des connexions au sein du projet d’un utilisateur.

Pour les appareils, cet identifiant est le `client_id`, indispensable lors de l’autorisation. Lors de l’implémentation, choisissez une source d’identifiant appropriée, comme le numéro de série de l’appareil, un UUID ou une autre chaîne unique. Si vous effectuez l’intégration sur un appareil Apple, nous recommandons d’utiliser un UUID persistant et unique qui reste identique après les redémarrages de l’appareil.

Faites preuve de prudence concernant les informations personnelles identifiables. Les adresses e-mail des utilisateurs ne sont pas des valeurs appropriées pour le `client_id`.

Assurez-vous également de maîtriser l’identifiant. Les adresses MAC des appareils ne conviennent pas, car elles n’appartiennent pas à votre logiciel et peuvent constituer des informations personnelles identifiables.

Si vous avez besoin d’aide pour choisir un identifiant approprié, notre équipe peut vous aider à déterminer une valeur adaptée qui simplifie l’intégration.

## Étape 1 : demander un code d’appareil {#step-1-requesting-a-device-code}

Pour commencer l’implémentation, demandez un code d’appareil via l’endpoint `/v2/auth/device/code` :

### Méthode d’appairage traditionnelle {#traditional-pairing-method}

```
curl -X POST https://api.frame.io/v2/auth/device/code \
    --form 'client_id=[client_id]' \
    --form 'client_secret=[client_secret]' \
    --form 'scope=asset_create offline' \
    | python -m json.tool
```

### Activer l’appairage par code URL {#enabling-url-code-pairing}

Pour l’appairage par code URL, modifiez l’appel d’API en ajoutant des en-têtes supplémentaires :

```
curl -X POST https://api.frame.io/v2/auth/device/code \
    --header "x-client-version: 2.0.0" \
    --header "x-client-platypus-enabled: true" \  # New header to enable URL pairing
    --form 'client_id=[client_id]' \
    --form 'client_secret=[client_secret]' \
    --form 'scope=asset_create offline' \
    | python -m json.tool
```

**Remarque :** ces endpoints d’authentification acceptent exclusivement des données de formulaire, et non du JSON. Après l’authentification, les autres endpoints acceptent des charges utiles JSON, mais les endpoints d’authentification rejettent les requêtes JSON.

#### Paramètres de la charge utile {#payload-parameters}

- **client_id** : l’identifiant unique de votre appareil physique. Son unicité doit être garantie, comme pour un numéro de série ou un UUID.

- **client_secret** : fourni par l’assistance Frame.io pour identifier votre modèle d’appareil. Cette valeur confidentielle doit rester inaccessible aux utilisateurs et être chiffrée lors de son stockage.

- **scope** : les permissions demandées, séparées par des espaces. Les appareils peuvent demander :

  - `asset_create` : permet la création et l’import d’assets.
  - `offline` : permet l’actualisation de l’autorisation via un jeton d’actualisation. Sans ce scope, les utilisateurs devraient autoriser de nouveau leur appareil toutes les 8 heures, à l’expiration des jetons d’autorisation.

Dans les implémentations concrètes, les appareils demandent généralement les deux scopes.

### Comprendre la réponse de l’API {#understanding-the-api-response}

La requête génère une réponse semblable à celle-ci :

#### Réponse d’appairage traditionnel {#traditional-pairing-response}

```
{
  "device_code": "[device_code]",
  "expires_in": 120,
  "interval": 5,
  "name": "MyDevice-[client_id]",
  "user_code": "573131"
}
```

#### Réponse d’appairage par URL {#url-pairing-response}

```
{
  "device_code": "[device_code]",
  "expires_in": 120,
  "interval": 5,
  "name": "MyDevice-[client_id]",
  "user_code": "573131",
  "verification_uri": "https://next.frame.io/pair",
  "verification_uri_complete": "https://next.frame.io/pair/573131"
}
```

#### Détail de la réponse {#response-breakdown}

- **device_code** : cet identifiant interne doit rester masqué aux utilisateurs ; il identifie la demande d’autorisation pendant l’interrogation (polling).
- **expires_in** : la durée de validité du code, en secondes.
- **interval** : l’intervalle d’interrogation recommandé, en secondes.
- **name** : l’identifiant de l’appareil qui se connecte.
- **user_code** : le code à six chiffres à saisir manuellement dans Frame.io pour appairer l’appareil.
- **verification_uri** : l’URL de base pour la saisie manuelle si la lecture du QR code n’est pas possible.
- **verification_uri_complete** : l’URL complète contenant le code d’appairage, destinée à être utilisée comme lien hypertexte dans une application mobile ou pour générer un QR code afin de diriger facilement l’utilisateur vers l’interface d’appairage.

### Afficher le QR code à l’utilisateur {#displaying-the-qr-code-to-the-user}

À l’aide de `verification_uri_complete`, générez et affichez un QR code sur l’écran de l’appareil afin que l’utilisateur puisse le scanner, pour un appairage efficace.

#### Exemple : écran d’appareil affichant un QR code {#example-device-screen-with-qr-code-displayed}

![Exemple d’écran d’appairage par QR code sur un appareil](/images/camera-to-cloud/implementing-c2c-authentication-and-authorization/193d938af906dbcbc9699953e9da5ddbeeee8cd75fdfabf0661127c2b528cdb4.webp)

Prévoyez toujours des solutions de repli : affichez le `user_code` et la `verification_uri` pour une saisie manuelle lorsque la lecture du QR code n’est pas possible. Vous pouvez aussi afficher la `verification_uri` sous forme de QR code statique à scanner avec un appareil mobile.

Pour les intégrations dans des applications mobiles, incluez la `verification_uri_complete` sous forme de lien hypertexte cliquable, car les utilisateurs ne peuvent pas scanner un QR code depuis l’appareil qui exécute l’application.

## Étape 2 : interroger l’API pour obtenir l’autorisation de l’utilisateur {#step-2-polling-for-user-authorization}

Après avoir fourni le code d’appairage ou le code URL, vérifiez la saisie de l’utilisateur avec cette requête :

```
curl -X POST https://api.frame.io/v2/auth/token \
    --form 'client_id=[client_id]' \
    --form 'device_code=[device_code]' \
    --form 'grant_type=urn:ietf:params:oauth:grant-type:device_code' \
    | python -m json.tool
```

### Paramètres de la charge utile {#payload-parameters-1}

- **client_id** : le même identifiant que celui utilisé à l’étape 1.
- **device_code** : la valeur `device_code` renvoyée précédemment.
- **grant_type** : l’identifiant du type d’octroi OAuth, toujours `urn:ietf:params:oauth:grant-type:device_code` pour cette implémentation.

Les premières tentatives d’interrogation renvoient généralement :

```
{
  "error": "authorization_pending"
}
```

Cette erreur non bloquante indique que l’utilisateur n’a pas encore terminé la saisie du code. Poursuivez l’interrogation jusqu’à la fin du processus.

> **Remarque pour les appareils iOS :** si l’utilisateur bascule vers l’application iOS Frame.io pour saisir le code d’appairage, votre application peut passer en arrière-plan. Lorsque votre application redevient active, par exemple dans `applicationDidBecomeActive`, reprenez l’interrogation afin que le flux d’autorisation puisse se poursuivre sans que l’utilisateur ait à relancer l’appairage.

Si vous recevez :

```
{
  "error": "expired_token"
}
```

Le code a expiré avant la saisie par l’utilisateur. Générez un nouveau code/QR code via l’étape 1, présentez-le à l’utilisateur et reprenez l’interrogation.

Une autorisation réussie produit :

```
{
  "access_token": "[access_token]",
  "expires_in": 28800,
  "refresh_token": "[refresh_token]",
  "token_type": "bearer"
}
```

Félicitations, vous avez autorisé votre appareil Camera to Cloud !

Examinons cette réponse :

- **access_token** : votre identifiant d’authentification pour accéder au backend de Frame.io, requis dans les en-têtes des futures requêtes API.
- **expires_in** : la durée de validité du jeton d’accès en secondes, au-delà de laquelle une actualisation est nécessaire.
- **refresh_token** : utilisé pour la gestion du jeton d’accès, principalement pour actualiser l’autorisation, mais également pour la révoquer.
- **token_type** : toujours `bearer` pour les implémentations de l’API C2C ; aucune action n’est requise.

## Assembler les étapes {#putting-the-steps-together}

Implémentons maintenant ces appels d’API en pseudo-code de type Python, en gérant l’expiration éventuelle du code d’appareil :

```python title="Python"
def authorize_with_frame():
    """
    Handles authorizing our device with Frame.io.
    """

    # Our client ID can be a serial number, UUID, or some other unique string.
    client_id = THIS_DEVICE.get_serial_number()

    while True:
        # Make the call to Frame.io to get our device codes.
        pairing_codes = c2c.get_device_codes(client_id)

        # We need to keep track of how long we have been polling for
        polling_started = datetime.now()

        # Now we are going to poll for authorization until the user enters the code.
        while True:

            # Re-write this output each time we poll. Note: This message will only update once
            # per `interval` (e.g., 5 seconds), so if a smooth countdown is desired, that will
            # need a different implementation.
            print(
                f"\rPAIRING CODE: {pairing_codes.user_code}, "
                f"EXPIRES IN: {pairing_codes.expires_in - (datetime.now() - polling_started).seconds} seconds"
            )

            # Wait for `interval` before polling each time.
            sleep(pairing_codes.interval)

            # Make a call to Frame.io to see if the user has entered the code and authorized
            # the device.
            authorization, error = c2c.poll_for_authorization(
                client_id, pairing_codes.device_code
            )

            if error and error.message == "authorization_pending":
                # If the authorization is pending, try again.
                continue
            elif error and error.message == "expired_token":
                # If the pairing codes have expired, break to generate new codes.
                break
            elif error:
                # If there was some other error, raise it.
                raise error
            else:
                # If there was no error, we have our authorization!
                return authorization

        # If we get here, our pairing codes expired. Let's try again.
        print("\nPairing code expired. Generating a new one...")
```

**Remarque :** la boucle externe gère les cas où les codes d’appairage expirent et où de nouveaux codes sont nécessaires.

Pour finir, récupérez et affichez les informations du projet depuis Frame.io afin de confirmer que l’appairage au projet souhaité a réussi. Nous aborderons ce point dans le prochain tutoriel.

## Créer et afficher des QR codes pour l’appairage {#creating-and-displaying-qr-codes-for-pairing}

Lors de la mise en œuvre de l’appairage par URL/QR code, vous devez générer un QR code à partir de la valeur `verification_uri_complete` de la réponse. Voici des exemples utilisant des bibliothèques populaires dans différents langages de programmation :

### Exemple Python avec qrcode {#python-example-using-qrcode}

```python title="Python"
import qrcode
from PIL import Image
import io

def generate_qr_code(verification_uri_complete, size=250):
    """
    Generate a QR code from the verification_uri_complete URL.
    
    Args:
        verification_uri_complete (str): The complete verification URI returned by Frame.io
        size (int, optional): Size of the QR code in pixels. Defaults to 250.
    
    Returns:
        PIL.Image: QR code image that can be displayed or saved
    """
    qr = qrcode.QRCode(
        version=1,
        error_correction=qrcode.constants.ERROR_CORRECT_L,
        box_size=10,
        border=4,
    )
    qr.add_data(verification_uri_complete)
    qr.make(fit=True)
    
    img = qr.make_image(fill_color="black", back_color="white")
    
    # Resize the image if needed
    img = img.resize((size, size))
    return img

# Example usage in authorization flow
def display_qr_for_pairing(pairing_codes):
    """
    Generate and display QR code along with manual pairing instructions.
    """
    if hasattr(pairing_codes, 'verification_uri_complete'):
        # Generate QR code from the verification URI
        qr_img = generate_qr_code(pairing_codes.verification_uri_complete)
        
        # Display the QR code on screen
        # For GUI applications like Tkinter, PyQt, etc.
        # display_image(qr_img)
        
        # For headless devices or testing, save to file
        qr_img.save("frame_io_pairing_qr.png")
        
        print(f"Scan the QR code or visit: {pairing_codes.verification_uri}")
        print(f"Manual code: {pairing_codes.user_code}")
    else:
        # Fallback for devices that received traditional pairing response
        print(f"Enter code on Frame.io: {pairing_codes.user_code}")
```

### Exemple JavaScript (Web ou Electron) {#javascript-example-web-or-electron}

```javascript
import QRCode from 'qrcode';

/**
 * Generate and display a QR code from the verification URI
 * @param {string} verificationUriComplete - The complete verification URI from Frame.io
 * @param {string} elementId - ID of the HTML element to display the QR code in
 */
function displayQRCode(verificationUriComplete, elementId = 'qrcode-container') {
  const element = document.getElementById(elementId);
  
  if (!element) {
    console.error(`Element with ID ${elementId} not found`);
    return;
  }
  
  // Clear any existing content
  element.innerHTML = '';
  
  // Generate QR code
  QRCode.toCanvas(element, verificationUriComplete, { width: 250 }, function(error) {
    if (error) {
      console.error('Error generating QR code:', error);
      // Fallback to displaying the URL as a link
      element.innerHTML = `<a href="${verificationUriComplete}" target="_blank">Click here to pair</a>`;
    }
  });
  
  // Also display manual pairing information
  const manualInfoDiv = document.createElement('div');
  manualInfoDiv.innerHTML = `
    <p>Scan the QR code or <a href="${verificationUriComplete}" target="_blank">click here</a> to pair your device.</p>
    <p>Manual code: ${userCode}</p>
  `;
  element.parentNode.appendChild(manualInfoDiv);
}

// Example usage in authorization flow
async function requestDeviceCode() {
  try {
    const response = await fetch('https://api.frame.io/v2/auth/device/code', {
      method: 'POST',
      headers: {
        'x-client-version': '2.0.0',
        'x-client-platypus-enabled': 'true'
      },
      body: new URLSearchParams({
        'client_id': YOUR_CLIENT_ID,
        'client_secret': YOUR_CLIENT_SECRET,
        'scope': 'asset_create offline'
      })
    });
    
    const data = await response.json();
    
    if (data.verification_uri_complete) {
      displayQRCode(data.verification_uri_complete);
      window.userCode = data.user_code; // Store for display purposes
    } else {
      // Fallback for traditional pairing
      displayManualPairingCode(data.user_code);
    }
    
    // Begin polling for authorization
    beginPollingForAuthorization(data.device_code, data.interval);
    
  } catch (error) {
    console.error('Error requesting device code:', error);
  }
}
```

### Exemple Android (Java) {#android-example-java}

```java
import android.graphics.Bitmap;
import android.widget.ImageView;
import com.google.zxing.BarcodeFormat;
import com.google.zxing.MultiFormatWriter;
import com.google.zxing.common.BitMatrix;

public void generateAndDisplayQRCode(String verificationUriComplete, ImageView qrCodeImageView) {
    try {
        MultiFormatWriter multiFormatWriter = new MultiFormatWriter();
        BitMatrix bitMatrix = multiFormatWriter.encode(verificationUriComplete, 
            BarcodeFormat.QR_CODE, 250, 250);
        BarcodeEncoder barcodeEncoder = new BarcodeEncoder();
        Bitmap bitmap = barcodeEncoder.createBitmap(bitMatrix);
        
        // Display in ImageView
        qrCodeImageView.setImageBitmap(bitmap);
        
    } catch (Exception e) {
        e.printStackTrace();
        // Fallback to displaying the URL as text
    }
}
```

### Exemple iOS (Swift) {#ios-example-swift}

```swift
import UIKit
import CoreImage

func generateQRCode(from string: String) -> UIImage? {
    let data = string.data(using: String.Encoding.utf8)
    
    if let filter = CIFilter(name: "CIQRCodeGenerator") {
        filter.setValue(data, forKey: "inputMessage")
        filter.setValue("H", forKey: "inputCorrectionLevel")
        
        if let outputImage = filter.outputImage {
            // Scale the image
            let transform = CGAffineTransform(scaleX: 10, y: 10)
            let scaledImage = outputImage.transformed(by: transform)
            
            // Convert to UIImage
            let context = CIContext()
            if let cgImage = context.createCGImage(scaledImage, from: scaledImage.extent) {
                return UIImage(cgImage: cgImage)
            }
        }
    }
    
    return nil
}
```

## Bonnes pratiques d’affichage des QR codes {#best-practices-for-qr-code-display}

Lors de la mise en œuvre de l’appairage par QR code, tenez compte de ces recommandations pour offrir la meilleure expérience utilisateur :

1. **Taille optimale** : affichez les QR codes dans un carré d’au moins 200 à 250 pixels pour une lecture fiable.

2. **Contraste** : assurez un contraste élevé entre le QR code et l’arrière-plan (noir sur blanc est idéal).

3. **Correction d’erreurs** : utilisez des niveaux de correction d’erreurs modérés (L ou M) pour équilibrer densité du code et fiabilité.

4. **Instructions claires** : indiquez clairement comment scanner le code, par exemple « Scannez ce code avec l’appareil photo de votre smartphone pour appairer votre appareil. »

5. **Plusieurs options** : fournissez toujours le code d’appairage manuel à côté du QR code comme solution de repli :

   ```
   Scan to pair:
   [QR CODE]

   Or enter code manually: 573131
   ```

6. **Lien hypertexte pour les applications mobiles** : si votre intégration est une application mobile, incluez la `verification_uri_complete` sous forme de lien cliquable, car les utilisateurs ne peuvent pas scanner un QR code depuis le même appareil.

7. **Tests** : testez vos QR codes avec différents appareils et dans diverses conditions d’éclairage pour garantir une lecture fiable.

## Dépannage {#troubleshooting}

Si vous rencontrez des problèmes, consultez ces scénarios courants et leurs solutions :

- **Bouton « Connect Device » non visible** : lorsque vous accédez au panneau de gestion C2C, cela peut indiquer :

  - **Permissions insuffisantes** : si un message relatif aux permissions s’affiche, contactez votre gestionnaire de compte pour ajuster les permissions ou vous attribuer un rôle approprié.
  - **Appareil déjà connecté** : après la connexion d’un appareil, le bouton principal « Add New Device » est remplacé par un menu à trois points dans l’angle supérieur droit du panneau C2C Connections.

- **Erreur de client invalide** : une réponse `invalid_client` indique une incohérence dans les informations de l’appareil, généralement due à un `client_secret` incorrect.

- **Erreur de requête incorrecte** : une réponse `bad_request` indique des données de requête mal formées. Vérifiez les noms des champs et assurez-vous que tous les champs obligatoires sont inclus.

Si votre problème n’est pas traité ici, faites-nous part de votre expérience afin que nous puissions enrichir cette section de dépannage.
