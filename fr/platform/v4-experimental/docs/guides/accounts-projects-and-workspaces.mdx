## Accès pour tous les comptes {#all-account-access}

Tous les comptes Frame V4, et pas seulement ceux gérés via l’Adobe Admin Console, peuvent créer des tokens et accéder à l’API V4. Clients et partenaires peuvent tester, développer et affiner leurs workflows à l’aide de nos toutes dernières fonctionnalités d’API.

<Steps>

<Step title="Créer un token d’authentification utilisateur">

Rendez-vous dans l’Adobe Developer Console pour créer un token d’authentification utilisateur. L’utilisateur doit utiliser le même Adobe ID que pour sa connexion à Frame afin de valider l’accès par token à l’API.

</Step>

<Step title="Créer des identifiants d’API">

Une fois que vous avez accès aux API, l’étape suivante consiste à créer des identifiants d’API, ou un token d’API, pour communiquer avec Frame. Créez vos identifiants d’API sur developer.adobe.com.

</Step>

</Steps>

![Accès au compte](/images/platform/docs/guides/accounts-projects-and-workspaces/706a4eb9324bc24a3465388a838455baf58384f128882a185dad2d1900f728a3.webp)

<Info>

Tous les comptes V4, qu’ils soient gérés par Frame (V4F) ou par Adobe (V4A), peuvent créer un projet dans l’Adobe Developer Console, puis créer des identifiants. Une fois que vous disposez d’un jeu d’identifiants (OAuth Client ID/Client Secret), vous pouvez vous intégrer au flux OAuth à trois étapes (three-legged) de l’Adobe Developer Platform. Connectez-vous avec votre Adobe Identity pour recevoir un token d’authentification et un refresh token valides afin d’effectuer des requêtes vers l’API Developer de Frame.io V4 !

</Info>

## Projets et Workspaces {#projects-and-workspaces}

### Nouveautés des Workspaces {#workspace-updates}

La page d’accueil de Frame.io a été repensée et s’appelle désormais la page Workspace. Les utilisateurs peuvent parcourir les Workspaces et les projets auxquels ils ont accès au sein d’un compte. Grâce à ce nouveau design, il est plus facile de voir qui appartient à un Workspace donné et d’inviter rapidement de nouvelles personnes.

<Note>

Dans Frame V3, les Workspaces s’appelaient des Teams.

</Note>

Dans V4, les Workspaces sont configurés en mode « sur invitation uniquement » : les utilisateurs ne voient donc que les Workspaces auxquels ils ont été explicitement invités. Par ailleurs, il n’existe pas de page Team Directory dans les paramètres du compte.

Pour gérer les permissions et les opérations associées, utilisez les endpoints Create, List, Delete et Update Workspace.

### Nouveautés des projets {#project-updates}

Le processus de création de projet a changé dans V4. Désormais, lorsque vous démarrez un nouveau projet, vous choisissez entre un projet vierge et un modèle de projet. Douze modèles, conçus pour les workflows créatifs courants, sont disponibles. Vous pouvez également choisir d’inclure les assets de démonstration du modèle, ou de commencer uniquement avec la structure du modèle. Le choix d’un modèle de projet crée immédiatement un nouveau projet dans votre Workspace.

Pour gérer les permissions et les opérations associées, utilisez les endpoints Create, List, Delete et Update Project.
