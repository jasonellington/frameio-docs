## Principes de base de l’actualisation des tokens {#basics-of-token-refresh}

Si vous avez inclus le scope ***offline*** dans votre requête d’identifiants OAuth2.0, une authentification réussie via l’application Accounts de Frame.io renverra une charge utile semblable à la suivante :

```json
{
  "access_token":"BEARER_TOKEN",
  "expires_in":3600,
  "refresh_token":"REFRESH_TOKEN",
  "scope":"account.read offline",
  "token_type":"bearer"
}
```

L’`access_token` est un bearer token qui peut être utilisé pour agir au nom de l’utilisateur authentifié ; il expire au bout de 3600 secondes (une heure), après quoi le `refresh_token` peut être utilisé pour obtenir un nouvel `access_token`. Le refresh token expire ensuite au bout de 30 jours ; l’utilisateur devra alors se reconnecter entièrement, ce qui produira une nouvelle paire de tokens d’accès et d’actualisation, et ainsi de suite.

Si vous ne demandez pas explicitement le scope *offline*, vous ne recevrez pas de `refresh_token` et devrez donc réauthentifier complètement l’utilisateur au bout d’une heure.

### Récupérer le refresh token lors d’une authentification réussie {#capturing-the-refresh-token-on-successful-authentication}

Inutile de préciser que vous ne pouvez pas utiliser un `refresh_token` que vous n’avez pas ; veillez donc, dans votre application, à :

- Demander le scope **offline**
- Récupérer le `refresh_token` renvoyé lors d’un callback réussi.

Pour plus de commodité, le callback de nos [guides sur les applications OAuth 2](https://developer.frame.io/oauth-2-applications/building-an-oauth-2-app) est reproduit ici, avec un appel `os` pour stocker le refresh token. Veuillez noter que deux exemples sont fournis : l’un avec PKCE configuré (sans en-tête d’authentification Basic), et l’autre sans (avec en-tête d’authentification Basic).

### Sans PKCE {#without-pkce}

```python title="Python"
def callback():
  # Where `request` refers to our initial call to the auth URL
  state = request.args.get('state')
  scope = request.args.get('scope')
  code = request.args.get('code')
  error = request.args.get('error')

  if error:
    return "Error: " + error

  # Set up for client authorization and set up the data you need to send.
  client_auth = requests.auth.HTTPBasicAuth(CLIENT_ID, CLIENT_SECRET)

  post_data = {
    "grant_type": "authorization_code",
    "code": code,
    "redirect_uri": REDIRECT_URI,
    "state": state,
    "scope": SCOPE
  }

  # Send a POST request with the data you need to receive an access token. 
  response = requests.post(TOKEN, auth=client_auth, data=post_data)    
	# Stash the refresh token for later
  os.environ['REFRESH_TOKEN'] = response.json()["refresh_token"]

  return response.text
```

### Avec PKCE {#with-pkce}

```python title="Python"
def callback():
  # Where `request` refers to our initial call to the auth URL
  state = request.args.get('state')
  scope = request.args.get('scope')
  code = request.args.get('code')
  error = request.args.get('error')

  if error:
    return "Error: " + error

  # If using PKCE, you must include the CLIENT_ID in your request body  
  post_data = {
    "grant_type": "authorization_code",
    "code": code,
    "redirect_uri": REDIRECT_URI,
    "state": state,
    "scope": SCOPE
    "client_id": CLIENT_ID 
  }

  # Send a POST request with the data you need to receive an access token.
  # If using PKCE, use the below request with no auth
  response = requests.post(TOKEN_URL, data=post_data)
  # Stash the refresh token for later
  os.environ['REFRESH_TOKEN'] = response.json()["refresh_token"]

  return response.text
```

## Exécuter une actualisation {#executing-a-refresh}

L’actualisation elle-même consiste en un seul appel à l’URL de token de Frame.io :

- Méthode : POST
- URL : **[https://applications.frame.io/oauth2/token](https://applications.frame.io/oauth2/token)**
- `Content-Type` : *application/x-www-form-urlencoded*

Une actualisation inclut toujours au moins les trois attributs suivants dans ses données de formulaire :

- `grant_type` : *refresh_token*
- `scope` : &lt;SCOPES>
- `refresh_token` : &lt;REFRESH_TOKEN>

Si vous utilisez PKCE, vous devrez inclure le `client_id` de votre application dans ces données de formulaire ; sinon, vous devrez inclure un en-tête d’authentification Basic avec le `client_id` et le `client_secret` de votre application comme nom d’utilisateur et mot de passe, respectivement.

### Sans PKCE {#without-pkce-1}

Comme pour [le callback d’authentification initial](https://developer.frame.io/oauth-2-applications/building-an-oauth-2-app#the-callback) sans PKCE, cette actualisation standard nécessite de fournir votre `client_id` et votre `client_secret` comme nom d’utilisateur et mot de passe dans un en-tête d’authentification Basic.

```python title="Python"
def refresh():
  # Fetch the refresh token, assuming we have it
  REFRESH_TOKEN = os.environ.get('REFRESH_TOKEN')

  client_auth = requests.auth.HTTPBasicAuth(CLIENT_ID,CLIENT_SECRET)
  post_data = {
    "grant_type": "refresh_token",
    "scope": SCOPE,
    "refresh_token": REFRESH_TOKEN
    # if using PKCE, you will need to include your client_id as below
    # "client_id": CLIENT_ID 
  }

  response = requests.post(TOKEN_URL, auth=client_auth, data=post_data)
  # Catch + stash a new Refresh Token
  os.environ['REFRESH_TOKEN'] = response.json()["refresh_token"]

  return response.text
```

### Avec PKCE {#with-pkce-1}

Là encore, nous reproduisons les règles de notre cycle `/callback` initial :

- Nous n’incluons pas d’en-tête `Authorization`
- Nous devons inclure le `client_id` dans notre charge utile

```python title="Python"
def refresh():
  # Fetch the refresh token, assuming we have it
  REFRESH_TOKEN = os.environ.get('REFRESH_TOKEN')

  post_data = {
    "grant_type": "refresh_token",
    "scope": SCOPE,
    "refresh_token": REFRESH_TOKEN
    "client_id": CLIENT_ID 
  }

  response = requests.post(TOKEN_URL, data=post_data)
  # Catch + stash a new Refresh Token
  os.environ['REFRESH_TOKEN'] = response.json()["refresh_token"]

  return response.text
```

Félicitations ! Vous savez désormais gérer l’intégralité du cycle de vie des tokens d’une application cliente OAuth2.0.
