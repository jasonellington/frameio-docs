Ngrok est un outil simple d’utilisation qui vous permet de créer un tunnel sécurisé sur votre machine locale, ainsi qu’une URL publique que vous pouvez utiliser pour tester votre projet local ou pour partager votre travail avec un client ou un collègue afin qu’il le révise. Vous pouvez configurer HTTP ou HTTPS et, compte tenu de la popularité de cet outil, si quelque chose ne fonctionne pas, vous trouverez de très nombreux articles décrivant différentes façons de résoudre votre problème. Cet article présente quelques méthodes simples pour installer ngrok, ainsi que la marche à suivre si vous n’arrivez pas à faire communiquer votre application web avec ngrok.

## Installer ngrok {#install-ngrok}

Vous pouvez utiliser ngrok de plusieurs manières

### Installer via le programme d’installation de ngrok {#install-via-the-ngrok-installer}

1. Rendez-vous sur le site web de ngrok et suivez les instructions qui y figurent : [https://ngrok.com/download](https://ngrok.com/download)
2. Si vous souhaitez bénéficier des fonctionnalités offertes par la connexion d’un compte, suivez ces instructions pour obtenir un compte et un jeton.

Vous n’êtes pas obligé de créer un compte ni d’ajouter le jeton, mais consultez tout de même la page de téléchargement pour voir si cela correspond à vos envies ou à vos besoins.

<Info>

**Remarque :**

Si vous utilisez cette méthode, ngrok s’exécute depuis l’emplacement où vous l’avez stocké, sauf si vous le rendez disponible dans tout votre système.

</Info>

### Installer avec Homebrew {#install-with-homebrew}

C’est ma méthode préférée pour installer ngrok. Si Homebrew est installé, il vous suffit de taper `homebrew cask install ngrok` . ngrok est installé pour vous et vous pouvez l’utiliser depuis n’importe où ! Mieux encore, vous n’avez pas besoin de taper `./ngrok` dans le terminal au début de chaque commande : vous pouvez simplement taper `ngrok`. Pour en savoir plus sur cette option, cliquez [ici](https://gist.github.com/wosephjeber/aa174fb851dfe87e644e).

## Utiliser ngrok {#use-ngrok}

Une fois ngrok configuré, choisissez un port, comme `3000`, et lancez-le depuis une ligne de commande du terminal avec la commande ngrok http `3000`. Vous n’êtes pas obligé d’utiliser le port `3000`, mais c’est un port couramment choisi lors de la configuration.

Si vous avez configuré ngrok pour qu’il s’exécute depuis un dossier spécifique, vous devez vous trouver dans le dossier où vous avez placé ngrok et utiliser la commande `./ngrok http 3000`.

Démarrez le serveur de votre projet pour qu’il écoute sur le même port : vous pourrez alors accéder à votre travail via l’adresse publique fournie par ngrok.

### Dépanner ngrok avec votre application web - Barre oblique finale {#troubleshooting-ngrok-with-your-web-app-trailing-slash}

Un problème que vous pourriez rencontrer avec ngrok est l’impossibilité de vous connecter à votre serveur lorsque vous configurez une URL ngrok à utiliser avec votre application web. Ce qui est frustrant avec ce problème, c’est que ngrok n’enregistre pas que vous lui avez envoyé quoi que ce soit. Vous pouvez ouvrir localhost:4040 pour voir ce qui se passe, et rien ne s’affichera. (localhost:4040 est fourni par ngrok pour vous permettre de surveiller les requêtes entrantes vers votre serveur.) Ngrok semble faire correspondre les adresses à /(.*) plutôt qu’à (/.*) : si vous n’ajoutez pas de barre oblique finale à la fin de votre adresse et que rien n’apparaît dans les outils de surveillance de ngrok, c’est que ngrok ne trouve pas de correspondance pour l’adresse indiquée.

Voici un exemple d’ajout d’une barre oblique finale : `http://something.ngrok.io/`

Vous pouvez également écrire vos applications d’exemple de façon à ce qu’elles pointent vers un endpoint comprenant une barre oblique. N’oubliez simplement pas que, pour que l’application Frame.io puisse joindre votre serveur, si votre application d’exemple utilise l’endpoint `/actions`, vous devez ajouter l’endpoint /actions à la fin de votre adresse ngrok. Par exemple, si l’adresse ngrok est `http://something.ngrok.io`, vous devrez la renseigner dans la configuration de votre Custom Action sous la forme `http://something.ngrok.io/actions`. Cela peut être différent pour d’autres applications web : faites donc des essais avec la fin de l’adresse ngrok si vous n’arrivez pas à faire fonctionner les choses immédiatement.

### Puis-je utiliser autre chose que ngrok ? Essayez Glitch ! {#can-i-use-something-besides-ngrok-try-glitch}

Glitch est une alternative très intéressante à ngrok, plus rapide à configurer. Glitch vous permet de créer un compte, puis de développer vos propres applications sur ses serveurs avec une URL accessible publiquement. Vous pouvez collaborer avec d’autres personnes, rendre votre code public ou privé, et choisir parmi une grande variété de langages et de plateformes. Consultez [https://glitch.com/create](https://glitch.com/create) pour voir ce qui est disponible.

Lorsque vous configurez votre projet sur Glitch, le problème de la barre oblique finale s’applique pour certaines applications web. Dans le cas de Frame.io, lorsque vous configurez une Custom Action sur [developer.frame.io](/fr/platform/v2), vous devez ajouter la barre oblique finale à la fin de l’URL fournie par Glitch. Vous n’avez rien d’autre à ajouter, même pour l’endpoint /actions.

### Y a-t-il quelque chose de déjà configuré que je pourrais essayer dès maintenant ? {#is-there-something-set-up-i-could-try-now}

Oui. Si vous ne souhaitez pas utiliser ngrok ni créer votre propre projet Glitch, nous avons configuré une application d’exemple que vous pouvez essayer ici : [https://frameio-custom-action.glitch.me](https://frameio-custom-action.glitch.me). N’oubliez pas d’ajouter une barre oblique finale lorsque vous saisissez cette adresse dans la zone Custom Actions de \[/).
