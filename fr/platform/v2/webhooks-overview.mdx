## Introduction {#introduction}

Les webhooks permettent de transformer les événements qui se produisent dans Frame.io en notifications pouvant être envoyées à des systèmes externes à des fins de traitement, de callbacks d’API et, en fin de compte, d’automatisation des workflows.

## Configuration {#setup}

Les webhooks peuvent être configurés dans la [section Webhooks de notre site développeur](https://developer.frame.io/app/webhooks). Un webhook nécessite :

- Nom — Affiché uniquement sur le site développeur.
- URL — L’adresse à laquelle les événements sont livrés.
- Team — La Team à laquelle ce webhook sera ajouté.
- Événements — Le ou les événements qui doivent déclencher le webhook.

## Événements pris en charge {#supported-events}

Un même webhook peut s’abonner à n’importe quel nombre des événements suivants :

### Projets {#projects}

| Événement | Déclencheur |
| --- | --- |
| `project.created` | Un nouveau projet est créé |
| `project.updated` | Les paramètres d’un projet sont mis à jour |
| `project.deleted` | Un projet est supprimé |

### Assets {#assets}

| Événement | Déclencheur |
| --- | --- |
| `asset.created` | Un asset est ajouté/créé pour la première fois dans Frame.io, mais probablement avant que son import soit terminé |
| `asset.copied` | Un asset a été copié |
| `asset.updated` | La description, le nom ou d’autres informations de fichier d’un asset sont modifiés |
| `asset.deleted` | Un asset est supprimé (manuellement ou autrement) |
| `asset.ready` | Tous les transcodages sont terminés, après l’import et le traitement d’un asset |
| `asset.label.updated` | Le libellé de statut d’un asset est défini, modifié ou supprimé |
| `asset.versioned` | Un asset est versionné |

<Warning>

**Versionnage des assets**

Lorsque l’événement `asset.versioned` se déclenche, vous recevez un payload contenant l’id de l’asset qui a été versionné, et non celui de la version stack elle-même. Ainsi, si vous comptez transmettre cet `id` à une autre fonction en pensant qu’il s’agit de l’id de la version stack, vous devrez d’abord rechercher et retrouver la ressource « parente » correspondante.

</Warning>

<Warning>

**Mises à jour du libellé des assets**

L’événement `asset.label.updated` ne se déclenche pas lorsque le libellé de statut est modifié via un appel `PUT` à l’endpoint `/v2/assets/:id` de l’API publique (`BES-408`). Il se déclenche en revanche lorsque le libellé de statut est mis à jour via n’importe quelle application ou intégration native de Frame.io (Web, iOS, Premiere, After Effects, FCPX, etc.).

</Warning>

### Commentaires {#comments}

| Événement | Déclencheur |
| --- | --- |
| `comment.created` | Un nouveau commentaire ou une nouvelle réponse est créé |
| `comment.updated` | Un commentaire est modifié |
| `comment.deleted` | Un commentaire est supprimé |
| `comment.completed` | Un commentaire est marqué comme terminé |
| `comment.uncompleted` | Un commentaire n’est plus marqué comme terminé |

### Liens de revue {#review-links}

| Événement | Déclencheur |
| --- | --- |
| `reviewlink.created` | Un nouveau lien de revue est créé |

### Collaborateurs {#collaborators}

| Événement | Déclencheur |
| --- | --- |
| `collaborator.created` | Un collaborateur a été ajouté à votre compte |
| `collaborator.deleted` | Un collaborateur a été retiré de votre compte |

### Membres d’équipe {#team-members}

| Événement | Déclencheur |
| --- | --- |
| `teammember.created` | Un membre d’équipe a été ajouté à votre compte |
| `teammember.deleted` | Un membre d’équipe a été retiré de votre compte |

## Payload {#payload}

Frame.io livre un payload JSON à l’endpoint de webhook spécifié. Voici un exemple de payload pour un événement *asset.created* :

```json
{
  "type": "asset.created",
  "resource": {
    "type": "asset",
    "id": "<asset-id>"
  },
  "user": {
    "id": "<user-id>"
  },
  "team": {
    "id": "<team-id>"
  }
}
```

Tous les payloads contiennent un champ `type`, qui indique le type d’événement survenu, ainsi qu’un objet `resource`. L’objet `resource` précise le `type` et l’`id` de la ressource concernée par cet événement.

Dans l’exemple ci-dessus d’un événement *asset.created*, il s’agirait de l’`id` de l’asset nouvellement créé. Des objets `user` et `team` sont également inclus. Ils font référence à l’utilisateur qui a déclenché l’événement et au contexte de Team de la ressource.

En dehors du contexte immédiat de l’utilisateur et de la Team, **nous n’incluons aucune information supplémentaire sur la ressource concernée**. Si votre application a besoin d’informations ou de contexte supplémentaires, nous vous recommandons d’utiliser notre API HTTP pour effectuer des requêtes complémentaires.

## Nouvelles tentatives {#retries}

Si une erreur (réponse avec un code de statut autre que 200) ou un délai d’expiration survient lors de la livraison du webhook à votre service, l’envoi du payload sera retenté trois fois, soit quatre tentatives de livraison au total.

## Sécurité {#security}

Par défaut, tous les webhooks sont fournis avec une clé de signature. Ce comportement n’est pas configurable. Cette clé peut être utilisée pour vérifier que la requête provient bien de Frame.io.

### Vérifier les signatures des webhooks {#verify-webhook-signatures}

Pour protéger une intégration contre les attaques de l’homme du milieu et les attaques par rejeu, il est essentiel de vérifier les signatures des webhooks. Cette vérification garantit que les payloads des webhooks ont bien été envoyés par Frame.io et que leur contenu n’a pas été modifié pendant le transport.

La requête `POST` comprend les en-têtes suivants :

| Nom | Description |
| --- | --- |
| `X-Frameio-Request-Timestamp` | L’heure de livraison du webhook |
| `X-Frameio-Signature` | La signature calculée |

**L’horodatage** correspond à l’heure de livraison depuis les systèmes de Frame.io. Il peut être utilisé pour empêcher les attaques par rejeu. Nous vous recommandons de vérifier que cette heure se situe à moins de 5 minutes de l’heure locale.

**La signature** est un hachage HMAC SHA256 calculé à l’aide de la clé de signature fournie lors de la création initiale du webhook.

Suivez ces étapes pour vérifier la signature :

1. Extrayez la signature des en-têtes HTTP
2. Créez un message à signer en combinant la version, l’heure de livraison et le corps de la requête : `v0:timestamp:body`
3. Calculez la signature HMAC SHA256 à l’aide de votre secret de signature.  *Remarque : la signature fournie est préfixée par `v0=`. Actuellement, Frame.io ne dispose que de cette version pour signer les requêtes. Veillez à ajouter ce préfixe au début de la signature que vous calculez.*
4. Comparez !

```python title="Python"
import hmac
import hashlib

def verify_signature(curr_time, req_time, signature, body, secret):
    """
    Verify Webhook signature
    :Args:
        curr_time (float): Current epoch time
        req_time (float): Request epoch time
        signature (str): Signature provided by the Frame.io API for the given request
        body (str): Webhook body from the received POST
        secret (str): The secret for this Webhook that you saved when you first created it
    """
    if int(curr_time) - int(req_time) < 500:
        message = 'v0:{}:{}'.format(req_time, body)
        calculated_signature = 'v0={}'.format(hmac.new(
            bytes(secret, 'latin-1'),
            msg=bytes(message, 'latin-1'),
            digestmod=hashlib.sha256).hexdigest())
        if calculated_signature == signature:
            return True
    return False
```

// Full Go sample code: https://github.com/Frameio/webhooks-example-app/blob/master/main.go

func handler(w http.ResponseWriter, r *http.Request) {
	out, err := httputil.DumpRequest(r, true)
	if err != nil {
		w.WriteHeader(http.StatusInternalServerError)
		return
	}

	log.Println(string(out))

	// Verify the message has been delivered in the last 5 minutes.
	timestampStr := r.Header.Get("X-Frameio-Request-Timestamp")
	timestamp, err := strconv.ParseInt(timestampStr, 10, 64)
	if err != nil {
		w.WriteHeader(http.StatusBadRequest)
		return
	}

	if time.Since(time.Unix(timestamp, 0)) > 5*time.Minute {
		w.WriteHeader(http.StatusBadRequest)
		return
	}

	// Verify request signature.
	expected := r.Header.Get("X-Frameio-Signature")
	signature, _ := computeSignature(r, timestamp, secretKey)
	if expected != signature {
		w.WriteHeader(http.StatusUnauthorized)
		return
	}

	var event *Event
	decoder := json.NewDecoder(r.Body)
	err = decoder.Decode(&event)
	if err != nil {
		w.WriteHeader(http.StatusInternalServerError)
		return
	}

	// Handle webhook here.
	log.Println(event.ID)

	w.WriteHeader(http.StatusOK)
}

// The request includes headers to enable the recipient to validate
// that the request is from Frame.io and that it's been delivered within
// the expected time range. To learn more about how this works, take a
// look at our docs https://docs.frame.io/docs/webhooks#section-security.
func computeSignature(r *http.Request, timestamp int64, secret string) (string, error) {
	body, err := ioutil.ReadAll(r.Body)
	if err != nil {
		return "", err
	}
	copy := body[:]
	r.Body = ioutil.NopCloser(bytes.NewReader(copy))

	msg := fmt.Sprintf("%s:%d:%s", version, timestamp, string(body))

	key := []byte(secret)
	h := hmac.New(sha256.New, key)
	h.Write([]byte(msg))

	result := fmt.Sprintf("%s=%s", version, hex.EncodeToString(h.Sum(nil)))

	return result, nil
}
