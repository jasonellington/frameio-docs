## Accès pour tous les comptes {#all-account-access}

Tous les comptes Frame V4 — et pas seulement ceux gérés via l’Adobe Admin Console — peuvent créer des tokens et accéder à l’API V4. Clients et partenaires peuvent tester, créer et affiner leurs workflows grâce à nos toutes dernières fonctionnalités d’API.

<Steps>

<Step title="Créer un token d’authentification utilisateur">

Rendez-vous sur l’Adobe Developer Console pour créer un token d’authentification utilisateur. L’utilisateur doit utiliser le même Adobe ID que pour sa connexion à Frame afin de valider l’accès au token d’API.

</Step>

<Step title="Créer des identifiants d’API">

Une fois que vous avez accès aux API, l’étape suivante consiste à créer des identifiants d’API, ou un token d’API, pour communiquer avec Frame. Créez vos identifiants d’API sur developer.adobe.com.

</Step>

</Steps>

![Account Access](/images/platform/docs/guides/accounts-projects-and-workspaces/706a4eb9324bc24a3465388a838455baf58384f128882a185dad2d1900f728a3.webp)

<Info>

Tous les comptes V4, qu’ils soient gérés par Frame (V4F) ou par Adobe (V4A), peuvent créer un projet dans l’Adobe Developer Console, puis créer des identifiants. Une fois que vous disposez d’un jeu d’identifiants (OAuth Client ID/Client Secret), vous pouvez vous intégrer au flux OAuth à trois étapes de l’Adobe Developer Platform. Connectez-vous avec votre Adobe Identity pour recevoir un token d’authentification et un refresh token valides afin d’envoyer des requêtes à la Frame.io V4 Developer API !

</Info>

## Projets et workspaces {#projects-and-workspaces}

### Nouveautés des workspaces {#workspace-updates}

La page d’accueil de Frame.io a été repensée et s’appelle désormais la page Workspace. Les utilisateurs peuvent y parcourir les workspaces et projets auxquels ils ont accès dans un compte. Grâce à ce nouveau design, il est plus facile de voir qui fait partie d’un workspace donné et d’inviter rapidement de nouvelles personnes.

<Note>

Dans Frame V3, les workspaces s’appelaient des Teams.

</Note>

Dans V4, les workspaces sont accessibles sur invitation uniquement : les utilisateurs ne verront donc que les workspaces auxquels ils ont été explicitement invités. De plus, il n’existe pas de page Team Directory dans les paramètres du compte.

Pour gérer les autorisations et les opérations associées, utilisez les endpoints Create, List, Delete et Update Workspace.

- Mettre à jour les rôles d’un utilisateur pour le workspace donné si l’utilisateur y a déjà été ajouté. Si l’utilisateur n’a pas été ajouté au workspace, il sera ajouté avec le rôle indiqué.

### Nouveautés des projets {#project-updates}

Le flux de création de projet a changé dans V4. Désormais, lorsque vous démarrez un nouveau projet, vous choisissez entre un projet vierge et un modèle de projet. Douze modèles sont disponibles, conçus pour les workflows créatifs courants. Vous pouvez également choisir d’inclure les assets de démonstration du modèle, ou de démarrer uniquement avec la structure du modèle. Choisir un modèle de projet crée immédiatement un nouveau projet dans votre workspace.

Pour gérer les autorisations et les opérations associées, utilisez les endpoints Create, List, Delete et Update Project.
