Questa guida descrive in dettaglio l'intero flusso per caricare file utilizzando l'API V4 di Frame.io. Tratta le richieste e le risposte API non elaborate sia per i caricamenti locali sia per quelli remoti.

<Info>

**Cerchi guide specifiche per gli SDK?** Per implementazioni del caricamento con suddivisione in blocchi, nuovi tentativi e monitoraggio dell'avanzamento integrati, consulta la [Guida al caricamento con l'SDK Python](/it/platform/docs/guides/uploading-to-frame-io/python-sdk-upload-guide).

</Info>

<Steps>

</Step>

<Step title="Credenziali di autenticazione">

</Step>

</Steps>

## Scegliere il metodo di caricamento {#choosing-your-upload-method}

Esistono due modi per caricare un file utilizzando l'API di Frame.io: `Create File (local upload)` e `Create File (remote upload)`.

<CardGroup cols={2}>

<Card title="Caricamento locale" icon="upload" iconType="solid">

Da usare quando il contenuto multimediale è accessibile localmente dalla tua applicazione, in modo simile al trascinamento di un file dal desktop

</Card>

<Card title="Caricamento remoto" icon="link" iconType="solid">

Da usare quando si accede al contenuto multimediale tramite la rete, ad esempio attraverso un'integrazione con un altro servizio

</Card>

</CardGroup>

In questa guida inizieremo dal caso più semplice, ovvero il completamento di un caricamento remoto.

## Caricamento remoto {#remote-upload}

Per creare un file tramite caricamento remoto, seleziona l'endpoint **Create File (remote upload)**. Il corpo della richiesta richiede il nome del file e il suo URL di origine.

<Warning>

Il caricamento remoto ha attualmente un **limite di dimensione dei file di 500 GB**. Per file più grandi di 500 GB, usa invece il [caricamento locale](#local-upload).

</Warning>

### Esempio di richiesta {#request-example}

```json
{ 
    "data": {
        "name": "my_file.jpg",
        "source_url": "https://upload.wikimedia.org/wikipedia/commons/e/e1/White_Pixel_1x1.jpg"
    }
}
```

### Esempio di risposta {#response-example}

Una richiesta riuscita produrrà una risposta simile a quella riportata di seguito:

## Caricamento locale {#local-upload}

Per creare un file tramite caricamento locale, seleziona l'endpoint **Create File (local upload)**. Il corpo della richiesta richiede il nome del file e la sua dimensione espressa in byte.

### Esempio di richiesta {#request-example-1}

```json
{ 
    "data": {
        "name": "my_file.jpg",
        "file_size": 50645990
    }
}
```

### Esempio di risposta {#response-example-1}

Se la richiesta va a buon fine, viene creata una risorsa file segnaposto priva di contenuto. A seconda della dimensione del file, il corpo della risposta includerà uno o più `upload_urls`. In questo esempio, dovremo gestire il caricamento in più parti.

```json
{
    "data": {
        "id": "fa18ba7b-b3ee-4dd6-9b31-bd07e554241d",
        "name": "my_file.jpg",
        "status": "created",
        "type": "file",
        "file_size": 50645990,
        "updated_at": "2025-06-26T20:08:06.823170Z",
        "media_type": "image/jpeg",
        "parent_id": "2e426fe0-f965-4594-8b2b-b4dff1dc00ec",
        "project_id": "7e46e495-4444-4555-8649-bee4d391a997",
        "created_at": "2025-06-26T20:08:06.751313Z",
        "upload_urls": [
            {
                "size": 16881997,
                "url": "https://frameio-uploads-development.s3-accelerate.amazonaws.com/parts/fa18ba7b-b3ee-4dd6-9b31-bd07e554241d/part_1?..."
            },
            {
                "size": 16881997,
                "url": "https://frameio-uploads-development.s3-accelerate.amazonaws.com/parts/fa18ba7b-b3ee-4dd6-9b31-bd07e554241d/part_2?..."
            },
            {
                "size": 16881996,
                "url": "https://frameio-uploads-development.s3-accelerate.amazonaws.com/parts/fa18ba7b-b3ee-4dd6-9b31-bd07e554241d/part_3?..."
            }
        ],
        "view_url": "https://next.frame.io/project/7e46e495-4444-4555-8649-bee4d391a997/view/fa18ba7b-b3ee-4dd6-9b31-bd07e554241d"
    }
}
```

<Warning>

**Requisiti importanti per il caricamento:**

Ecco alcuni dettagli importanti da tenere a mente quando invii le successive richieste di caricamento:

- Il metodo della richiesta HTTP deve essere `PUT`
- L'header `x-amz-acl` deve essere incluso e impostato su private
- L'header `Content-Type` deve corrispondere al `media_type` specificato nella richiesta **Create File (local upload)** originale. Questo vale anche quando il file viene caricato in parti separate. Nell'esempio precedente, il valore di `media_type` è `image/jpeg`. Pertanto, anche il valore di `Content-Type` deve essere `image/jpeg`.

</Warning>

## Caricamento multiparte {#multi-part-upload}

Quando per un determinato file vengono restituiti più URL di caricamento, dovrai suddividere il file di origine in blocchi ed eseguire una richiesta PUT per ciascuno di essi.

<Info>

**Consigliato:** la [Guida al caricamento con l'SDK Python](/it/platform/docs/guides/uploading-to-frame-io/python-sdk-upload-guide) tratta il caricamento multiparte con `FrameioUploader`, che gestisce in modo nativo la suddivisione in blocchi, i caricamenti paralleli, i nuovi tentativi e il monitoraggio dell'avanzamento.

</Info>

Se hai bisogno di implementare il caricamento manualmente, ad esempio in un linguaggio privo di SDK o per avere il pieno controllo del processo, lo script seguente mostra come suddividere un file in blocchi e caricare ciascuno di essi utilizzando gli URL prefirmati.

### Esempio di implementazione in Python {#python-implementation-example}

```python title="Multi-part Upload Script"
import requests
import math
from typing import List
from tqdm import tqdm  # For progress bar

def upload_file_in_chunks(file_path: str, upload_urls: list[str], content_type: str | None = None, chunk_size: int | None = None) -> bool:
    """
    Upload a file in chunks using presigned URLs.
    """
    try:
        # Auto-detect content type based on file extension
        if content_type is None:
            detected_content_type, _ = mimetypes.guess_type(file_path)
            content_type = detected_content_type # Default fallback

        print(f"Detected content type: {content_type}")

        # Get file size
        with open(file_path, 'rb') as f:
            f.seek(0, 2)  # Seek to end of file
            file_size = f.tell()

        # Calculate chunk size if not provided
        if chunk_size is None:
            chunk_size = math.ceil(file_size / len(upload_urls))

        print(f"File size: {file_size} bytes")
        print(f"Chunk size: {chunk_size} bytes")
        print(f"Number of chunks: {len(upload_urls)}")

        # Upload each chunk
        with open(file_path, 'rb') as f:
            with tqdm(total=len(upload_urls), desc="Uploading chunks") as pbar:
                for i, url in enumerate(upload_urls):
                    start_byte = i * chunk_size
                    end_byte = min(start_byte + chunk_size, file_size)

                    # Read chunk from file
                    f.seek(start_byte)
                    chunk = f.read(end_byte - start_byte)

                    print(f"Uploading chunk {i+1}: {len(chunk)} bytes")

                    # Upload chunk with minimal headers matching the signature
                    response = requests.put(
                        url,
                        data=chunk,
                        headers={
                            'content-type': content_type,
                            'x-amz-acl': 'private'
                        }
                    )

                    if response.status_code != 200:
                        print(f"Failed to upload chunk {i+1}. Status code: {response.status_code}")
                        print(f"Response text: {response.text}")
                        print(f"Response headers: {dict(response.headers)}")
                        return False
                    else:
                        print(f"Chunk {i+1} uploaded successfully!")

                    pbar.update(1)

        return True

    except Exception as e:
        print(f"Error during upload: {str(e)}")
        return False

# Example usage
if __name__ == "__main__":
    # Replace these with your actual values
    file_path = "/Users/MyComputer/local_upload/sample.jpg"  # Path to your file
    upload_urls = [
        "https://frameio-uploads-development.s3-accelerate.amazonaws.com/parts/fa18ba7b-b3ee-4dd6-9b31-bd07e554241d/part_1?...",
        "https://frameio-uploads-development.s3-accelerate.amazonaws.com/parts/fa18ba7b-b3ee-4dd6-9b31-bd07e554241d/part_2?...",
        "https://frameio-uploads-development.s3-accelerate.amazonaws.com/parts/fa18ba7b-b3ee-4dd6-9b31-bd07e554241d/part_3?..."
    ]
    content_type = "image/jpeg"

    print("Starting file upload...")
    success = upload_file_in_chunks(file_path, upload_urls, content_type)

    if success:
        print("File upload completed successfully!")
    else:
        print("File upload failed!")
```

## Riepilogo del flusso di caricamento {#upload-flow-summary}

<Steps>

<Step title="Scegli il metodo di caricamento">

Scegli tra il caricamento remoto (file accessibile tramite URL) e il caricamento locale (file sul tuo sistema)

</Step>

<Step title="Crea la richiesta del file">

Esegui la richiesta iniziale per creare la risorsa file con i metadati richiesti

</Step>

<Step title="Gestisci gli URL di caricamento">

Per i caricamenti locali, elabora gli upload_urls restituiti (parte singola o più parti)

</Step>

<Step title="Carica il contenuto del file">

Usa richieste PUT con gli header corretti per caricare il contenuto del file negli URL forniti

</Step>

<Step title="Verifica il caricamento">

Controlla lo stato del file per confermare che il caricamento e l'elaborazione siano andati a buon fine

</Step>

</Steps>

<Info>

**Passaggi successivi**: una volta caricato il file, puoi utilizzare l'ID del file restituito per aggiungere commenti, creare condivisioni o eseguire altre operazioni con l'API V4 di Frame.io.

</Info>
