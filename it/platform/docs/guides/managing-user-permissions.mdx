---
title: "Gestione delle autorizzazioni degli utenti"
---

Questa guida spiega come gestire le autorizzazioni degli utenti con l’API Frame.io V4. Illustra come funzionano le autorizzazioni a livello di Account, Workspace e Project e quali endpoint utilizzare per ciascun livello.

---

## Livelli di autorizzazione {#permission-levels}

In Frame.io le autorizzazioni vengono gestite a livello di Account, Workspace e Project. Ogni livello utilizza un proprio insieme di ruoli:

```
Account 
│
├── (admin)  - full access to all Workspaces, Projects, and Restricted Projects
│
└── (member)
        │
        ├── Workspace - (full_access | editor | edit_only | commenter | viewer)
        │       │
        │       └── Project - (full_access | editor | edit_only | commenter | viewer)
        │
        └── Restricted Project - (members require direct invite)
```

Ogni utente ha un ruolo nell’account. Tramite l’API puoi impostare il ruolo di un utente su <Tooltip tip="Nelle risposte dell’API potresti vedere i ruoli Owner e Reviewer, ma questi ruoli non sono configurabili tramite l’API. Maggiori dettagli sono disponibili nella sezione Autorizzazioni a livello di Account.">`admin` o `member`.</Tooltip>
Gli Account Admin hanno accesso completo a tutti i Workspace e Project. Gli Account Member possono essere aggiunti selettivamente ai Workspace e ai Project di cui hanno bisogno.

Quando aggiungi un Account Member a un Workspace, il livello di autorizzazione che assegni (`full_access`, `editor`, `edit_only`, `commenter` o `viewer`) si applica a tutti i Project esistenti e futuri al suo interno. Ad esempio, se aggiungi un Account Member come `viewer`, avrà autorizzazioni `viewer` ogni volta che accede a qualsiasi Project di quel Workspace.

Lo stesso Account Member può essere aggiunto a un Project specifico all’interno di quel Workspace come `editor`.  Di conseguenza, ogni volta che accede a quel Project avrà autorizzazioni `editor`. Le sue autorizzazioni `viewer` continuano ad applicarsi a tutti gli altri Project di quel Workspace.

Poiché le assegnazioni ai Project sono separate da quelle ai Workspace, se rimuovi quell’Account Member dal Workspace, manterrà le sue autorizzazioni `editor` per quel singolo Project.

I Restricted Project costituiscono l’eccezione. Gli Account Member richiedono sempre un invito diretto. Maggiori informazioni nella sezione Autorizzazioni a livello di Project più avanti.

## Autorizzazioni a livello di Account {#account-level-permissions}

Ogni utente del tuo Account ha un ruolo:

| Ruolo | Autorizzazioni | Configurabile tramite API | Endpoint |
| --- | --- | --- | --- |
| Owner | Accesso completo a tutti i Workspace e Project. Uno per account | No | — |
| <Tooltip tip="Etichettato 'Content Admin' nell’interfaccia">`admin`</Tooltip> | Accesso completo a tutti i Workspace e Project | Sì | `PATCH /accounts/:account_id/users/:user_id` |
| `member` | Autorizzazioni impostate a livello di Workspace e/o Project | Sì | `PATCH /accounts/:account_id/users/:user_id` |
| Reviewer | Accesso solo tramite link di condivisione. Creato quando un utente viene aggiunto a una condivisione protetta | <Tooltip tip="I Reviewer compaiono negli elenchi degli utenti dell’account perché si autenticano in Frame.io, ma sono esterni al sistema di autorizzazioni di Workspace e Project. Accedono ai contenuti solo tramite link di condivisione protetti.">No</Tooltip> | — |

---

Gli Account Admin hanno accesso completo ovunque. Per limitare l’accesso di un Admin a risorse specifiche, cambia prima il suo ruolo nell’account in Member, quindi aggiungilo ai Workspace o ai Project di cui ha bisogno.

Ad esempio:

<Steps>

<Step title="Elenca i ruoli degli utenti dell’account per trovare l’ID utente e confermarne il ruolo attuale:">

```bash

curl https://api.frame.io/v4/accounts/:account_id/users \
     -H "Authorization: Bearer <token>"
```

</Step>

<Step title="Aggiorna il ruolo nell’account in Member:">

```bash

curl -X PATCH https://api.frame.io/v4/accounts/:account_id/users/:user_id \
 -H "Authorization: Bearer <token>" \
 -H "Content-Type: application/json" \
 -d '{
"data": {
"role": "member"
}
}'
```

</Step>

<Step title="Aggiungilo a un Project:">

```bash

curl -X PATCH https://api.frame.io/v4/accounts/:account_id/projects/:project_id/users/:user_id \
  -H "Authorization: Bearer <token>" \
  -H "Content-Type: application/json" \
  -d '{
"data": {
 "role": "edit_only"
}
}'
```

</Step>

</Steps>

## Autorizzazioni a livello di Workspace {#workspace-level-permissions}

Quando aggiungi un Account Member a un Workspace, questi ottiene quel livello di autorizzazione su tutti i Project al suo interno. I Workspace sono accessibili solo su invito, quindi gli Account Member vedono solo i Workspace a cui sono stati aggiunti.

<br />

| Ruolo | Autorizzazioni |
| --- | --- |
| `full_access` | Caricare, gestire, condividere, commentare, visualizzare, scaricare, gestire le impostazioni e invitare utenti |
| `editor` | Caricare, gestire, condividere, commentare, visualizzare, scaricare |
| `edit_only` | Caricare, gestire, commentare, visualizzare. Non può condividere né scaricare |
| `commenter` | Visualizzare e commentare |
| `viewer` | Solo visualizzazione |

<br />

## Autorizzazioni a livello di Project {#project-level-permissions}

I Project utilizzano gli stessi livelli di autorizzazione dei Workspace. Aggiungi un utente direttamente a un Project quando ha bisogno di accedere solo a quel Project specifico, oppure quando necessita di un livello di autorizzazione diverso da quello assegnato nel Workspace. Gli utenti non hanno bisogno dell’accesso al Workspace per essere aggiunti a un Project.

<br />

| Ruolo | Autorizzazioni |
| --- | --- |
| `full_access` | Caricare, gestire, condividere, commentare, visualizzare, scaricare, gestire le impostazioni e invitare utenti |
| `editor` | Caricare, gestire, condividere, commentare, visualizzare, scaricare |
| `edit_only` | Caricare, gestire, commentare, visualizzare. Non può condividere né scaricare |
| `commenter` | Visualizzare e commentare |
| `viewer` | Solo visualizzazione |

<br />

**Esempio:  aggiungere un utente a un Project**

```bash

curl -X PATCH https://api.frame.io/v4/accounts/:account_id/projects/:project_id/users/:user_id \
     -H "Authorization: Bearer <token>" \
     -H "Content-Type: application/json" \
     -d '{
  "data": {
    "role": "full_access"
  }
}'
```

---

### Restricted Project {#restricted-projects}

I Restricted Project richiedono un invito diretto. L’accesso al Workspace non viene ereditato,
quindi gli utenti possono accedere a un Restricted Project solo se vi sono stati aggiunti direttamente.

Per concedere l’accesso a un Member, aggiungilo al Project con il livello di autorizzazione appropriato.

<Note>

Gli Account Admin e gli Owner costituiscono l’eccezione e hanno accesso a tutti
i Restricted Project.

</Note>
