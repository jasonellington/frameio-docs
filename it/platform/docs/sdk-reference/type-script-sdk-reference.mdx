### Installazione {#installation}

```bash
npm i -s frameio
```

---

### Utilizzo {#usage}

Crea un'istanza del client e usala come segue:

```typescript
import { FrameioClient } from "frameio";

const client = new FrameioClient({ token: "YOUR_TOKEN" });
await client.metadataFields.metadataFieldDefinitionsCreate("b2702c44-c6da-4bb6-8bbd-be6e547ccf1b", {
    data: {
        field_type: "select",
        field_configuration: {
            enable_add_new: false,
            options: [
                {
                    display_name: "Option 1",
                },
                {
                    display_name: "Option 2",
                },
            ],
        },
        name: "Fields definition name",
    },
});
```

---

### Tipi di richiesta e risposta {#request-and-response-types}

L'SDK esporta tutti i tipi di richiesta e risposta come interfacce TypeScript. È sufficiente importarli con il seguente namespace:

```typescript
import { Frameio } from "frameio";

const request: Frameio.UpdateFieldDefinitionParams = {
    ...
};
```

---

### Gestione delle eccezioni {#exception-handling}

Quando l'API restituisce un codice di stato di errore (risposta 4xx o 5xx), viene generata una sottoclasse del seguente errore.

```typescript
import { FrameioError } from "frameio";

try {
    await client.metadataFields.metadataFieldDefinitionsCreate(...);
} catch (err) {
    if (err instanceof FrameioError) {
        console.log(err.statusCode);
        console.log(err.message);
        console.log(err.body);
        console.log(err.rawResponse);
    }
}
```

### Avanzate {#advanced}

#### Header aggiuntivi {#additional-headers}

Se desideri inviare header aggiuntivi come parte della richiesta, usa l'opzione di richiesta headers.

```typescript
const response = await client.metadataFields.metadataFieldDefinitionsCreate(..., {
    headers: {
        'X-Custom-Header': 'custom value'
    }
});
```

#### Parametri aggiuntivi della query string {#additional-query-string-parameters}

Se desideri inviare parametri aggiuntivi della query string come parte della richiesta, usa l'opzione di richiesta queryParams.

```typescript
const response = await client.metadataFields.metadataFieldDefinitionsCreate(..., {
    queryParams: {
        'customQueryParamKey': 'custom query param value'
    }
});
```

---

#### Tentativi ripetuti {#retries}

L'SDK è dotato di tentativi ripetuti automatici con backoff esponenziale. Una richiesta viene ripetuta finché è considerata ripetibile e il numero di tentativi non ha superato il limite configurato (valore predefinito: 2).

Una richiesta è considerata ripetibile quando viene restituito uno dei seguenti codici di stato HTTP:

- 408 (Timeout)
- 429 (Troppe richieste)
- 5XX (Errori interni del server)

<br />

Usa l'opzione di richiesta `maxRetries` per configurare questo comportamento.

```typescript
const response = await client.metadataFields.metadataFieldDefinitionsCreate(..., {
    maxRetries: 0 // override maxRetries at the request level
});
```

---

#### Timeout {#timeouts}

Per impostazione predefinita, l'SDK usa un timeout di 60 secondi. Usa l'opzione timeoutInSeconds per configurare questo comportamento.

```typescript
const response = await client.metadataFields.metadataFieldDefinitionsCreate(..., {
    timeoutInSeconds: 30 // override timeout to 30s
});
```

#### Annullamento delle richieste {#aborting-requests}

L'SDK consente agli utenti di annullare le richieste in qualsiasi momento passando un segnale di annullamento.

```typescript
const controller = new AbortController();
const response = await client.metadataFields.metadataFieldDefinitionsCreate(..., {
    abortSignal: controller.signal
});
controller.abort(); // aborts the request
```

---

#### Accesso ai dati grezzi della risposta {#access-raw-response-data}

L'SDK fornisce accesso ai dati grezzi della risposta, inclusi gli header, tramite il metodo `.withRawResponse()`. Il metodo `.withRawResponse()` restituisce una promise che si risolve in un oggetto con le proprietà `data` e `rawResponse`.

```typescript
const { data, rawResponse } = await client.metadataFields.metadataFieldDefinitionsCreate(...).withRawResponse();

console.log(data);
console.log(rawResponse.headers['X-My-Header']);
```

#### Compatibilità con i runtime {#runtime-compatibility}

L'SDK funziona nei seguenti runtime:

- Node.js 18+
- Vercel
- Cloudflare Workers
- Deno v1.25+
- Bun 1.0+
- React Native

#### Personalizzazione del client Fetch {#customizing-fetch-client}

L'SDK ti consente di personalizzare il client HTTP / la funzione Fetch sottostante. Se lavori in un ambiente non supportato, questa è una soluzione di emergenza per garantire il funzionamento dell'SDK.

```typescript
import { FrameioClient } from "frameio";

const client = new FrameioClient({
    ...
    fetcher: // provide your implementation here
});
```

#### Autenticazione {#auth}

<AccordionGroup>

<Accordion title="new ServerToServerAuth({ clientId, clientSecret, ... })">

Esegue l'autenticazione tramite il grant OAuth 2.0 `client_credentials`. Questo flusso non coinvolge un utente e non restituisce un refresh token. Quando il token di accesso scade, l'SDK ne richiede automaticamente uno nuovo usando le credenziali del client.

```typescript title="usage"
import { FrameioClient, ServerToServerAuth } from "frameio";

const auth = new ServerToServerAuth({
    clientId: "YOUR_CLIENT_ID",
    clientSecret: "YOUR_CLIENT_SECRET",
});
const client = new FrameioClient({ token: () => auth.getToken() });
```

**Parametri**

`clientId`: `string` — ID client OAuth di Adobe IMS.

`clientSecret`: `string` — Client secret OAuth di Adobe IMS.

`scopes`: `string` — Ambiti separati da spazi (OAuth 2.0 RFC 6749). Valore predefinito: gli ambiti server-to-server.

`imsBaseUrl`: `string` — URL di base di IMS per ambienti di staging o alternativi. Valore predefinito: produzione.

`fetch`: `typeof fetch` — Implementazione personalizzata di fetch (per proxy, TLS e così via).

`onTokenRefreshed`: `OnTokenRefreshed` — Callback facoltativa attivata dopo ogni recupero del token.

`timeout`: `number` — Timeout delle richieste HTTP in millisecondi. Valore predefinito: 30000.

`maxRetries`: `number` — Numero massimo di tentativi ripetuti in caso di errori temporanei. Valore predefinito: 2.

`refreshBuffer`: `number` — Secondi prima della scadenza in cui attivare un aggiornamento proattivo. Valore predefinito: 60.

`logger`: `Logger` — Istanza del logger per l'output diagnostico.

**Metodi**

`getToken(): Promise<string>` — Restituisce un token di accesso valido, aggiornandolo se necessario. Passalo al client: `new FrameioClient({ token: () => auth.getToken() })`.

`authenticate(): Promise<TokenResponse>` — Recupera esplicitamente un nuovo token di accesso.

`revoke(): Promise<void>` — Revoca i token lato server e cancella lo stato locale.

`exportTokens(): ExportedTokens` — Esporta lo stato corrente dei token per renderlo persistente.

`importTokens(data: ExportedTokens): void` — Ripristina lo stato dei token da un oggetto esportato in precedenza.

</Accordion>

<Accordion title="new WebAppAuth({ clientId, clientSecret, redirectUri, ... })">

Esegue l'autenticazione tramite il grant OAuth 2.0 `authorization_code`. Usalo per applicazioni lato server in grado di memorizzare in modo sicuro un client secret.

```typescript title="usage"
import { randomBytes } from "crypto";
import { FrameioClient, WebAppAuth } from "frameio";

const auth = new WebAppAuth({
    clientId: "YOUR_CLIENT_ID",
    clientSecret: "YOUR_CLIENT_SECRET",
    redirectUri: "https://myapp.com/callback",
});
const url = auth.getAuthorizationUrl({ state: randomBytes(24).toString("hex") });
// redirect the user to url ...
await auth.exchangeCode("CODE_FROM_CALLBACK");
const client = new FrameioClient({ token: () => auth.getToken() });
```

**Parametri**

`clientId`: `string` — ID client OAuth di Adobe IMS.

`clientSecret`: `string` — Client secret OAuth di Adobe IMS.

`redirectUri`: `string` — URI di reindirizzamento registrato.

`scopes`: `string` — Ambiti separati da spazi (OAuth 2.0 RFC 6749).

`imsBaseUrl`: `string` — URL di base di IMS per ambienti di staging o alternativi. Valore predefinito: produzione.

`fetch`: `typeof fetch` — Implementazione personalizzata di fetch (per proxy, TLS e così via).

`onTokenRefreshed`: `OnTokenRefreshed` — Callback facoltativa attivata dopo ogni aggiornamento del token.

`timeout`: `number` — Timeout delle richieste HTTP in millisecondi. Valore predefinito: 30000.

`maxRetries`: `number` — Numero massimo di tentativi ripetuti in caso di errori temporanei. Valore predefinito: 2.

`refreshBuffer`: `number` — Secondi prima della scadenza in cui attivare un aggiornamento proattivo. Valore predefinito: 60.

`logger`: `Logger` — Istanza del logger per l'output diagnostico.

**Metodi**

`getToken(): Promise<string>` — Restituisce un token di accesso valido, aggiornandolo se necessario.

`getAuthorizationUrl({ state }): string` — Crea l'URL di autorizzazione di Adobe IMS. Passa un valore CSRF/state opaco che verrà restituito.

`exchangeCode(code: string): Promise<TokenResponse>` — Scambia un codice di autorizzazione con access token e refresh token.

`refresh(): Promise<TokenResponse>` — Attiva manualmente un aggiornamento del token.

`revoke(): Promise<void>` — Revoca i token lato server e cancella lo stato locale.

`exportTokens(): ExportedTokens` — Esporta lo stato corrente dei token per renderlo persistente.

`importTokens(data: ExportedTokens): void` — Ripristina lo stato dei token da un oggetto esportato in precedenza.

</Accordion>

<Accordion title="new SPAAuth({ clientId, redirectUri, ... })">

Esegue l'autenticazione tramite `authorization_code` + PKCE (senza client secret). Usalo per single-page app basate su browser che non possono memorizzare in modo sicuro un client secret.

```typescript title="usage"
import { randomBytes } from "crypto";
import { FrameioClient, SPAAuth } from "frameio";

const auth = new SPAAuth({
    clientId: "YOUR_CLIENT_ID",
    redirectUri: "https://myapp.com/cb",
});
const result = await auth.getAuthorizationUrl({ state: randomBytes(24).toString("hex") });
// redirect the user to result.url, store result.codeVerifier ...
await auth.exchangeCode({ code: "CODE_FROM_CALLBACK", codeVerifier: result.codeVerifier });
const client = new FrameioClient({ token: () => auth.getToken() });
```

**Parametri**

`clientId`: `string` — ID client OAuth di Adobe IMS.

`redirectUri`: `string` — URI di reindirizzamento registrato.

`scopes`: `string` — Ambiti separati da spazi (OAuth 2.0 RFC 6749).

`imsBaseUrl`: `string` — URL di base di IMS per ambienti di staging o alternativi. Valore predefinito: produzione.

`fetch`: `typeof fetch` — Implementazione personalizzata di fetch (per proxy, TLS e così via).

`onTokenRefreshed`: `OnTokenRefreshed` — Callback facoltativa attivata dopo ogni aggiornamento del token.

`timeout`: `number` — Timeout delle richieste HTTP in millisecondi. Valore predefinito: 30000.

`maxRetries`: `number` — Numero massimo di tentativi ripetuti in caso di errori temporanei. Valore predefinito: 2.

`refreshBuffer`: `number` — Secondi prima della scadenza in cui attivare un aggiornamento proattivo. Valore predefinito: 60.

`logger`: `Logger` — Istanza del logger per l'output diagnostico.

**Metodi**

`getToken(): Promise<string>` — Restituisce un token di accesso valido, aggiornandolo se necessario.

`getAuthorizationUrl({ state }): Promise<AuthorizationUrlResult>` — Crea l'URL di autorizzazione di Adobe IMS con una challenge PKCE. Restituisce un `AuthorizationUrlResult` con `url` e `codeVerifier`.

`exchangeCode({ code, codeVerifier }): Promise<TokenResponse>` — Scambia un codice di autorizzazione + un verifier PKCE con i token.

`refresh(): Promise<TokenResponse>` — Attiva manualmente un aggiornamento del token.

`revoke(): Promise<void>` — Revoca i token lato server e cancella lo stato locale.

`exportTokens(): ExportedTokens` — Esporta lo stato corrente dei token per renderlo persistente.

`importTokens(data: ExportedTokens): void` — Ripristina lo stato dei token da un oggetto esportato in precedenza.

</Accordion>

<Accordion title="new NativeAppAuth({ clientId, redirectUri, ... })">

Esegue l'autenticazione tramite `authorization_code` + PKCE per applicazioni desktop e mobili. Condivide la stessa API di `SPAAuth`; usa un URI di reindirizzamento con schema personalizzato (ad es. `myapp://callback`).

```typescript title="usage"

    clientId: "YOUR_CLIENT_ID",
    redirectUri: "myapp://callback",
});
const result = await auth.getAuthorizationUrl({ state: randomBytes(24).toString("hex") });
// open result.url in the system browser, store result.codeVerifier ...
await auth.exchangeCode({ code: "CODE_FROM_CALLBACK", codeVerifier: result.codeVerifier });
const client = new FrameioClient({ token: () => auth.getToken() });
```

**Parametri**

`clientId`: `string` — ID client OAuth di Adobe IMS.

`redirectUri`: `string` — URI di reindirizzamento registrato (sono supportati schemi personalizzati).

`scopes`: `string` — Ambiti separati da spazi (OAuth 2.0 RFC 6749).

`imsBaseUrl`: `string` — URL di base di IMS per ambienti di staging o alternativi. Valore predefinito: produzione.

`fetch`: `typeof fetch` — Implementazione personalizzata di fetch (per proxy, TLS e così via).

`onTokenRefreshed`: `OnTokenRefreshed` — Callback facoltativa attivata dopo ogni aggiornamento del token.

`timeout`: `number` — Timeout delle richieste HTTP in millisecondi. Valore predefinito: 30000.

`maxRetries`: `number` — Numero massimo di tentativi ripetuti in caso di errori temporanei. Valore predefinito: 2.

`refreshBuffer`: `number` — Secondi prima della scadenza in cui attivare un aggiornamento proattivo. Valore predefinito: 60.

`logger`: `Logger` — Istanza del logger per l'output diagnostico.

**Metodi**

Come per `SPAAuth`: `getToken()`, `getAuthorizationUrl({ state })`, `exchangeCode({ code, codeVerifier })`, `refresh()`, `revoke()`, `exportTokens()`, `importTokens(data)`.

</Accordion>

<Accordion title="AuthorizationUrlResult">

Oggetto restituito da `SPAAuth.getAuthorizationUrl()` e `NativeAppAuth.getAuthorizationUrl()`. Contiene l'URL di autorizzazione e il code verifier PKCE.

**Proprietà**

#### Eccezioni di autenticazione {#auth-exceptions}

Tutti gli errori di autenticazione estendono `FrameioAuthError` e possono essere importati da `frameio`.

| Eccezione | Descrizione |
| --- | --- |
| `FrameioAuthError` | Errore di base per tutti gli errori dell'SDK di autenticazione. |
| `AuthenticationError` | Lo scambio o l'aggiornamento del token non è riuscito. Ha le proprietà `errorCode` ed `errorDescription`. |
| `TokenExpiredError` | Il refresh token è scaduto; è necessario autenticarsi di nuovo. |
| `NetworkError` | Una richiesta di rete non è riuscita (timeout, errore di connessione e così via). |
| `RateLimitError` | Adobe IMS ha restituito 429 e i tentativi ripetuti sono esauriti. Ha una proprietà `retryAfter`. |
| `PKCEError` | La verifica PKCE non è riuscita. |
| `ConfigurationError` | La configurazione richiesta è mancante o non valida. |
