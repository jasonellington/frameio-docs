## Was ist die Camera to Cloud API? {#what-is-the-camera-to-cloud-api}

Die Camera to Cloud (C2C) API bietet eine sichere Methode, um Medien direkt nach Abschluss der Aufnahme ohne weitere Benutzereingaben an Frame.io zu übertragen. Bei Frame.io ist es unser Ziel, Medien zur Prüfung und Zusammenarbeit bereitzustellen, sobald die Aufnahme stoppt oder Metadaten eingegeben werden.

Während der Entwicklung haben wir festgestellt, dass die C2C API als eigenes, spezialisiertes Backend-System getrennt vom Hauptökosystem von Frame.io funktionieren muss, um Integratoren und Benutzern die bestmögliche Erfahrung zu bieten. Auch wenn diese Architekturentscheidung zunächst nicht intuitiv erscheinen mag, erläutert dieses Dokument unsere Überlegungen anhand der Leitprinzipien hinter C2C.

## Mehr als nur Kameramaterial {#beyond-camera-footage}

Obwohl die API aus Gründen der Klarheit und Wiedererkennbarkeit „Camera to Cloud“ heißt, gehen ihre Fähigkeiten über Kameramaterial hinaus. Die C2C API verarbeitet viele Arten digitaler Inhalte. Ob Ihr Gerät Audio, Video, PDFs oder andere Dateitypen erzeugt – Frame.io kann sie alle aufnehmen. Die API vereinfacht die Übertragung jedes digitalen Assets von der Erstellung bis zum Cloud-Speicher mit minimalem Aufwand.

## Schreiben, aber nicht lesen {#write-but-don’t-read}

Frame.io hält hohe Sicherheitsstandards ein, und die Anbindung von Geräten bringt potenzielle Sicherheitsaspekte mit sich. Vielen Geräten zur Medienaufnahme fehlen herkömmliche Sicherheitsfunktionen wie Passwörter oder Bildschirmsperren, da sie ursprünglich nicht für eine Netzwerkverbindung konzipiert wurden. Würde man diesen Geräten vollen Zugriff auf die Frame.io API gewähren, könnten unbeaufsichtigte Geräte Sicherheitslücken verursachen.

Zudem benötigen Gerätebediener häufig nur Zugriff auf bestimmte Elemente statt auf das gesamte Projekt. Ihre Rolle beschränkt sich möglicherweise auf das Erstellen bestimmter Medien-Assets, nicht auf die Verwaltung des gesamten Projekts.

Daraus ergab sich unser zentrales Designprinzip: Aufnahmegeräte dienen in erster Linie dazu, Medien zu erstellen – nicht dazu, Inhalte aus anderen Quellen zu prüfen oder zu kommentieren. Der beste Sicherheitsansatz bestand darin, eine API zu entwickeln, die gezielt auf ihre wesentliche Funktion beschränkt ist: das Hochladen von Daten in die Cloud. Durch den vollständigen Verzicht auf Lesefunktionen haben wir unbefugten Zugriff auf sensible Projektinformationen wirksam verhindert.

## Design für Geräte mit eingeschränkten Benutzeroberflächen {#designing-for-devices-with-limited-interfaces}

Die bestehenden APIs von Frame.io wurden unter der Annahme entwickelt, dass sie mit Anwendungen mit grafischer Benutzeroberfläche interagieren. Diese Anwendungen konnten Benutzern Optionen anzeigen, deren Auswahl dann an den Server gesendet wurde.

Das C2C-Ökosystem umfasst jedoch physische Geräte mit eingeschränkter oder gar keiner GUI und möglicherweise ohne Mechanismen für Benutzereingaben. Dies erforderte einen grundlegend anderen Ansatz für die Benutzerinteraktion.

Bei der Entwicklung von C2C mussten wir ein System schaffen, das auf Geräten mit eingeschränkten Oberflächen effektiv funktioniert. Das bedeutete, ein Interaktionsmodell zu entwickeln, das keine Benutzereingaben am Gerät selbst erfordert, da solche Eingaben in vielen Fällen unmöglich sein können.

Diese Einschränkung schloss die Verwendung unserer bestehenden API-Architektur aus, die auf webbasierten Authentifizierungsabläufen und der Auswahl von Zielordnern durch den Benutzer beruhte. Wir mussten nicht nur die Aktionen vereinfachen, die ein Gerät ausführen kann, sondern auch die gesamte Benutzererfahrung rund um diese Aktionen.

## Berücksichtigung unterbrochener Konnektivität {#accommodating-intermittent-connectivity}

Neben den Einschränkungen der Benutzeroberfläche arbeiten viele Geräte im C2C-Ökosystem in Umgebungen mit unvorhersehbarer Netzwerkverbindung. Wir haben unsere API so konzipiert, dass die Kommunikation mit dem Backend minimiert und die Anzahl der im Betrieb notwendigen Aufrufe reduziert wird, um Profis, die an abgelegenen Orten mit eingeschränktem WLAN oder Mobilfunk arbeiten, eine zuverlässige Erfahrung zu bieten.

## Vereinfachte Integration {#simplifying-integration}

Unsere Priorität war es, die Integration so einfach wie möglich zu gestalten. Wir haben eine fokussierte API mit einer minimalen Anzahl von Endpunkten, geringen Anforderungen an die Serveraushandlung und einem eng definierten, auf unsere Ziele abgestimmten Umfang entwickelt. Uns ist bewusst, dass dies für manche Integratoren die erste Implementierung von Netzwerkaufrufen an Drittanbieter sein könnte. Ob Sie ein erfahrener Entwickler sind, der eine effiziente Implementierung sucht, oder neu bei REST-APIs – wir haben die Erfahrung zugänglich und unkompliziert gestaltet.
