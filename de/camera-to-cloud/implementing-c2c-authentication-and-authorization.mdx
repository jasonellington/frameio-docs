## Einführung {#introduction}

Diese Anleitung zeigt den Authentifizierungs- und Autorisierungsprozess für Camera to Cloud (C2C)-Geräte in einem Frame.io-Projekt. Wir betrachten sowohl die Standardmethode mit manueller Codeeingabe als auch den erweiterten Ansatz der Kopplung per QR-Code für eine optimale Benutzererfahrung.

## Was benötige ich? {#what-will-i-need}

Falls noch nicht geschehen, lesen Sie bitte die Anleitung [Bevor wir mit der Implementierung beginnen](/de/camera-to-cloud/implementing-c2c-setting-up).

Sie sollten von unserem Team ein `client_secret` zur Identifizierung Ihrer Integration erhalten haben. Falls nicht, lesen Sie bitte [diese Einführung](/de/camera-to-cloud/getting-started-with-cloud-device-integrations) in das C2C-Ökosystem und wenden Sie sich an unser Team.

### Voraussetzungen für die Kopplung per URL und QR-Code {#prerequisites-for-url-&-qr-code-pairing}

Um die Kopplung per URL und QR-Code zu implementieren, müssen Sie folgende Anforderungen erfüllen:

- **Gerätekompatibilität**: Vergewissern Sie sich, dass Ihr Gerät die Generierung von URLs/QR-Codes während des Kopplungsvorgangs unterstützt.

## Den Authentifizierungsablauf durchgehen {#walking-through-the-auth-flow}

Um den Autorisierungsablauf aus Sicht des Benutzers zu verstehen, nutzen Sie bitte diese Ressourcen:

- [Support-Artikel](https://help.frame.io/en/collections/8960335-frame-io-c2c) zum Hinzufügen neuer Geräte.
- [Schulungsvideo](https://help.frame.io/en/articles/5091124-camera-to-cloud-training-series) zur Autorisierung eines Teradek Cube.

Dieser Autorisierungsprozess minimiert den Implementierungsaufwand. Sie müssen nicht:

- Zu Webbrowsern weiterleiten (außer bei Verwendung der Kopplung per URL-Code)
- Die Benutzerauthentifizierung von Frame.io handhaben
- Oberflächen zur Konto- oder Projektauswahl bereitstellen
- Komplexe UI-Komponenten über einfache Informationsanzeigen hinaus entwickeln

### Die Benutzererfahrung mit der Kopplung per URL-Code verbessern {#enhancing-the-user-experience-with-url-code-pairing}

Moderne Benutzer erwarten effiziente Interaktionen mit Geräten. Der aktuelle manuelle Kopplungsprozess funktioniert zwar zufriedenstellend, lässt sich aber optimieren.

Durch die Implementierung der Kopplung per URL und QR-Code – ähnlich wie bei Streamingdiensten wie Netflix oder Disney+ – können wir den Prozess erheblich vereinfachen, Eingabefehler minimieren und die Kopplungszeit verkürzen.

## Geräteidentifizierung (client_id) {#device-identification-client_id}

Jedes physische Gerät benötigt eine eindeutige Kennung, damit Verbindungen innerhalb des Projekts eines Benutzers nachverfolgt werden können.

Bei Geräten ist diese Kennung die `client_id`, die bei der Autorisierung unerlässlich ist. Ziehen Sie bei der Implementierung geeignete Quellen für die Kennung in Betracht, etwa Seriennummern des Geräts, UUIDs oder andere eindeutige Zeichenfolgen. Wenn Sie auf einem Apple-Gerät integrieren, empfehlen wir eine eindeutige, persistente UUID, die über Neustarts des Geräts hinweg gleich bleibt.

Seien Sie vorsichtig mit personenbezogenen Daten. E-Mail-Adressen von Benutzern sind keine geeigneten Werte für die `client_id`.

Stellen Sie außerdem sicher, dass Sie die Kontrolle über die Kennung haben. MAC-Adressen von Geräten sind ungeeignet, da sie nicht Ihrer Software gehören und personenbezogene Daten darstellen können.

Wenn Sie Unterstützung bei der Auswahl einer geeigneten Kennung benötigen, kann Ihnen unser Team helfen, einen passenden Wert zu finden, der die Integration vereinfacht.

## Schritt 1: Einen Gerätecode anfordern {#step-1-requesting-a-device-code}

Fordern Sie zu Beginn der Implementierung über den Endpunkt `/v2/auth/device/code` einen Gerätecode an:

### Herkömmliche Kopplungsmethode {#traditional-pairing-method}

```
curl -X POST https://api.frame.io/v2/auth/device/code \
    --form 'client_id=[client_id]' \
    --form 'client_secret=[client_secret]' \
    --form 'scope=asset_create offline' \
    | python -m json.tool
```

### Kopplung per URL-Code aktivieren {#enabling-url-code-pairing}

Ergänzen Sie für die Kopplung per URL-Code den API-Aufruf um zusätzliche Header:

```
curl -X POST https://api.frame.io/v2/auth/device/code \
    --header "x-client-version: 2.0.0" \
    --header "x-client-platypus-enabled: true" \  # New header to enable URL pairing
    --form 'client_id=[client_id]' \
    --form 'client_secret=[client_secret]' \
    --form 'scope=asset_create offline' \
    | python -m json.tool
```

**Hinweis:** Diese Authentifizierungsendpunkte akzeptieren ausschließlich Formulardaten, kein JSON. Nach der Authentifizierung akzeptieren andere Endpunkte JSON-Payloads, die Authentifizierungsendpunkte lehnen JSON-Anfragen jedoch ab.

#### Payload-Parameter {#payload-parameters}

- **client_id**: Die eindeutige Kennung Ihres physischen Geräts. Sie muss garantiert eindeutig sein, etwa eine Seriennummer oder UUID.

- **client_secret**: Wird vom Frame.io-Support bereitgestellt, um Ihr Gerätemodell zu identifizieren. Dieser vertrauliche Wert sollte vor Benutzern geschützt und verschlüsselt gespeichert werden.

- **scope**: Die angeforderten Berechtigungen, durch Leerzeichen getrennt. Geräte können Folgendes anfordern:

  - `asset_create`: Ermöglicht das Erstellen und Hochladen von Assets.
  - `offline`: Erlaubt das Aktualisieren der Autorisierung per Refresh-Token. Ohne diesen Scope müssten Benutzer ihr Gerät alle 8 Stunden erneut autorisieren, da Autorisierungstokens ablaufen.

In der Praxis fordern Geräte in der Regel beide Scopes an.

### Die API-Antwort verstehen {#understanding-the-api-response}

Die Anfrage erzeugt eine Antwort ähnlich der folgenden:

#### Antwort bei herkömmlicher Kopplung {#traditional-pairing-response}

```
{
  "device_code": "[device_code]",
  "expires_in": 120,
  "interval": 5,
  "name": "MyDevice-[client_id]",
  "user_code": "573131"
}
```

#### Antwort bei Kopplung per URL {#url-pairing-response}

```
{
  "device_code": "[device_code]",
  "expires_in": 120,
  "interval": 5,
  "name": "MyDevice-[client_id]",
  "user_code": "573131",
  "verification_uri": "https://next.frame.io/pair",
  "verification_uri_complete": "https://next.frame.io/pair/573131"
}
```

#### Aufschlüsselung der Antwort {#response-breakdown}

- **device_code**: Diese interne Kennung sollte vor Benutzern verborgen bleiben und identifiziert die Autorisierungsanfrage beim Polling.
- **expires_in**: Die Gültigkeitsdauer des Codes in Sekunden.
- **interval**: Das empfohlene Polling-Intervall in Sekunden.
- **name**: Die Kennung des sich verbindenden Geräts.
- **user_code**: Der sechsstellige Code zur manuellen Eingabe in Frame.io für die Gerätekopplung.
- **verification_uri**: Die Basis-URL für die manuelle Eingabe, falls das Scannen eines QR-Codes nicht möglich ist.
- **verification_uri_complete**: Die vollständige URL mit dem Kopplungscode, gedacht zur Verlinkung in einer mobilen App oder zur Generierung eines QR-Codes, um Benutzer schneller zur Kopplungsoberfläche zu führen.

### Den QR-Code für den Benutzer anzeigen {#displaying-the-qr-code-to-the-user}

Generieren Sie mithilfe von `verification_uri_complete` einen QR-Code und zeigen Sie ihn auf dem Gerätebildschirm an, damit der Benutzer ihn scannen kann und die Kopplung effizient erfolgt.

#### Beispiel: Gerätebildschirm mit angezeigtem QR-Code {#example-device-screen-with-qr-code-displayed}

![Beispiel für einen Bildschirm zur Gerätekopplung per QR-Code](/images/camera-to-cloud/implementing-c2c-authentication-and-authorization/193d938af906dbcbc9699953e9da5ddbeeee8cd75fdfabf0661127c2b528cdb4.webp)

Bieten Sie immer Ausweichoptionen an: Zeigen Sie `user_code` und `verification_uri` zur manuellen Eingabe an, wenn das Scannen eines QR-Codes nicht möglich ist. Alternativ können Sie die `verification_uri` als statischen QR-Code zum Scannen mit Mobilgeräten anzeigen.

Bei Integrationen in mobile Apps sollten Sie `verification_uri_complete` als antippbaren Hyperlink einbinden, da Benutzer QR-Codes nicht auf dem Gerät scannen können, auf dem die App läuft.

## Schritt 2: Per Polling auf die Benutzerautorisierung warten {#step-2-polling-for-user-authorization}

Nachdem Sie den Kopplungscode oder URL-Code bereitgestellt haben, prüfen Sie mit dieser Anfrage, ob der Benutzer ihn eingegeben hat:

```
curl -X POST https://api.frame.io/v2/auth/token \
    --form 'client_id=[client_id]' \
    --form 'device_code=[device_code]' \
    --form 'grant_type=urn:ietf:params:oauth:grant-type:device_code' \
    | python -m json.tool
```

### Payload-Parameter {#payload-parameters-1}

- **client_id**: Dieselbe Kennung wie in Schritt 1.
- **device_code**: Der zuvor zurückgegebene Wert `device_code`.
- **grant_type**: Die Kennung des OAuth-Grant-Typs, für diese Implementierung stets `urn:ietf:params:oauth:grant-type:device_code`.

Erste Polling-Versuche geben in der Regel Folgendes zurück:

```
{
  "error": "authorization_pending"
}
```

Dieser nicht schwerwiegende Fehler zeigt an, dass der Benutzer die Codeeingabe noch nicht abgeschlossen hat. Setzen Sie das Polling fort, bis sie abgeschlossen ist.

> **Hinweis für Geräte mit iOS-Apps:** Wenn der Benutzer zur Frame.io-iOS-App wechselt, um den Kopplungscode einzugeben, wird Ihre App möglicherweise in den Hintergrund verschoben. Sobald Ihre App wieder aktiv wird, etwa in `applicationDidBecomeActive`, setzen Sie das Polling fort, damit der Autorisierungsablauf weiterlaufen kann, ohne dass der Benutzer die Kopplung neu starten muss.

Wenn Sie Folgendes erhalten:

```
{
  "error": "expired_token"
}
```

Der Code ist abgelaufen, bevor der Benutzer ihn eingegeben hat. Generieren Sie über Schritt 1 einen neuen Code/QR-Code, zeigen Sie ihn dem Benutzer an und setzen Sie das Polling fort.

Eine erfolgreiche Autorisierung liefert:

```
{
  "access_token": "[access_token]",
  "expires_in": 28800,
  "refresh_token": "[refresh_token]",
  "token_type": "bearer"
}
```

Herzlichen Glückwunsch zur erfolgreichen Autorisierung Ihres Camera to Cloud-Geräts!

Sehen wir uns diese Antwort genauer an:

- **access_token**: Ihre Authentifizierungsberechtigung für den Zugriff auf das Frame.io-Backend, die in den Headern künftiger API-Anfragen erforderlich ist.
- **expires_in**: Die Gültigkeitsdauer des Zugriffstokens in Sekunden, nach deren Ablauf eine Aktualisierung erforderlich ist.
- **refresh_token**: Wird zur Verwaltung des Zugriffstokens verwendet, hauptsächlich zum Aktualisieren der Autorisierung, aber auch zum Widerrufen.
- **token_type**: Bei Implementierungen der C2C API stets `bearer`; es ist keine Aktion erforderlich.

## Die Schritte zusammenführen {#putting-the-steps-together}

Implementieren wir diese API-Aufrufe nun in Python-ähnlichem Pseudocode und behandeln dabei auch einen möglichen Ablauf des Gerätecodes:

```python title="Python"
def authorize_with_frame():
    """
    Handles authorizing our device with Frame.io.
    """

    # Our client ID can be a serial number, UUID, or some other unique string.
    client_id = THIS_DEVICE.get_serial_number()

    while True:
        # Make the call to Frame.io to get our device codes.
        pairing_codes = c2c.get_device_codes(client_id)

        # We need to keep track of how long we have been polling for
        polling_started = datetime.now()

        # Now we are going to poll for authorization until the user enters the code.
        while True:

            # Re-write this output each time we poll. Note: This message will only update once
            # per `interval` (e.g., 5 seconds), so if a smooth countdown is desired, that will
            # need a different implementation.
            print(
                f"\rPAIRING CODE: {pairing_codes.user_code}, "
                f"EXPIRES IN: {pairing_codes.expires_in - (datetime.now() - polling_started).seconds} seconds"
            )

            # Wait for `interval` before polling each time.
            sleep(pairing_codes.interval)

            # Make a call to Frame.io to see if the user has entered the code and authorized
            # the device.
            authorization, error = c2c.poll_for_authorization(
                client_id, pairing_codes.device_code
            )

            if error and error.message == "authorization_pending":
                # If the authorization is pending, try again.
                continue
            elif error and error.message == "expired_token":
                # If the pairing codes have expired, break to generate new codes.
                break
            elif error:
                # If there was some other error, raise it.
                raise error
            else:
                # If there was no error, we have our authorization!
                return authorization

        # If we get here, our pairing codes expired. Let's try again.
        print("\nPairing code expired. Generating a new one...")
```

**Hinweis:** Die äußere Schleife behandelt Fälle, in denen Kopplungscodes ablaufen und neue Codes benötigt werden.

Rufen Sie als letzten Schritt Projektinformationen von Frame.io ab und zeigen Sie sie an, um die erfolgreiche Kopplung mit dem gewünschten Projekt zu bestätigen. Darauf gehen wir im nächsten Tutorial ein.

## QR-Codes für die Kopplung erstellen und anzeigen {#creating-and-displaying-qr-codes-for-pairing}

Bei der Implementierung der Kopplung per URL/QR-Code müssen Sie aus dem Wert `verification_uri_complete` in der Antwort einen QR-Code generieren. Hier sind Beispiele mit beliebten Bibliotheken in verschiedenen Programmiersprachen:

### Python-Beispiel mit qrcode {#python-example-using-qrcode}

```python title="Python"
import qrcode
from PIL import Image
import io

def generate_qr_code(verification_uri_complete, size=250):
    """
    Generate a QR code from the verification_uri_complete URL.
    
    Args:
        verification_uri_complete (str): The complete verification URI returned by Frame.io
        size (int, optional): Size of the QR code in pixels. Defaults to 250.
    
    Returns:
        PIL.Image: QR code image that can be displayed or saved
    """
    qr = qrcode.QRCode(
        version=1,
        error_correction=qrcode.constants.ERROR_CORRECT_L,
        box_size=10,
        border=4,
    )
    qr.add_data(verification_uri_complete)
    qr.make(fit=True)
    
    img = qr.make_image(fill_color="black", back_color="white")
    
    # Resize the image if needed
    img = img.resize((size, size))
    return img

# Example usage in authorization flow
def display_qr_for_pairing(pairing_codes):
    """
    Generate and display QR code along with manual pairing instructions.
    """
    if hasattr(pairing_codes, 'verification_uri_complete'):
        # Generate QR code from the verification URI
        qr_img = generate_qr_code(pairing_codes.verification_uri_complete)
        
        # Display the QR code on screen
        # For GUI applications like Tkinter, PyQt, etc.
        # display_image(qr_img)
        
        # For headless devices or testing, save to file
        qr_img.save("frame_io_pairing_qr.png")
        
        print(f"Scan the QR code or visit: {pairing_codes.verification_uri}")
        print(f"Manual code: {pairing_codes.user_code}")
    else:
        # Fallback for devices that received traditional pairing response
        print(f"Enter code on Frame.io: {pairing_codes.user_code}")
```

### JavaScript-Beispiel (Web oder Electron) {#javascript-example-web-or-electron}

```javascript
import QRCode from 'qrcode';

/**
 * Generate and display a QR code from the verification URI
 * @param {string} verificationUriComplete - The complete verification URI from Frame.io
 * @param {string} elementId - ID of the HTML element to display the QR code in
 */
function displayQRCode(verificationUriComplete, elementId = 'qrcode-container') {
  const element = document.getElementById(elementId);
  
  if (!element) {
    console.error(`Element with ID ${elementId} not found`);
    return;
  }
  
  // Clear any existing content
  element.innerHTML = '';
  
  // Generate QR code
  QRCode.toCanvas(element, verificationUriComplete, { width: 250 }, function(error) {
    if (error) {
      console.error('Error generating QR code:', error);
      // Fallback to displaying the URL as a link
      element.innerHTML = `<a href="${verificationUriComplete}" target="_blank">Click here to pair</a>`;
    }
  });
  
  // Also display manual pairing information
  const manualInfoDiv = document.createElement('div');
  manualInfoDiv.innerHTML = `
    <p>Scan the QR code or <a href="${verificationUriComplete}" target="_blank">click here</a> to pair your device.</p>
    <p>Manual code: ${userCode}</p>
  `;
  element.parentNode.appendChild(manualInfoDiv);
}

// Example usage in authorization flow
async function requestDeviceCode() {
  try {
    const response = await fetch('https://api.frame.io/v2/auth/device/code', {
      method: 'POST',
      headers: {
        'x-client-version': '2.0.0',
        'x-client-platypus-enabled': 'true'
      },
      body: new URLSearchParams({
        'client_id': YOUR_CLIENT_ID,
        'client_secret': YOUR_CLIENT_SECRET,
        'scope': 'asset_create offline'
      })
    });
    
    const data = await response.json();
    
    if (data.verification_uri_complete) {
      displayQRCode(data.verification_uri_complete);
      window.userCode = data.user_code; // Store for display purposes
    } else {
      // Fallback for traditional pairing
      displayManualPairingCode(data.user_code);
    }
    
    // Begin polling for authorization
    beginPollingForAuthorization(data.device_code, data.interval);
    
  } catch (error) {
    console.error('Error requesting device code:', error);
  }
}
```

### Android-Beispiel (Java) {#android-example-java}

```java
import android.graphics.Bitmap;
import android.widget.ImageView;
import com.google.zxing.BarcodeFormat;
import com.google.zxing.MultiFormatWriter;
import com.google.zxing.common.BitMatrix;
import com.journeyapps.barcodescanner.BarcodeEncoder;

public void generateAndDisplayQRCode(String verificationUriComplete, ImageView qrCodeImageView) {
    try {
        MultiFormatWriter multiFormatWriter = new MultiFormatWriter();
        BitMatrix bitMatrix = multiFormatWriter.encode(verificationUriComplete, 
            BarcodeFormat.QR_CODE, 250, 250);
        BarcodeEncoder barcodeEncoder = new BarcodeEncoder();
        Bitmap bitmap = barcodeEncoder.createBitmap(bitMatrix);
        
        // Display in ImageView
        qrCodeImageView.setImageBitmap(bitmap);
        
    } catch (Exception e) {
        e.printStackTrace();
        // Fallback to displaying the URL as text
    }
}
```

### iOS-Beispiel (Swift) {#ios-example-swift}

```swift
import UIKit
import CoreImage

func generateQRCode(from string: String) -> UIImage? {
    let data = string.data(using: String.Encoding.utf8)
    
    if let filter = CIFilter(name: "CIQRCodeGenerator") {
        filter.setValue(data, forKey: "inputMessage")
        filter.setValue("H", forKey: "inputCorrectionLevel")
        
        if let outputImage = filter.outputImage {
            // Scale the image
            let transform = CGAffineTransform(scaleX: 10, y: 10)
            let scaledImage = outputImage.transformed(by: transform)
            
            // Convert to UIImage
            let context = CIContext()
            if let cgImage = context.createCGImage(scaledImage, from: scaledImage.extent) {
                return UIImage(cgImage: cgImage)
            }
        }
    }
    
    return nil
}

// Usage in your view controller
func displayPairingQRCode(verificationUriComplete: String) {
    if let qrCodeImage = generateQRCode(from: verificationUriComplete) {
        qrCodeImageView.image = qrCodeImage

        pairingCodeLabel.text = userCode
    } else {
        // Fallback to manual code display
        pairingInstructionsLabel.text = "Enter this code on Frame.io:"
        pairingCodeLabel.text = userCode
    }
}
```

## Best Practices für die Anzeige von QR-Codes {#best-practices-for-qr-code-display}

Beachten Sie bei der Implementierung der Kopplung per QR-Code diese Richtlinien für die beste Benutzererfahrung:

1. **Optimale Größe**: Zeigen Sie QR-Codes mit mindestens 200–250 Pixeln im Quadrat an, damit sie zuverlässig gescannt werden können.

2. **Kontrast**: Sorgen Sie für einen hohen Kontrast zwischen QR-Code und Hintergrund (schwarz auf weiß ist ideal).

3. **Fehlerkorrektur**: Verwenden Sie moderate Fehlerkorrekturstufen (L oder M), um Codedichte und Zuverlässigkeit auszubalancieren.

4. **Klare Anweisungen**: Geben Sie klare Hinweise zum Scannen des Codes, etwa „Scannen Sie diesen Code mit der Kamera Ihres Smartphones, um Ihr Gerät zu koppeln.“

5. **Mehrere Optionen**: Stellen Sie neben dem QR-Code immer auch den manuellen Kopplungscode als Ausweichlösung bereit:

   ```
   Scan to pair:
   [QR CODE]

   Or enter code manually: 573131
   ```

6. **Hyperlink für mobile Apps**: Wenn Ihre Integration eine mobile Anwendung ist, binden Sie `verification_uri_complete` als antippbaren Link ein, da Benutzer einen QR-Code nicht auf demselben Gerät scannen können.

7. **Tests**: Testen Sie Ihre QR-Codes mit verschiedenen Geräten und unter verschiedenen Lichtverhältnissen, um ein zuverlässiges Scannen sicherzustellen.

## Fehlerbehebung {#troubleshooting}

Wenn Probleme auftreten, sehen Sie sich diese häufigen Szenarien und Lösungen an:

- **Schaltfläche „Connect Device“ nicht sichtbar**: Wenn Sie das C2C-Verwaltungsfenster öffnen, kann dies auf Folgendes hinweisen:

  - **Unzureichende Berechtigungen**: Wenn Sie eine Meldung zu Berechtigungen sehen, wenden Sie sich an Ihren Account Manager, um die Berechtigungen anzupassen oder eine geeignete Rolle zuzuweisen.
  - **Bestehende Geräteverbindung**: Nachdem ein Gerät verbunden wurde, wird die primäre Schaltfläche „Add New Device“ durch ein Drei-Punkte-Menü in der oberen rechten Ecke des Fensters „C2C Connections“ ersetzt.

- **Fehler „Invalid Client“**: Eine `invalid_client`-Antwort weist auf nicht übereinstimmende Geräteinformationen hin, in der Regel aufgrund eines falschen `client_secret`.

- **Fehler „Bad Request“**: Eine `bad_request`-Antwort weist auf fehlerhafte Anfragedaten hin. Überprüfen Sie die Feldnamen und stellen Sie sicher, dass alle erforderlichen Felder enthalten sind.

Wenn Ihr Problem hier nicht behandelt wird, teilen Sie uns Ihre Erfahrungen bitte mit, damit wir diesen Abschnitt zur Fehlerbehebung verbessern können.
