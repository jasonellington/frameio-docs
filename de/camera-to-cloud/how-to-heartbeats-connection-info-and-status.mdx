## Einführung {#introduction}

Dieser Leitfaden erklärt, wie Sie den Gerätestatus verwalten und die Synchronisierung mit Frame.io aufrechterhalten. Wir verwenden ein Websocket-Protokoll, das eine Echtzeitkommunikation zwischen Frame.io und Ihrem Gerät ermöglicht. Wenn Sie mit Websockets nicht vertraut sind, hilft Ihnen dieser Leitfaden, deren Implementierung für C2C-Integrationen zu verstehen.

Websockets ermöglichen es Frame.io, Nachrichten an Ihr Gerät zu senden, und bieten durch eine dauerhafte Verbindung einen effizienteren Kommunikationskanal als herkömmliche HTTP-Requests.

In diesem Leitfaden behandeln wir:

- Das Öffnen einer Socket-Verbindung, um anzuzeigen, dass Ihr Gerät „online“ ist
- Das Abrufen von Informationen über die Verbindung Ihres Geräts
- Die Überprüfung der Verfügbarkeit des Frame.io-Backends

## Voraussetzungen {#prerequisites}

Falls noch nicht geschehen, lesen Sie bitte den Leitfaden [C2C implementieren: Einrichtung](/de/camera-to-cloud/implementing-c2c-setting-up), bevor Sie fortfahren.

Sie benötigen das `access_token`, das Sie im Rahmen des [Authentifizierungs- und Autorisierungsprozesses](/de/camera-to-cloud/implementing-c2c-authentication-and-authorization) erhalten haben. Beachten Sie, dass Tokens nach 8 Stunden ablaufen, sodass Sie Ihr Token möglicherweise aktualisieren oder den Autorisierungsprozess erneut durchlaufen müssen.

Für die Beispiele zur Websocket-Verbindung in diesem Leitfaden empfehlen wir [websocat](https://github.com/vi/websocat), ein CLI-Tool mit ausführlichen Installationsanleitungen für verschiedene Betriebssysteme.

<Info>

**MacOS**

Installation mit: `brew install websocat`

</Info>

## Verbindungsinformationen abrufen {#retrieving-connection-information}

Nach jeder neuen Autorisierung oder Token-Aktualisierung sollte Ihr Gerät sofort den `identity`-Endpunkt abfragen. Dieser liefert wichtige Informationen über Ihre Verbindung:

```shell
curl -X GET https://api.frame.io/v2/devices/me \
    --header 'Authorization: Bearer [access_token]' \
    --header 'x-client-version: 2.0.0' \
    | python -m json.tool
```

Die Antwort sieht ungefähr so aus (einige Daten gekürzt):

```

        "creator": {
            "_type": "user",
            "id": "e7e96254-8bd6-4d59-b54d-28c58570a8de",

    "status": "online",
    ...

```

Dieser Endpunkt hilft bei der Überprüfung der Verbindungsdetails. Ihr Gerät sollte Nutzern diese Informationen anzeigen:

- `project.name` – Der Name des verbundenen Projekts

- `authorization.creator.name` – Der Nutzer, der das Gerät autorisiert hat

- `authorization.expires_at` (optional) – Ablaufzeitpunkt der Verbindung, falls festgelegt

- `status` (optional) – Gerätestatus, der folgende Werte haben kann:

  - `online` – Das Gerät ist online und gekoppelt
  - `offline` – Das Gerät hat seit über 5 Minuten nicht kommuniziert (eine Abfrage dieses Endpunkts ändert den Status auf `online`)
  - `paused` – Das Gerät wurde im Bereich „C2C Connections“ von Frame.io vorübergehend deaktiviert

Da sich Ablauf- und Pausenstatus in Frame.io jederzeit ändern können, sollten Sie diese Informationen regelmäßig abfragen, wenn Sie sie Nutzern anzeigen. Wir empfehlen, die Abfragehäufigkeit auf höchstens einmal alle 60 Sekunden zu begrenzen.

<Info>

**id**

Notieren Sie sich den `id`-Wert, da Sie ihn im nächsten Abschnitt für die Websocket-Verbindung benötigen

</Info>

## Die Websocket-Verbindung herstellen {#establishing-the-websocket-connection}

Der Bereich „C2C Connections“ in Frame.io zeigt den Verbindungsstatus jedes Geräts an. Wenn ein Gerät eine aktive Socket-Verbindung hat, wird es als `online` mit einer grünen Anzeige in der oberen linken Ecke der Karte dargestellt. Geräte ohne aktive Verbindung erscheinen als `offline` und ausgegraut.

Der Server beendet Socket-Verbindungen automatisch nach 60 Sekunden ohne „Heartbeat“-Nachricht. Dieses Intervall ist zwar ausreichend, wir empfehlen jedoch, aus Gründen der Zuverlässigkeit alle 15 Sekunden einen Heartbeat zu senden. Wenn die Verbindung unerwartet geschlossen wird, stellen Sie sie einfach erneut her.

Die Verbindung zum Websocket von Frame.io erfolgt in zwei Schritten:

1. Durchführen des TCP/IP-Handshakes und Öffnen der physischen Websocket-Verbindung
2. Beitreten zum spezifischen Kanal des Geräts, um Ihr Gerät gegenüber unserem Backend zu identifizieren

So öffnen Sie die Websocket-Verbindung:

```shell
websocat -n "wss://api.frame.io/devices/websocket?Authorization=Bearer ACCESS_TOKEN"
```

<Info>

**Der Authorization-Header**

Anders als bei den üblichen API-Endpunkten, bei denen das Access Token im `Authorization`-Header übergeben wird, wird es bei Websocket-Verbindungen als URL-kodierter Query-Parameter mitgegeben. Beachten Sie, dass Sie dennoch `Bearer ` (mit Leerzeichen) vor Ihrem Access Token angeben müssen. In URL-kodierten Strings werden Leerzeichen als `%20` dargestellt, daher ist diese Formatierung zu erwarten.

</Info>

Eine erfolgreiche Verbindung gibt den Statuscode `101` zurück, der den Protokollwechsel zu `wss` anzeigt. Ihre Websocket-Bibliothek erledigt dies möglicherweise automatisch. Ein abgelaufenes Token führt zu einer `403`-Antwort.

Treten Sie als Nächstes dem Kanal Ihres Geräts bei, indem Sie diese JSON-Nachricht mit der `id` aus Ihren Verbindungsinformationen senden:

```json
{"topic":"devices:YOUR_DEVICE_ID", "event":"phx_join", "payload":"", "ref":"channel_connect"}
```

Sie erhalten eine Bestätigung:

```json
{"event":"phx_reply","payload":{"response":{},"status":"ok"},"ref":"channel_connect","topic":"devices:YOUR_DEVICE_ID"}
```

<Info>

**Die Felder ref und payload**

Das Feld `ref` ordnet Antworten den auslösenden Events zu. Da die Reihenfolge der Events nicht garantiert ist, hilft diese Kennung dabei, Serverantworten den auslösenden Events zuzuordnen. Frame.io verwendet dieses Feld nicht für eingehende Events – es dient ausschließlich als Referenz für den Client. Das Feld `payload` muss immer vorhanden sein, kann aber oft ein leerer String sein (wir geben an, wenn eine Payload bestimmte Inhalte erfordert).

</Info>

Sehen Sie im C2C-Dashboard nach – Ihr Gerät sollte jetzt online angezeigt werden! Wir empfehlen, einen Hintergrundprozess zu implementieren, der diese Verbindung aufrechterhält:

```python title="Python"
def heartbeat_task():
    """
    Task that emits heartbeats every 15 seconds.
    """

    while True:
        c2c.emit_socket_heartbeat()
        sleep(15)
```

Das Format der Heartbeat-Nachricht:

```json
{"topic":"phoenix", "event":"heartbeat", "payload":"", "ref":"heartbeat"}
```

Darauf erhalten Sie diese Antwort:

```json
{"event":"phx_reply","payload":{"response":{},"status":"ok"},"ref":"heartbeat","topic":"phoenix"}
```

Mit einer aktiven Socket-Verbindung und einem Kanalabonnement wird Ihr Gerät im Bereich „C2C Connections“ von Frame.io als online angezeigt. Wird die Verbindung beendet, erscheint es als offline.

## Gerätestatus anzeigen {#displaying-device-status}

Anstatt die rohen Statuswerte (`online`, `offline`, `paused`) anzuzeigen, empfehlen wir, sie in aussagekräftigere Anzeigen für Nutzer zu übersetzen:

- **Pausiert**: true/false – Zeigen Sie `true` an, wenn der Status `paused` ist, andernfalls `false`
- **Verbunden**: true/false – Gibt an, ob das Gerät das Frame.io-Backend erreichen kann (siehe Test der Backend-Verbindung weiter unten)

## Den Pausenstatus verwalten {#managing-the-paused-status}

Die Anzeige des Pausenstatus ist zwar optional, es ist jedoch wichtig, seine Funktion zu verstehen.

Die Pausenfunktion dient dazu, das Hochladen sensibler Inhalte vorübergehend zu blockieren. Sie blockiert keinen Netzwerkverkehr, verhindert aber, dass bestimmte Medien Frame.io erreichen. Das ist beispielsweise nützlich bei Dreharbeiten mit sensiblem Material, bei denen eine sofortige Speicherung in der Cloud unangemessen sein könnte.

Das Pausieren wird über die Oberfläche von Frame.io gesteuert, nicht über Ihre Integration. Wenn ein Gerät pausiert ist, werden nur Medien blockiert, die während des Pausenzeitraums erstellt wurden – zuvor aufgenommene Medien können weiterhin hochgeladen werden.

Wichtige Hinweise:

- Verlassen Sie sich nicht allein auf den Identity-Endpunkt, um zu prüfen, ob ein Upload zulässig ist – unser Backend übernimmt dies automatisch
- Socket-Events benachrichtigen Sie über Statusänderungen mit `event: "status_updated"` und `payload: "paused"` oder `"resumed"`
- Events können zwar bei der Verwaltung des Status helfen, sie können jedoch verpasst oder in falscher Reihenfolge zugestellt werden
- Ein `409`-Fehler beim Upload bedeutet nicht zwangsläufig, dass das Gerät aktuell pausiert ist – er kann auch darauf hinweisen, dass die Medien während eines früheren Pausenzeitraums erstellt wurden
- Wenn Sie einen Pausenstatus anzeigen, überprüfen Sie dessen Richtigkeit, indem Sie regelmäßig die Verbindungsinformationen abfragen

## Backend-Konnektivität überprüfen {#verifying-backend-connectivity}

Um die Verfügbarkeit des Frame.io-Backends zu prüfen, verwenden Sie diesen Endpunkt:

```shell
curl -X GET https://api.frame.io/health \
    | python -m json.tool
```

Dieser Endpunkt erfordert keine Autorisierung. Eine erfolgreiche Antwort zeigt an, dass eine Verbindung besteht:

```json
{
    "ok": true
}
```

Dieser Health-Check ist besonders wertvoll, da er die Konnektivität speziell zu Frame.io bestätigt und nicht nur die allgemeine Netzwerkverfügbarkeit. Es kann Situationen geben, in denen Ihr Netzwerk funktioniert, Frame.io aber aufgrund von Dienstproblemen oder Routing-Problemen nicht erreichbar ist.
