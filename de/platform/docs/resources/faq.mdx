## Fragen zur Kompatibilität {#compatibility-questions}

<AccordionGroup>

<Accordion title="Ist die Frame.io V4 API abwärtskompatibel?">

<Warning>

Nein. Das auf der Adobe MAX veröffentlichte Frame.io-Produkt funktioniert grundlegend anders und legt den Schwerpunkt auf andere Workflows als die Legacy-Version. Aufgrund dieser Unterschiede ist die neue API nicht abwärtskompatibel.

</Warning>

</Accordion>

<Accordion title="Wie wird künftig mit der Abwärtskompatibilität umgegangen?">

Da Abwärtskompatibilität für Kunden, die produktionsreife Integrationen mit hohen Verfügbarkeitsanforderungen betreiben, ein wichtiges Anliegen ist, gestalten wir die V4 API so, dass sie über einen benutzerdefinierten HTTP-Header eine zusätzliche Versionierungsebene unterstützt. So können Clients sich für die Nutzung experimenteller Endpoints entscheiden, Breaking Changes vermeiden, und wir können innerhalb des `/v4`-API-Namespace Garantien für die Abwärtskompatibilität bieten.

</Accordion>

<Accordion title="Funktionieren die Automatisierungen, die ich mit dem Legacy-Produkt eingerichtet habe, weiterhin, sobald die V4 API allgemein verfügbar ist? D. h. werden diese automatisch zu V4 migriert?">

<Warning>

Alle Automatisierungen, die Legacy-Developer-Tokens verwenden, funktionieren für V4-Accounts nicht mehr. Wir haben **keine** Möglichkeit, sie zu V4 zu migrieren.

</Warning>

</Accordion>

</AccordionGroup>

<AccordionGroup>

<Accordion title="Wird die V4 API nur für Enterprise-Kunden verfügbar sein?">

Die V4 API ist derzeit für neue Enterprise-Kunden sowie für ausgewählte Kunden und Partner über Test-Accounts verfügbar.

</Accordion>

<Accordion title="Können wir Collections in V4 programmgesteuert erstellen und verwalten?">

<Info>

Bisher sind noch keine Collections-Endpoints öffentlich verfügbar. Die Verwaltung von Collections befindet sich jedoch in Entwicklung.

</Info>

</Accordion>

## Medien und Dateien {#media-&-files}

<AccordionGroup>

<Accordion title="Wie lange sind Medienlink-URLs gültig?">

Die in `media_links` zurückgegebenen URLs (z. B. `download_url`, `inline_url` und `url`) sind **temporäre signierte URLs** – sie laufen ab und können nicht unbegrenzt wiederverwendet werden.

| URL-Typ | Ablauf |
| --- | --- |
| Download- und Inline-URLs (`original`, `high_quality`, `efficient`, `video_h264_180`) | Bis zu 24 Stunden |
| Thumbnail- und Vorschau-URLs (`thumbnail`) | Bis zu 24 Stunden |

In der Praxis ist der Ablauf auf 12:00 Uhr mittags oder Mitternacht UTC ausgerichtet. Die tatsächlich verbleibende Zeit beim Erhalt einer URL kann daher je nach Zeitpunkt der Anfrage zwischen wenigen Minuten und 24 Stunden liegen.

**Speichern oder cachen Sie diese URLs nicht.** Fordern Sie jedes Mal, wenn Sie eine Datei bereitstellen oder darauf zugreifen müssen, einen neuen Satz `media_links` an. Der Versuch, eine abgelaufene URL zu verwenden, führt zu einem `403`-Fehler vom CDN.

</Accordion>

</AccordionGroup>
