## Zugriff für alle Konten {#all-account-access}

Alle Frame-V4-Konten – nicht nur die über die Adobe Admin Console verwalteten – können Tokens erstellen und auf die V4 API zugreifen. Kunden und Partner können ihre Workflows mit unseren neuesten API-Funktionen testen, entwickeln und verfeinern.

<Steps>

<Step title="Benutzer-Authentifizierungstoken erstellen">

Besuchen Sie die Adobe Developer Console, um ein Benutzer-Authentifizierungstoken zu erstellen. Der Benutzer muss dieselbe Adobe ID wie für seine Frame-Anmeldung verwenden, um den API-Tokenzugriff zu validieren.

</Step>

<Step title="API-Anmeldedaten erstellen">

Sobald Sie Zugriff auf die APIs haben, besteht der nächste Schritt darin, API-Anmeldedaten bzw. ein API-Token zu erstellen, um mit Frame zu kommunizieren. Erstellen Sie Ihre API-Anmeldedaten unter developer.adobe.com.

</Step>

</Steps>

![Kontozugriff](/images/platform/docs/guides/accounts-projects-and-workspaces/706a4eb9324bc24a3465388a838455baf58384f128882a185dad2d1900f728a3.webp)

<Info>

Alle V4-Konten, ob von Frame verwaltet (V4F) oder von Adobe verwaltet (V4A), können in der Adobe Developer Console ein Projekt und anschließend Anmeldedaten erstellen. Sobald Sie über Anmeldedaten verfügen (OAuth Client ID/Client Secret), können Sie die Integration mit dem dreibeinigen OAuth-Flow der Adobe Developer Platform durchführen. Melden Sie sich mit Ihrer Adobe Identity an, um ein gültiges Auth- und Refresh-Token zu erhalten und Anfragen an die Frame.io V4 Developer API zu stellen!

</Info>

## Projekte und Workspaces {#projects-and-workspaces}

### Workspace-Aktualisierungen {#workspace-updates}

Die Startseite von Frame.io ist neu und heißt jetzt Workspace-Seite. Benutzer können die Workspaces und Projekte durchsuchen, auf die sie in einem Konto Zugriff haben. Dank dieses neuen Designs ist leichter zu erkennen, wer zu einem bestimmten Workspace gehört, und neue Personen lassen sich schnell einladen.

<Note>

In Frame V3 hießen Workspaces Teams.

</Note>

Workspaces sind in V4 auf „Nur auf Einladung“ eingestellt, sodass Benutzer nur Workspaces sehen, zu denen sie ausdrücklich eingeladen wurden. Außerdem gibt es in den Kontoeinstellungen keine Teamverzeichnis-Seite.

Verwenden Sie zum Verwalten von Berechtigungen und zugehörigen Vorgängen die Endpunkte zum Erstellen, Auflisten, Löschen und Aktualisieren von Workspaces.

<CardGroup cols={1}>

<Card title="Vorgänge zur Workspace-Verwaltung" icon="users" iconType="solid" horizontal={true}>

- Benutzerrollen für einen bestimmten Workspace auflisten.
- Einen Benutzer aus einem bestimmten Workspace entfernen.
- Benutzerrollen für den angegebenen Workspace aktualisieren, wenn der Benutzer dem Workspace bereits hinzugefügt wurde. Wurde der Benutzer dem Workspace noch nicht hinzugefügt, wird er mit der angegebenen Rolle hinzugefügt.

</Card>

</CardGroup>

### Projekt-Aktualisierungen {#project-updates}

Der Ablauf zum Erstellen von Projekten hat sich in V4 geändert. Wenn Sie jetzt ein neues Projekt starten, wählen Sie zwischen einem leeren Projekt und einer Projektvorlage. Es stehen zwölf Vorlagen zur Auswahl, die für gängige kreative Workflows konzipiert sind. Sie können außerdem festlegen, ob die Demo-Assets der Vorlage enthalten sein sollen oder ob Sie nur mit der Vorlagenstruktur beginnen möchten. Die Auswahl einer Projektvorlage erstellt sofort ein neues Projekt in Ihrem Workspace.

Verwenden Sie zum Verwalten von Berechtigungen und zugehörigen Vorgängen die Endpunkte zum Erstellen, Auflisten, Löschen und Aktualisieren von Projekten.

<CardGroup cols={1}>

<Card title="Vorgänge zur Projektverwaltung" icon="folder" iconType="solid" horizontal={true}>

- Benutzerrollen für ein bestimmtes Projekt auflisten.
- Einen Benutzer aus einem bestimmten Projekt entfernen.
- Benutzerrollen für das angegebene Projekt aktualisieren, wenn der Benutzer dem Projekt bereits hinzugefügt wurde. Wurde der Benutzer dem Projekt noch nicht hinzugefügt, wird er mit der angegebenen Rolle hinzugefügt.

</Card>

</CardGroup>
