---
title: "Benutzerberechtigungen verwalten"
---

Dieser Leitfaden erklärt, wie Sie Benutzerberechtigungen mit der Frame.io V4 API verwalten. Er beschreibt, wie Berechtigungen auf Konto-, Workspace- und Projektebene funktionieren und welche Endpunkte auf der jeweiligen Ebene zu verwenden sind.

---

## Berechtigungsebenen {#permission-levels}

Berechtigungen in Frame.io werden auf Konto-, Workspace- und Projektebene verwaltet. Jede Ebene verwendet ihre eigenen Rollen:

```
Account 
│
├── (admin)  - full access to all Workspaces, Projects, and Restricted Projects
│
└── (member)
        │
        ├── Workspace - (full_access | editor | edit_only | commenter | viewer)
        │       │
        │       └── Project - (full_access | editor | edit_only | commenter | viewer)
        │
        └── Restricted Project - (members require direct invite)
```

Jeder Benutzer hat eine Kontorolle. Über die API können Sie die Rolle eines Benutzers auf <Tooltip tip="In API-Antworten können auch Owner und Reviewer zurückgegeben werden, diese Rollen sind jedoch nicht über die API konfigurierbar. Weitere Details dazu finden Sie im Abschnitt zu Berechtigungen auf Kontoebene.">`admin` oder `member` setzen.</Tooltip>
Account Admins haben vollen Zugriff auf alle Workspaces und Projekte. Account Members können gezielt zu den Workspaces und Projekten hinzugefügt werden, die sie benötigen.

Wenn Sie ein Account Member zu einem Workspace hinzufügen, gilt die zugewiesene Berechtigungsstufe (`full_access`, `editor`, `edit_only`, `commenter` oder `viewer`) für alle bestehenden und zukünftigen Projekte darin. Wenn Sie beispielsweise ein Account Member als `viewer` hinzufügen, hat es bei jedem Zugriff auf ein Projekt in diesem Workspace `viewer`-Berechtigungen.

Dasselbe Account Member kann einem bestimmten Projekt innerhalb dieses Workspace als `editor` hinzugefügt werden. Infolgedessen hat es bei jedem Zugriff auf dieses Projekt `editor`-Berechtigungen. Für alle anderen Projekte in diesem Workspace gelten weiterhin seine `viewer`-Berechtigungen.

Da Projektzuweisungen von Workspace-Zuweisungen getrennt sind, behält das Account Member seine `editor`-Berechtigungen für dieses eine Projekt, auch wenn Sie es aus dem Workspace entfernen.

Restricted Projects sind die Ausnahme. Account Members benötigen hier immer eine direkte Einladung. Mehr dazu im Abschnitt zu Berechtigungen auf Projektebene weiter unten.

## Berechtigungen auf Kontoebene {#account-level-permissions}

Jeder Benutzer in Ihrem Konto hat eine Rolle:

| Rolle | Berechtigungen | Über API konfigurierbar | Endpunkt |
| --- | --- | --- | --- |
| Owner | Vollzugriff auf alle Workspaces und Projekte. Einer pro Konto | Nein | — |
| <Tooltip tip="In der Benutzeroberfläche als 'Content Admin' bezeichnet">`admin`</Tooltip> | Vollzugriff auf alle Workspaces und Projekte | Ja | `PATCH /accounts/:account_id/users/:user_id` |
| `member` | Berechtigungen werden auf Workspace- und/oder Projektebene festgelegt | Ja | `PATCH /accounts/:account_id/users/:user_id` |
| Reviewer | Zugriff nur über Freigabelinks. Wird erstellt, wenn ein Benutzer zu einer sicheren Freigabe hinzugefügt wird | <Tooltip tip="Reviewer erscheinen in den Benutzerlisten des Kontos, da sie sich bei Frame.io authentifizieren, sie existieren jedoch außerhalb des Berechtigungssystems für Workspaces und Projekte. Sie greifen nur über sichere Freigabelinks auf Inhalte zu.">Nein</Tooltip> | — |

---

Account Admins haben überall vollen Zugriff. Um den Zugriff eines Admins auf bestimmte Ressourcen zu beschränken, ändern Sie zunächst seine Kontorolle in Member und fügen Sie ihn dann zu den benötigten Workspaces oder Projekten hinzu.

Zum Beispiel:

<Steps>

<Step title="Rollen der Kontobenutzer auflisten, um die Benutzer-ID zu finden und die aktuelle Rolle zu bestätigen:">

```bash

curl https://api.frame.io/v4/accounts/:account_id/users \
     -H "Authorization: Bearer <token>"
```

</Step>

<Step title="Kontorolle auf Member aktualisieren:">

```bash

curl -X PATCH https://api.frame.io/v4/accounts/:account_id/users/:user_id \
 -H "Authorization: Bearer <token>" \
 -H "Content-Type: application/json" \
 -d '{
"data": {
"role": "member"
}
}'
```

</Step>

<Step title="Benutzer zu einem Projekt hinzufügen:">

```bash

curl -X PATCH https://api.frame.io/v4/accounts/:account_id/projects/:project_id/users/:user_id \
  -H "Authorization: Bearer <token>" \
  -H "Content-Type: application/json" \
  -d '{
"data": {
 "role": "edit_only"
}
}'
```

</Step>

</Steps>

## Berechtigungen auf Workspace-Ebene {#workspace-level-permissions}

Wenn Sie ein Account Member zu einem Workspace hinzufügen, erhält es diese Berechtigungsstufe für alle Projekte darin. Workspaces sind nur auf Einladung zugänglich, daher sehen Account Members nur die Workspaces, zu denen sie hinzugefügt wurden.

<br />

| Rolle | Berechtigungen |
| --- | --- |
| `full_access` | Hochladen, verwalten, freigeben, kommentieren, ansehen, herunterladen, Einstellungen verwalten und Benutzer einladen |
| `editor` | Hochladen, verwalten, freigeben, kommentieren, ansehen, herunterladen |
| `edit_only` | Hochladen, verwalten, kommentieren, ansehen. Kein Freigeben oder Herunterladen |
| `commenter` | Ansehen und kommentieren |
| `viewer` | Nur ansehen |

<br />

## Berechtigungen auf Projektebene {#project-level-permissions}

Projekte verwenden dieselben Berechtigungsstufen wie Workspaces. Fügen Sie einen Benutzer direkt zu einem Projekt hinzu, wenn er nur Zugriff auf dieses bestimmte Projekt benötigt oder wenn er eine andere Berechtigungsstufe als in seiner Workspace-Zuweisung benötigt. Benutzer benötigen keinen Workspace-Zugriff, um zu einem Projekt hinzugefügt zu werden.

<br />

| Rolle | Berechtigungen |
| --- | --- |
| `full_access` | Hochladen, verwalten, freigeben, kommentieren, ansehen, herunterladen, Einstellungen verwalten und Benutzer einladen |
| `editor` | Hochladen, verwalten, freigeben, kommentieren, ansehen, herunterladen |
| `edit_only` | Hochladen, verwalten, kommentieren, ansehen. Kein Freigeben oder Herunterladen |
| `commenter` | Ansehen und kommentieren |
| `viewer` | Nur ansehen |

<br />

**Beispiel: Einen Benutzer zu einem Projekt hinzufügen**

```bash

curl -X PATCH https://api.frame.io/v4/accounts/:account_id/projects/:project_id/users/:user_id \
     -H "Authorization: Bearer <token>" \
     -H "Content-Type: application/json" \
     -d '{
  "data": {
    "role": "full_access"
  }
}'
```

---

### Restricted Projects {#restricted-projects}

Restricted Projects erfordern eine direkte Einladung. Workspace-Zugriff wird nicht übernommen,
sodass Benutzer nur dann auf ein Restricted Project zugreifen können, wenn sie direkt hinzugefügt wurden.

Um einem Member Zugriff zu gewähren, fügen Sie es mit der entsprechenden Berechtigungsstufe zum Projekt hinzu.

<Note>

Account Admins und Owners sind die Ausnahme und haben Zugriff auf alle
Restricted Projects.

</Note>
