### Installation {#installation}

```bash
npm i -s frameio
```

---

### Verwendung {#usage}

Instanziieren und verwenden Sie den Client wie folgt:

```typescript
import { FrameioClient } from "frameio";

const client = new FrameioClient({ token: "YOUR_TOKEN" });
await client.metadataFields.metadataFieldDefinitionsCreate("b2702c44-c6da-4bb6-8bbd-be6e547ccf1b", {
    data: {
        field_type: "select",
        field_configuration: {
            enable_add_new: false,
            options: [
                {
                    display_name: "Option 1",
                },
                {
                    display_name: "Option 2",
                },
            ],
        },
        name: "Fields definition name",
    },
});
```

---

### Anfrage- und Antworttypen {#request-and-response-types}

Das SDK exportiert alle Anfrage- und Antworttypen als TypeScript-Interfaces. Importieren Sie sie einfach über den folgenden Namespace:

```typescript
import { Frameio } from "frameio";

const request: Frameio.UpdateFieldDefinitionParams = {
    ...
};
```

---

### Ausnahmebehandlung {#exception-handling}

Wenn die API einen Fehlerstatuscode zurückgibt (4xx- oder 5xx-Antwort), wird eine Unterklasse des folgenden Fehlers ausgelöst.

```typescript
import { FrameioError } from "frameio";

try {
    await client.metadataFields.metadataFieldDefinitionsCreate(...);
} catch (err) {
    if (err instanceof FrameioError) {
        console.log(err.statusCode);
        console.log(err.message);
        console.log(err.body);
        console.log(err.rawResponse);
    }
}
```

### Erweitert {#advanced}

#### Zusätzliche Header {#additional-headers}

Wenn Sie zusätzliche Header mit der Anfrage senden möchten, verwenden Sie die Anfrageoption headers.

```typescript
const response = await client.metadataFields.metadataFieldDefinitionsCreate(..., {
    headers: {
        'X-Custom-Header': 'custom value'
    }
});
```

#### Zusätzliche Query-String-Parameter {#additional-query-string-parameters}

Wenn Sie zusätzliche Query-String-Parameter mit der Anfrage senden möchten, verwenden Sie die Anfrageoption queryParams.

```typescript
const response = await client.metadataFields.metadataFieldDefinitionsCreate(..., {
    queryParams: {
        'customQueryParamKey': 'custom query param value'
    }
});
```

---

#### Wiederholungsversuche {#retries}

Das SDK verfügt über automatische Wiederholungsversuche mit exponentiellem Backoff. Eine Anfrage wird wiederholt, solange sie als wiederholbar gilt und die Anzahl der Wiederholungsversuche das konfigurierte Limit (Standard: 2) nicht überschritten hat.

Eine Anfrage gilt als wiederholbar, wenn einer der folgenden HTTP-Statuscodes zurückgegeben wird:

- 408 (Zeitüberschreitung)
- 429 (Zu viele Anfragen)
- 5XX (Interne Serverfehler)

<br />

Verwenden Sie die Anfrageoption `maxRetries`, um dieses Verhalten zu konfigurieren.

```typescript
const response = await client.metadataFields.metadataFieldDefinitionsCreate(..., {
    maxRetries: 0 // override maxRetries at the request level
});
```

---

#### Timeouts {#timeouts}

Das SDK verwendet standardmäßig ein Timeout von 60 Sekunden. Verwenden Sie die Option timeoutInSeconds, um dieses Verhalten zu konfigurieren.

```typescript
const response = await client.metadataFields.metadataFieldDefinitionsCreate(..., {
    timeoutInSeconds: 30 // override timeout to 30s
});
```

#### Anfragen abbrechen {#aborting-requests}

Mit dem SDK können Anfragen jederzeit abgebrochen werden, indem ein Abort-Signal übergeben wird.

```typescript
const controller = new AbortController();
const response = await client.metadataFields.metadataFieldDefinitionsCreate(..., {
    abortSignal: controller.signal
});
controller.abort(); // aborts the request
```

---

#### Zugriff auf Rohdaten der Antwort {#access-raw-response-data}

Das SDK bietet über die Methode `.withRawResponse()` Zugriff auf die Rohdaten der Antwort, einschließlich der Header. Die Methode `.withRawResponse()` gibt ein Promise zurück, das zu einem Objekt mit den Eigenschaften `data` und `rawResponse` aufgelöst wird.

```typescript
const { data, rawResponse } = await client.metadataFields.metadataFieldDefinitionsCreate(...).withRawResponse();

console.log(data);
console.log(rawResponse.headers['X-My-Header']);
```

#### Laufzeitkompatibilität {#runtime-compatibility}

Das SDK funktioniert in den folgenden Laufzeitumgebungen:

- Node.js 18+
- Vercel
- Cloudflare Workers
- Deno v1.25+
- Bun 1.0+
- React Native

#### Fetch-Client anpassen {#customizing-fetch-client}

Das SDK bietet Ihnen die Möglichkeit, den zugrunde liegenden HTTP-Client bzw. die Fetch-Funktion anzupassen. Wenn Sie in einer nicht unterstützten Umgebung arbeiten, können Sie so als Notlösung sicherstellen, dass das SDK funktioniert.

```typescript
import { FrameioClient } from "frameio";

const client = new FrameioClient({
    ...
    fetcher: // provide your implementation here
});
```

#### Authentifizierung {#auth}

<AccordionGroup>

<Accordion title="new ServerToServerAuth({ clientId, clientSecret, ... })">

Authentifizierung über den OAuth-2.0-Grant `client_credentials`. Dieser Flow erfordert keinen Benutzer und gibt kein Refresh-Token zurück. Wenn das Zugriffstoken abläuft, fordert das SDK mithilfe der Client-Anmeldedaten automatisch ein neues an.

```typescript title="usage"
import { FrameioClient, ServerToServerAuth } from "frameio";

const auth = new ServerToServerAuth({
    clientId: "YOUR_CLIENT_ID",
    clientSecret: "YOUR_CLIENT_SECRET",
});
const client = new FrameioClient({ token: () => auth.getToken() });
```

**Parameter**

`clientId`: `string` — Adobe IMS OAuth-Client-ID.

`clientSecret`: `string` — Adobe IMS OAuth-Client-Secret.

`scopes`: `string` — Durch Leerzeichen getrennte Scopes (OAuth 2.0 RFC 6749). Standardmäßig die Server-to-Server-Scopes.

`imsBaseUrl`: `string` — IMS-Basis-URL für Staging- bzw. alternative Umgebungen. Standardmäßig die Produktionsumgebung.

`fetch`: `typeof fetch` — Benutzerdefinierte Fetch-Implementierung (für Proxy, TLS usw.).

`onTokenRefreshed`: `OnTokenRefreshed` — Optionaler Callback, der nach jedem Token-Abruf ausgelöst wird.

`timeout`: `number` — Timeout für HTTP-Anfragen in Millisekunden. Standardwert: 30000.

`maxRetries`: `number` — Maximale Anzahl von Wiederholungsversuchen bei vorübergehenden Fehlern. Standardwert: 2.

`refreshBuffer`: `number` — Sekunden vor Ablauf, zu denen eine proaktive Aktualisierung ausgelöst wird. Standardwert: 60.

`logger`: `Logger` — Logger-Instanz für Diagnoseausgaben.

**Methoden**

`getToken(): Promise<string>` — Gibt ein gültiges Zugriffstoken zurück und aktualisiert es bei Bedarf. Übergeben Sie es an den Client: `new FrameioClient({ token: () => auth.getToken() })`.

`authenticate(): Promise<TokenResponse>` — Ruft explizit ein neues Zugriffstoken ab.

`revoke(): Promise<void>` — Widerruft Tokens serverseitig und löscht den lokalen Zustand.

`exportTokens(): ExportedTokens` — Exportiert den aktuellen Token-Zustand zur Persistierung.

`importTokens(data: ExportedTokens): void` — Stellt den Token-Zustand aus einem zuvor exportierten Objekt wieder her.

</Accordion>

<Accordion title="new WebAppAuth({ clientId, clientSecret, redirectUri, ... })">

Authentifizierung über den OAuth-2.0-Grant `authorization_code`. Verwenden Sie dies für serverseitige Anwendungen, die ein Client-Secret sicher speichern können.

```typescript title="usage"
import { randomBytes } from "crypto";
import { FrameioClient, WebAppAuth } from "frameio";

const auth = new WebAppAuth({
    clientId: "YOUR_CLIENT_ID",
    clientSecret: "YOUR_CLIENT_SECRET",
    redirectUri: "https://myapp.com/callback",
});
const url = auth.getAuthorizationUrl({ state: randomBytes(24).toString("hex") });
// redirect the user to url ...
await auth.exchangeCode("CODE_FROM_CALLBACK");
const client = new FrameioClient({ token: () => auth.getToken() });
```

**Parameter**

`clientId`: `string` — Adobe IMS OAuth-Client-ID.

`clientSecret`: `string` — Adobe IMS OAuth-Client-Secret.

`redirectUri`: `string` — Registrierte Weiterleitungs-URI.

`scopes`: `string` — Durch Leerzeichen getrennte Scopes (OAuth 2.0 RFC 6749).

`imsBaseUrl`: `string` — IMS-Basis-URL für Staging- bzw. alternative Umgebungen. Standardmäßig die Produktionsumgebung.

`fetch`: `typeof fetch` — Benutzerdefinierte Fetch-Implementierung (für Proxy, TLS usw.).

`onTokenRefreshed`: `OnTokenRefreshed` — Optionaler Callback, der nach jeder Token-Aktualisierung ausgelöst wird.

`timeout`: `number` — Timeout für HTTP-Anfragen in Millisekunden. Standardwert: 30000.

`maxRetries`: `number` — Maximale Anzahl von Wiederholungsversuchen bei vorübergehenden Fehlern. Standardwert: 2.

`refreshBuffer`: `number` — Sekunden vor Ablauf, zu denen eine proaktive Aktualisierung ausgelöst wird. Standardwert: 60.

`logger`: `Logger` — Logger-Instanz für Diagnoseausgaben.

**Methoden**

`getToken(): Promise<string>` — Gibt ein gültiges Zugriffstoken zurück und aktualisiert es bei Bedarf.

`getAuthorizationUrl({ state }): string` — Erstellt die Adobe IMS-Autorisierungs-URL. Übergeben Sie einen undurchsichtigen CSRF-/State-Wert, der zurückgegeben wird.

`exchangeCode(code: string): Promise<TokenResponse>` — Tauscht einen Autorisierungscode gegen Zugriffs- und Refresh-Tokens aus.

`refresh(): Promise<TokenResponse>` — Löst manuell eine Token-Aktualisierung aus.

`revoke(): Promise<void>` — Widerruft Tokens serverseitig und löscht den lokalen Zustand.

`exportTokens(): ExportedTokens` — Exportiert den aktuellen Token-Zustand zur Persistierung.

`importTokens(data: ExportedTokens): void` — Stellt den Token-Zustand aus einem zuvor exportierten Objekt wieder her.

</Accordion>

<Accordion title="new SPAAuth({ clientId, redirectUri, ... })">

Authentifizierung über `authorization_code` + PKCE (ohne Client-Secret). Verwenden Sie dies für browserbasierte Single-Page-Apps, die ein Client-Secret nicht sicher speichern können.

```typescript title="usage"
import { randomBytes } from "crypto";
import { FrameioClient, SPAAuth } from "frameio";

const auth = new SPAAuth({
    clientId: "YOUR_CLIENT_ID",
    redirectUri: "https://myapp.com/cb",
});
const result = await auth.getAuthorizationUrl({ state: randomBytes(24).toString("hex") });
// redirect the user to result.url, store result.codeVerifier ...
await auth.exchangeCode({ code: "CODE_FROM_CALLBACK", codeVerifier: result.codeVerifier });
const client = new FrameioClient({ token: () => auth.getToken() });
```

**Parameter**

`clientId`: `string` — Adobe IMS OAuth-Client-ID.

`redirectUri`: `string` — Registrierte Weiterleitungs-URI.

`scopes`: `string` — Durch Leerzeichen getrennte Scopes (OAuth 2.0 RFC 6749).

`imsBaseUrl`: `string` — IMS-Basis-URL für Staging- bzw. alternative Umgebungen. Standardmäßig die Produktionsumgebung.

`fetch`: `typeof fetch` — Benutzerdefinierte Fetch-Implementierung (für Proxy, TLS usw.).

`onTokenRefreshed`: `OnTokenRefreshed` — Optionaler Callback, der nach jeder Token-Aktualisierung ausgelöst wird.

`timeout`: `number` — Timeout für HTTP-Anfragen in Millisekunden. Standardwert: 30000.

`maxRetries`: `number` — Maximale Anzahl von Wiederholungsversuchen bei vorübergehenden Fehlern. Standardwert: 2.

`refreshBuffer`: `number` — Sekunden vor Ablauf, zu denen eine proaktive Aktualisierung ausgelöst wird. Standardwert: 60.

`logger`: `Logger` — Logger-Instanz für Diagnoseausgaben.

**Methoden**

`getToken(): Promise<string>` — Gibt ein gültiges Zugriffstoken zurück und aktualisiert es bei Bedarf.

`getAuthorizationUrl({ state }): Promise<AuthorizationUrlResult>` — Erstellt die Adobe IMS-Autorisierungs-URL mit einer PKCE-Challenge. Gibt ein `AuthorizationUrlResult` mit `url` und `codeVerifier` zurück.

`exchangeCode({ code, codeVerifier }): Promise<TokenResponse>` — Tauscht einen Autorisierungscode + PKCE-Verifier gegen Tokens aus.

`refresh(): Promise<TokenResponse>` — Löst manuell eine Token-Aktualisierung aus.

`importTokens(data: ExportedTokens): void` — Stellt den Token-Zustand aus einem zuvor exportierten Objekt wieder her.

<Accordion title="new NativeAppAuth({ clientId, redirectUri, ... })">

```typescript title="usage"
import { randomBytes } from "crypto";

    clientId: "YOUR_CLIENT_ID",
    redirectUri: "myapp://callback",
});
const result = await auth.getAuthorizationUrl({ state: randomBytes(24).toString("hex") });
// open result.url in the system browser, store result.codeVerifier ...
await auth.exchangeCode({ code: "CODE_FROM_CALLBACK", codeVerifier: result.codeVerifier });

```

**Parameter**

`clientId`: `string` — Adobe IMS OAuth-Client-ID.

`redirectUri`: `string` — Registrierte Weiterleitungs-URI (benutzerdefiniertes Schema wird unterstützt).

`scopes`: `string` — Durch Leerzeichen getrennte Scopes (OAuth 2.0 RFC 6749).

`imsBaseUrl`: `string` — IMS-Basis-URL für Staging- bzw. alternative Umgebungen. Standardmäßig die Produktionsumgebung.

`fetch`: `typeof fetch` — Benutzerdefinierte Fetch-Implementierung (für Proxy, TLS usw.).

`onTokenRefreshed`: `OnTokenRefreshed` — Optionaler Callback, der nach jeder Token-Aktualisierung ausgelöst wird.

`timeout`: `number` — Timeout für HTTP-Anfragen in Millisekunden. Standardwert: 30000.

`maxRetries`: `number` — Maximale Anzahl von Wiederholungsversuchen bei vorübergehenden Fehlern. Standardwert: 2.

`refreshBuffer`: `number` — Sekunden vor Ablauf, zu denen eine proaktive Aktualisierung ausgelöst wird. Standardwert: 60.

`logger`: `Logger` — Logger-Instanz für Diagnoseausgaben.

**Methoden**

Wie bei `SPAAuth`: `getToken()`, `getAuthorizationUrl({ state })`, `exchangeCode({ code, codeVerifier })`, `refresh()`, `revoke()`, `exportTokens()`, `importTokens(data)`.

<Accordion title="AuthorizationUrlResult">

Objekt, das von `SPAAuth.getAuthorizationUrl()` und `NativeAppAuth.getAuthorizationUrl()` zurückgegeben wird. Enthält die Autorisierungs-URL und den PKCE-Code-Verifier.

**Eigenschaften**

#### Authentifizierungsausnahmen {#auth-exceptions}

Alle Authentifizierungsfehler erweitern `FrameioAuthError` und können aus `frameio` importiert werden.

| Ausnahme | Beschreibung |
| --- | --- |
| `FrameioAuthError` | Basisfehler für alle Fehler des Auth-SDK. |
| `AuthenticationError` | Token-Austausch oder -Aktualisierung fehlgeschlagen. Besitzt die Eigenschaften `errorCode` und `errorDescription`. |
| `TokenExpiredError` | Das Refresh-Token ist abgelaufen; eine erneute Authentifizierung ist erforderlich. |
| `NetworkError` | Eine Netzwerkanfrage ist fehlgeschlagen (Timeout, Verbindungsfehler usw.). |
| `RateLimitError` | Adobe IMS hat 429 zurückgegeben und die Wiederholungsversuche sind ausgeschöpft. Besitzt die Eigenschaft `retryAfter`. |
| `PKCEError` | PKCE-Verifizierung fehlgeschlagen. |
| `ConfigurationError` | Erforderliche Konfiguration fehlt oder ist ungültig. |

Ebenso wird ein Medienlink in der Antwort auf null gesetzt, wenn ein angeforderter Transcode-Link für eine bestimmte Datei nicht existiert (z.
