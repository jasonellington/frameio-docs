## Zugriff für alle Accounts {#all-account-access}

Alle Frame-V4-Accounts – nicht nur diejenigen, die über die Adobe Admin Console verwaltet werden – können Token erstellen und auf die V4-API zugreifen. Kundinnen, Kunden und Partner können ihre Workflows mit unseren neuesten API-Funktionen testen, entwickeln und verfeinern.

<Steps>

<Step title="Token für die Benutzerauthentifizierung erstellen">

Rufen Sie die Adobe Developer Console auf, um ein Token für die Benutzerauthentifizierung zu erstellen. Der User muss dieselbe Adobe ID wie für seine Frame-Anmeldung verwenden, damit der Zugriff über das API-Token validiert werden kann.

</Step>

<Step title="API-Anmeldedaten erstellen">

Sobald Sie Zugriff auf die APIs haben, besteht der nächste Schritt darin, API-Anmeldedaten bzw. ein API-Token zu erstellen, um mit Frame zu kommunizieren. Erstellen Sie Ihre API-Anmeldedaten auf developer.adobe.com.

</Step>

</Steps>

![Account Access](/images/platform/docs/guides/accounts-projects-and-workspaces/706a4eb9324bc24a3465388a838455baf58384f128882a185dad2d1900f728a3.webp)

<Info>

Alle V4-Accounts, ob von Frame verwaltet (V4F) oder von Adobe verwaltet (V4A), können ein Project in der Adobe Developer Console und anschließend Anmeldedaten erstellen. Sobald Sie über Anmeldedaten verfügen (OAuth Client ID/Client Secret), können Sie den dreibeinigen OAuth-Flow der Adobe Developer Platform integrieren. Melden Sie sich mit Ihrer Adobe Identity an, um ein gültiges Auth- und Refresh-Token zu erhalten, mit dem Sie Anfragen an die Frame.io V4 Developer API senden können!

</Info>

## Projects und Workspaces {#projects-and-workspaces}

### Neuerungen bei Workspaces {#workspace-updates}

Die Startseite von Frame.io ist neu und heißt jetzt Workspace-Seite. User können die Workspaces und Projects durchsuchen, auf die sie in einem Account Zugriff haben. Dank dieses neuen Designs ist es einfacher zu sehen, wer zu einem bestimmten Workspace gehört, und schnell neue Personen einzuladen.

<Note>

In Frame V3 hießen Workspaces noch Teams.

</Note>

Workspaces sind in V4 auf „Nur auf Einladung“ eingestellt, sodass User nur die Workspaces sehen, zu denen sie ausdrücklich eingeladen wurden. Außerdem gibt es in den Account-Einstellungen keine Seite „Team Directory“ mehr.

Verwenden Sie zur Verwaltung von Berechtigungen und zugehörigen Vorgängen die Endpunkte zum Erstellen, Auflisten, Löschen und Aktualisieren von Workspaces.

<CardGroup cols={1}>

<Card title="Vorgänge zur Workspace-Verwaltung" icon="users" iconType="solid" horizontal={true}>

- User-Rollen für einen bestimmten Workspace auflisten.
- Einen User aus einem bestimmten Workspace entfernen.
- User-Rollen für den angegebenen Workspace aktualisieren, wenn der User dem Workspace bereits hinzugefügt wurde. Wurde der User dem Workspace noch nicht hinzugefügt, wird er mit der angegebenen Rolle hinzugefügt.

</Card>

</CardGroup>

### Neuerungen bei Projects {#project-updates}

Der Ablauf zum Erstellen von Projects hat sich in V4 geändert. Wenn Sie jetzt ein neues Project beginnen, wählen Sie zwischen einem leeren Project und einer Projektvorlage. Es stehen zwölf Vorlagen zur Auswahl, die für gängige kreative Workflows konzipiert sind. Sie können auch festlegen, ob die Demo-Assets der Vorlage enthalten sein sollen, oder nur mit der Struktur der Vorlage beginnen. Wenn Sie eine Projektvorlage auswählen, wird sofort ein neues Project in Ihrem Workspace erstellt.

Verwenden Sie zur Verwaltung von Berechtigungen und zugehörigen Vorgängen die Endpunkte zum Erstellen, Auflisten, Löschen und Aktualisieren von Projects.

<CardGroup cols={1}>

<Card title="Vorgänge zur Projektverwaltung" icon="folder" iconType="solid" horizontal={true}>

- User-Rollen für ein bestimmtes Project auflisten.
- Einen User aus einem bestimmten Project entfernen.
- User-Rollen für das angegebene Project aktualisieren, wenn der User dem Project bereits hinzugefügt wurde. Wurde der User dem Project noch nicht hinzugefügt, wird er mit der angegebenen Rolle hinzugefügt.

</Card>

</CardGroup>
