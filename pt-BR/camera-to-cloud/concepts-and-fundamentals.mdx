## Noções básicas de redes e glossário {#networking-basics-and-glossary}

Em sua essência, a API do Frame.io permite a comunicação entre os servidores do Frame.io e o seu dispositivo ou aplicativo, exigindo interações de rede para cada operação.

Uma comunicação clara é essencial em qualquer relacionamento, inclusive entre servidores e clientes. Assim como ocorrem mal-entendidos em conversas do dia a dia, desafios semelhantes existem quando computadores trocam informações.

Além de lidar com os problemas comuns de comunicação, precisamos garantir a transmissão segura de dados sensíveis. O Frame.io exige criptografia em todas as comunicações com o servidor, adicionando as camadas de segurança necessárias ao processo.

Ao implementar a API C2C, você provavelmente usará bibliotecas de terceiros para lidar com os detalhes de rede. No entanto, como os componentes de rede frequentemente geram erros no mundo real, é valioso entender os processos subjacentes ao interagir com os servidores do Frame.io. Aqui está um glossário conciso da terminologia essencial:

### Chaves públicas e privadas {#public-and-private-keys}

Uma chave pública funciona como um cadeado, enquanto uma chave privada serve como a chave correspondente.

Pense neste cenário: você quer enviar uma mensagem confidencial a um colega, garantindo a privacidade até a entrega.

Primeiro, peça ao seu colega que lhe envie um cadeado do qual só ele tem a chave.

Ao receber esse cadeado, guarde sua mensagem confidencial em um recipiente trancado com ele. Embora qualquer pessoa que manuseie o recipiente possa ver o cadeado, apenas o seu colega tem a chave para acessar o conteúdo. O cadeado não tem nenhuma utilidade para terceiros não autorizados que tentem ver a mensagem. Nem mesmo você consegue abri-lo sem a chave.

Quando seu colega recebe o recipiente trancado, ele simplesmente usa a chave para acessar o conteúdo.

Chaves públicas e privadas funcionam da mesma forma. Você pode compartilhar uma chave pública amplamente. Os destinatários criptografam mensagens com essa chave, mas apenas quem possui a chave privada pode descriptografar essas comunicações. Enquanto a chave privada permanecer confidencial, a chave pública não poderá ser usada para decodificar as mensagens criptografadas que ela cria.

Esse mecanismo de chave pública/privada é a base do funcionamento do TLS, permitindo que as partes se comuniquem abertamente enquanto estabelecem canais seguros e privados.

### Certificados {#certificates}

Os certificados contêm chaves públicas e privadas, autenticadas por autoridades de certificação confiáveis.

Quando uma Autoridade de Certificação valida uma chave, ela essencialmente atesta a autenticidade da chave. Os destinatários de uma chave pública — como uma do Google — podem verificar esse endosso de autoridades de certificação reconhecidas. Chaves sem endosso são consideradas potencialmente fraudulentas e disparam alertas de segurança.

Os certificados do Frame.io são validados pela autoridade de certificação Amazon Root CA 1. Esses certificados estão disponíveis em vários recursos, incluindo a biblioteca Certifi (usada pela Mozilla e pela biblioteca Python Requests).

Para a implementação, recomendamos o [repositório no GitHub](https://github.com/certifi/python-certifi) da Certifi e o [pacote de certificados PEM](https://github.com/certifi/python-certifi/blob/master/certifi/cacert.pem) para validar requisições HTTPS para api.frame.io.

## Requisições HTTP/S {#http/s-requests}

O HTTP é onipresente na navegação web — aparecendo no início de quase todo endereço de site. O HTTP (Hypertext Transfer Protocol) estabelece protocolos padronizados de comunicação entre computadores.

Você pode pensar no HTTP como um sistema de formulários padronizados para interações entre cliente e servidor — semelhante aos formulários governamentais exigidos para solicitações de informações ou inscrições em programas. Sem formulários devidamente preenchidos, os órgãos governamentais não conseguem processar nem responder às solicitações.

As requisições HTTP viabilizam todas as interações com o aplicativo Frame.io. No contexto da API C2C, os tipos de requisição HTTP representam as funcionalidades disponíveis.

Para uma visão geral abrangente do HTTP, consulte [este artigo informativo](https://www.freecodecamp.org/news/http-and-everything-you-need-to-know-about-it/). Entender esses fundamentos é essencial antes de prosseguir. Se você é novo em requisições HTTP, considere revisar materiais introdutórios. Para uma preparação ideal, familiarize-se com estes conceitos de HTTP:

<Card title="Componentes de URL" icon="link" iconType="solid">

Embora as bibliotecas de rede normalmente cuidem da construção das requisições, o [RFC do HTTP/1.1](https://greenbytes.de/tech/webdav/rfc2616.html) oferece um recurso de referência, se necessário.

## Autenticação e autorização {#authentication-and-authorization}

Exploraremos esses conceitos com mais profundidade mais adiante, mas é importante entender estes princípios fundamentais:

<CardGroup cols={2}>

<Card title="Autenticação" icon="key" iconType="solid">

A autenticação verifica se as requisições vêm das fontes declaradas. Quando você faz login em sites com credenciais de nome de usuário/senha, está se autenticando ao demonstrar que conhece a senha. A autenticação multifator — como receber códigos de verificação por mensagem de texto — representa mecanismos de autenticação adicionais.

</Card>

<Card title="Autorização" icon="user-shield" iconType="solid">

A autorização confirma a permissão para executar ações específicas. Quando você adiciona colaboradores a projetos do Frame.io ou a documentos do Google, está autorizando o acesso deles. O Frame.io ou o Google já autenticaram anteriormente a identidade desses usuários, permitindo que você autorize a participação deles com confiança.

</Card>

</CardGroup>

<CardGroup cols={2}>

<Card title="OAuth" icon="lock" iconType="solid">

O OAuth (Open Authorization) fornece uma estrutura padronizada para o gerenciamento de autorizações por meio da integração com serviços de autenticação de terceiros.

</Card>

<Card title="Escopos" icon="list-check" iconType="solid">

Os escopos definem as ações autorizadas disponíveis para os usuários. Ao conectar dispositivos ao Frame.io, você solicitará e receberá escopos específicos que autorizam determinadas operações. Por exemplo, o escopo `asset_create` permite a criação e o upload de assets. Conceitualmente, os escopos funcionam como conjuntos de permissões.

</Card>

</CardGroup>
