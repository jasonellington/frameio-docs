## Introdução {#introduction}

Este guia demonstra o processo de autenticação e autorização de dispositivos Camera to Cloud (C2C) em um projeto do Frame.io. Vamos explorar tanto o método padrão de inserção manual de código quanto a abordagem aprimorada de pareamento por QR code, para uma experiência de usuário ideal.

## Do que vou precisar? {#what-will-i-need}

Se ainda não o fez, leia o guia [Antes de começar a implementar](/pt-BR/camera-to-cloud/implementing-c2c-setting-up).

Você deve ter recebido da nossa equipe um `client_secret` para identificar sua integração. Caso contrário, consulte [esta introdução](/pt-BR/camera-to-cloud/getting-started-with-cloud-device-integrations) ao ecossistema C2C e entre em contato com a nossa equipe.

### Pré-requisitos para pareamento por URL e QR code {#prerequisites-for-url-&-qr-code-pairing}

Para implementar o pareamento por URL e QR code, verifique se você atende a estes requisitos:

- **Compatibilidade do dispositivo**: verifique se o seu dispositivo é capaz de gerar URL/QR code durante o processo de pareamento.

## Percorrendo o fluxo de autenticação {#walking-through-the-auth-flow}

Para entender o fluxo de autorização do ponto de vista do usuário, consulte estes recursos:

- [Artigo de suporte](https://help.frame.io/en/collections/8960335-frame-io-c2c) sobre como adicionar novos dispositivos.
- [Vídeo de treinamento](https://help.frame.io/en/articles/5091124-camera-to-cloud-training-series) sobre como autorizar um Teradek Cube.

Esse processo de autorização minimiza os requisitos de implementação. Você não precisará:

- Redirecionar para navegadores da web (a menos que use o pareamento por código de URL)
- Lidar com a autenticação de usuários do Frame.io
- Apresentar interfaces de seleção de conta/projeto
- Desenvolver componentes de interface complexos além de exibições básicas de informações

### Melhorando a experiência do usuário com o pareamento por código de URL {#enhancing-the-user-experience-with-url-code-pairing}

Os usuários modernos esperam interações eficientes com os dispositivos. Embora o processo atual de pareamento manual funcione adequadamente, ele pode ser otimizado.

Ao implementar o pareamento por URL e QR code — semelhante ao de serviços de streaming como Netflix ou Disney+ — podemos simplificar significativamente o processo, minimizar erros de digitação e reduzir o tempo de pareamento.

## Identificação do dispositivo (client_id) {#device-identification-client_id}

Cada dispositivo físico precisa de um identificador exclusivo para o rastreamento da conexão dentro do projeto de um usuário.

Para dispositivos, esse identificador é o `client_id`, essencial durante a autorização. Ao implementar, considere fontes de identificador adequadas, como números de série do dispositivo, UUIDs ou outras strings exclusivas. Se você estiver integrando em um dispositivo Apple, recomendamos usar um UUID exclusivo e persistente, que se mantenha o mesmo entre reinicializações do dispositivo.

Tenha cuidado com informações de identificação pessoal. Endereços de e-mail de usuários não são valores apropriados para `client_id`.

Além disso, certifique-se de que você controla o identificador. Endereços MAC de dispositivos não são adequados, pois não pertencem ao seu software e podem constituir informações de identificação pessoal.

Se precisar de orientação para escolher um identificador apropriado, nossa equipe pode ajudar a determinar um valor adequado que simplifique a integração.

## Etapa 1: solicitando um código de dispositivo {#step-1-requesting-a-device-code}

Para começar a implementação, solicite um código de dispositivo por meio do endpoint `/v2/auth/device/code`:

### Método de pareamento tradicional {#traditional-pairing-method}

```
curl -X POST https://api.frame.io/v2/auth/device/code \
    --form 'client_id=[client_id]' \
    --form 'client_secret=[client_secret]' \
    --form 'scope=asset_create offline' \
    | python -m json.tool
```

### Ativando o pareamento por código de URL {#enabling-url-code-pairing}

Para o pareamento por código de URL, modifique a chamada de API com cabeçalhos adicionais:

```
curl -X POST https://api.frame.io/v2/auth/device/code \
    --header "x-client-version: 2.0.0" \
    --header "x-client-platypus-enabled: true" \  # New header to enable URL pairing
    --form 'client_id=[client_id]' \
    --form 'client_secret=[client_secret]' \
    --form 'scope=asset_create offline' \
    | python -m json.tool
```

**Observação:** esses endpoints de autenticação aceitam exclusivamente dados de formulário, não JSON. Após a autenticação, os outros endpoints aceitarão payloads JSON, mas os endpoints de autenticação rejeitarão solicitações JSON.

#### Parâmetros do payload {#payload-parameters}

- **client_id**: o identificador exclusivo do seu dispositivo físico. Deve ter unicidade garantida, como um número de série ou UUID.

- **client_secret**: fornecido pelo suporte do Frame.io para identificar o seu modelo de dispositivo. Esse valor confidencial deve permanecer protegido dos usuários e ser criptografado quando armazenado.

- **scope**: as permissões solicitadas, separadas por espaços. Os dispositivos podem solicitar:

  - `asset_create`: permite a criação e o upload de assets.
  - `offline`: permite renovar a autorização por meio de um refresh token. Sem esse escopo, os usuários precisariam reautorizar o dispositivo a cada 8 horas, pois os tokens de autorização expiram.

Nas implementações práticas, os dispositivos normalmente solicitam os dois escopos.

### Entendendo a resposta da API {#understanding-the-api-response}

A solicitação gera uma resposta semelhante a:

#### Resposta do pareamento tradicional {#traditional-pairing-response}

```
{
  "device_code": "[device_code]",
  "expires_in": 120,
  "interval": 5,
  "name": "MyDevice-[client_id]",
  "user_code": "573131"
}
```

#### Resposta do pareamento por URL {#url-pairing-response}

```
{
  "device_code": "[device_code]",
  "expires_in": 120,
  "interval": 5,
  "name": "MyDevice-[client_id]",
  "user_code": "573131",
  "verification_uri": "https://next.frame.io/pair",
  "verification_uri_complete": "https://next.frame.io/pair/573131"
}
```

#### Detalhamento da resposta {#response-breakdown}

- **device_code**: esse identificador interno deve permanecer oculto para os usuários e identifica a solicitação de autorização durante o polling.
- **expires_in**: o período de validade do código, em segundos.
- **interval**: o intervalo de polling recomendado, em segundos.
- **name**: o identificador do dispositivo que está se conectando.
- **user_code**: o código de seis dígitos para inserção manual no Frame.io para o pareamento do dispositivo.
- **verification_uri**: a URL base para inserção manual, caso a leitura do QR code não esteja disponível.
- **verification_uri_complete**: a URL completa contendo o código de pareamento, destinada a ser usada como hiperlink em um aplicativo móvel ou para gerar um QR code, simplificando a navegação do usuário até a interface de pareamento.

### Exibindo o QR code para o usuário {#displaying-the-qr-code-to-the-user}

Usando o `verification_uri_complete`, gere e exiba na tela do dispositivo um QR code para o usuário escanear, facilitando um pareamento eficiente.

#### Exemplo: tela do dispositivo com o QR code exibido {#example-device-screen-with-qr-code-displayed}

![Exemplo de tela de pareamento por QR code em um dispositivo](/images/camera-to-cloud/implementing-c2c-authentication-and-authorization/193d938af906dbcbc9699953e9da5ddbeeee8cd75fdfabf0661127c2b528cdb4.webp)

Sempre ofereça opções alternativas: exiba o `user_code` e o `verification_uri` para inserção manual quando não for possível escanear o QR code. Como alternativa, considere exibir o `verification_uri` como um QR code estático para leitura no celular.

Em integrações de aplicativos móveis, inclua o `verification_uri_complete` como um hiperlink tocável, já que os usuários não conseguem escanear QR codes a partir do dispositivo em que o aplicativo está sendo executado.

## Etapa 2: fazendo polling da autorização do usuário {#step-2-polling-for-user-authorization}

Depois de fornecer o código de pareamento ou o código de URL, verifique se o usuário o inseriu com esta solicitação:

```
curl -X POST https://api.frame.io/v2/auth/token \
    --form 'client_id=[client_id]' \
    --form 'device_code=[device_code]' \
    --form 'grant_type=urn:ietf:params:oauth:grant-type:device_code' \
    | python -m json.tool
```

### Parâmetros do payload {#payload-parameters-1}

- **client_id**: o mesmo identificador usado na Etapa 1.
- **device_code**: o valor de `device_code` retornado anteriormente.
- **grant_type**: o identificador do tipo de concessão OAuth, sempre `urn:ietf:params:oauth:grant-type:device_code` nesta implementação.

As primeiras tentativas de polling normalmente retornam:

```
{
  "error": "authorization_pending"
}
```

Esse erro não fatal indica que o usuário ainda não concluiu a inserção do código. Continue fazendo polling até a conclusão.

> **Observação para aplicativos em dispositivos iOS:** se o usuário alternar para o aplicativo do Frame.io para iOS para inserir o código de pareamento, seu aplicativo pode ir para segundo plano. Quando seu aplicativo voltar a ficar ativo, como em `applicationDidBecomeActive`, retome o polling para que o fluxo de autorização possa continuar sem exigir que o usuário reinicie o pareamento.

Se você receber:

```
{
  "error": "expired_token"
}
```

O código expirou antes que o usuário o inserisse. Gere um novo código/QR code por meio da Etapa 1, apresente-o ao usuário e retome o polling.

Uma autorização bem-sucedida produz:

```
{
  "access_token": "[access_token]",
  "expires_in": 28800,
  "refresh_token": "[refresh_token]",
  "token_type": "bearer"
}
```

Parabéns por autorizar com sucesso seu dispositivo Camera to Cloud!

Vamos examinar essa resposta:

- **access_token**: sua credencial de autenticação para acessar o back-end do Frame.io, obrigatória nos cabeçalhos das futuras solicitações à API.
- **expires_in**: o período de validade do access token, em segundos, após o qual é necessário renová-lo.
- **refresh_token**: usado para o gerenciamento do access token, principalmente para renovar a autorização, mas também aplicável à revogação.
- **token_type**: sempre `bearer` nas implementações da API C2C, sem exigir nenhuma ação.

## Juntando as etapas {#putting-the-steps-together}

Agora vamos implementar essas chamadas de API em um pseudocódigo semelhante a Python, tratando a possível expiração do código de dispositivo:

```python title="Python"
def authorize_with_frame():
    """
    Handles authorizing our device with Frame.io.
    """

    # Our client ID can be a serial number, UUID, or some other unique string.
    client_id = THIS_DEVICE.get_serial_number()

    while True:
        # Make the call to Frame.io to get our device codes.
        pairing_codes = c2c.get_device_codes(client_id)

        # We need to keep track of how long we have been polling for
        polling_started = datetime.now()

        # Now we are going to poll for authorization until the user enters the code.
        while True:

            # Re-write this output each time we poll. Note: This message will only update once
            # per `interval` (e.g., 5 seconds), so if a smooth countdown is desired, that will
            # need a different implementation.
            print(
                f"\rPAIRING CODE: {pairing_codes.user_code}, "
                f"EXPIRES IN: {pairing_codes.expires_in - (datetime.now() - polling_started).seconds} seconds"
            )

            # Wait for `interval` before polling each time.
            sleep(pairing_codes.interval)

            # Make a call to Frame.io to see if the user has entered the code and authorized
            # the device.
            authorization, error = c2c.poll_for_authorization(
                client_id, pairing_codes.device_code
            )

            if error and error.message == "authorization_pending":
                # If the authorization is pending, try again.
                continue
            elif error and error.message == "expired_token":
                # If the pairing codes have expired, break to generate new codes.
                break
            elif error:
                # If there was some other error, raise it.
                raise error
            else:
                # If there was no error, we have our authorization!
                return authorization

        # If we get here, our pairing codes expired. Let's try again.
        print("\nPairing code expired. Generating a new one...")
```

**Observação:** o loop externo trata os casos em que os códigos de pareamento expiram e novos códigos são necessários.

Como etapa final, obtenha e exiba as informações do projeto a partir do Frame.io para confirmar que o pareamento foi feito com o projeto pretendido. Abordaremos isso no próximo tutorial.

## Criando e exibindo QR codes para pareamento {#creating-and-displaying-qr-codes-for-pairing}

Ao implementar o pareamento por URL/QR code, você precisará gerar um QR code a partir do valor `verification_uri_complete` da resposta. Aqui estão exemplos usando bibliotecas populares em diferentes linguagens de programação:

### Exemplo em Python usando qrcode {#python-example-using-qrcode}

```python title="Python"
import qrcode
from PIL import Image
import io

def generate_qr_code(verification_uri_complete, size=250):
    """
    Generate a QR code from the verification_uri_complete URL.
    
    Args:
        verification_uri_complete (str): The complete verification URI returned by Frame.io
        size (int, optional): Size of the QR code in pixels. Defaults to 250.
    
    Returns:
        PIL.Image: QR code image that can be displayed or saved
    """
    qr = qrcode.QRCode(
        version=1,
        error_correction=qrcode.constants.ERROR_CORRECT_L,
        box_size=10,
        border=4,
    )
    qr.add_data(verification_uri_complete)
    qr.make(fit=True)
    
    img = qr.make_image(fill_color="black", back_color="white")
    
    # Resize the image if needed
    img = img.resize((size, size))
    return img

# Example usage in authorization flow
def display_qr_for_pairing(pairing_codes):
    """
    Generate and display QR code along with manual pairing instructions.
    """
    if hasattr(pairing_codes, 'verification_uri_complete'):
        # Generate QR code from the verification URI
        qr_img = generate_qr_code(pairing_codes.verification_uri_complete)
        
        # Display the QR code on screen
        # For GUI applications like Tkinter, PyQt, etc.
        # display_image(qr_img)
        
        # For headless devices or testing, save to file
        qr_img.save("frame_io_pairing_qr.png")
        
        print(f"Scan the QR code or visit: {pairing_codes.verification_uri}")
        print(f"Manual code: {pairing_codes.user_code}")
    else:
        # Fallback for devices that received traditional pairing response
        print(f"Enter code on Frame.io: {pairing_codes.user_code}")
```

### Exemplo em JavaScript (Web ou Electron) {#javascript-example-web-or-electron}

```javascript
import QRCode from 'qrcode';

/**
 * Generate and display a QR code from the verification URI
 * @param {string} verificationUriComplete - The complete verification URI from Frame.io
 * @param {string} elementId - ID of the HTML element to display the QR code in
 */
function displayQRCode(verificationUriComplete, elementId = 'qrcode-container') {
  const element = document.getElementById(elementId);
  
  if (!element) {
    console.error(`Element with ID ${elementId} not found`);
    return;
  }
  
  // Clear any existing content
  element.innerHTML = '';
  
  // Generate QR code
  QRCode.toCanvas(element, verificationUriComplete, { width: 250 }, function(error) {
    if (error) {
      console.error('Error generating QR code:', error);
      // Fallback to displaying the URL as a link
      element.innerHTML = `<a href="${verificationUriComplete}" target="_blank">Click here to pair</a>`;
    }
  });
  
  // Also display manual pairing information
  const manualInfoDiv = document.createElement('div');
  manualInfoDiv.innerHTML = `
    <p>Scan the QR code or <a href="${verificationUriComplete}" target="_blank">click here</a> to pair your device.</p>
    <p>Manual code: ${userCode}</p>
  `;
  element.parentNode.appendChild(manualInfoDiv);
}

// Example usage in authorization flow
async function requestDeviceCode() {
  try {
    const response = await fetch('https://api.frame.io/v2/auth/device/code', {
      method: 'POST',
      headers: {
        'x-client-version': '2.0.0',
        'x-client-platypus-enabled': 'true'
      },
      body: new URLSearchParams({
        'client_id': YOUR_CLIENT_ID,
        'client_secret': YOUR_CLIENT_SECRET,
        'scope': 'asset_create offline'
      })
    });
    
    const data = await response.json();
    
    if (data.verification_uri_complete) {
      displayQRCode(data.verification_uri_complete);
      window.userCode = data.user_code; // Store for display purposes
    } else {
      // Fallback for traditional pairing
      displayManualPairingCode(data.user_code);
    }
    
    // Begin polling for authorization
    beginPollingForAuthorization(data.device_code, data.interval);
    
  } catch (error) {
    console.error('Error requesting device code:', error);
  }
}
```

### Exemplo para Android (Java) {#android-example-java}

```java
import android.graphics.Bitmap;
import android.widget.ImageView;
import com.google.zxing.BarcodeFormat;
import com.google.zxing.MultiFormatWriter;
import com.google.zxing.common.BitMatrix;

public void generateAndDisplayQRCode(String verificationUriComplete, ImageView qrCodeImageView) {
    try {
        MultiFormatWriter multiFormatWriter = new MultiFormatWriter();
        BitMatrix bitMatrix = multiFormatWriter.encode(verificationUriComplete, 
            BarcodeFormat.QR_CODE, 250, 250);
        BarcodeEncoder barcodeEncoder = new BarcodeEncoder();
        Bitmap bitmap = barcodeEncoder.createBitmap(bitMatrix);
        
        // Display in ImageView
        qrCodeImageView.setImageBitmap(bitmap);
        
    } catch (Exception e) {
        e.printStackTrace();
        // Fallback to displaying the URL as text
    }
}
```

### Exemplo para iOS (Swift) {#ios-example-swift}

```swift
import UIKit
import CoreImage

func generateQRCode(from string: String) -> UIImage? {
    let data = string.data(using: String.Encoding.utf8)
    
    if let filter = CIFilter(name: "CIQRCodeGenerator") {
        filter.setValue(data, forKey: "inputMessage")
        filter.setValue("H", forKey: "inputCorrectionLevel")
        
        if let outputImage = filter.outputImage {
            // Scale the image
            let transform = CGAffineTransform(scaleX: 10, y: 10)
            let scaledImage = outputImage.transformed(by: transform)
            
            // Convert to UIImage
            let context = CIContext()
            if let cgImage = context.createCGImage(scaledImage, from: scaledImage.extent) {
                return UIImage(cgImage: cgImage)
            }
        }
    }
    
    return nil
}
```

## Boas práticas para exibição de QR codes {#best-practices-for-qr-code-display}

Ao implementar o pareamento por QR code, considere estas diretrizes para oferecer a melhor experiência ao usuário:

1. **Tamanho ideal**: exiba os QR codes com pelo menos 200-250 pixels de lado para uma leitura confiável.

2. **Contraste**: garanta um alto contraste entre o QR code e o fundo (preto sobre branco é o ideal).

3. **Correção de erros**: use níveis moderados de correção de erros (L ou M) para equilibrar a densidade do código e a confiabilidade.

4. **Instruções claras**: forneça orientações claras sobre como escanear o código, como “Escaneie este código com a câmera do seu smartphone para parear seu dispositivo.”

5. **Várias opções**: sempre forneça o código de pareamento manual junto com o QR code como alternativa:

   ```
   Scan to pair:
   [QR CODE]

   Or enter code manually: 573131
   ```

6. **Hiperlink para aplicativos móveis**: se a sua integração for um aplicativo móvel, inclua o `verification_uri_complete` como um link tocável, já que os usuários não conseguem escanear um QR code a partir do mesmo dispositivo.

7. **Testes**: teste seus QR codes com vários dispositivos e condições de iluminação para garantir uma leitura confiável.

## Solução de problemas {#troubleshooting}

Se você encontrar problemas, consulte estes cenários comuns e suas soluções:

- **Botão “Connect Device” não visível**: ao acessar o painel de gerenciamento do C2C, isso pode indicar:

  - **Permissões insuficientes**: se você vir uma mensagem sobre permissões, entre em contato com o gerente da sua conta para ajustar as permissões ou atribuir uma função apropriada.
  - **Conexão de dispositivo existente**: depois de conectar um dispositivo, o botão principal “Add New Device” é substituído por um menu de três pontos no canto superior direito do painel C2C Connections.

- **Erro de cliente inválido**: uma resposta `invalid_client` indica divergência nas informações do dispositivo, normalmente devido a um `client_secret` incorreto.

- **Erro de solicitação inválida**: uma resposta `bad_request` indica dados de solicitação malformados. Verifique os nomes dos campos e garanta que todos os campos obrigatórios estejam incluídos.

Se o seu problema não estiver abordado aqui, compartilhe sua experiência para que possamos aprimorar esta seção de solução de problemas.
