---
title: "Gerenciando permissões de usuários"
---

Este guia explica como gerenciar permissões de usuários com a API V4 do Frame.io. Ele aborda como as permissões funcionam nos níveis de Account, Workspace e Project, e quais endpoints usar em cada um.

---

## Níveis de permissão {#permission-levels}

As permissões no Frame.io são gerenciadas nos níveis de Account, Workspace e Project. Cada nível usa seu próprio conjunto de funções:

```
Account 
│
├── (admin)  - full access to all Workspaces, Projects, and Restricted Projects
│
└── (member)
        │
        ├── Workspace - (full_access | editor | edit_only | commenter | viewer)
        │       │
        │       └── Project - (full_access | editor | edit_only | commenter | viewer)
        │
        └── Restricted Project - (members require direct invite)
```

Todo usuário tem uma função na conta. Pela API, você pode definir a função de um usuário como <Tooltip tip="Você pode ver Owner e Reviewer nas respostas da API, mas essas funções não podem ser configuradas pela API. Mais detalhes sobre isso estão na seção Permissões no nível da conta.">`admin` ou `member`.</Tooltip>
Os Account Admins têm acesso total a todos os Workspaces e Projects. Os Account Members podem ser adicionados seletivamente aos Workspaces e Projects de que precisam.

Quando você adiciona um Account Member a um Workspace, o nível de permissão atribuído (`full_access`, `editor`, `edit_only`, `commenter` ou `viewer`) se aplica a todos os Projects existentes e futuros dentro dele. Por exemplo, se você adicionar um Account Member como `viewer`, ele terá permissões de `viewer` sempre que acessar qualquer Project nesse Workspace.

Esse mesmo Account Member pode ser adicionado a um Project específico dentro desse Workspace como `editor`. Como resultado, sempre que acessar esse Project, ele terá permissões de `editor`. As permissões de `viewer` continuam valendo para todos os outros Projects desse Workspace.

Como as atribuições de Project são separadas das atribuições de Workspace, se você remover esse Account Member do Workspace, ele manterá as permissões de `editor` nesse Project específico.

Os Restricted Projects são a exceção. Os Account Members sempre precisam de um convite direto. Saiba mais na seção Permissões no nível do Project, abaixo.

## Permissões no nível da conta {#account-level-permissions}

Todo usuário da sua conta tem uma função:

| Função | Permissões | Configurável via API | Endpoint |
| --- | --- | --- | --- |
| Owner | Acesso total a todos os Workspaces e Projects. Um por conta | Não | — |
| <Tooltip tip="Chamado de 'Content Admin' na interface">`admin`</Tooltip> | Acesso total a todos os Workspaces e Projects | Sim | `PATCH /accounts/:account_id/users/:user_id` |
| `member` | Permissões definidas no nível do Workspace e/ou do Project | Sim | `PATCH /accounts/:account_id/users/:user_id` |
| Reviewer | Acesso somente por meio de links de compartilhamento. Criado quando um usuário é adicionado a um compartilhamento seguro | <Tooltip tip="Os Reviewers aparecem nas listas de usuários da conta porque se autenticam no Frame.io, mas ficam fora do sistema de permissões de Workspace e Project. Eles acessam o conteúdo somente por meio de links de compartilhamento seguros.">Não</Tooltip> | — |

---

Os Account Admins têm acesso total em todos os lugares. Para limitar o acesso de um Admin a recursos específicos, primeiro altere a função dele na conta para Member e, em seguida, adicione-o aos Workspaces ou Projects de que ele precisa.

Por exemplo:

<Steps>

<Step title="Liste as funções dos usuários da conta para encontrar o ID do usuário e confirmar a função atual:">

```bash

curl https://api.frame.io/v4/accounts/:account_id/users \
     -H "Authorization: Bearer <token>"
```

</Step>

<Step title="Atualize a função na conta para Member:">

```bash

curl -X PATCH https://api.frame.io/v4/accounts/:account_id/users/:user_id \
 -H "Authorization: Bearer <token>" \
 -H "Content-Type: application/json" \
 -d '{
"data": {
"role": "member"
}
}'
```

</Step>

<Step title="Adicione o usuário a um Project:">

```bash

curl -X PATCH https://api.frame.io/v4/accounts/:account_id/projects/:project_id/users/:user_id \
  -H "Authorization: Bearer <token>" \
  -H "Content-Type: application/json" \
  -d '{
"data": {
 "role": "edit_only"
}
}'
```

</Step>

</Steps>

## Permissões no nível do Workspace {#workspace-level-permissions}

Quando você adiciona um Account Member a um Workspace, ele passa a ter esse nível de permissão em todos os Projects dentro dele. Os Workspaces são acessíveis somente por convite, então os Account Members veem apenas os Workspaces aos quais foram adicionados.

<br />

| Função | Permissões |
| --- | --- |
| `full_access` | Enviar, gerenciar, compartilhar, comentar, visualizar, baixar, gerenciar configurações e convidar usuários |
| `editor` | Enviar, gerenciar, compartilhar, comentar, visualizar, baixar |
| `edit_only` | Enviar, gerenciar, comentar, visualizar. Não pode compartilhar nem baixar |
| `commenter` | Visualizar e comentar |
| `viewer` | Somente visualizar |

<br />

## Permissões no nível do Project {#project-level-permissions}

Os Projects usam os mesmos níveis de permissão que os Workspaces. Adicione um usuário diretamente a um Project quando ele precisar de acesso somente a esse Project específico ou quando precisar de um nível de permissão diferente do atribuído no Workspace. Os usuários não precisam ter acesso ao Workspace para serem adicionados a um Project.

<br />

| Função | Permissões |
| --- | --- |
| `full_access` | Enviar, gerenciar, compartilhar, comentar, visualizar, baixar, gerenciar configurações e convidar usuários |
| `editor` | Enviar, gerenciar, compartilhar, comentar, visualizar, baixar |
| `edit_only` | Enviar, gerenciar, comentar, visualizar. Não pode compartilhar nem baixar |
| `commenter` | Visualizar e comentar |
| `viewer` | Somente visualizar |

<br />

**Exemplo: adicionar um usuário a um Project**

```bash

curl -X PATCH https://api.frame.io/v4/accounts/:account_id/projects/:project_id/users/:user_id \
     -H "Authorization: Bearer <token>" \
     -H "Content-Type: application/json" \
     -d '{
  "data": {
    "role": "full_access"
  }
}'
```

---

### Restricted Projects {#restricted-projects}

Os Restricted Projects exigem um convite direto. O acesso ao Workspace não é herdado,
então os usuários só podem acessar um Restricted Project se tiverem sido adicionados diretamente a ele.

Para conceder acesso a um Member, adicione-o ao Project com o nível de permissão adequado.

<Note>

Os Account Admins e Owners são a exceção e têm acesso a todos os
Restricted Projects.

</Note>
