title: "Links de mídia"
---

O Frame.io armazena e processa os arquivos enviados aos seus projetos — imagens, vídeos, PDFs e muito mais. Ao recuperar um arquivo pela API, a resposta básica inclui metadados principais, como o nome do arquivo, o status e uma `view_url` para abri-lo no app do Frame.io. Para acessar o conteúdo real do arquivo — o original, uma prévia ou renditions de diferentes qualidades — você usa **includes**.

Este guia explica os includes de links de mídia disponíveis nos endpoints **List Files** e **Get File**, o que cada um retorna e quando usar cada um.

## O que são includes? {#what-are-includes}

Includes são campos opcionais que você pode solicitar junto com a resposta de um arquivo. Por padrão, a API retorna apenas os metadados principais do arquivo — nome, status, tipo, timestamps e `view_url`. Os includes permitem optar por dados adicionais, mantendo as respostas enxutas quando você não precisa de tudo.

### Como adicionar includes {#how-to-add-includes}

Passe uma lista de nomes de includes separados por vírgula no parâmetro de consulta `include` de qualquer requisição **Get File** ou **List Files**:

```bash title="Single include"
GET /v4/accounts/{account_id}/files/{file_id}?include=media_links.thumbnail
```

```bash title="Multiple includes"
GET /v4/accounts/{account_id}/files/{file_id}?include=media_links.thumbnail,media_links.original
```

```bash title="Includes on List Files"
GET /v4/accounts/{account_id}/folders/{folder_id}/files?include=media_links.thumbnail
```

Os includes funcionam da mesma forma tanto no endpoint de arquivo único quanto no de listagem. Quando usados em List Files, os includes são resolvidos para cada arquivo da resposta.

### Exemplos com SDK {#sdk-examples}

<CodeGroup>

```python title="Python SDK"
import frameio

client = frameio.Frameio(auth="<YOUR_TOKEN>")

file = client.files.get(
    file_id="93e4079d-0a8a-4bf3-96cd-e6a03c465e5e",
    include=["media_links.thumbnail", "media_links.original"]
)

print(file.media_links.thumbnail.url)
```

```typescript title="TypeScript SDK"
import Frameio from "frameio";

const client = new Frameio({ auth: "<YOUR_TOKEN>" });

const file = await client.files.get("93e4079d-0a8a-4bf3-96cd-e6a03c465e5e", {
  include: ["media_links.thumbnail", "media_links.original"],
});

console.log(file.media_links?.thumbnail?.url);
```

</CodeGroup>

Os includes que não forem solicitados são totalmente omitidos da resposta.

## media_links.original {#media_links-original}

Retorna URLs assinadas que apontam para o **arquivo original exatamente como foi enviado** — sem processamento, sem conversão.

### Campos {#fields}

| Campo | Tipo | Descrição |
| --- | --- | --- |
| `download_url` | string \| null | URL assinada que força o download do arquivo (`Content-Disposition: attachment`) |
| `inline_url` | string \| null | URL assinada que abre o arquivo diretamente no navegador (`Content-Disposition: inline; filename=<name>`) |

### Quando usar {#when-to-use}

Use `media_links.original` quando precisar do arquivo de origem — por exemplo, para permitir que um usuário baixe o MOV, MP4, MXF, AVI, PSD, PNG ou TIFF original, ou para passar os bytes originais para outro sistema.

### Exemplo de requisição {#example-request}

```bash
GET /v4/accounts/{account_id}/files/{file_id}?include=media_links.original
```

### Exemplo de resposta {#example-response}

```json
{
  "data": {
    "id": "93e4079d-0a8a-4bf3-96cd-e6a03c465e5e",
    "name": "hero-banner.png",
    "type": "file",
    "media_links": {
      "original": {
        "download_url": "https://s3.amazonaws.com/...",
        "inline_url": "https://s3.amazonaws.com/..."
      }
    }
  }
}
```

<Warning>

Essas URLs são **URLs assinadas temporárias do S3** — elas expiram. Não as armazene em cache nem as guarde; solicite uma URL nova sempre que precisar.

</Warning>

## media_links.thumbnail {#media_links-thumbnail}

Retorna uma **imagem de prévia em PNG** do asset, com altura máxima de 540px. Esta é uma rendition processada — não o arquivo original — e marcas d'água podem ser aplicadas, dependendo das configurações da sua conta.

### Campos {#fields-1}

| Campo | Tipo | Descrição |
| --- | --- | --- |
| `download_url` | string \| null | URL assinada que força o download da miniatura em PNG |
| `url` | string \| null | URL assinada que serve a miniatura em PNG inline, sem cabeçalho `Content-Disposition` |

### Quando usar {#when-to-use-1}

Use `media_links.thumbnail` quando precisar **exibir uma prévia visual** do asset — por exemplo, em uma visualização em grade, uma galeria ou um seletor de arquivos. Ela carrega mais rápido que o original e está sempre em formato PNG compatível com a web.

### Exemplo de requisição {#example-request-1}

```bash
GET /v4/accounts/{account_id}/files/{file_id}?include=media_links.thumbnail
```

### Exemplo de resposta {#example-response-1}

```json
{
  "data": {
    "id": "93e4079d-0a8a-4bf3-96cd-e6a03c465e5e",
    "name": "hero-banner.png",
    "type": "file",
    "media_links": {
      "thumbnail": {
        "download_url": "https://s3.amazonaws.com/...",
        "url": "https://s3.amazonaws.com/..."
      }
    }
  }
}
```

## media_links.high_quality {#media_links-high_quality}

Retorna uma URL de download para a **melhor rendition processada disponível** do asset. O Frame.io processa os uploads por meio de uma escala de resoluções que chega a no máximo 2160p. A API retorna a rendition mais alta disponível **no momento da requisição** — portanto, se apenas uma rendition de 540p tiver terminado de ser processada quando você fizer a requisição, a API retornará 540p até que renditions mais altas estejam prontas.

### Campos {#fields-2}

| Campo | Tipo | Descrição |
| --- | --- | --- |
| `download_url` | string \| null | URL assinada da rendition de mais alta qualidade disponível no momento da requisição |

### Quando usar {#when-to-use-2}

Use `media_links.high_quality` quando quiser a **versão de melhor qualidade sem precisar do original** — por exemplo, para exportar uma rendition em alta resolução para processamento posterior ou apresentar uma prévia em resolução total. Se você precisar da maior qualidade possível, verifique o campo `status` do arquivo e solicite este include quando o arquivo estiver `ready`, para garantir que toda a escala de resoluções tenha sido processada.

### Exemplo de requisição {#example-request-2}

```bash
GET /v4/accounts/{account_id}/files/{file_id}?include=media_links.high_quality
```

### Exemplo de resposta {#example-response-2}

```json
{
  "data": {
    "id": "93e4079d-0a8a-4bf3-96cd-e6a03c465e5e",
    "name": "hero-banner.png",
    "type": "file",
    "media_links": {
      "high_quality": {
        "download_url": "https://s3.amazonaws.com/..."
      }
    }
  }
}
```

## media_links.efficient {#media_links-efficient}

Retorna uma URL de download para a **menor rendition processada disponível**. É o oposto de `high_quality` — o Frame.io escolhe a rendition de menor resolução disponível.

### Campos {#fields-3}

| Campo | Tipo | Descrição |
| --- | --- | --- |
| `download_url` | string \| null | URL assinada da rendition menor/mais eficiente |

### Quando usar {#when-to-use-3}

Use `media_links.efficient` quando **a largura de banda ou o tamanho do arquivo importarem mais que a qualidade** — por exemplo, para gerar prévias rápidas em um ambiente com pouca largura de banda ou alimentar um pipeline de miniaturas que não precisa de resolução total.

### Exemplo de requisição {#example-request-3}

```bash
GET /v4/accounts/{account_id}/files/{file_id}?include=media_links.efficient
```

### Exemplo de resposta {#example-response-3}

```json
{
  "data": {
    "id": "93e4079d-0a8a-4bf3-96cd-e6a03c465e5e",
    "name": "hero-banner.png",
    "type": "file",
    "media_links": {
      "efficient": {
        "download_url": "https://s3.amazonaws.com/..."
      }
    }
  }
}
```

## media_links.video_h264_180 {#media_links-video_h264_180}

Retorna URLs de streaming e download para uma **transcodificação de vídeo H264 de baixa resolução em 180p** do asset.

<Warning>

Este é um include legado. Ele será `null` se nenhuma transcodificação em 180p tiver sido gerada para o asset. Para a maioria dos casos de uso, prefira `media_links.efficient`, que seleciona a melhor rendition de baixa qualidade disponível em vez de depender da existência de uma transcodificação específica.

</Warning>

### Campos {#fields-4}

| Campo | Tipo | Descrição |
| --- | --- | --- |
| `download_url` | string \| null | URL assinada para baixar o vídeo H264 em 180p |
| `url` | string \| null | URL assinada para fazer streaming do vídeo H264 em 180p |

### Quando usar {#when-to-use-4}

Use `media_links.video_h264_180` quando precisar especificamente de uma transcodificação H264 em 180p garantida — por exemplo, para integrar com um player ou pipeline legado que exige exatamente esse formato. Se a transcodificação não existir para um determinado asset, ambas as URLs serão `null`.

<Warning>

O arquivo video_h264_180 não inclui áudio. Ele se destina a ser usado para prévias muito eficientes, quando necessário.

</Warning>

### Exemplo de requisição {#example-request-4}

```bash
GET /v4/accounts/{account_id}/files/{file_id}?include=media_links.video_h264_180
```

### Exemplo de resposta {#example-response-4}

```json
{
  "data": {
    "id": "93e4079d-0a8a-4bf3-96cd-e6a03c465e5e",
    "name": "interview-clip.mp4",
    "type": "file",
    "media_links": {
      "video_h264_180": {
        "download_url": "https://s3.amazonaws.com/...",
        "url": "https://s3.amazonaws.com/..."
      }
    }
  }
}
```

## media_links.scrub_sheet {#media_links-scrub_sheet}

Retorna uma **sprite sheet WebP** — uma única imagem contendo uma grade de miniaturas de quadros do vídeo, amostrados de forma uniforme ao longo da duração do vídeo. Ela é usada para criar interfaces de scrubbing de vídeo, em que o player exibe um quadro de prévia enquanto o usuário arrasta pela linha do tempo.

<Info>

As scrub sheets são geradas **somente para assets de vídeo**. O include retornará URLs `null` para imagens, PDFs e outros arquivos que não sejam de vídeo.

</Info>

### Campos {#fields-5}

| Campo | Tipo | Descrição |
| --- | --- | --- |
| `download_url` | string \| null | URL assinada para baixar a sprite sheet WebP |
| `url` | string \| null | URL assinada para carregar a sprite sheet WebP inline |
| `metadata` | object \| null | Informações de layout dos blocos para extrair quadros individuais (somente na API experimental) |

**Campos de `metadata`:**

| Campo | Tipo | Descrição |
| --- | --- | --- |
| `tile_x` | integer | Número de colunas de miniaturas na grade |
| `tile_y` | integer | Número de linhas de miniaturas na grade |
| `thumb_width` | integer | Largura de cada miniatura em pixels |
| `thumb_height` | integer | Altura de cada miniatura em pixels |
| `padding` | integer | Espaço em pixels entre as miniaturas |
| `frames` | integer | Número total de quadros amostrados na sheet |

### Quando usar {#when-to-use-5}

Use `media_links.scrub_sheet` ao criar um player de vídeo ou uma interface de linha do tempo personalizados que precisem exibir uma miniatura de prévia enquanto o usuário faz scrubbing. Em vez de fazer uma requisição separada para cada quadro, a sprite sheet reúne todos os quadros de prévia em um único download de imagem.

### Exemplo de requisição {#example-request-5}

```bash
GET /v4/accounts/{account_id}/files/{file_id}?include=media_links.scrub_sheet
```

### Exemplo de resposta {#example-response-5}

```json
{
  "data": {
    "id": "93e4079d-0a8a-4bf3-96cd-e6a03c465e5e",
    "name": "interview-clip.mp4",
    "type": "file",
    "media_links": {
      "scrub_sheet": {
        "download_url": "https://assets.frame.io/...",
        "url": "https://assets.frame.io/...",
        "metadata": {
          "tile_x": 10,
          "tile_y": 10,
          "thumb_width": 160,
          "thumb_height": 90,
          "padding": 1,
          "frames": 100
        }
      }
    }
  }
}
```

### Extraindo um quadro da sprite sheet {#extracting-a-frame-from-the-sprite-sheet}

A sprite sheet é uma grade de `tile_x` colunas × `tile_y` linhas. Para exibir a miniatura de um determinado índice de quadro (começando em zero), calcule a posição dele dentro da imagem:

```javascript
function getFrameOffset(frameIndex, metadata) {
  const { tile_x, thumb_width, thumb_height, padding } = metadata;

  const col = frameIndex % tile_x;
  const row = Math.floor(frameIndex / tile_x);

  return {
    x: col * (thumb_width + padding),
    y: row * (thumb_height + padding),
    width: thumb_width,
    height: thumb_height,
  };
}
```

Em seguida, você pode usar o `background-position` do CSS para exibir o bloco correto da sprite sheet:

```javascript
function applyFrameToElement(el, frameIndex, scrubSheet) {
  const { x, y, width, height } = getFrameOffset(frameIndex, scrubSheet.metadata);

  el.style.backgroundImage = `url(${scrubSheet.url})`;
  el.style.backgroundPosition = `-${x}px -${y}px`;
  el.style.width = `${width}px`;
  el.style.height = `${height}px`;
}
```

Para mapear uma posição de reprodução (em segundos) para um índice de quadro, use a duração total do vídeo e o número de quadros na sheet:

```javascript
function positionToFrameIndex(currentSeconds, durationSeconds, metadata) {
  const progress = currentSeconds / durationSeconds;
  return Math.min(
    Math.floor(progress * metadata.frames),
    metadata.frames - 1
  );
}
```

<Info>

O campo `metadata` está disponível somente na versão experimental da API. Na API v4 estável, `scrub_sheet` retorna apenas `download_url` e `url`.

</Info>

## Combinando vários includes {#combining-multiple-includes}

Você pode solicitar vários includes em uma única chamada à API:

```bash
GET /v4/accounts/{account_id}/files/{file_id}?include=media_links.thumbnail,media_links.original
```

```json
{
  "data": {
    "id": "93e4079d-0a8a-4bf3-96cd-e6a03c465e5e",
    "name": "hero-banner.png",
    "type": "file",
    "media_links": {
      "thumbnail": {
        "download_url": "https://s3.amazonaws.com/...",
        "url": "https://s3.amazonaws.com/..."
      },
      "original": {
        "download_url": "https://s3.amazonaws.com/...",
        "inline_url": "https://s3.amazonaws.com/..."
      }
    }
  }
}
```

## Escolhendo o include certo {#choosing-the-right-include}

| Objetivo | Include a usar |
| --- | --- |
| Exibir uma imagem de prévia na sua interface | `media_links.thumbnail` |
| Permitir que um usuário baixe o arquivo original | `media_links.original` |
| Abrir o arquivo original diretamente no navegador | `media_links.original` → `inline_url` |
| Obter a rendition de melhor qualidade para exportação | `media_links.high_quality` |
| Obter uma rendition pequena para uso com pouca largura de banda | `media_links.efficient` |
| Fazer streaming ou baixar um vídeo de baixa resolução (legado) | `media_links.video_h264_180` |
| Criar uma interface de scrubbing de vídeo com prévias de quadros | `media_links.scrub_sheet` |
| Levar um usuário ao arquivo no Frame.io | Use a `view_url` da resposta básica do arquivo |

<Info>

A `view_url` — disponível em toda resposta de arquivo sem precisar de um include — é um deep link permanente para o app web do Frame.io. Ela **não** é uma URL de mídia; ela abre a interface do Frame.io e não expira. Use-a quando quiser direcionar um usuário para revisar ou comentar um asset diretamente no Frame.io, e não quando precisar servir ou baixar o arquivo programaticamente.

</Info>

## Disponibilidade dos includes {#include-availability}

Os includes de links de mídia só são preenchidos depois que o Frame.io termina de processar o arquivo enviado. Se você solicitar um include imediatamente após o upload, as URLs podem ser `null` enquanto a transcodificação estiver em andamento. Verifique o campo `status` no objeto do arquivo — os includes estarão disponíveis quando o status for `ready`.
