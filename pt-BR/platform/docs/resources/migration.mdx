## Introdução {#introduction}

A API Frame.io V4 é uma reformulação da API Legacy, frequentemente chamada de *endpoints V2* ou *API Frame.io V3*. A reformulação aproveita ao máximo os novos recursos e funcionalidades do Frame V4, mantendo todas as funcionalidades relevantes da API Legacy. Este guia descreve as principais diferenças entre as APIs Legacy e V4 e oferece orientações passo a passo para ajudar você a migrar sem complicações.

## Checklist de migração {#migration-checklist}

<Steps>

<Step title="Autenticação">

Para <Tooltip tip="Contas que usavam a API Legacy com um token de desenvolvedor gerado e foram migradas automaticamente para a V4. Contas criadas na V4 ou migradas manualmente não estão incluídas">**contas migradas automaticamente para a V4**</Tooltip> que ainda não são administradas pelo Adobe Admin Console, você pode continuar usando os tokens de desenvolvedor Legacy gerenciados no [site para desenvolvedores do Frame.io](/pt-BR/platform/welcome), mas precisará adicionar às suas solicitações à API um cabeçalho com a chave `x-frameio-legacy-token-auth` e o valor `true`. Caso contrário, siga as etapas da seção [Autenticação](#adobe-developer-console-managed-authentication) abaixo.

</Step>

<Step title="Atualizar as chamadas de API existentes">

Todas as rotas da API Legacy precisarão ser mapeadas para as novas rotas e payloads JSON da API V4. Há uma tabela de [mapeamento](#endpoint-mappings-legacy-api-to-v4) bastante abrangente abaixo para ajudar nesse processo.

</Step>

<Step title="Testes são altamente recomendados">

**Teste minuciosamente.** Como há muitas mudanças na API, recomendamos testar com uma conta V4 para garantir que a nova API esteja funcionando conforme o esperado.

</Step>

<Step title="Implementar um login dedicado">

Implemente um método de login dedicado para a V4, já que as URLs de autenticação são separadas. A URL de autenticação da V4 é diferente da URL da API Legacy, não retorna na resposta as contas que ainda não foram atualizadas para a V4 e deve ser tratada como uma integração separada.

</Step>

</Steps>

<Note>

Se houver algum endpoint que não esteja listado na tabela de mapeamento abaixo e sobre o qual você tenha dúvidas, entre em contato com nossa equipe de suporte em [support@frame.io](mailto:support@frame.io).

</Note>

## Autenticação gerenciada pelo Adobe Developer Console {#adobe-developer-console-managed-authentication}

Para contas migradas para a V4 que são gerenciadas pelo [Adobe Developer Console](https://developer.adobe.com/developer-console/), você precisará usar a API V4 com OAuth 2.0. Siga as etapas abaixo.

<Steps>

<Step title="Criar um projeto Adobe">

**Crie um projeto no Adobe Developer Console** e adicione o Frame.io como produto.

</Step>

<Step title="Escolher o tipo de autenticação">

**Autentique-se.** Consulte o [Guia de autenticação](https://developer.adobe.com/frameio/guides/Authentication/) para obter mais informações. Se a sua conta V4 ainda não for gerenciada pelo Adobe Admin Console, você pode pular esta etapa.

- **Autenticação de usuário**: conecta-se ao Frame usando um Client ID e/ou Client Secret e exige que um usuário faça login com seu nome de usuário e senha.
- **Autenticação servidor a servidor**: conecta-se ao Frame usando Client ID e Client Secret, mas não exige a participação de um usuário para fazer login pelo navegador.

</Step>

<Step title="Implementar a autenticação Bearer">

**Autenticação JWT Bearer**: em cada solicitação à API, passe o token de autenticação por meio de um cabeçalho com a chave `Authorization` e o valor `Bearer <IMS_ACCESS_TOKEN>`.

</Step>

</Steps>

## Mapeamento de endpoints (API Legacy para V4) {#endpoint-mappings-legacy-api-to-v4}

<Note>

Se você usa a autenticação com token de desenvolvedor legado, precisará adicionar às suas solicitações à API um cabeçalho com a chave x-frameio-legacy-token-auth e o valor true.

</Note>

Observações gerais para ajudar na migração:

<Steps>

<Step title="Payloads">

Os payloads de solicitação e resposta podem ser diferentes.

</Step>

<Step title="Teams → Workspaces">

”Teams” na API Legacy equivalem a “Workspaces” na V4.

</Step>

<Step title="Assets">

”Assets” na API Legacy agora estão divididos em “Files”, “Folders” e “Version Stacks” na V4.

</Step>

<Step title="Permissões">

As permissões e funções são diferentes na V4, o que altera a estrutura dos endpoints. Na V4, existem funções de usuário de workspace e de projeto. Para mais detalhes, consulte [Gerenciar permissões de usuários](/pt-BR/platform/docs/guides/managing-user-permissions).

</Step>

</Steps>

### 8. Compartilhamentos (review links / apresentações) {#8-shares-review-links-/-presentations}

No Frame V4, os links de compartilhamento não são mais divididos entre review links e presentation links. Na V4, o link de compartilhamento agora pode ser configurado com estilos diferentes para corresponder à experiência de revisão ou de apresentação.

Observação: não é possível interagir com review links e presentations legados pela API V4.

### 9. Webhooks {#9-webhooks}

Os webhooks que você usava na V3 serão migrados e, na maior parte, funcionarão da mesma forma. Na migração, eles serão desativados e precisarão ser ativados para funcionar. Serão necessárias algumas alterações para eventos de assets, que agora estão divididos entre arquivos e pastas. Há alguns novos eventos específicos da V4 aos quais você deve ficar atento: metadata.value.updated, eventos relacionados a coleções e eventos relacionados a shares.

Antes de reativar os webhooks migrados, consulte os [limites de taxa de webhooks](/pt-BR/platform/docs/guides/webhooks#webhook-rate-limits). Os eventos de webhooks e de Custom Actions da V4 compartilham limites de **1.000 eventos por minuto** e **20.000 eventos por hora**, por conta. Ambos os limites se aplicam ao volume combinado em toda a conta.

## Etapas da migração {#migration-steps}

<Steps>

<Step title="Ajustar endpoints V2 não compatíveis">

**Ajuste** todos os endpoints Legacy V2 não compatíveis.

</Step>

<Step title="Atualizar as URLs base">

**Atualize as URLs base** de `api.frame.io/v2/...` para `api.frame.io/v4/...`.

</Step>

<Step title="Atualizar as solicitações à API">

**Atualize as solicitações à API** no seu código para que façam referência ao novo esquema de endpoints.

</Step>

<Step title="Atualizar os payloads JSON">

**Atualize os payloads JSON** dos esquemas de solicitação/resposta para garantir que você esteja produzindo e consumindo os campos corretos.

</Step>

<Step title="Atualizar a terminologia">

Atualize a terminologia: “teams” → “workspaces”; “assets” → “files/folders”; “review links” ou “presentation links” → “shares” no seu código e no seu front-end.

</Step>

<Step title="Testar os endpoints">

**Teste** todos os endpoints recém-atualizados. Se você receber 403, 404 ou 422, confirme os endpoints, o formato do payload da solicitação etc.

</Step>

<Step title="Analisar as respostas de erro">

**Analise** as novas respostas de erro detalhadas, procurando o problema na resposta JSON `{"errors": [...]}` caso sua chamada à API falhe.

</Step>

<Step title="Implantar em produção">

**Implante** em produção depois de validar com uma conta V4 do [Frame.io](http://frame.io/).

</Step>

</Steps>

## Tratamento de erros e problemas comuns {#error-handling-&-common-issues}

<Note>

Algumas rotas retornam erros com descrições personalizadas que podem ser ligeiramente diferentes dos exemplos abaixo.

</Note>

<CardGroup cols={2}>

<Card title="Erros do cliente (4xx)" icon="triangle-exclamation" iconType="solid">

- **400** Bad Request: verifique a exatidão do payload.
- **401** Unauthorized: token de autorização inválido ou ausente.
- **403** Forbidden: scope ausente ou o usuário não tem acesso.
- **404** Not Found: confirme o endpoint, a versão da API ou os IDs.
- **422** Unprocessable Entity: valide os dados da solicitação
- **429** Too Many Requests: implemente novas tentativas com backoff.

</Card>

<Card title="Erros do servidor (5xx)" icon="server" iconType="solid">

- **500** Internal Server Error: tente novamente após um breve intervalo.

</Card>

</CardGroup>
