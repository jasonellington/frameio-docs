title: "Frame.io MCP"
---

Frame.io MCP 托管于 `https://mcp.frame.io/v1/mcp`，可将 Claude、ChatGPT、Cursor、VS Code 和 GitHub Copilot 等兼容 MCP 的客户端连接到您的 Frame.io 账户。连接后，您就可以借助 AI 智能体来驱动您在 Frame.io 中的各项操作。

本指南介绍 MCP 的工作原理、如何连接到它，以及运行后它能做什么，并附有工具参考和示例提示词，帮助您快速上手。如果您刚接触 MCP，下一节会在介绍连接步骤之前先讲解该协议。

---

## Model Context Protocol {#model-context-protocol}

MCP 是由 Anthropic 创建的开放标准，用于将 AI 客户端连接到外部系统。已连接的系统会公开一组工具，即 AI 智能体可以调用的操作。当您发出请求时，智能体会选择合适的工具、调用服务器，并使用响应来完成请求。

有关 MCP 的更多信息，请参阅 Anthropic 的[最初发布公告](https://www.anthropic.com/news/model-context-protocol)。

---

## 工作原理 {#how-it-works}

### 架构 {#architecture}

```
┌───────────────┐        ┌─────────────────────┐        ┌───────────────┐
│   AI Agent    │        │     Frame.io MCP    │        │ Frame.io API  │
│(Claude, etc.) │◀──────▶│  mcp.frame.io/mcp   │◀──────▶│ api.frame.io  │
└───────────────┘        └──────────┬──────────┘        └───────────────┘
                                    │
                           ┌────────┴────────┐
                           │   Adobe Login   │
                           │  (OAuth 2.0)    │
                           └─────────────────┘
```

---

### 身份验证 {#authentication}

身份验证通过 Adobe IMS 使用 OAuth 2.0，并需要一个与您的 Frame.io 账户关联的 Adobe ID。MCP 不支持 Frame.io Legacy 账户。

每个客户端都有各自独特的连接步骤（详见下文），但基本流程如下：身份验证仅在首次连接时运行一次，之后 MCP 会自动处理令牌刷新。您会被重定向到 Adobe 登录屏幕进行登录并授权访问，然后返回 AI 智能体，此时连接已激活。

工具调用以您的 Frame.io 权限运行。MCP 只能执行您的账户角色已允许的操作，因此试图超出您访问权限的工具会返回权限错误，而不会执行该操作。有关角色与功能的对应关系，请参阅[管理用户权限](/cn/platform/docs/guides/managing-user-permissions)。

#### Adobe Managed Accounts（AMA）与 Frame Managed Accounts（FMA） {#adobe-managed-accounts-ama-and-frame-managed-accounts-fma}

Frame.io 有两种以不同方式管理的用户账户类型，这在身份验证过程中很重要。完整说明请参阅 [Frame Managed 与 Adobe Managed 账户](https://help.frame.io/en/articles/13719174-frame-managed-vs-adobe-managed-accounts)。

**Frame Managed Accounts（FMA）**直接在 Frame.io 中创建和管理。在 IMS 提示时使用您的 Adobe 凭据登录并授权访问，即可完成连接。

**Adobe Managed Accounts（AMA）**通过 Adobe Admin Console 进行管理，通常面向企业团队。与 FMA 一样，身份验证也通过 IMS 进行，但关键区别在于，同一个 Adobe 身份可以属于多个组织（有时标记为账户或账户配置文件）。您通过哪个组织进行身份验证，决定了 MCP 可以访问哪个 Frame.io 账户。

当 OAuth 流程在浏览器中打开时，Adobe IMS 会检查您是否已登录。如果已登录，它会复用该会话，而不会要求您选择配置文件。如果该会话所属的组织与您的 Frame.io 账户所关联的组织不同，您虽然会成功通过身份验证，但会进入错误的位置。MCP 可以无错误地连接，但 Frame.io API 调用会返回空结果或权限错误。

如果您使用的是 AMA，并在连接后遇到这种情况，请参阅"故障排除"中的 [AMA 多账户身份验证错误](#ama-multi-account-authentication-errors)。

---

连接需要一个关联了 Adobe ID 的有效 Frame.io 账户（有关连接 Adobe 身份验证的更多信息，请参阅[此处](https://help.frame.io/en/articles/11758018-connecting-to-adobe-authentication)）。

## 连接到 Claude {#connecting-to-claude}

以下步骤适用于 Claude Desktop。Claude 也可在 Web、iOS、Cowork 和 Code Desktop 上使用。请参阅 [Anthropic 的连接器文档](https://support.claude.com/en/articles/11176164-use-connectors-to-extend-claude-s-capabilities)，确认您所使用平台的设置步骤。

<Steps>

<Step title="打开连接器">

在 Claude Desktop 中，从菜单栏打开 **Customize**。在左侧边栏中选择 **Connectors**，然后点击 Connectors 面板右上角的 **+**。

</Step>

<Step title="输入服务器详细信息">

在 **Add custom connector** 对话框中，填写以下两个字段：

```
  Name: Frame.io
  URL: https://mcp.frame.io/v1/mcp
```

点击 **Add**。

</Step>

<Step title="进行身份验证">

Frame.io 会出现在 **Not connected** 部分，并带有 **CUSTOM** 标签。点击右侧面板中的 **Connect**。您将被带到 Adobe IMS。使用与您的 Frame.io 账户关联的 Adobe ID 登录。授权后，您将返回 Claude Desktop。

</Step>

<Step title="检查工具权限">

完成身份验证后，Frame.io 会移至 **Web** 部分。右侧面板会列出工具，分为 **Interactive tools** 和 **Read-only tools**。

每组都有一个权限设置，默认为 **Needs approval**。点击下拉菜单进行更改：

| 设置 | 行为 |
| --- | --- |
| Always allow | Claude 调用工具时不会提示 |
| Needs approval | Claude 在每次调用工具前都会暂停并询问 |
| Blocked | Claude 无法使用这些工具 |
| Custom | 按工具单独配置权限 |

只读工具可以放心设置为 **Always allow**。在您阅读下方的[工具审批设置](#tool-approval-settings)部分之前，请将所有其他工具保持为 **Needs approval**。

有关更多详细信息，请参阅 Claude 关于[连接器权限](https://support.claude.com/en/articles/11176164-use-connectors-to-extend-claude-s-capabilities)的文档。

</Step>

<Step title="使用 Frame.io 工具">

连接后，用自然语言让 Claude 执行 Frame.io 任务。Claude 会自动调出连接器的工具，并为每个请求选择合适的工具。

</Step>

</Steps>

<Tip>

要确认连接是否正常，可以问 Claude：*"List my Frame.io accounts."*

</Tip>

## 连接到 ChatGPT {#connecting-to-chatgpt}

以下步骤适用于 ChatGPT 桌面应用。ChatGPT Web 和 ChatGPT iOS 也支持 Frame.io MCP 工具。请参阅 [OpenAI 帮助中心关于 ChatGPT 中应用的说明](https://help.openai.com/en/articles/11487775-connectors-in-chatgpt)，确认您所使用平台的设置步骤。

<Steps>

<Step title="添加服务器">

在 ChatGPT 中，打开 **Settings** 并选择 **Plugins**（位于左侧菜单的 **Integrations** 下）。在右上角打开 **Add** 菜单并选择 **Add MCP Server**。将类型设置为 **Streamable HTTP**，并填写：

```
 Name: Frame.io
 URL: https://mcp.frame.io/v1/mcp
```

点击 **Save**。Frame.io 会被添加到服务器表中，并带有一个 **Authenticate** 按钮。

</Step>

<Step title="进行身份验证">

点击 Frame.io 旁边的 **Authenticate** 以开始 Adobe 登录。使用与您的 Frame.io 账户关联的 Adobe ID 登录并授权访问。

</Step>

<Step title="检查工具权限">

ChatGPT 会根据操作类型和应用权限，在执行某些操作前请求确认。在更改这些默认设置之前，请阅读[工具审批设置](#tool-approval-settings)部分。写入和删除类工具（例如上传、移动文件、删除和更改分享）值得在自动化之前仔细检查。

在受管理的工作区中，您可用的操作也可能由工作区管理员控制。

</Step>

<Step title="使用 Frame.io 工具">

在相关情况下让 ChatGPT 使用 Frame.io，从编辑框中选择 **Frame.io**，或使用 **@Frame.io** 直接提及它。

<Tip>

要确认连接是否正常，可以问：*"@Frame.io List my Frame.io accounts."*

</Tip>

</Step>

</Steps>

## 连接到 GitHub Copilot CLI {#connecting-to-the-github-copilot-cli}

以下步骤假定您已安装 GitHub Copilot CLI。请参阅 [GitHub 的 Copilot CLI 文档](https://docs.github.com/en/copilot/how-tos/use-copilot-agents/use-copilot-cli)进行设置。

<Steps>

<Step title="添加服务器">

在活动的 Copilot CLI 会话中运行：

```
/mcp add frameio
```

CLI 会引导您逐个字段填写一个简短的表单：

```
Type: HTTP
URL: https://mcp.frame.io/v1/mcp
HTTP Headers: leave blank
Tools: * to enable all of Frame.io's tools
Defer Tools: Auto
```

**Tools** 控制服务器的哪些工具可用。`*` 会启用全部工具。如果只想启用特定工具，请列出以逗号分隔的工具名称。

**Defer Tools** 控制这些工具的加载方式。`Auto` 通过工具搜索按需加载工具，因此在需要之前，其定义不会占用上下文窗口，这非常适合像 Frame.io 这样的大型工具集。`Never` 会预先加载所有工具。在这里，`Auto` 是更好的默认选项。

</Step>

<Step title="进行身份验证">

填写完表单后，CLI 会输出 `Server Saved` 和 `OAuth authentication is required`。

按 Enter 进行身份验证，浏览器窗口将打开 Adobe 登录页面。使用与您的 Frame.io 账户关联的 Adobe ID 登录并授权访问。

成功后，CLI 会输出 `Successfully authenticated with frameio`，并返回活动 MCP 服务器列表。

</Step>

<Step title="使用 Frame.io 工具">

用自然语言向 Copilot 提问，当您的请求需要时，它会使用 Frame.io 工具。运行 `/mcp show frameio` 或 `/mcp list` 以确认服务器显示为已连接。

<Tip>

要确认连接是否正常，可以问：*"List my Frame.io accounts."*

</Tip>

</Step>

</Steps>

### 工具审批设置 {#tool-approval-settings}

连接任何 MCP 服务器（不仅仅是这个）都会让您的 AI 智能体使用您的访问权限和凭据执行操作。请像对待任何可以访问您账户或文件的集成一样谨慎对待它。

在更改任何权限设置的默认值之前，请先了解工具执行的工作方式。

当某个工具类别设置为 **Always allow** 时，您的 AI 智能体会自动调用这些工具，不会进行确认，也不会预览即将发生的操作。这对于只读查询来说没有问题。但这意味着像 *"把这些整理到正确的文件夹中"* 这样的提示词，可能会在您有机会检查文件去向之前就把文件移到错误的位置。

**推荐的默认设置：**

| 工具类型 | 推荐处理方式 |
| --- | --- |
| Read | 如果您的客户端支持，可以放心自动批准 |
| Write | 在每次调用运行前进行检查 |
| Delete | 在每次调用运行前进行检查，这些操作会删除内容 |

<Tip>

**只读工具**

只读工具带有标准的 `readOnlyHint` 注解，Claude、ChatGPT、VS Code 和 Cursor 会据此将读取操作识别为非修改性操作，通常会将其单独分组或跳过审批提示。具体处理方式因客户端而异。

</Tip>

每个客户端实现审批的方式都不同。没有任何一个设置在所有地方都以相同方式工作：

- **Claude Desktop：**在连接器的设置面板中，按工具类别设置权限，或通过 **Custom** 设置按单个工具设置权限。请参阅 Claude 关于[连接器权限](https://support.claude.com/en/articles/11176164-use-connectors-to-extend-claude-s-capabilities)的文档
- **ChatGPT：**默认情况下，在执行某些操作前会请求确认。您可以在当前对话的剩余部分记住某个选择，但开始新对话时会重置。有关更多详细信息，请参阅 [OpenAI 帮助中心关于 ChatGPT 中应用的说明](https://help.openai.com/en/articles/11487775-connectors-in-chatgpt)。
- **VS Code：**首次出现提示时确认您信任该服务器，然后在工具调用运行时进行批准。使用 Chat 视图中的 **Configure Tools** 按钮启用或禁用单个工具，并从命令面板运行 **MCP: Reset Trust** 以重新确认服务器。有关更多详细信息，请参阅 VS Code 关于[管理审批和权限](https://code.visualstudio.com/docs/agents/run/approvals)的文档。
- **Cursor：**在 **Settings > Agents > Approvals & Execution** 下选择 Run Mode。Auto-review（默认）会在执行有风险的调用前询问。Allowlist 和 Run Everything 会完全跳过审批。有关更多详细信息，请参阅 Cursor 关于 [Run Modes](https://cursor.com/docs/agent/security/run-modes) 的文档。
- **GitHub Copilot CLI：**Copilot 会在运行工具前进行提示，并提供仅允许一次或在整个会话中允许的选项。运行 `/mcp` 可查看已配置的服务器及其工具。

如有疑问，请保留客户端的默认审批行为。它只会增加一个确认步骤，却能帮助您在错误发生之前发现它。

### 设置与导航 {#setup-and-navigation}

| 工具 | 类型 | 说明 |
| --- | --- | --- |
| `mandatory_init` | Setup | 加载 Frame.io 使用指南，并默认列出您可以访问的账户的第一页。 |
| `read_context` | Read | 显示已登录的用户，并帮助您浏览账户、工作区和项目。您可以选择要查看的内容，或按 ID 打开特定的账户、工作区或项目。 |
| `search_assets` | Read | 按名称或内容在账户中搜索项目、文件夹、文件和版本堆栈。 |

### 资源与结构 {#assets-and-structure}

| 工具 | 类型 | 说明 |

## 断开连接 {#disconnecting}

每个客户端都有各自断开或移除 Frame.io MCP 的具体方法：

- **Claude Desktop：**前往 **Customize > Connectors**，找到 Frame.io 并将其移除。有关更多详细信息，请参阅 Claude 关于[连接器](https://support.claude.com/en/articles/11176164-use-connectors-to-extend-claude-s-capabilities)的文档。
- **ChatGPT：**有两种选择。要**断开连接**（保留已安装的插件但停止其访问），请打开 **Settings > Plugins > Frame.io** 并将其关闭；重新打开即可恢复连接。要完全移除，请在侧边栏中打开 **Plugins**，在 **Installed** 下选择 **Frame.io**，然后选择 **Uninstall**。如需再次使用，您需要从插件目录重新安装。有关更多详细信息，请参阅 [OpenAI 帮助中心关于 ChatGPT 中应用的说明](https://help.openai.com/en/articles/11487775-connectors-in-chatgpt)。
- **VS Code：**从您的 MCP 配置中移除 Frame.io 条目。有关更多详细信息，请参阅 VS Code 关于[管理 MCP 服务器](https://code.visualstudio.com/docs/agent-customization/mcp-servers)的文档。
- **Cursor：**从 `~/.cursor/mcp.json`（即添加时使用的同一文件）中移除 `frameio-mcp` 条目。
- **GitHub Copilot CLI：**运行 `/mcp delete [server-name]` 以移除服务器。

## 故障排除 {#troubleshooting}

### 在 2026 年 10 月 7 日之前配置了 Frame.io MCP {#configured-the-frame-io-mcp-before-october-7-2026}

检查其服务器 URL 是否与当前的 V1 URL 一致：**`https://mcp.frame.io/v1/mcp`**

如有需要请更新，然后重启或重新连接 MCP 服务器。

### OAuth 循环或身份验证失败 {#oauth-loop-or-authentication-failure}

使用与您的 Frame.io 账户关联的 Adobe ID 登录。如果您有多个 Adobe 账户，请确认使用的是正确的账户。在客户端中移除并重新添加 Frame.io MCP 会启动一个新的 OAuth 会话。

### AMA 多账户身份验证错误 {#ama-multi-account-authentication-errors}

如果 Adobe IMS 静默复用了现有的浏览器会话，您可能会在未被提示选择的情况下通过身份验证进入错误的组织。解决方法是清除被复用的 Adobe 会话。在重新连接之前，清除浏览器中 Adobe 登录域的 Cookie，或在同一浏览器中打开一个单独的 Adobe 标签页并从中完全退出登录。清除之前的会话后，您将在身份验证时看到配置文件选择选项，从而可以选择正确的组织。

### 添加后 Frame.io MCP 不可见或无法连接 {#frame-io-mcp-not-visible-or-not-connecting-after-adding}

确认 URL 完全为 `https://mcp.frame.io/v1/mcp`。添加后可能需要重启客户端。

### 对话中没有可用工具 {#tools-not-available-in-conversation}

确认 Frame.io MCP 在您的客户端中显示为已连接。如果已连接但工具仍然缺失，请检查权限中的工具类别是否未被设置为 **Blocked**。

此外，

### 连接成功但未显示任何工作区或项目 {#connected-successfully-but-no-workspaces-or-projects-appear}

您已通过身份验证，但所连接的账户中可能没有工作区，或者您可能完全处于错误的账户中。请先让您的 AI 智能体列出所有账户。如果您可以访问多个账户，可能需要指定其他账户 ID。AMA 用户还应确认自己是在正确的 Adobe 组织下进行的身份验证（见上文）。

### 特定工具出现权限错误 {#permission-errors-on-specific-tools}

工具调用反映的是您的 Frame.io 账户权限。上传需要 Contributor 访问权限。有关详细信息，请参阅[管理用户权限](/cn/platform/docs/guides/managing-user-permissions)。

### 上传停滞或资源卡在处理中 {#upload-stalled-or-asset-stuck-in-processing}

让您的 AI 智能体直接检查状态：*"我最近上传的文件的上传状态如何？"* 它会调用 `get_upload_status`。大型或高分辨率文件可能需要几分钟才能完成转码。
