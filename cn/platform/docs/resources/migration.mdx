## 简介 {#introduction}

Frame.io V4 API 是对 Legacy API（通常称为 *V2 端点*或 *Frame.io V3 API*）的重新设计。此次重新设计充分利用了 Frame V4 的新功能和特性，同时保留了 Legacy API 的所有相关功能。本指南概述了 Legacy API 与 V4 API 之间的主要区别，并提供分步指导，帮助您顺利完成迁移。

## 迁移检查清单 {#migration-checklist}

<Steps>

<Step title="身份验证">

对于尚未通过 Adobe Admin Console 管理的 <Tooltip tip="曾使用生成的开发者令牌调用 Legacy API 并已自动迁移到 V4 的账户。在 V4 上创建或手动迁移的账户不包括在内">**自动迁移到 V4 的账户**</Tooltip>，您可以继续使用在 [Frame.io 开发者网站](/cn/platform/welcome)中管理的 Legacy 开发者令牌，但需要在 API 请求中添加一个键为 `x-frameio-legacy-token-auth`、值为 `true` 的标头。否则，请按照下方[身份验证](#adobe-developer-console-managed-authentication)部分中的步骤操作。

</Step>

<Step title="更新现有 API 调用">

所有 Legacy API 路由都需要映射到新的 V4 API 路由和 JSON 负载。下方提供了一个相当全面的[映射](#endpoint-mappings-legacy-api-to-v4)表，以协助完成此过程。

</Step>

<Step title="强烈建议进行测试">

**进行全面测试。** 由于 API 有许多变化，建议使用 V4 账户进行测试，以确保新 API 按预期工作。

</Step>

<Step title="实现专用登录">

由于授权 URL 不同，请为 V4 实现专用的登录方式。V4 授权 URL 与 Legacy API 不同，它不会在响应中返回尚未升级到 V4 的账户，因此应将其视为一个独立的集成。

</Step>

</Steps>

<Note>

如果您对下方映射表中未列出的某个端点有疑问，请通过 [support@frame.io](mailto:support@frame.io) 联系我们的支持团队以了解更多信息。

</Note>

## 通过 Adobe Developer Console 管理的身份验证 {#adobe-developer-console-managed-authentication}

对于通过 [Adobe Developer Console](https://developer.adobe.com/developer-console/) 管理的已迁移到 V4 的账户，您需要通过 OAuth2.0 使用 V4 API。请按照以下步骤操作。

<Steps>

<Step title="创建 Adobe 项目">

**在 Adobe Developer Console 中创建一个项目**，并将 Frame.io 添加为产品。

</Step>

<Step title="选择身份验证类型">

**进行身份验证。** 有关更多信息，请参阅[身份验证指南](https://developer.adobe.com/frameio/guides/Authentication/)。如果您的 V4 账户尚未通过 Adobe Admin Console 管理，可以跳过此步骤。

- **用户身份验证**：使用 Client ID 和/或 Client Secret 连接到 Frame，并要求用户使用其用户名和密码登录。
- **服务器到服务器身份验证**：使用 Client ID 和 Client Secret 连接到 Frame，但不需要用户参与通过浏览器登录。

</Step>

<Step title="实现 Bearer 身份验证">

**JWT Bearer 身份验证**：对于每个 API 请求，通过键为 `Authorization`、值为 `Bearer <IMS_ACCESS_TOKEN>` 的标头传递身份验证令牌。

</Step>

</Steps>

## 端点映射（Legacy API 到 V4） {#endpoint-mappings-legacy-api-to-v4}

<Note>

如果您使用的是旧版开发者令牌身份验证，则需要在 API 请求中添加一个键为 x-frameio-legacy-token-auth、值为 true 的标头。

</Note>

有助于迁移的一般说明：

<Steps>

<Step title="负载">

请求和响应负载可能有所不同。

</Step>

<Step title="Teams → Workspaces">

Legacy API 中的"Teams"相当于 V4 中的"Workspaces"。

</Step>

<Step title="Assets">

Legacy API 中的"Assets"在 V4 中被拆分为"Files"、"Folders"和"Version Stacks"。

</Step>

<Step title="权限">

V4 中的权限和角色有所不同，这改变了端点的结构。在 V4 中，有工作区和项目两级用户角色。有关更多详细信息，请参阅[管理用户权限](/cn/platform/docs/guides/managing-user-permissions)。

</Step>

</Steps>

### 9. Webhooks {#9-webhooks}

您在 V3 中使用的 webhook 将被迁移过来，并且在大多数情况下功能保持不变。迁移时它们会被禁用，需要重新启用才能运行。资源事件需要进行一些更改，这些事件现在被拆分为文件事件和文件夹事件。还有一些 V4 特有的新事件需要注意：metadata.value.updated、collection 相关事件和 share 相关事件。

在重新启用已迁移的 webhook 之前，请查看 [webhook 速率限制](/cn/platform/docs/guides/webhooks#webhook-rate-limits)。V4 webhook 和 Custom Action 事件共享每个账户**每分钟 1,000 个事件**和**每小时 20,000 个事件**的限制。这两项限制都适用于整个账户中两者的合计量。

### 10. Custom Actions {#10-custom-actions}

## 迁移步骤 {#migration-steps}

<Steps>

<Step title="调整不受支持的 V2 端点">

**调整**所有不受支持的 Legacy V2 端点。

</Step>

<Step title="更新基础 URL">

将**基础 URL** 从 `api.frame.io/v2/...` **更新**为 `api.frame.io/v4/...`。

</Step>

<Step title="更新 API 请求">

**更新**代码中的 **API 请求**，以引用新的端点架构。

</Step>

<Step title="更新 JSON 负载">

**更新**请求/响应架构的 **JSON 负载**，确保您生成和使用的是正确的字段。

</Step>

<Step title="更新术语">

在您的代码和前端中更新术语："teams" → "workspaces"；"assets" → "files/folders"；"review links" 或 "presentation links" → "shares"。

</Step>

<Step title="测试端点">

**测试**所有新更新的端点。如果遇到 403、404、422 错误，请确认端点、请求负载结构等。

</Step>

<Step title="解析错误响应">

如果 API 调用失败，请**解析**新的详细错误响应，在 `{"errors": [...]}` JSON 响应中查找问题。

</Step>

<Step title="部署到生产环境">

使用 V4 [Frame.io](http://frame.io/) 账户验证后，**部署**到生产环境。

</Step>

</Steps>

## 错误处理与常见问题 {#error-handling-&-common-issues}

<Note>

某些路由返回的错误带有自定义描述，可能与以下示例略有不同。

</Note>

<CardGroup cols={2}>

<Card title="客户端错误（4xx）" icon="triangle-exclamation" iconType="solid">

- **400** Bad Request：检查负载是否准确。
- **401** Unauthorized：授权令牌无效或缺失。
- **403** Forbidden：缺少 scope 或用户没有访问权限。
- **404** Not Found：确认端点、API 版本或 ID。
- **422** Unprocessable Entity：验证请求数据
- **429** Too Many Requests：实现带退避的重试。

</Card>

<Card title="服务器错误（5xx）" icon="server" iconType="solid">

- **500** Internal Server Error：短暂延迟后重试。

</Card>

</CardGroup>
