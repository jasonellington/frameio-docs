## 兼容性问题 {#compatibility-questions}

<AccordionGroup>

<Accordion title="Frame.io V4 API 是否向后兼容？">

<Warning>

否。在 Adobe MAX 上发布的 Frame.io 产品在运行方式上与旧版存在根本差异，并侧重于不同的工作流。由于这些差异，新 API 不向后兼容。

</Warning>

</Accordion>

<Accordion title="今后将如何处理向后兼容性？">

我们认识到，对于管理具有高可用性要求的生产级集成的客户而言，向后兼容性是一个重要问题。因此，我们正在设计 V4 API，通过自定义 HTTP 标头支持额外一层版本控制，使客户端可以选择使用实验性端点、避免破坏性变更，并在 `/v4` API 命名空间内提供向后兼容性保证。

</Accordion>

<Accordion title="V4 API 正式发布后，我在旧版产品中设置的自动化是否仍能正常工作？即这些自动化是否会自动迁移到 V4？">

<Warning>

所有使用旧版开发者令牌的自动化都将无法在 V4 账户中使用。我们**没有**任何方法将其迁移到 V4。

</Warning>

</Accordion>

</AccordionGroup>

## 媒体与文件 {#media-&-files}

<AccordionGroup>

<Accordion title="媒体链接 URL 的有效期是多久？">

`media_links` 中返回的 URL（例如 `download_url`、`inline_url` 和 `url`）是**临时签名 URL**——它们会过期，无法无限期重复使用。

| URL 类型 | 有效期 |
| --- | --- |
| 下载和内联 URL（`original`、`high_quality`、`efficient`、`video_h264_180`） | 最长 24 小时 |
| 缩略图和预览 URL（`thumbnail`） | 最长 24 小时 |

实际上，过期时间与 UTC 正午或午夜对齐，因此根据请求发出的时间，您收到 URL 时的实际剩余时间可能在几分钟到 24 小时之间。

**请勿存储或缓存这些 URL。** 每次需要提供或访问文件时，请始终请求一组新的 `media_links`。尝试使用已过期的 URL 会导致 CDN 返回 `403` 错误。

</Accordion>

</AccordionGroup>
