Frame.io 操作（Actions）可让您快速执行常见的媒体操作，例如下载、重命名和复制项目——还允许将第三方工具和服务的集成直接呈现在 [Frame.io](https://next.frame.io/) 的用户界面中。

## 关于操作 {#about-actions}

随着自定义操作（Custom Actions）的推出，开发者可以在 Frame.io V4 中配置和管理自己的操作。自定义操作利用与 [Webhook](https://developer.adobe.com/frameio/guides/Webhooks/) 相同的底层事件系统，为开发者提供了另一种机制，将资产与其 Frame.io 账户中用户最看重的工具连接起来。

操作可以由启用该操作的 Frame.io 工作区中的任何成员（Member）执行。执行操作时，Frame.io 会向您提供的 URL 发送负载。接收方应用会返回 HTTP 状态码以确认已收到，或返回自定义回调，以在 Frame.io 界面中呈现额外的表单字段。接收方应用可以是您自己托管的程序或服务，甚至可以是 Workfront Fusion 或 Zapier 等低代码/无代码 IPaaS 工具。

使用自定义操作，可以将集成以可编程 UI 组件的形式直接构建到 [Frame.io](https://next.frame.io/) 中。这使得用户可以在应用内触发工作流，并利用与 webhook 相同的底层事件路由。您可以创建由用户触发的单步或多步表单，这些表单会以另一个表单或基本响应的形式返回到 Frame.io。当用户在资产上点击自定义操作时，Frame.io 会向您提供的 URL 发送负载。接收方应用会返回 HTTP 状态码以确认已收到，或返回可在 Frame.io 中呈现额外 UI 的自定义回调。

## 速率限制 {#rate-limits}

自定义操作事件与 webhook 事件计入相同的账户级限制：**每分钟 1,000 个事件**和**每小时 20,000 个事件**。这两项限制均适用于整个账户的合计事件量，而不是分别适用于每个自定义操作或 webhook 订阅。

达到任一限制时，额外的自定义操作事件将被**丢弃**，不会排队或自动重试。

这些是事件量限制，而不是管理自定义操作时的 API 请求限制。有关详细信息，请参阅 [Webhook 速率限制](/cn/platform/docs/guides/webhooks#webhook-rate-limits)。

## 迁移的操作 {#migrated-actions}

迁移到包含之前在旧版 Frame.io 中创建的自定义操作的 Frame.io V4 账户时，需要注意以下几点。

### 操作状态 {#action-status}

账户迁移到 Frame.io V4 后，所有在早期版本中创建的自定义操作的状态都将为 ‘null’，并会被自动禁用。这让用户有机会在启用操作之前先将其更新为使用 V4 API，因为任何未更新的操作都将失败。要识别处于此状态的操作，请访问“操作设置”页面并查看 “Status” 列；如果使用 API，则可检查 is_active 字段。

### 可操作的资源：文件、文件夹和版本堆栈 {#actionable-resources-files-folders-&-version-stacks}

由于在 Frame.io V4 API 中，不同的资产类型被划分为独立的资源，因此在解析操作负载中收到的资源 ID 时，可能需要考虑一些行为差异。单个文件的行为很简单，ID 将对应执行该操作的特定文件。同样，对于文件夹，您将收到执行该操作的文件夹的 ID；不过，根据您的用例，在定义操作行为时您有多种选择。如果您想与文件夹资源本身交互，可以使用文件夹 ID 对 Frame.io API 进行后续调用。或者，您可能希望获取该文件夹的子项，以便对其中的资产做进一步处理。当在版本堆栈上执行操作时，您的负载将包含 ‘Head Asset’ 的 ID，即堆栈中最顶层的文件，也是 Frame.io 界面中显示的文件。

您可以在我们的[迁移指南](/cn/platform/v4-experimental/docs/resources/migration)中进一步了解 Frame.io 旧版 API 与 V4 之间的差异。

<Info>

使用 API 配置[自定义操作](/cn/platform/v4-experimental/api-reference/custom-actions/actions-show)。

</Info>

自定义操作需要以下内容：

| 字段名称 | 描述 |
| --- | --- |
| Name | 您为自定义操作选择的名称。它将显示在 Frame.io 中可用自定义操作的菜单里。 |
| Description | 说明该操作的作用，供参考使用（描述不会出现在 Frame.io Web 应用中）。 |
| Event | 内部事件键，帮助您区分标准 webhook 事件和您自己的事件。 |
| URL | 事件的投递地址。 |
| Workspace | 将使用该自定义操作的工作区。 |

## 配置您的自定义操作 {#configure-your-custom-action}

当用户触发自定义操作时，Frame.io 会向您提供的 URL 发送负载。接收方应用可以返回 HTTP 状态码以确认已收到，或返回可在 [Frame.io](https://next.frame.io/) 中呈现额外 UI 的自定义回调。

<Warning>

为工作区创建自定义操作需要账户管理员（Account Admin）权限。如果您没有访问权限，请联系管理员修改您的权限。

</Warning>

### 多资产配置 {#multi-asset-configuration}

多资产支持由配置驱动，必须在 [Web 端](https://next.frame.io/settings/actions)操作的配置模态框中显式启用。可以在创建新操作时启用，也可以在更新现有操作时启用。

启用多资产支持后，负载格式会立即切换。旧版负载和支持多资产的负载是互斥的。

### 从旧版负载迁移 {#migrating-from-the-legacy-payload}

<Warning>

**旧版负载计划弃用**

旧版负载计划弃用，强烈建议用户迁移其服务以处理新负载。

通过启用配置标志并更新负载处理逻辑，操作可以无缝过渡到支持多资产负载。

1. 将单数形式的 `resource` 对象替换为 `resources` 列表
2. 更新代码以遍历 `resources` 列表
3. 在操作配置中启用多资产标志

</Warning>

| 字段名称 | 描述 |
| --- | --- |
| `account_id` | 操作的唯一账户 ID。 |
| `action_id` | 操作的唯一 ID。 |
| `interaction_id` | 由 Frame.io 生成的唯一标识符，用于在多个请求（例如链式消息回调或表单回调）中跟踪您的事务。在操作的整个序列中保持不变。 |
| `project_id` | 操作的唯一项目 ID。 |
| `resource.id` | 触发操作的资源的 ID。 |
| `resource.type` | 触发操作的资源的类型。 |
| `type` | 配置操作时在 `event` 字段中提供的名称。 |
| `user.id` | 触发操作的用户的 ID。 |
| `workspace.id` | 使用该操作的工作区的 ID。 |
| `data` | 包含表单字段名称和用户所选值的键值对。您的应用通过它了解用户做出了哪些选择。 |

## 交互、重试和超时 {#interactions-retries-and-timeouts}

`interaction_id` 是一个唯一标识符，用于跟踪随时间推进的交互过程。如果您不需要回应用户，只需返回 200 状态码即可完成。虽然这是可选的，但我们建议包含有关操作结果的信息，例如成功消息或错误提示。自定义操作支持消息回调。

<Note>

Frame.io 期望在 10 秒内收到响应，并在等待成功响应期间最多重试 5 次。理想情况下，应立即返回响应，并在通过自定义操作触发后再执行异步操作。

</Note>

## 创建消息回调 {#create-a-message-callback}

在对 webhook 事件的 HTTP 响应中，您可以返回一个描述消息的 JSON 对象，该消息将在 Frame.io 界面中返回给发起操作的用户。

```json
{
  "title": "Success!",
  "description": "The thing worked! Nice."
}
```

消息可让您直接在 Frame.io 界面中向用户提供反馈。如果您需要向用户收集更多信息，请改用**表单回调**。

## 创建表单回调 {#create-a-form-callback}

假设您在开始处理之前需要更多信息。例如，您可能要将内容上传到一个需要额外详细信息的系统。您可以在响应中描述一个表单，由用户填写并提交回给您。示例如下：

```json
{
  "title": "Need some more info!",
  "description": "Getting ready to submit this file!",
  "fields": [
    {
      "type": "text",
      "label": "Title",
      "name": "title",
      "value": "MyVideo.mp4"
    },
    {
      "type": "select",
      "label": "Captions",
      "name": "captions",
      "options": [
        {
          "name": "Off",
          "value": "off"
        },
        {
          "name": "On",
          "value": "on"
        }
      ]
    }
  ]
}
```

当用户提交表单时，您将在与初始 POST 相同的 URL 上收到一个事件：

```json
POST /your/url
{
  "type": "your-specified-event-name",
  "interaction_id": "the-same-id-as-before",
  "action_id": "unique-id-for-this-custom-action",
  "data":{
    "title": "MyVideo.mp4",
    "captions": "off"
  }
}
```

表单上添加的所有自定义字段都会出现在 Frame.io 发送的 JSON 负载的 `data` 部分中。使用 `interaction_id` 将初始请求与这份新的表单数据对应起来。您可以回复一条消息，也可以链接另一个表单。通过将操作、表单和消息串联起来，您可以借助外部系统的业务逻辑，在 Frame.io 中有效地编排多步骤工作流。

## 安全性与验证 {#security-and-verification}

默认情况下，所有自定义操作在创建时都会生成一个签名密钥。此项不可配置。该密钥可用于验证请求是否来自 Frame.io。`POST` 请求中包含以下内容：

| 名称 | 描述 |
| --- | --- |
| `X-Frameio-Request-Timestamp` | 自定义操作被触发的时间。 |
| `X-Frameio-Signature` | 计算得出的签名。 |

<CardGroup cols={2}>

<Card title="时间戳验证" icon="clock" iconType="solid">

**时间戳**是请求在离开 Frame.io 网络时被签名的时间，可用于防止重放攻击。我们建议验证该时间与本地时间相差不超过 5 分钟。

</Card>

<Card title="签名验证" icon="shield" iconType="solid">

**签名**是使用首次创建自定义操作时提供的签名密钥生成的 HMAC SHA-256 哈希。

</Card>

</CardGroup>

### 验证签名 {#verifying-the-signature}

<Steps>

<Step title="提取签名">

从 HTTP 标头中提取签名。

</Step>

<Step title="创建待签名消息">

将版本、投递时间和请求体组合成 `v0:timestamp:body`，以创建待签名的消息。

</Step>

<Step title="计算 HMAC SHA256">

使用您的签名密钥计算 HMAC SHA256 签名。

</Step>

<Step title="比较签名">

将您计算出的签名与提供的签名进行比较！

</Step>

</Steps>

<Note>

提供的签名带有 `v0=` 前缀。目前 Frame.io 只有这一种用于签名请求的版本。您需要在计算出的签名前添加此前缀。

</Note>

```python title="Python"
import hmac
import hashlib

def verify_signature(curr_time, req_time, signature, body, secret):
    """
    Verify webhook/custom action signature
    :Args:
        curr_time (float): Current epoch time
        req_time (float): Request epoch time
        signature (str): Signature provided by the frame.io API for the given request
        body (str): Custom Action body from the received POST
        secret (str): The secret for this Custom Action that you saved when you first created it
    """
    if int(curr_time) - int(req_time) < 500:
        message = 'v0:{}:{}'.format(req_time, body)
        calculated_signature = 'v0={}'.format(hmac.new(
            bytes(secret, 'latin-1'),
            msg=bytes(message, 'latin-1'),
            digestmod=hashlib.sha256).hexdigest())
        if calculated_signature == signature:
            return True
    return False
```
