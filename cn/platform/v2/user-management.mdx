## 概述 {#overview}

本教程介绍如何通过 Frame.io API 对 Users 进行基本管理。本教程假定读者已经通过 OAuth2.0 或 Developer Token 设置好了[认证](/cn/platform/v2/authentication)。

### 核心概念 {#core-concepts}

撇开不同 Team Member 角色和权限的具体细微差别不谈，在通过 Frame.io API 管理 Users 时，需要理解两个重要要点：

1. **Team Members 属于 Teams**，并可以访问这些 Teams 中的所有非私有 Projects。Team Managers 和 Admins 都是 Team Member 角色的扩展。
2. **Project Collaborators 属于单个 Project**。根据这些 Projects 的配置方式，他们可能能够也可能无法创建 Presentations、下载 Assets 或邀请其他 Collaborators。

有关更多信息，请参阅我们关于 [Team Members 与 Collaborators](https://support.frame.io/getting-started/sharing-with-your-team-or-clients/difference-between-team-members-vs-collaborators) 以及 [Account 管理角色](https://support.frame.io/enterprise-accounts/enterprise-account-management-roles)的支持文档。

### Users 如何加入 Accounts {#how-users-join-accounts}

一般来说，新 Users 由现有 Users 邀请，可以直接邀请，也可以通过唯一的 Project 加入 URL 邀请。Team Members 还可以：

1. 将自己添加到其 Account 内公开 Teams 中的非私有 Projects
2. 将自己添加到其 Account 内的公开 Teams
3. 申请加入其 Account 内的私有 Teams

在所有情况下，加入操作都会经过一系列逻辑步骤，包括检查之前的租户关系、创建“pending”记录，以及在适当时发送邀请或加入申请电子邮件。

好消息是，所有这些逻辑都已由 Frame.io API 进行了抽象。如果您想将某人添加到 Project，请使用 Collaborator 路由；如果您想邀请某人加入 Team，请使用 Team Member 路由。

### 所需 scopes {#required-scopes}

| Scope | 原因 |
| --- | --- |
| **Teams:** Update | 添加和移除 Team Members。 |
| **Projects:** Update | 添加和移除 Project Collaborators。 |

## 管理 Team Members {#managing-team-members}

### 添加 Team Members {#adding-team-members}

要将新的 Team Member 添加到 Team，您需要：

1. 目标 Team 的 `id`
2. 目标 User 的电子邮件地址。

然后，只需向 `https://api.frame.io/v2/teams/:id/members` 发出经过授权的 `POST` 请求，并在正文 payload 中包含目标 User 的电子邮件，如下所示：

```json
{
    "email": "user@example.com"
}
```

**如果您邀请的 User 已经是您组织中的 Team Member**，API 响应会表明这一点：

```json
{
    "_type": "team_member",
    "id": "<team-member-record-id>",
    "role": "member",
    "team_id": "<team-id>",
    "user_id": "<user-id>"
}
```

**如果您邀请的 User 尚未加入您的组织**，您的请求将触发邀请流程，API 响应将类似于：

```json
{
    "_type": "pending_team_member",
    "email": "user@example.com",
    "id": "<oending-team-member-record-id>",
    "role": "member",
    "team_id": "<team-id>
}
```

**注意**：由于该 User 尚未创建或尚未被识别，`pending_team_member` 响应中不会有可映射的 `user_id`。

### 移除 Team Members {#removing-team-members}

要从 Team 中移除 Team Member，您需要：

1. 目标 Team 的 `id`
2. 目标 User 的电子邮件地址。

接下来，您将对添加 Team Member 时使用的同一 URL 发出 `DELETE` 调用，并传入一个特殊的查询字符串：

`DELETE` [`https://api.frame.io/v2/teams/:id/members/_?email=user@example.com`](/cn/platform/v2/api-reference/teams/add-team-member)

<Info>

**什么是 'include' 模式？**

**注意** `/_?email=` 这种结构——这是 Frame.io API 中一种称为 ‘include’ 的特殊模式，它让您可以在 API 请求中请求额外的数据（在本例中为用户的电子邮件地址））。

</Info>

调用成功后，API 将返回与添加 Team Member 时类似的 payload。如果该 Team Member 是首次被删除，您会看到一个与调用时间相匹配的 `updated_at` 属性。如果该 Team Member 之前已被删除，该时间戳不会更新（即它会反映该 Team Member 最初被移除的时间）。

```json
{
    "_type": "team_member",
    "id": "<team-member-record-id>",
    "role": "member",
    "team_id": "<team-id>",
    "user_id": "<user-id>",
    "updated_at": "<timestamp>"
}
```

尝试移除不存在或从未与该 Team 关联的 Team Members 将导致 404 错误。

## 管理 Project Collaborators {#managing-project-collaborators}

### 添加 Project Collaborators {#adding-project-collaborators}

Collaborator 管理与 Team Member 管理极为相似。要向团队添加新的 Collaborator，您需要：

1. 目标 Project 的 `id`
2. 目标 User 的电子邮件地址。

然后，向 [`https://api.frame.io/v2/projects/:id/collaborators`](/cn/platform/v2/api-reference/projects/add-collaborator-to-project) 发出经过授权的 `POST` 请求，并在正文 payload 中包含目标 User 的电子邮件：

```json
{
    "email": "user@example.com"
}
```

**如果您邀请的 User 已被识别**，并且可以立即实例化 Collaborator 角色，API 响应会表明这一点，并返回一个完整的 User 对象：

```json
{
    "_type": "collaborator",
    "creator_id": "<inviting-user-id>",
    "id": "<collaborator-record-id>",
    "project_id": "<project-id>",
    "user": {
        "_type": "user",
       <...>
    },
    "user_id": "<user-id>"
}
```

<Info>

**Team 成员资格**

如果该 User 已经是您组织中的 Team Member，但不是目标 Project 的成员，您仍然可以使用 Collaborate 路由，API 的响应与上面相同。在后台，该 Team Member 将被添加到您的目标 Project 中，并且仍然是 Team Member。换句话说，您不会因为使用此路由而意外地“降级”Team Members。

</Info>

**如果您邀请的 User 是您组织的新成员**，您的请求将触发邀请流程，API 将返回一条 `pending_collaborator` 记录，如下所示：

```json
{
    "_type": "pending_collaborator",
    "email": "user@example.com",
    "id": "<pending-collaborator-record-id>",
    "project_id": "<project-id>"
}
```

### 移除 Project Collaborators {#removing-project-collaborators}

**注意：** 此过程与（上文中）Team Members 的处理方式基本相同。

要从 Project 中移除 Collaborator，您需要：

1. 目标 Project 的 `id`。
2. 目标 User 的电子邮件地址。

接下来，您将对添加 Collaborator 时使用的同一 URL 发出 `DELETE` 调用，并传入一个特殊的查询字符串。

`DELETE` [`https://api.frame.io/v2/projects/:id/collaborators/_?email=user@example.com`](/cn/platform/v2/api-reference/teams/add-team-member)

调用成功后，API 将返回与添加 Project Collaborator 时类似的 payload：

```json
{
    "_type": "collaborator",
    "creator_id": "<inviting-user-id>",
    "id": "<collaborator-record-id>",
    "project_id": "<project-id>",
    "user": {
        "_type": "user",
       <...>
    },
    "user_id": "<user-id>"
}
```

尝试移除不存在或从未与该 Project 关联的 Collaborators 将导致 404 错误。

<Warning>

**警告：移除 Collaborator 不是幂等操作**

与移除 Team Member 不同，尝试移除已被移除的 Collaborators 将导致 404 错误

</Warning>
