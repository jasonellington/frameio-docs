Esta guía detalla el flujo completo para cargar archivos con la API V4 de Frame.io. Cubre las solicitudes y respuestas sin procesar de la API tanto para cargas locales como remotas.

<Info>

**¿Buscas guías específicas para los SDK?** Para implementaciones de carga con división en fragmentos, reintentos y seguimiento del progreso integrados, consulta la [guía de carga con el SDK de Python](/es/platform/docs/guides/uploading-to-frame-io/python-sdk-upload-guide).

</Info>

## Requisitos previos {#prerequisites}

Antes de empezar a cargar archivos, asegúrate de haber completado estos pasos de configuración:

<Steps>

<Step title="Cuenta de Frame.io V4">

Tienes una cuenta de Frame.io V4 administrada a través de la [Adobe Admin Console](https://adminconsole.adobe.com/), O BIEN has [cambiado a la autenticación de Adobe](https://help.frame.io/en/articles/11758018-connecting-to-adobe-authentication) para el usuario de tu cuenta

</Step>

<Step title="Configuración de Adobe Developer Console">

Has iniciado sesión en la [Adobe Developer Console](https://developer.adobe.com/console) y has añadido la API de Frame.io a un proyecto nuevo o existente

</Step>

<Step title="Credenciales de autenticación">

Has generado las [credenciales de autenticación adecuadas](https://developer.adobe.com/frameio/guides/Authentication/) para tu proyecto

</Step>

<Step title="Token de acceso">

Has usado correctamente esas credenciales para generar un token de acceso

</Step>

</Steps>

## Elegir el método de carga {#choosing-your-upload-method}

Hay dos formas de cargar un archivo con la API de Frame.io: `Create File (local upload)` y `Create File (remote upload)`.

<CardGroup cols={2}>

<Card title="Carga local" icon="upload" iconType="solid">

Úsala cuando tu aplicación tenga acceso local al contenido multimedia, de forma similar a arrastrar un archivo desde tu escritorio

</Card>

<Card title="Carga remota" icon="link" iconType="solid">

Úsala cuando se acceda al contenido multimedia a través de la red, por ejemplo, mediante una integración con otro servicio

</Card>

</CardGroup>

En esta guía empezaremos por el caso más sencillo: completar una carga remota.

## Carga remota {#remote-upload}

Para crear un archivo mediante carga remota, selecciona el endpoint **Create File (remote upload)**. El cuerpo de la solicitud requiere el nombre del archivo y su URL de origen.

<Warning>

Actualmente, la carga remota tiene un **límite de tamaño de archivo de 500 GB**. Para archivos de más de 500 GB, usa la [carga local](#local-upload).

</Warning>

### Ejemplo de solicitud {#request-example}

```json
{ 
    "data": {
        "name": "my_file.jpg",
        "source_url": "https://upload.wikimedia.org/wikipedia/commons/e/e1/White_Pixel_1x1.jpg"
    }
}
```

### Ejemplo de respuesta {#response-example}

Una solicitud correcta devolverá una respuesta como la siguiente:

## Carga local {#local-upload}

Para crear un archivo mediante carga local, selecciona el endpoint **Create File (local upload)**. El cuerpo de la solicitud requiere el nombre del archivo y su tamaño especificado en bytes.

### Ejemplo de solicitud {#request-example-1}

```json
{ 
    "data": {
        "name": "my_file.jpg",
        "file_size": 50645990
    }
}
```

### Ejemplo de respuesta {#response-example-1}

Si la solicitud se realiza correctamente, se crea un recurso de archivo provisional sin contenido. Según el tamaño del archivo, el cuerpo de la respuesta incluirá una o varias `upload_urls`. En este ejemplo, tendremos que gestionar la carga en varias partes.

```json
{
    "data": {
        "id": "fa18ba7b-b3ee-4dd6-9b31-bd07e554241d",
        "name": "my_file.jpg",
        "status": "created",
        "type": "file",
        "file_size": 50645990,
        "updated_at": "2025-06-26T20:08:06.823170Z",
        "media_type": "image/jpeg",
        "parent_id": "2e426fe0-f965-4594-8b2b-b4dff1dc00ec",
        "project_id": "7e46e495-4444-4555-8649-bee4d391a997",
        "created_at": "2025-06-26T20:08:06.751313Z",
        "upload_urls": [
            {
                "size": 16881997,
                "url": "https://frameio-uploads-development.s3-accelerate.amazonaws.com/parts/fa18ba7b-b3ee-4dd6-9b31-bd07e554241d/part_1?..."
            },
            {
                "size": 16881997,
                "url": "https://frameio-uploads-development.s3-accelerate.amazonaws.com/parts/fa18ba7b-b3ee-4dd6-9b31-bd07e554241d/part_2?..."
            },
            {
                "size": 16881996,
                "url": "https://frameio-uploads-development.s3-accelerate.amazonaws.com/parts/fa18ba7b-b3ee-4dd6-9b31-bd07e554241d/part_3?..."
            }
        ],
        "view_url": "https://next.frame.io/project/7e46e495-4444-4555-8649-bee4d391a997/view/fa18ba7b-b3ee-4dd6-9b31-bd07e554241d"
    }
}
```

<Warning>

**Requisitos importantes de la carga:**

Estos son detalles importantes que debes tener en cuenta al enviar las solicitudes de carga posteriores:

- El método de la solicitud HTTP debe ser `PUT`
- Debe incluirse el encabezado `x-amz-acl` con el valor private
- El encabezado `Content-Type` debe coincidir con el `media_type` especificado en la solicitud original de **Create File (local upload)**. Esto se aplica incluso cuando el archivo se carga en partes separadas. En el ejemplo anterior, el valor de `media_type` es `image/jpeg`. Por lo tanto, el valor de `Content-Type` también debe ser `image/jpeg`.

</Warning>

## Carga en varias partes {#multi-part-upload}

Cuando un archivo genera más de una URL de carga, tendrás que dividir el archivo de origen en fragmentos y emitir una solicitud PUT para cada uno.

<Info>

**Recomendado:** la [guía de carga con el SDK de Python](/es/platform/docs/guides/uploading-to-frame-io/python-sdk-upload-guide) cubre la carga en varias partes con `FrameioUploader`, que gestiona de forma nativa la división en fragmentos, las cargas en paralelo, los reintentos y el seguimiento del progreso.

</Info>

Si necesitas implementar la carga manualmente (por ejemplo, en un lenguaje sin SDK o para tener un control total del proceso), el siguiente script muestra cómo dividir un archivo en fragmentos y cargar cada uno usando las URL prefirmadas.

### Ejemplo de implementación en Python {#python-implementation-example}

```python title="Multi-part Upload Script"
import requests
import math
from typing import List
from tqdm import tqdm  # For progress bar

def upload_file_in_chunks(file_path: str, upload_urls: list[str], content_type: str | None = None, chunk_size: int | None = None) -> bool:
    """
    Upload a file in chunks using presigned URLs.
    """
    try:
        # Auto-detect content type based on file extension
        if content_type is None:
            detected_content_type, _ = mimetypes.guess_type(file_path)
            content_type = detected_content_type # Default fallback

        print(f"Detected content type: {content_type}")

        # Get file size
        with open(file_path, 'rb') as f:
            f.seek(0, 2)  # Seek to end of file
            file_size = f.tell()

        # Calculate chunk size if not provided
        if chunk_size is None:
            chunk_size = math.ceil(file_size / len(upload_urls))

        print(f"File size: {file_size} bytes")
        print(f"Chunk size: {chunk_size} bytes")
        print(f"Number of chunks: {len(upload_urls)}")

        # Upload each chunk
        with open(file_path, 'rb') as f:
            with tqdm(total=len(upload_urls), desc="Uploading chunks") as pbar:
                for i, url in enumerate(upload_urls):
                    start_byte = i * chunk_size
                    end_byte = min(start_byte + chunk_size, file_size)

                    # Read chunk from file
                    f.seek(start_byte)
                    chunk = f.read(end_byte - start_byte)

                    print(f"Uploading chunk {i+1}: {len(chunk)} bytes")

                    # Upload chunk with minimal headers matching the signature
                    response = requests.put(
                        url,
                        data=chunk,
                        headers={
                            'content-type': content_type,
                            'x-amz-acl': 'private'
                        }
                    )

                    if response.status_code != 200:
                        print(f"Failed to upload chunk {i+1}. Status code: {response.status_code}")
                        print(f"Response text: {response.text}")
                        print(f"Response headers: {dict(response.headers)}")
                        return False
                    else:
                        print(f"Chunk {i+1} uploaded successfully!")

                    pbar.update(1)

        return True

    except Exception as e:
        print(f"Error during upload: {str(e)}")
        return False

# Example usage
if __name__ == "__main__":
    # Replace these with your actual values
    file_path = "/Users/MyComputer/local_upload/sample.jpg"  # Path to your file
    upload_urls = [
        "https://frameio-uploads-development.s3-accelerate.amazonaws.com/parts/fa18ba7b-b3ee-4dd6-9b31-bd07e554241d/part_1?...",
        "https://frameio-uploads-development.s3-accelerate.amazonaws.com/parts/fa18ba7b-b3ee-4dd6-9b31-bd07e554241d/part_2?...",
        "https://frameio-uploads-development.s3-accelerate.amazonaws.com/parts/fa18ba7b-b3ee-4dd6-9b31-bd07e554241d/part_3?..."
    ]
    content_type = "image/jpeg"

    print("Starting file upload...")
    success = upload_file_in_chunks(file_path, upload_urls, content_type)

    if success:
        print("File upload completed successfully!")
    else:
        print("File upload failed!")
```

## Resumen del flujo de carga {#upload-flow-summary}

<Steps>

<Step title="Elegir el método de carga">

Decide entre la carga remota (archivo accesible mediante una URL) o la carga local (archivo en tu sistema)

</Step>

<Step title="Solicitud de creación del archivo">

Realiza la solicitud inicial para crear el recurso de archivo con los metadatos necesarios

</Step>

<Step title="Gestionar las URL de carga">

En las cargas locales, procesa las upload_urls devueltas (una sola parte o varias)

</Step>

<Step title="Cargar el contenido del archivo">

Usa solicitudes PUT con los encabezados adecuados para cargar el contenido del archivo en las URL proporcionadas

</Step>

<Step title="Verificar la carga">

Comprueba el estado del archivo para confirmar que la carga y el procesamiento se han completado correctamente

</Step>

</Steps>

<Info>

**Próximos pasos**: una vez cargado el archivo, puedes usar el ID de archivo devuelto para añadir comentarios, crear shares o realizar otras operaciones con la API V4 de Frame.io.

</Info>
