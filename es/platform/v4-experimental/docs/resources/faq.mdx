## Preguntas sobre compatibilidad {#compatibility-questions}

<AccordionGroup>

<Accordion title="¿Es la API de Frame.io V4 compatible con versiones anteriores?">

<Warning>

No. El producto Frame.io lanzado en Adobe MAX funciona de maneras fundamentalmente distintas y prioriza flujos de trabajo diferentes a los de la versión heredada. Debido a estas diferencias, la nueva API no es compatible con versiones anteriores.

</Warning>

</Accordion>

<Accordion title="¿Cómo se gestionará la compatibilidad con versiones anteriores en el futuro?">

Conscientes de que la compatibilidad con versiones anteriores es una preocupación importante para los clientes que gestionan integraciones de calidad de producción con altos requisitos de disponibilidad, estamos diseñando la API V4 para que admita un nivel adicional de control de versiones mediante un encabezado HTTP personalizado. Esto permitirá a los clientes optar por usar endpoints experimentales, evitar cambios incompatibles y ofrecer garantías de compatibilidad con versiones anteriores dentro del espacio de nombres de la API `/v4`.

</Accordion>

<Accordion title="Cuando la API V4 esté disponible de forma general, ¿seguirán funcionando las automatizaciones que configuré con el producto heredado? Es decir, ¿se migrarán automáticamente a V4?">

<Warning>

Todas las automatizaciones que usan tokens de desarrollador heredados dejarán de funcionar en las cuentas de V4. **No** tenemos ninguna forma de migrarlas a V4.

</Warning>

</Accordion>

</AccordionGroup>

## Contenido multimedia y archivos {#media-&-files}

<AccordionGroup>

<Accordion title="¿Durante cuánto tiempo son válidas las URL de los enlaces multimedia?">

Las URL devueltas en `media_links` (como `download_url`, `inline_url` y `url`) son **URL firmadas temporales**: caducan y no se pueden reutilizar indefinidamente.

| Tipo de URL | Caducidad |
| --- | --- |
| URL de descarga e inline (`original`, `high_quality`, `efficient`, `video_h264_180`) | Hasta 24 horas |
| URL de miniatura y vista previa (`thumbnail`) | Hasta 24 horas |

En la práctica, la caducidad se alinea con el mediodía o la medianoche UTC, por lo que el tiempo restante real cuando recibes una URL puede oscilar entre unos minutos y 24 horas, según el momento en que se realice la solicitud.

**No almacenes ni guardes en caché estas URL.** Solicita siempre un nuevo conjunto de `media_links` cada vez que necesites servir un archivo o acceder a él. Intentar usar una URL caducada provocará un error `403` de la CDN.

</Accordion>

</AccordionGroup>
