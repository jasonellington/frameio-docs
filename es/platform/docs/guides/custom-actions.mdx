Las Actions de Frame.io ofrecen acceso rápido a operaciones multimedia habituales, como descargar, renombrar y duplicar elementos, y también permiten que las integraciones con herramientas y servicios de terceros aparezcan directamente en la interfaz de usuario de [Frame.io](https://next.frame.io/).

## Acerca de las Actions {#about-actions}

Con la introducción de las Custom Actions, los desarrolladores pueden configurar y gestionar sus propias Actions en Frame.io V4. Aprovechando el mismo sistema de eventos subyacente que los [Webhooks](https://developer.adobe.com/frameio/guides/Webhooks/), las Custom Actions son un mecanismo alternativo para que los desarrolladores conecten sus assets con las herramientas que más importan a los usuarios de su Account de Frame.io.

Cualquier usuario que sea Member del Workspace de Frame.io en el que la Action está habilitada puede ejecutarla. Al ejecutar una Action, Frame.io envía un payload a una URL que tú proporcionas. La aplicación receptora responde con un código de estado HTTP para confirmar la recepción, o con un callback personalizado para mostrar campos de formulario adicionales en la interfaz de Frame.io. La aplicación receptora puede ser tu propio programa o servicio alojado, o incluso una herramienta iPaaS low-code/no-code como Workfront Fusion o Zapier.

Usa las Custom Actions para crear integraciones directamente en [Frame.io](https://next.frame.io/) como componentes de interfaz programables. Esto permite flujos de trabajo que los usuarios pueden activar desde la aplicación, aprovechando el mismo enrutamiento de eventos subyacente que los webhooks. Puedes crear formularios de uno o varios pasos activados por el usuario que vuelven a Frame.io como otro formulario o como una respuesta básica. Y cuando un usuario hace clic en una Custom Action sobre un Asset, Frame.io envía un payload a una URL que tú proporcionas. La aplicación receptora responde con un código de estado HTTP para confirmar la recepción, o con un callback personalizado que puede mostrar interfaz adicional en Frame.io.

## Límites de frecuencia {#rate-limits}

Los eventos de Custom Actions cuentan para los mismos límites a nivel de cuenta que los eventos de webhook: **1.000 eventos por minuto** y **20.000 eventos por hora**. Ambos límites se aplican a su volumen combinado en toda la cuenta, no por separado a cada Custom Action o suscripción de webhook.

Cuando se alcanza cualquiera de los dos límites, los eventos adicionales de Custom Actions se **descartan**; no se ponen en cola ni se reintentan automáticamente.

Se trata de límites de volumen de eventos, no de límites de solicitudes a la API para gestionar Custom Actions. Consulta [Límites de frecuencia de los webhooks](/es/platform/docs/guides/webhooks#webhook-rate-limits) para más detalles.

## Actions migradas {#migrated-actions}

Hay algunas cosas que debes tener en cuenta al migrar a una Account de Frame.io V4 que contiene Custom Actions creadas previamente en la versión legacy de Frame.io.

### Estado de las Actions {#action-status}

Al migrar la Account a Frame.io V4, todas las Custom Actions creadas en versiones anteriores tendrán el estado 'null' y se desactivarán automáticamente. Esto da a los usuarios la oportunidad de actualizar primero sus Actions para que usen la API V4 antes de habilitarlas, ya que cualquier Action que no se haya actualizado fallará. Para identificar las Actions en este estado, visita la página de configuración de Actions y consulta la columna "Status" o, si usas la API, comprueba el campo is_active.

### Recursos compatibles: archivos, carpetas y Version Stacks {#actionable-resources-files-folders-&-version-stacks}

Dado que en la API V4 de Frame.io los tipos de asset se separan en recursos distintos, puede haber comportamientos que considerar al interpretar el ID de recurso recibido en el payload de tu Action. El comportamiento para archivos individuales es sencillo, ya que el ID corresponde al archivo concreto sobre el que se ejecutó la Action. Del mismo modo, para las carpetas recibirás el ID de la carpeta sobre la que se ejecutó la Action; sin embargo, según tu caso de uso, tienes varias opciones al definir el comportamiento de tu Action. Usa el ID de la carpeta para hacer llamadas posteriores a la API de Frame.io si quieres interactuar con el propio recurso de carpeta. Como alternativa, puede que quieras obtener los elementos hijos de esa carpeta para procesar los assets que contiene. Cuando una Action se ejecuta sobre un Version Stack, tu payload contendrá el ID del 'Head Asset', que es el archivo superior del Stack y el que se muestra en la interfaz de Frame.io.

Puedes leer más sobre las diferencias entre la API Legacy de Frame.io y la V4 en nuestra [Guía de migración](/es/platform/docs/resources/migration).

## Configura tu Custom Action {#configure-your-custom-action}

Cuando un usuario activa una Custom Action, Frame.io envía un payload a una URL que tú proporcionas. La aplicación receptora puede responder con un código de estado HTTP para confirmar la recepción, o con un callback personalizado que muestra interfaz adicional en [Frame.io](https://next.frame.io/).

<Warning>

Se necesitan permisos de Account Admin para crear Custom Actions en un Workspace. Pide a tu Admin que modifique tus permisos si no tienes acceso.

</Warning>

### Configuración de varios assets {#multi-asset-configuration}

La compatibilidad con varios assets depende de la configuración y debe habilitarse explícitamente desde el modal de configuración de la Action [en la Web](https://next.frame.io/settings/actions). Puede hacerse durante la creación de una nueva Action o al actualizar una existente.

Cuando se habilita la compatibilidad con varios assets, el formato del payload cambia de inmediato. El payload legacy y el payload compatible con varios assets son mutuamente excluyentes.

### Migrar desde el payload legacy {#migrating-from-the-legacy-payload}

<Warning>

**Retirada prevista del payload legacy**

Está prevista la retirada del payload legacy, por lo que se recomienda encarecidamente a los usuarios que migren sus servicios para procesar el nuevo payload.

Al habilitar el indicador de configuración y actualizar el manejo del payload, una Action puede pasar sin problemas a admitir un payload con varios assets.

1. Sustituye el uso del objeto singular `resource` por la lista `resources`
2. Actualiza el código para iterar sobre la lista `resources`
3. Habilita el indicador Multi-asset en la configuración de Actions

</Warning>

## Interacciones, reintentos y tiempos de espera {#interactions-retries-and-timeouts}

El `interaction_id` es un identificador único para hacer seguimiento de la interacción a medida que evoluciona. Si no necesitas responder al usuario, devuelve un código de estado 200 y listo. Aunque es opcional, recomendamos incluir información sobre el resultado de la acción, como un mensaje de éxito o una alerta de error. Las Custom Actions admiten message callbacks.

<Note>

Frame.io espera una respuesta en menos de 10 segundos e intenta reintentar hasta 5 veces mientras espera una respuesta correcta. Lo ideal es que la respuesta sea inmediata y que las acciones asíncronas ocurran después del disparo mediante una Custom Action.

</Note>

## Crear un Message Callback {#create-a-message-callback}

En tu respuesta HTTP al evento de webhook, puedes devolver un objeto JSON que describe un mensaje que se mostrará al usuario que inició la acción en la interfaz de Frame.io.

```json
{
  "title": "Success!",
  "description": "The thing worked! Nice."
}
```

Los mensajes te permiten dar información al usuario directamente en la interfaz de Frame.io. Si necesitas recopilar información adicional del usuario, usa **Form Callbacks** en su lugar.

## Crear un Form Callback {#create-a-form-callback}

Supongamos que necesitas más información antes de iniciar tu proceso. Por ejemplo, puede que estés subiendo contenido a un sistema que requiere detalles adicionales. Puedes describir un formulario en tu respuesta, que el usuario rellena y te devuelve. Aquí tienes un ejemplo:

```json
{
  "title": "Need some more info!",
  "description": "Getting ready to submit this file!",
  "fields": [
    {
      "type": "text",
      "label": "Title",
      "name": "title",
      "value": "MyVideo.mp4"
    },
    {
      "type": "select",
      "label": "Captions",
      "name": "captions",
      "options": [
        {
          "name": "Off",
          "value": "off"
        },
        {
          "name": "On",
          "value": "on"
        }
      ]
    }
  ]
}
```

Cuando el usuario envía el formulario, recibirás un evento en la misma URL que el POST inicial:

```json
POST /your/url
{
  "type": "your-specified-event-name",
  "interaction_id": "the-same-id-as-before",
  "action_id": "unique-id-for-this-custom-action",
  "data":{
    "title": "MyVideo.mp4",
    "captions": "off"
  }
}
```

Todos los campos personalizados añadidos a un formulario aparecen en la sección `data` del payload JSON enviado por Frame.io. Usa el `interaction_id` para relacionar la solicitud inicial con los nuevos datos del formulario. Puedes responder con un mensaje o encadenar otro formulario. Al encadenar Actions, formularios y mensajes, puedes programar de forma eficaz flujos de trabajo de varios pasos en Frame.io con la lógica de negocio de un sistema externo.

## Tipos de campo compatibles {#supported-field-types}

### Campo de texto {#text-field}

Un campo de texto sencillo sin parámetros adicionales.

```json
{  
  "type": "text",
  "label": "Title",
  "name": "title",
  "value": "MyVideo.mp4"
}
```

### Área de texto {#text-area}

Un área de texto sencilla sin parámetros adicionales.

```json
{  
  "type": "textarea",
  "label": "Description",
  "name": "description",
  "value": "This video is really, really popular."
}
```

### Lista de selección {#select-list}

Define una lista de opciones entre las que el usuario puede elegir. Debe incluir una lista `options`, cuyos elementos deben incluir un `name` legible por humanos y un `value` interpretable por máquinas.

```json
{
  "type": "select",
  "label": "Captions",
  "name": "captions",
  "value": "off",
  "options": [
       {
         "name": "Off",
         "value": "off"
       },
       {
         "name": "On",
         "value": "on"
      }
   ]
}
```

### Casilla de verificación {#checkbox}

Una casilla de verificación sencilla sin parámetros adicionales.

```json
{ 
   "type": "boolean", 
   "name": "enabled", 
   "label": "Enabled", 
   "value": "false"
}
```

### Enlace {#link}

Un enlace sencillo sin parámetros adicionales.

```json
{
  "type": "link",
  "name": "videoLink",
  "label": "Video Link",
  "value": "https://www.youtube.com/watch?v=XtX1zv9CEVc"
}
```

## Seguridad y verificación {#security-and-verification}

De forma predeterminada, todas las Custom Actions tienen una clave de firma generada durante su creación. Esto no es configurable. Esta clave puede usarse para verificar que la solicitud procede de Frame.io. La solicitud `POST` incluye lo siguiente:

| Nombre | Descripción |
| --- | --- |
| `X-Frameio-Request-Timestamp` | El momento en que se activó tu Custom Action. |
| `X-Frameio-Signature` | La firma calculada. |

<CardGroup cols={2}>

<Card title="Verificación de la marca de tiempo" icon="clock" iconType="solid">

**La marca de tiempo** es el momento en que se firmó la solicitud al salir de la red de Frame.io. Puede usarse para evitar ataques de repetición. Recomendamos verificar que esta hora esté dentro de un margen de 5 minutos respecto a la hora local.

</Card>

<Card title="Verificación de la firma" icon="shield" iconType="solid">

**La firma** es un hash HMAC SHA-256 que utiliza la clave de firma proporcionada cuando se crea la Custom Action por primera vez.

</Card>

</CardGroup>

### Verificar la firma {#verifying-the-signature}

<Steps>

<Step title="Extrae la firma">

Extrae la firma de los encabezados HTTP.

</Step>

<Step title="Crea el mensaje que se va a firmar">

Crea un mensaje para firmar combinando la versión, la hora de entrega y el cuerpo de la solicitud `v0:timestamp:body`.

</Step>

<Step title="Calcula el HMAC SHA256">

Calcula la firma HMAC SHA256 con tu secreto de firma.

</Step>

<Step title="Compara las firmas">

¡Compara la firma que calculaste con la proporcionada!

</Step>

</Steps>

<Note>

La firma proporcionada lleva el prefijo `v0=`. Actualmente, Frame.io solo tiene esta versión para firmar solicitudes. Tendrás que añadir este prefijo a la firma que calcules.

</Note>

```python title="Python"
import hmac
import hashlib

def verify_signature(curr_time, req_time, signature, body, secret):
    """
    Verify webhook/custom action signature
    :Args:
        curr_time (float): Current epoch time
        req_time (float): Request epoch time
        signature (str): Signature provided by the frame.io API for the given request
        body (str): Custom Action body from the received POST
        secret (str): The secret for this Custom Action that you saved when you first created it
    """
    if int(curr_time) - int(req_time) < 500:
        message = 'v0:{}:{}'.format(req_time, body)
        calculated_signature = 'v0={}'.format(hmac.new(
            bytes(secret, 'latin-1'),
            msg=bytes(message, 'latin-1'),
            digestmod=hashlib.sha256).hexdigest())
        if calculated_signature == signature:
            return True
    return False
```
