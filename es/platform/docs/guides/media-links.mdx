---
title: "Enlaces multimedia"
---

Frame.io almacena y procesa los archivos que se suben a tus proyectos: imágenes, videos, PDF y más. Cuando recuperas un archivo a través de la API, la respuesta básica incluye metadatos esenciales como el nombre del archivo, su estado y una `view_url` para abrirlo en la aplicación de Frame.io. Para acceder al contenido real del archivo (el original, una vista previa o versiones en distintas calidades), se usan los **includes**.

Esta guía explica los includes de enlaces multimedia disponibles en los endpoints **List Files** y **Get File**, qué devuelve cada uno y cuándo usarlos.

## ¿Qué son los includes? {#what-are-includes}

Los includes son campos opcionales que puedes solicitar junto con la respuesta de un archivo. De forma predeterminada, la API solo devuelve los metadatos esenciales del archivo: nombre, estado, tipo, marcas de tiempo y `view_url`. Los includes te permiten solicitar datos adicionales, de modo que las respuestas se mantienen ligeras cuando no lo necesitas todo.

### Cómo añadir includes {#how-to-add-includes}

Pasa una lista de nombres de includes separados por comas en el parámetro de consulta `include` de cualquier solicitud **Get File** o **List Files**:

```bash title="Single include"
GET /v4/accounts/{account_id}/files/{file_id}?include=media_links.thumbnail
```

```bash title="Multiple includes"
GET /v4/accounts/{account_id}/files/{file_id}?include=media_links.thumbnail,media_links.original
```

```bash title="Includes on List Files"
GET /v4/accounts/{account_id}/folders/{folder_id}/files?include=media_links.thumbnail
```

Los includes funcionan igual tanto en el endpoint de un solo archivo como en el de lista. Cuando se usan en List Files, los includes se resuelven para cada archivo de la respuesta.

### Ejemplos con los SDK {#sdk-examples}

<CodeGroup>

```python title="Python SDK"
import frameio

client = frameio.Frameio(auth="<YOUR_TOKEN>")

file = client.files.get(
    file_id="93e4079d-0a8a-4bf3-96cd-e6a03c465e5e",
    include=["media_links.thumbnail", "media_links.original"]
)

print(file.media_links.thumbnail.url)
```

```typescript title="TypeScript SDK"
import Frameio from "frameio";

const client = new Frameio({ auth: "<YOUR_TOKEN>" });

const file = await client.files.get("93e4079d-0a8a-4bf3-96cd-e6a03c465e5e", {
  include: ["media_links.thumbnail", "media_links.original"],
});

console.log(file.media_links?.thumbnail?.url);
```

</CodeGroup>

Los includes que no se solicitan se omiten por completo de la respuesta.

## media_links.original {#media_links-original}

Devuelve URL firmadas que apuntan al **archivo original exactamente como se subió**, sin procesamiento ni conversión.

### Campos {#fields}

| Campo | Tipo | Descripción |
| --- | --- | --- |
| `download_url` | string \| null | URL firmada que fuerza la descarga del archivo (`Content-Disposition: attachment`) |
| `inline_url` | string \| null | URL firmada que abre el archivo directamente en el navegador (`Content-Disposition: inline; filename=<name>`) |

### Cuándo usarlo {#when-to-use}

Usa `media_links.original` cuando necesites el archivo de origen; por ejemplo, para permitir que un usuario descargue el MOV, MP4, MXF, AVI, PSD, PNG o TIFF original, o para pasar los bytes originales a otro sistema.

### Ejemplo de solicitud {#example-request}

```bash
GET /v4/accounts/{account_id}/files/{file_id}?include=media_links.original
```

### Ejemplo de respuesta {#example-response}

```json
{
  "data": {
    "id": "93e4079d-0a8a-4bf3-96cd-e6a03c465e5e",
    "name": "hero-banner.png",
    "type": "file",
    "media_links": {
      "original": {
        "download_url": "https://s3.amazonaws.com/...",
        "inline_url": "https://s3.amazonaws.com/..."
      }
    }
  }
}
```

<Warning>

Estas URL son **URL firmadas temporales de S3**: caducan. No las almacenes en caché ni las guardes; solicita una URL nueva cada vez que la necesites.

</Warning>

## media_links.thumbnail {#media_links-thumbnail}

Devuelve una **imagen de vista previa PNG** del asset, con una altura máxima de 540 px. Se trata de una versión procesada, no del archivo original, y es posible que se apliquen marcas de agua según la configuración de tu cuenta.

### Campos {#fields-1}

| Campo | Tipo | Descripción |
| --- | --- | --- |
| `download_url` | string \| null | URL firmada que fuerza la descarga de la miniatura PNG |
| `url` | string \| null | URL firmada que sirve la miniatura PNG en línea, sin encabezado `Content-Disposition` |

### Cuándo usarlo {#when-to-use-1}

Usa `media_links.thumbnail` cuando necesites **mostrar una vista previa visual** del asset; por ejemplo, en una vista de cuadrícula, una galería o un selector de archivos. Carga más rápido que el original y siempre está en formato PNG compatible con la web.

### Ejemplo de solicitud {#example-request-1}

```bash
GET /v4/accounts/{account_id}/files/{file_id}?include=media_links.thumbnail
```

### Ejemplo de respuesta {#example-response-1}

```json
{
  "data": {
    "id": "93e4079d-0a8a-4bf3-96cd-e6a03c465e5e",
    "name": "hero-banner.png",
    "type": "file",
    "media_links": {
      "thumbnail": {
        "download_url": "https://s3.amazonaws.com/...",
        "url": "https://s3.amazonaws.com/..."
      }
    }
  }
}
```

## media_links.high_quality {#media_links-high_quality}

Devuelve una URL de descarga de la **mejor versión procesada disponible** del asset. Frame.io procesa las subidas mediante una escalera de resoluciones que llega hasta 2160p. La API devuelve la versión más alta disponible **en el momento de la solicitud**, por lo que, si solo ha terminado de procesarse una versión de 540p cuando haces la solicitud, la API devolverá 540p hasta que estén listas las versiones superiores.

### Campos {#fields-2}

| Campo | Tipo | Descripción |
| --- | --- | --- |
| `download_url` | string \| null | URL firmada de la versión de mayor calidad disponible en el momento de la solicitud |

### Cuándo usarlo {#when-to-use-2}

Usa `media_links.high_quality` cuando quieras la **versión de mejor calidad sin necesitar el original**; por ejemplo, para exportar una versión de alta resolución para un procesamiento posterior o para mostrar una vista previa a resolución completa. Si necesitas la máxima calidad posible, comprueba el campo `status` del archivo y solicita este include cuando el archivo esté `ready`, para asegurarte de que se ha procesado toda la escalera de resoluciones.

### Ejemplo de solicitud {#example-request-2}

```bash
GET /v4/accounts/{account_id}/files/{file_id}?include=media_links.high_quality
```

### Ejemplo de respuesta {#example-response-2}

```json
{
  "data": {
    "id": "93e4079d-0a8a-4bf3-96cd-e6a03c465e5e",
    "name": "hero-banner.png",
    "type": "file",
    "media_links": {
      "high_quality": {
        "download_url": "https://s3.amazonaws.com/..."
      }
    }
  }
}
```

## media_links.efficient {#media_links-efficient}

Devuelve una URL de descarga de la **versión procesada más pequeña disponible**. Es lo contrario de `high_quality`: Frame.io elige la versión de menor resolución disponible.

### Campos {#fields-3}

| Campo | Tipo | Descripción |
| --- | --- | --- |
| `download_url` | string \| null | URL firmada de la versión más pequeña/más eficiente |

### Cuándo usarlo {#when-to-use-3}

Usa `media_links.efficient` cuando **el ancho de banda o el tamaño del archivo importan más que la calidad**; por ejemplo, para generar vistas previas rápidas en un entorno con poco ancho de banda o para alimentar un pipeline de miniaturas que no necesita la resolución completa.

### Ejemplo de solicitud {#example-request-3}

```bash
GET /v4/accounts/{account_id}/files/{file_id}?include=media_links.efficient
```

### Ejemplo de respuesta {#example-response-3}

```json
{
  "data": {
    "id": "93e4079d-0a8a-4bf3-96cd-e6a03c465e5e",
    "name": "hero-banner.png",
    "type": "file",
    "media_links": {
      "efficient": {
        "download_url": "https://s3.amazonaws.com/..."
      }
    }
  }
}
```

## media_links.video_h264_180 {#media_links-video_h264_180}

Devuelve URL de streaming y de descarga de una **transcodificación de video H264 de baja resolución a 180p** del asset.

<Warning>

Este es un include legacy. Será `null` si no se generó una transcodificación a 180p para el asset. Para la mayoría de los casos de uso, es preferible `media_links.efficient`, que selecciona la mejor versión de baja calidad disponible en lugar de depender de que exista una transcodificación concreta.

</Warning>

### Campos {#fields-4}

| Campo | Tipo | Descripción |
| --- | --- | --- |
| `download_url` | string \| null | URL firmada para descargar el video H264 a 180p |
| `url` | string \| null | URL firmada para reproducir en streaming el video H264 a 180p |

### Cuándo usarlo {#when-to-use-4}

Usa `media_links.video_h264_180` cuando necesites específicamente una transcodificación H264 a 180p garantizada; por ejemplo, para integrarte con un reproductor o pipeline legacy que requiera exactamente este formato. Si la transcodificación no existe para un asset determinado, ambas URL serán `null`.

<Warning>

El archivo video_h264_180 no incluye audio. Está pensado para usarse en vistas previas muy eficientes cuando sea necesario.

</Warning>

### Ejemplo de solicitud {#example-request-4}

```bash
GET /v4/accounts/{account_id}/files/{file_id}?include=media_links.video_h264_180
```

### Ejemplo de respuesta {#example-response-4}

```json
{
  "data": {
    "id": "93e4079d-0a8a-4bf3-96cd-e6a03c465e5e",
    "name": "interview-clip.mp4",
    "type": "file",
    "media_links": {
      "video_h264_180": {
        "download_url": "https://s3.amazonaws.com/...",
        "url": "https://s3.amazonaws.com/..."
      }
    }
  }
}
```

## media_links.scrub_sheet {#media_links-scrub_sheet}

Devuelve una **hoja de sprites WebP**: una sola imagen que contiene una cuadrícula de miniaturas de fotogramas del video muestreados de manera uniforme a lo largo de su duración. Se usa para crear interfaces de scrubbing de video, en las que el reproductor muestra un fotograma de vista previa mientras el usuario arrastra por la línea de tiempo.

<Info>

Las hojas de scrubbing se generan **solo para assets de video**. El include devolverá URL `null` para imágenes, PDF y otros archivos que no sean de video.

</Info>

### Campos {#fields-5}

| Campo | Tipo | Descripción |
| --- | --- | --- |
| `download_url` | string \| null | URL firmada para descargar la hoja de sprites WebP |
| `url` | string \| null | URL firmada para cargar la hoja de sprites WebP en línea |
| `metadata` | object \| null | Información de la disposición de los mosaicos para extraer fotogramas individuales (solo en la API experimental) |

**Campos de `metadata`:**

| Campo | Tipo | Descripción |
| --- | --- | --- |
| `tile_x` | integer | Número de columnas de miniaturas en la cuadrícula |
| `tile_y` | integer | Número de filas de miniaturas en la cuadrícula |
| `thumb_width` | integer | Ancho de cada miniatura en píxeles |
| `thumb_height` | integer | Alto de cada miniatura en píxeles |
| `padding` | integer | Separación en píxeles entre miniaturas |
| `frames` | integer | Número total de fotogramas muestreados en la hoja |

### Cuándo usarlo {#when-to-use-5}

Usa `media_links.scrub_sheet` cuando crees un reproductor de video personalizado o una interfaz de línea de tiempo que necesite mostrar una miniatura de vista previa mientras el usuario hace scrubbing. En lugar de hacer una solicitud independiente para cada fotograma, la hoja de sprites agrupa todos los fotogramas de vista previa en una sola descarga de imagen.

### Ejemplo de solicitud {#example-request-5}

```bash
GET /v4/accounts/{account_id}/files/{file_id}?include=media_links.scrub_sheet
```

### Ejemplo de respuesta {#example-response-5}

```json
{
  "data": {
    "id": "93e4079d-0a8a-4bf3-96cd-e6a03c465e5e",
    "name": "interview-clip.mp4",
    "type": "file",
    "media_links": {
      "scrub_sheet": {
        "download_url": "https://assets.frame.io/...",
        "url": "https://assets.frame.io/...",
        "metadata": {
          "tile_x": 10,
          "tile_y": 10,
          "thumb_width": 160,
          "thumb_height": 90,
          "padding": 1,
          "frames": 100
        }
      }
    }
  }
}
```

### Extraer un fotograma de la hoja de sprites {#extracting-a-frame-from-the-sprite-sheet}

La hoja de sprites es una cuadrícula de `tile_x` columnas × `tile_y` filas. Para mostrar la miniatura de un índice de fotograma determinado (empezando en cero), calcula su posición dentro de la imagen:

```javascript
function getFrameOffset(frameIndex, metadata) {
  const { tile_x, thumb_width, thumb_height, padding } = metadata;

  const col = frameIndex % tile_x;
  const row = Math.floor(frameIndex / tile_x);

  return {
    x: col * (thumb_width + padding),
    y: row * (thumb_height + padding),
    width: thumb_width,
    height: thumb_height,
  };
}
```

A continuación, puedes usar la propiedad CSS `background-position` para mostrar el mosaico correcto de la hoja de sprites:

```javascript
function applyFrameToElement(el, frameIndex, scrubSheet) {
  const { x, y, width, height } = getFrameOffset(frameIndex, scrubSheet.metadata);

  el.style.backgroundImage = `url(${scrubSheet.url})`;
  el.style.backgroundPosition = `-${x}px -${y}px`;
  el.style.width = `${width}px`;
  el.style.height = `${height}px`;
}
```

Para convertir una posición de reproducción (en segundos) en un índice de fotograma, usa la duración total del video y el número de fotogramas de la hoja:

```javascript
function positionToFrameIndex(currentSeconds, durationSeconds, metadata) {
  const progress = currentSeconds / durationSeconds;
  return Math.min(
    Math.floor(progress * metadata.frames),
    metadata.frames - 1
  );
}
```

<Info>

El campo `metadata` solo está disponible en la versión experimental de la API. En la API v4 estable, `scrub_sheet` solo devuelve `download_url` y `url`.

</Info>

## Combinar varios includes {#combining-multiple-includes}

Puedes solicitar varios includes en una sola llamada a la API:

```bash
GET /v4/accounts/{account_id}/files/{file_id}?include=media_links.thumbnail,media_links.original
```

```json
{
  "data": {
    "id": "93e4079d-0a8a-4bf3-96cd-e6a03c465e5e",
    "name": "hero-banner.png",
    "type": "file",
    "media_links": {
      "thumbnail": {
        "download_url": "https://s3.amazonaws.com/...",
        "url": "https://s3.amazonaws.com/..."
      },
      "original": {
        "download_url": "https://s3.amazonaws.com/...",
        "inline_url": "https://s3.amazonaws.com/..."
      }
    }
  }
}
```

## Elegir el include adecuado {#choosing-the-right-include}

| Objetivo | Include que debes usar |
| --- | --- |
| Mostrar una imagen de vista previa en tu interfaz | `media_links.thumbnail` |
| Permitir que un usuario descargue el archivo original | `media_links.original` |
| Abrir el archivo original directamente en el navegador | `media_links.original` → `inline_url` |
| Obtener la versión de mejor calidad para exportar | `media_links.high_quality` |
| Obtener una versión pequeña para usos con poco ancho de banda | `media_links.efficient` |
| Reproducir en streaming o descargar un video de baja resolución (legacy) | `media_links.video_h264_180` |
| Crear una interfaz de scrubbing de video con vistas previas de fotogramas | `media_links.scrub_sheet` |
| Llevar a un usuario al archivo en Frame.io | Usa `view_url` de la respuesta básica del archivo |

<Info>

`view_url`, disponible en todas las respuestas de archivo sin necesidad de un include, es un enlace profundo permanente a la aplicación web de Frame.io. **No** es una URL multimedia: abre la interfaz de Frame.io y no caduca. Úsala cuando quieras dirigir a un usuario a revisar o comentar un asset directamente en Frame.io, no cuando necesites servir o descargar el archivo mediante programación.

</Info>

## Disponibilidad de los includes {#include-availability}

Los includes de enlaces multimedia solo se rellenan cuando Frame.io ha terminado de procesar el archivo subido. Si solicitas un include inmediatamente después de la subida, las URL pueden ser `null` mientras la transcodificación está en curso. Comprueba el campo `status` del objeto de archivo: los includes estarán disponibles cuando el estado sea `ready`.
