## Introducción {#introduction}

La API Frame.io V4 es un rediseño de la API Legacy, a menudo denominada *endpoints V2* o *API Frame.io V3*. El rediseño aprovecha al máximo las nuevas capacidades y funciones de Frame V4 y mantiene toda la funcionalidad relevante de la API Legacy. Esta guía describe las principales diferencias entre la API Legacy y la API V4 y ofrece instrucciones paso a paso para ayudarte a migrar sin problemas.

## Lista de comprobación de la migración {#migration-checklist}

<Steps>

<Step title="Autenticación">

En el caso de las <Tooltip tip="Cuentas que usaban la API Legacy con un token de desarrollador generado y que se migraron automáticamente a V4. No se incluyen las cuentas creadas en V4 ni las migradas manualmente">**cuentas migradas automáticamente a V4**</Tooltip> que todavía no se administran mediante Adobe Admin Console, puedes seguir usando los tokens de desarrollador Legacy gestionados en el [sitio para desarrolladores de Frame.io](/es/platform/welcome), pero tendrás que añadir a tus solicitudes a la API un encabezado con la clave `x-frameio-legacy-token-auth` y el valor `true`. De lo contrario, debes seguir los pasos de la sección [Autenticación](#adobe-developer-console-managed-authentication) que aparece más abajo.

</Step>

<Step title="Actualizar las llamadas a la API existentes">

Todas las rutas de la API Legacy deberán asignarse a las nuevas rutas y cargas JSON de la API V4. Más abajo encontrarás una tabla de [correspondencias](#endpoint-mappings-legacy-api-to-v4) bastante completa para ayudarte en este proceso.

</Step>

<Step title="Se recomienda encarecidamente realizar pruebas">

**Realiza pruebas exhaustivas.** Como la API presenta muchos cambios, se recomienda hacer pruebas con una cuenta V4 para asegurarte de que la nueva API funciona como se espera.

</Step>

<Step title="Implementar un inicio de sesión específico">

Implementa un método de inicio de sesión específico para V4, ya que las URL de autenticación son distintas. La URL de autenticación de V4 es diferente de la de la API Legacy, no devolverá en la respuesta las cuentas que aún no se hayan actualizado a V4 y debe tratarse como una integración independiente.

</Step>

</Steps>

<Note>

Si tienes preguntas sobre algún endpoint que no aparece en la tabla de correspondencias siguiente, ponte en contacto con nuestro equipo de soporte en [support@frame.io](mailto:support@frame.io).

</Note>

## Autenticación gestionada mediante Adobe Developer Console {#adobe-developer-console-managed-authentication}

En el caso de las cuentas migradas a V4 que se gestionan a través de [Adobe Developer Console](https://developer.adobe.com/developer-console/), tendrás que usar la API V4 con OAuth 2.0. Deberás seguir los pasos siguientes.

<Steps>

<Step title="Crear un proyecto de Adobe">

**Crea un proyecto en Adobe Developer Console** y añade Frame.io como producto.

</Step>

<Step title="Elegir el tipo de autenticación">

**Autentícate.** Consulta la [Guía de autenticación](https://developer.adobe.com/frameio/guides/Authentication/) para obtener más información. Si tu cuenta V4 todavía no se gestiona mediante Adobe Admin Console, puedes omitir este paso.

- **Autenticación de usuario**: se conecta a Frame mediante un Client ID o un Client Secret, y requiere que un usuario inicie sesión con su nombre de usuario y contraseña.
- **Autenticación de servidor a servidor**: se conecta a Frame mediante un Client ID y un Client Secret, pero no requiere que un usuario intervenga para iniciar sesión a través de un navegador.

</Step>

<Step title="Implementar la autenticación Bearer">

**Autenticación JWT Bearer**: en cada solicitud a la API, envía el token de autenticación mediante un encabezado con la clave `Authorization` y el valor `Bearer <IMS_ACCESS_TOKEN>`.

</Step>

</Steps>

## Correspondencias de endpoints (de la API Legacy a V4) {#endpoint-mappings-legacy-api-to-v4}

<Note>

Si usas la autenticación con token de desarrollador Legacy, tendrás que añadir a tus solicitudes a la API un encabezado con la clave x-frameio-legacy-token-auth y el valor true.

</Note>

Notas generales para ayudarte con la migración:

<Steps>

<Step title="Cargas útiles">

Las cargas útiles de solicitud y respuesta pueden ser distintas.

</Step>

<Step title="Teams → Workspaces">

Los "Teams" de la API Legacy equivalen a los "Workspaces" de V4.

</Step>

<Step title="Assets">

Los "Assets" de la API Legacy ahora se dividen en "Files", "Folders" y "Version Stacks" en V4.

</Step>

<Step title="Permisos">

Los permisos y roles son diferentes en V4, lo que cambia la estructura de los endpoints. En V4 hay roles de usuario de espacio de trabajo y de proyecto. Para obtener más información, consulta [Gestionar los permisos de usuario](/es/platform/docs/guides/managing-user-permissions).

</Step>

</Steps>

### 8. Shares (enlaces de revisión / presentaciones) {#8-shares-review-links-/-presentations}

Nota: no se admite interactuar con enlaces de revisión y presentaciones Legacy mediante la API V4.

### 9. Webhooks {#9-webhooks}

Los webhooks que usabas en V3 se migrarán y, en su mayor parte, funcionarán igual. Al migrarse, quedarán deshabilitados y tendrás que habilitarlos para que funcionen. Habrá que hacer algunos cambios en los eventos de assets, que ahora se dividen en archivos y carpetas. Hay algunos eventos nuevos específicos de V4 que conviene conocer: metadata.value.updated, eventos relacionados con colecciones y eventos relacionados con shares.

Antes de volver a habilitar los webhooks migrados, revisa los [límites de tasa de los webhooks](/es/platform/docs/guides/webhooks#webhook-rate-limits). Los eventos de webhooks y de Custom Actions de V4 comparten unos límites de **1000 eventos por minuto** y **20 000 eventos por hora** por cuenta. Ambos límites se aplican a su volumen combinado en toda la cuenta.

### 10. Custom Actions {#10-custom-actions}

## Pasos de la migración {#migration-steps}

<Steps>

<Step title="Ajustar los endpoints V2 no admitidos">

**Ajusta** los endpoints Legacy V2 que no se admitan.

</Step>

<Step title="Actualizar las URL base">

**Actualiza las URL base** de `api.frame.io/v2/...` a `api.frame.io/v4/...`.

</Step>

<Step title="Actualizar las solicitudes a la API">

**Actualiza las solicitudes a la API** de tu código para que hagan referencia al nuevo esquema de endpoints.

</Step>

<Step title="Actualizar las cargas JSON">

**Actualiza las cargas JSON** de los esquemas de solicitud y respuesta para asegurarte de que generas y consumes los campos correctos.

</Step>

<Step title="Actualizar la terminología">

Actualiza la terminología: "teams" → "workspaces"; "assets" → "files/folders"; "review links" o "presentation links" → "shares" en tu código y en tu front-end.

</Step>

<Step title="Probar los endpoints">

**Prueba** todos los endpoints recién actualizados. Si ves errores 403, 404 o 422, comprueba los endpoints, la forma de la carga útil de la solicitud, etc.

</Step>

<Step title="Analizar las respuestas de error">

**Analiza** las nuevas respuestas de error detalladas y busca el problema en la respuesta JSON `{"errors": [...]}` si tu llamada a la API falla.

</Step>

<Step title="Desplegar en producción">

**Despliega** en producción una vez validado con una cuenta V4 de [Frame.io](http://frame.io/).

</Step>

</Steps>

## Gestión de errores y problemas habituales {#error-handling-&-common-issues}

<Note>

Algunas rutas devuelven errores con descripciones personalizadas que pueden diferir ligeramente de los ejemplos siguientes.

</Note>

<CardGroup cols={2}>

<Card title="Errores del cliente (4xx)" icon="triangle-exclamation" iconType="solid">

- **400** Bad Request: comprueba que la carga útil sea correcta.
- **401** Unauthorized: token de autorización no válido o ausente.
- **403** Forbidden: falta un scope o el usuario no tiene acceso.
- **404** Not Found: comprueba el endpoint, la versión de la API o los ID.
- **422** Unprocessable Entity: valida los datos de la solicitud
- **429** Too Many Requests: implementa reintentos con retroceso.

</Card>

<Card title="Errores del servidor (5xx)" icon="server" iconType="solid">

- **500** Internal Server Error: vuelve a intentarlo tras una breve espera.

</Card>

</CardGroup>
