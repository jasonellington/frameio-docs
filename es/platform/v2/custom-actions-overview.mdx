Las Custom Actions son una forma de crear integraciones directamente en Frame.io como componentes de interfaz programables. Esto hace posible toda una clase de workflows que los usuarios pueden activar desde la aplicación, aprovechando el mismo enrutamiento de eventos subyacente que los [Webhooks](/es/platform/v2/webhooks-overview). Actualmente, las Custom Actions están disponibles para los Assets y se muestran en el menú desplegable contextual (clic derecho) disponible en cualquier Asset, como se ve en la imagen siguiente.

![actions-1](/images/platform/v2/custom-actions-overview/69bc65d3924a350e0c1d5a8062e41b15cbc3b01f1f3b8ec5050356b76aa1989a.webp)

Un Asset es una representación completa de un archivo en S3 y de su contexto en Frame.io. Esto incluye las transcodificaciones, el contexto de usuario/equipo/proyecto y los metadatos. Cuando un usuario hace clic en una Custom Action sobre un Asset, Frame.io envía un payload a una URL que tú proporcionas. La aplicación receptora puede responder con un código de estado HTTP para simplemente confirmar la recepción, o con un callback personalizado que puede mostrar una interfaz adicional en Frame.io.

## Configura tu Custom Action {#setup-your-custom-action}

<Info>

**Comprueba tus permisos**

Se necesitan permisos de Team Manager para crear Custom Actions para un equipo. Pide a tu administrador que modifique tus permisos si no tienes acceso.

</Info>

Las Custom Actions se pueden configurar en la sección [Custom Actions](https://developer.frame.io/actions) de [developer.frame.io](/es/platform/v2). Una acción requiere:

| Nombre del campo | Descripción |
| --- | --- |
| Name | El nombre que elijas para tu Custom Action. Se mostrará en el menú de Custom Actions disponibles en Frame.io. |
| Description | Explica qué hace la acción, a modo de referencia (la descripción no aparece en la aplicación web de Frame.io). |
| Event | Clave de evento interna que te ayuda a diferenciar entre los eventos de webhook estándar y los tuyos. |
| URL | Dónde se entregan los eventos. |
| Team | El equipo que usará la Custom Action. |

## Clic: qué contiene el payload que recibes de Frame.io {#click-what’s-in-the-payload-you-receive-from-frame-io}

Cuando el usuario hace clic en tu Custom Action, se envía un payload a la URL que especificaste en el campo URL.

```json
POST /your/url
{
  "action_id": "2444cccc-7777-4a11-8ddd-05aa45bb956b",
  "interaction_id": "aafa3qq2-c1f6-4111-92b2-4aa64277c33f",
  "project": {
    "id": "a7d6a74b-d45d-4019-9069-24651e0b9f64"
  },
  "resource": {
    "id": "9q2e5555-3a22-44dd-888a-abbb72c3333b",
    "type": "asset"
  },
  "team": {
    "id": "54353cd2-c6ee-4aa1-954a-ce9e19602aa9"
  },
  "type": "my.action",
  "user": {
    "id": "fb57eee0-79f2-4bc7-9b70-99fbc175175c"
  }
}
```

Puedes usar este payload para identificar:

- Cuál de tus Custom Actions se ha pulsado
- En qué recurso se ha hecho clic
- Qué usuario realizó la acción

| Nombre del campo | Descripción |
| --- | --- |
| `action_id` | El id único de esta Action. Siempre será el mismo para una Action determinada. |
| `interaction_id` | Es un identificador único generado por Frame.io que puedes usar para hacer el seguimiento de tu transacción. Este identificador será el mismo durante toda una secuencia de una Action, incluidos los formularios de callback. |
| `type` | El nombre del evento que pusiste en el campo Event al configurar tu Action. |
| `resource.id` | El id del recurso desde el que activaste tu Action (normalmente un Asset). |
| `resource.type` | El tipo de recurso desde el que activaste tu Action (normalmente *asset*) |

<Info>

**Acerca de las interacciones**

El `interaction_id` se proporciona como identificador único para ayudarte a hacer el seguimiento de la interacción a medida que evoluciona. Si no necesitas responder al usuario, simplemente devuelve un código de estado 200 y listo. Aunque es opcional, recomendamos incluir algo de información sobre el resultado de la acción, como un simple mensaje de éxito o una alerta de error. Las Custom Actions admiten callbacks de mensaje.

</Info>

<Info>

**Reintentos y tiempos de espera**

Nuestra aplicación espera una respuesta en menos de 5 segundos e intentará reintentar hasta 5 veces mientras espera una respuesta correcta. Lo ideal es que respondas de inmediato y realices cualquier acción de forma asíncrona después de que se active mediante una Custom Action.

</Info>

## Crear un callback de mensaje {#create-a-message-callback}

En tu respuesta HTTP al evento del webhook, puedes devolver un objeto JSON que describa un mensaje que se mostrará al usuario que inició la acción en la interfaz de Frame.io. Si quieres probar a crear un mensaje y ver cómo queda, puedes usar nuestro [Custom Action Builder](https://next.frame.io/settings/actions), que te permite configurar callbacks de mensaje o formularios y ver cómo aparecerían en la aplicación web de Frame.io.

Este es un objeto de ejemplo:

```json
{
  "title": "Success!",
  "description": "The thing worked! Nice."
}
```

Esto mostrará al usuario una alerta como esta:
![actions-3](/images/platform/v2/custom-actions-overview/a7fe1ec18a4467f8b450b31d1e3a70ab26beece9f5ed828166f4d35973e55c3c.webp)

Los mensajes son una forma sencilla de cerrar el ciclo de vida de la acción proporcionando contexto variable al usuario que actúa, sin pedirle que cambie de contexto.

Esto basta para muchos casos de uso, pero a veces el payload inicial y las llamadas posteriores a la API de Frame.io no proporcionan suficiente contexto a la aplicación receptora. Para estos casos, también admitimos **callbacks de formulario**.

## Crear un callback de formulario {#create-a-form-callback}

Supongamos que necesitas más información antes de iniciar tu proceso. Por ejemplo, puede que estés subiendo contenido a un sistema que requiere detalles y ajustes adicionales. Puedes "describir" un formulario en tu respuesta, ¡y el usuario lo verá de verdad! ¡Y lo rellenará! ¡Y te lo enviarán de vuelta!

Este es un ejemplo que mostrará un formulario en la interfaz de Frame.io que el usuario que inició la acción puede rellenar y enviar:

```json
{
  "title": "Need some more info!",
  "description": "Getting ready to submit this file!",
  "fields": [
    {
      "type": "text",
      "label": "Title",
      "name": "title",
      "value": "MyVideo.mp4"
    },
    {
      "type": "select",
      "label": "Captions",
      "name": "captions",
      "options": [
        {
          "name": "Off",
          "value": "off"
        },
        {
          "name": "On",
          "value": "on"
        }
      ]
    }
  ]
}
```

![actions-form](/images/platform/v2/custom-actions-overview/4538043046be16b30b0230c21291dde8ae51554dc1da719bec8b9f7561c7c8a1.webp)

Cuando el usuario envía el formulario, recibirás un evento en la misma URL que el POST inicial:

```json
POST /your/url​
{
  "type": "your-specified-event-name",
  "interaction_id": "the-same-id-as-before",
  "action_id": "unique-id-for-this-custom-action",
  "data":{
    "title": "MyVideo.mp4",
    "captions": "off"
  }
}
```

Todos los campos personalizados que añadiste a tu formulario aparecen en la sección `data` del payload JSON enviado por Frame.io

Usa el `interaction_id` para relacionar la solicitud inicial con estos nuevos datos del formulario. Y, de nuevo, si quieres, puedes responder con un mensaje (¡o incluso con otro formulario!).

Encadenando Actions, formularios y mensajes, puedes programar de forma efectiva workflows completos de Assets en Frame.io con la lógica de negocio de un sistema externo.

¡Usa la imaginación! El límite es el cielo.

### Detalles de los formularios {#form-details}

Al igual que los mensajes, los formularios admiten los atributos `title` y `description`, que se muestran en la parte superior del formulario. Además, cada campo de formulario acepta los siguientes atributos básicos:

- `type`: indica a la interfaz de Frame.io qué tipo de datos esperar y qué componente mostrar.
- `label`: aparece en la interfaz como encabezado sobre el campo.
- `name`: clave con la que se identificará el campo en el payload posterior.
- `value`: valor con el que se rellenará previamente el campo.

### Tipos de campo admitidos {#supported-field-types}

**Campo de texto**
Un campo de texto simple sin parámetros adicionales.

```json
{  
  "type": "text",
  "label": "Title",
  "name": "title",
  "value": "MyVideo.mp4"
}
```

**Área de texto**
Un área de texto simple sin parámetros adicionales.

```json
{  
  "type": "textarea",
  "label": "Description",
  "name": "description",
  "value": "This video is really, really popular."
}
```

**Lista de selección**
Define una lista de opciones entre las que el usuario puede elegir. Debe incluir una lista `options`, cada uno de cuyos elementos debe incluir un `name` legible por humanos y un `value` interpretable por máquinas.

```json
{
  "type": "select",
  "label": "Captions",
  "name": "captions",
  "value": "off",
  "options": [
       {
         "name": "Off",
         "value": "off"
       },
       {
         "name": "On",
         "value": "on"
      }
   ]
}
```

## Las Custom Actions y el modelo de permisos de Frame.io {#custom-actions-and-the-frame-io-permissions-model}

Los Webhooks y las Custom Actions tienen un modelo de permisos especial: pertenecen a un **Team**, no a un usuario concreto que exista en un Team o una Account. Esto significa que:

- Cualquier Admin o Team Manager puede crear una Custom Action en un Team.
- Cualquier Admin o Team Manager puede modificar o eliminar una Custom Action existente en un Team. Una vez modificada, todos los usuarios verán inmediatamente el resultado del cambio.

## Seguridad {#security}

De forma predeterminada, todas las Custom Actions tienen una clave de firma generada durante su creación. Esto no es configurable. Esta clave puede usarse para verificar que la solicitud procede de Frame.io.

### Verificación {#verification}

La solicitud `POST` incluye lo siguiente

| Nombre | Descripción |
| --- | --- |
| `X-Frameio-Request-Timestamp` | El momento en que se activó tu Custom Action. |
| `X-Frameio-Signature` | La firma calculada. |

**La marca de tiempo** es el momento en que se firmó la solicitud al salir de la red de Frame.io. Puede usarse para evitar ataques de repetición. Recomendamos verificar que esta hora esté dentro de un margen de 5 minutos respecto a la hora local.

**La firma** es un hash HMAC SHA-256 que utiliza la clave de firma proporcionada cuando se crea la Custom Action por primera vez.

#### Verificar la firma {#verifying-the-signature}

1. Extrae la firma de los encabezados HTTP
2. Crea un mensaje para firmar combinando la versión, la hora de entrega y el cuerpo de la solicitud

- `v0:timestamp:body`

3. Calcula la firma HMAC SHA256 con tu secreto de firma.

- Nota: la firma proporcionada lleva el prefijo `v0=`. Actualmente Frame.io solo tiene esta versión para firmar solicitudes. Tendrás que añadir este prefijo a la firma que calcules.

4. ¡Compara!

```python title="Python"
import hmac
import hashlib

def verify_signature(curr_time, req_time, signature, body, secret):
    """
    Verify webhook/custom action signature
    :Args:
        curr_time (float): Current epoch time
        req_time (float): Request epoch time
        signature (str): Signature provided by the frame.io API for the given request
        body (str): Custom Action body from the received POST
        secret (str): The secret for this Custom Action that you saved when you first created it
    """
    if int(curr_time) - int(req_time) < 500:
        message = 'v0:{}:{}'.format(req_time, body)
        calculated_signature = 'v0={}'.format(hmac.new(
            bytes(secret, 'latin-1'),
            msg=bytes(message, 'latin-1'),
            digestmod=hashlib.sha256).hexdigest())
        if calculated_signature == signature:
            return True
    return False
```
