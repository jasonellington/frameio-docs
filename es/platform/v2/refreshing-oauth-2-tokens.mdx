## Conceptos básicos de la actualización de tokens {#basics-of-token-refresh}

Suponiendo que hayas incluido el scope ***offline*** en tu solicitud de credenciales de OAuth2.0, una autenticación correcta mediante la aplicación Accounts de Frame.io devolverá un payload similar al siguiente:

```json
{
  "access_token":"BEARER_TOKEN",
  "expires_in":3600,
  "refresh_token":"REFRESH_TOKEN",
  "scope":"account.read offline",
  "token_type":"bearer"
}
```

El `access_token` es un bearer token que se puede usar para actuar en nombre del usuario autenticado; caducará después de 3600 segundos (una hora) y, a partir de entonces, se puede usar el `refresh_token` para obtener un nuevo `access_token`. A su vez, el refresh token caducará después de 30 días, momento en el que necesitarás que el usuario vuelva a iniciar sesión desde cero, lo que generará un nuevo par de tokens de acceso/actualización; y así sucesivamente.

Si no solicitas el scope *offline* explícitamente, no recibirás un `refresh_token` y, por lo tanto, después de una hora tendrás que volver a autenticar completamente al usuario.

### Capturar el refresh token tras una autenticación correcta {#capturing-the-refresh-token-on-successful-authentication}

Obviamente, no puedes usar un `refresh_token` que no tienes, así que asegúrate de que tu aplicación:

- Solicite el scope **offline**
- Capture el `refresh_token` que se devuelve en un callback correcto.

Para mayor comodidad, aquí se reproduce el callback de nuestras [guías de aplicaciones OAuth 2](https://developer.frame.io/oauth-2-applications/building-an-oauth-2-app), con una llamada a `os` para guardar el refresh token. Ten en cuenta que se proporcionan dos ejemplos: uno con PKCE configurado (no incluye el encabezado de autenticación básica) y otro sin él (incluye el encabezado de autenticación básica).

### Sin PKCE {#without-pkce}

```python title="Python"
def callback():
  # Where `request` refers to our initial call to the auth URL
  state = request.args.get('state')
  scope = request.args.get('scope')
  code = request.args.get('code')
  error = request.args.get('error')

  if error:
    return "Error: " + error

  # Set up for client authorization and set up the data you need to send.
  client_auth = requests.auth.HTTPBasicAuth(CLIENT_ID, CLIENT_SECRET)

  post_data = {
    "grant_type": "authorization_code",
    "code": code,
    "redirect_uri": REDIRECT_URI,
    "state": state,
    "scope": SCOPE
  }

  # Send a POST request with the data you need to receive an access token. 
  response = requests.post(TOKEN, auth=client_auth, data=post_data)    
	# Stash the refresh token for later
  os.environ['REFRESH_TOKEN'] = response.json()["refresh_token"]

  return response.text
```

### Con PKCE {#with-pkce}

```python title="Python"
def callback():
  # Where `request` refers to our initial call to the auth URL
  state = request.args.get('state')
  scope = request.args.get('scope')
  code = request.args.get('code')
  error = request.args.get('error')

  if error:
    return "Error: " + error

  # If using PKCE, you must include the CLIENT_ID in your request body  
  post_data = {
    "grant_type": "authorization_code",
    "code": code,
    "redirect_uri": REDIRECT_URI,
    "state": state,
    "scope": SCOPE
    "client_id": CLIENT_ID 
  }

  # Send a POST request with the data you need to receive an access token.
  # If using PKCE, use the below request with no auth
  response = requests.post(TOKEN_URL, data=post_data)
  # Stash the refresh token for later
  os.environ['REFRESH_TOKEN'] = response.json()["refresh_token"]

  return response.text
```

## Ejecutar una actualización {#executing-a-refresh}

La actualización en sí es una única llamada a la URL de tokens de Frame.io:

- Método: POST
- URL: **[https://applications.frame.io/oauth2/token](https://applications.frame.io/oauth2/token)**
- `Content-Type`: *application/x-www-form-urlencoded*

Una actualización siempre incluirá al menos los siguientes tres atributos en sus datos de formulario:

- `grant_type`: *refresh_token*
- `scope`: &lt;SCOPES>
- `refresh_token`: &lt;REFRESH_TOKEN>

Si usas PKCE, deberás incluir el `client_id` de tu aplicación en estos datos de formulario; si no, deberás incluir un encabezado de autenticación Basic con el `client_id` y el `client_secret` de tu aplicación como nombre de usuario y contraseña, respectivamente.

### Sin PKCE {#without-pkce-1}

Al igual que al [realizar el callback de autenticación inicial](https://developer.frame.io/oauth-2-applications/building-an-oauth-2-app#the-callback) sin PKCE, esta actualización estándar requerirá proporcionar tu `client_id` y tu `client_secret` como nombre de usuario y contraseña en un encabezado de autenticación Basic.

```python title="Python"
def refresh():
  # Fetch the refresh token, assuming we have it
  REFRESH_TOKEN = os.environ.get('REFRESH_TOKEN')

  client_auth = requests.auth.HTTPBasicAuth(CLIENT_ID,CLIENT_SECRET)
  post_data = {
    "grant_type": "refresh_token",
    "scope": SCOPE,
    "refresh_token": REFRESH_TOKEN
    # if using PKCE, you will need to include your client_id as below
    # "client_id": CLIENT_ID 
  }

  response = requests.post(TOKEN_URL, auth=client_auth, data=post_data)
  # Catch + stash a new Refresh Token
  os.environ['REFRESH_TOKEN'] = response.json()["refresh_token"]

  return response.text
```

### Con PKCE {#with-pkce-1}

Una vez más, imitamos las reglas de nuestro ciclo inicial de `/callback`:

- No incluimos un encabezado `Authorization`
- Debemos incluir el `client_id` en nuestro payload

```python title="Python"
def refresh():
  # Fetch the refresh token, assuming we have it
  REFRESH_TOKEN = os.environ.get('REFRESH_TOKEN')

  post_data = {
    "grant_type": "refresh_token",
    "scope": SCOPE,
    "refresh_token": REFRESH_TOKEN
    "client_id": CLIENT_ID 
  }

  response = requests.post(TOKEN_URL, data=post_data)
  # Catch + stash a new Refresh Token
  os.environ['REFRESH_TOKEN'] = response.json()["refresh_token"]

  return response.text
```

¡Felicidades! Ahora puedes gestionar todo el ciclo de vida de los tokens de una aplicación cliente OAuth2.0.
