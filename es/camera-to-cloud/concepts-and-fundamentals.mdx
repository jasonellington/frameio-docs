## Conceptos básicos de redes y glosario {#networking-basics-and-glossary}

En esencia, la API de Frame.io permite la comunicación entre los servidores de Frame.io y tu dispositivo o aplicación, lo que requiere interacciones de red para cada operación.

Una comunicación clara es esencial en cualquier relación, incluida la que existe entre servidores y clientes. Del mismo modo que se producen malentendidos en las conversaciones cotidianas, existen desafíos similares cuando los ordenadores intercambian información.

Además de resolver los problemas habituales de comunicación, debemos garantizar la transmisión segura de datos confidenciales. Frame.io exige el cifrado de todas las comunicaciones con el servidor, lo que añade las capas de seguridad necesarias al proceso.

Al implementar la API C2C, probablemente utilizarás bibliotecas de terceros para gestionar los detalles de red. Sin embargo, como los componentes de red suelen generar errores en situaciones reales, es útil comprender los procesos subyacentes al interactuar con los servidores de Frame.io. Aquí tienes un glosario conciso de la terminología esencial:

<CardGroup cols={2}>

<Card title="TCP/IP" icon="network-wired" iconType="solid">

Transmission Control Protocol / Internet Protocol: componentes y capas estandarizados que permiten la transferencia de datos a escala mundial. Para obtener más información, recomendamos este [recurso accesible y de alto nivel](https://www.freecodecamp.org/news/what-is-tcp-ip-layers-and-protocols-explained/).

</Card>

TLS representa la evolución de SSL, aunque el acrónimo original sigue utilizándose ampliamente. Para obtener más información sobre TLS, [consulta esta descripción general](https://www.internetsociety.org/deploy360/tls/basics/).

</Card>

### Claves públicas y privadas {#public-and-private-keys}

Una clave pública funciona como un candado, mientras que una clave privada actúa como la llave correspondiente.

Imagina este escenario: quieres enviar un mensaje confidencial a un colega y garantizar su privacidad hasta la entrega.

Primero, pide a tu colega que te envíe un candado del que solo él tenga la llave.

Al recibir ese candado, guarda tu mensaje confidencial en un contenedor y ciérralo con él. Aunque cualquiera que manipule el contenedor puede ver el candado, solo tu colega tiene la llave para acceder al contenido. El candado no tiene ningún valor para terceros no autorizados que intenten ver el mensaje. Ni siquiera tú puedes abrirlo sin la llave.

Cuando tu colega recibe el contenedor cerrado, simplemente usa su llave para acceder al contenido.

Las claves públicas y privadas funcionan de la misma manera. Puedes compartir una clave pública ampliamente. Los destinatarios cifran los mensajes con esta clave, pero solo quien posee la clave privada puede descifrar esas comunicaciones. Mientras la clave privada se mantenga confidencial, la clave pública no puede utilizarse para descodificar los mensajes cifrados que genera.

Este mecanismo de claves públicas y privadas es la base del funcionamiento de TLS, ya que permite que las partes se comuniquen abiertamente mientras establecen canales seguros y privados.

### Certificados {#certificates}

Los certificados contienen claves públicas y privadas, autenticadas por autoridades de certificación de confianza.

Cuando una autoridad de certificación valida una clave, básicamente garantiza su autenticidad. Quienes reciben una clave pública (por ejemplo, una de Google) pueden verificar este respaldo por parte de autoridades de certificación reconocidas. Las claves sin respaldo se consideran potencialmente fraudulentas y activan alertas de seguridad.

Los certificados de Frame.io están validados por la autoridad de certificación Amazon Root CA 1. Estos certificados están disponibles a través de diversos recursos, como la biblioteca Certifi (utilizada por Mozilla y por la biblioteca Requests de Python).

Para la implementación, recomendamos el [repositorio de GitHub](https://github.com/certifi/python-certifi) de Certifi y su [paquete de certificados PEM](https://github.com/certifi/python-certifi/blob/master/certifi/cacert.pem) para validar las solicitudes HTTPS a api.frame.io.

Un ordenador que proporciona o almacena información para otros ordenadores. Cuando accedes a Frame.io a través de un navegador web, tu navegador solicita contenido al servidor de Frame.io, que responde en consecuencia. <CardGroup cols={2}>

<Card title="HTTP/S" icon="globe" iconType="solid">

Hypertext Transfer Protocol / Secure: opera dentro de la capa de aplicación del modelo TCP/IP. La diferencia entre HTTP y HTTPS es la seguridad: HTTPS incorpora la verificación TLS/SSL en las comunicaciones de red. HTTP ha evolucionado a través de varias versiones, estableciendo nuevos estándares con el tiempo. La versión 1.1 sigue siendo el estándar mundial y debe utilizarse para las comunicaciones con la API de Frame.io.

</Card>

<Card title="API RESTful" icon="code" iconType="solid">

REST (Representational State Transfer) es una metodología de diseño para desarrollar API basadas en patrones de solicitud-respuesta HTTP. REST suele utilizarse como forma abreviada para referirse al enfoque general de usar HTTP para la interacción entre programas (a diferencia de la comunicación entre un navegador y una página web), incluso cuando la API no se ajusta estrictamente a los principios REST.

</Card>

</CardGroup>

JavaScript Object Notation: un formato estandarizado de intercambio de datos. Aunque se desarrolló inicialmente para objetos de JavaScript, se ha convertido en un estándar universal para las comunicaciones en red. La API C2C entrega sus respuestas como datos JSON.

## Solicitudes HTTP/S {#http/s-requests}

HTTP está presente en toda la navegación web: aparece al principio de casi todas las direcciones de sitios web. HTTP (Hypertext Transfer Protocol) establece protocolos estandarizados de comunicación entre ordenadores.

Puedes pensar en HTTP como un sistema estandarizado de formularios para las interacciones cliente-servidor, similar a los formularios oficiales que se exigen para solicitar información o inscribirse en programas. Sin formularios correctamente cumplimentados, los organismos públicos no pueden procesar ni responder a las solicitudes.

Las solicitudes HTTP permiten todas las interacciones con la aplicación Frame.io. Dentro del marco de la API C2C, los tipos de solicitudes HTTP representan las capacidades funcionales disponibles.

Para obtener una descripción completa de HTTP, consulta [este artículo informativo](https://www.freecodecamp.org/news/http-and-everything-you-need-to-know-about-it/). Comprender estos fundamentos es esencial antes de continuar. Si eres nuevo en las solicitudes HTTP, considera revisar material introductorio. Para prepararte de forma óptima, familiarízate con estos conceptos de HTTP:

## Autenticación y autorización {#authentication-and-authorization}

Exploraremos estos conceptos con más detalle más adelante, pero es importante comprender estos principios fundamentales:

<CardGroup cols={2}>

<Card title="Autenticación" icon="key" iconType="solid">

La autenticación verifica que las solicitudes proceden de las fuentes que dicen ser. Cuando inicias sesión en sitios web con un nombre de usuario y una contraseña, te autenticas demostrando que conoces la contraseña. La autenticación multifactor (como recibir códigos de verificación por mensaje de texto) representa mecanismos de autenticación adicionales.

</Card>

<Card title="Autorización" icon="user-shield" iconType="solid">

La autorización confirma el permiso para realizar acciones específicas. Cuando añades colaboradores a proyectos de Frame.io o a documentos de Google, estás autorizando su acceso. Frame.io o Google han autenticado previamente la identidad de esos usuarios, lo que te permite autorizar su participación con confianza.

</Card>

</CardGroup>

<CardGroup cols={2}>

<Card title="OAuth" icon="lock" iconType="solid">

OAuth (Open Authorization) proporciona un marco estandarizado para la gestión de autorizaciones mediante la integración con servicios de autenticación de terceros.

</Card>

<Card title="Ámbitos" icon="list-check" iconType="solid">

Los ámbitos (scopes) definen las acciones autorizadas disponibles para los usuarios. Al conectar dispositivos a Frame.io, solicitarás y recibirás ámbitos específicos que autorizan determinadas operaciones. Por ejemplo, el ámbito `asset_create` permite crear y subir assets. Conceptualmente, los ámbitos funcionan como conjuntos de permisos.

</Card>

</CardGroup>
